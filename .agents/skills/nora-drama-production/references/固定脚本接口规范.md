# 固定脚本接口规范

资源项目的请求按[项目资源与版本管理](../../studio-workspace-browser/references/项目资源与版本管理.md)传准确输入版本；返修填写`resource_id`，实际编辑源填写`base_file`，新视频目标可填写稳定`resource_key`。下方旧目录示例只表示业务对象名和原记录位置，受理后实际输出返回资源版本路径；新记录使用该返回路径，不再写阶段媒体副本。已提交旧清单及原请求保持历史事实。

## 视频批准的一次收尾

常规一采、二采批准及[后处理自动采用](逐集目录与资产管理规范.md#后处理自动采用)使用[video_approve.py](../scripts/video_approve.py)，一次完成采用登记、实际来源记录、业务进度更新和运行网页核对。场次画布需要单独留档时使用下文入口。不上传素材、不调用生成或媒体处理、不清缓存、不自动进入下一制作阶段。

后处理存在[同轮次产物清单](逐集目录与资产管理规范.md#同轮次后处理产物)时，采用单位为整个R，全套产物一起归位；默认文件只作选定入口，采用计数按轮次。清单不授予批准。重复请求核对全套文件及当前采用后复用，不重新生成。无交付声明的历史已完成请求仍只读返回原收据；迁移或新增交付须另存接续请求，不能改写原请求。

Agent只确定具体采用身份、用户批准原话或后处理自动采用依据，以及原提交清单，填写一份请求；不逐段提取技术来源，不手写两套技术来源清单、进度替换原文、包配置或网页请求。请求放在本批最前P的实际共同执行附件，例如：

```json
{
  "approval_text": "按后处理自动采用规则录入。",
  "approval_scope": "来源二采EP001-C001-P001-R001-二采及EP001-C001-P002-R001-二采已获批，批准入口见对应视频工作稿审阅区；本批后处理按规则自动采用。",
  "identities": ["EP001-C001-P001-R001-后处理", "EP001-C001-P002-R001-后处理"],
  "postprocess_delivery": {"EP001-C001-P001-R001-后处理": "workflow", "EP001-C001-P002-R001-后处理": "workflow"},
  "submission_plans": ["09-剧集制作/EP001/其他资料/执行附件/EP001-C001-P001-R001-后处理/任务清单.json"]
}
```

```sh
python .agents/skills/nora-drama-production/scripts/video_approve.py \
  --project projects/项目名 \
  --plan 09-剧集制作/EP001/其他资料/执行附件/EP001-C001-P001-R001-后处理/批准收尾请求.json --apply
```

Python 3.11+、标准库。正常批准直接执行一次`--apply`；默认不带此参数只读核对采用输入，不移动、不留档、不联网，也不写结果。不要例行先预览、再执行、再人工重查同一批数据。

- `identities`必须逐项指明同一集、场次、阶段中的EP/C/P/R，不能写“最新”或由脚本解释自然语言；同一P只选一个版本。`approval_text`必须是用户实际批准原话；后处理自动采用时填写“按后处理自动采用规则录入”或用户实际授权原话，在`approval_scope`注明“来源二采已获批，后处理按规则自动采用”及具体来源二采身份／批准入口，不伪造新增审片反馈。`approval_time`可选带时区时间，不猜填，自动采用登记时间不当作用户后处理审片时间。用户限定画面、音轨或接受已知缺陷时，填写`approval_scope`保留实际批准范围，不扩大决定。
- 后处理新增请求必填`postprocess_delivery`，键与`identities`逐项一致，值仅`workflow`（只有常规工作流交付）或`products`（本轮包含定制／多产物交付）。这是Agent依据已有制作计划填写的类型声明，不增加用户审批。`products`要求该身份下的`后处理产物.json`及本轮全部产物齐备；`workflow`遇到已有产物清单也会停止，不能借普通类型绕过清单。所有分段预检通过后才开始采用。缺文件或类型冲突先补齐既有计划，不能改为workflow先收尾。
- 清单逐项填写现有产物路径；常规来源也须列入。收尾工具预检全套文件后统一移动到阶段采用目录，更新清单、播放关联和采用记录。兼容历史清单中常规来源填写采用目标的方式，以原输出凭据核对候选。更换采用时整套旧轮次退回候选位置。默认展示项不限制批准或下载范围；MP4凭据不作为MOV字节证明。
- `submission_plans`填写本次批准对象实际使用的原任务清单，可跨原批次；单段返修只需提供返修任务清单。来源读取先按`identities`筛选，再读取命中任务的执行结果；同一清单内未选中的失败或未完成任务不阻塞本次批准，不再为此手工拆出来源清单。选中对象的来源缺失或冲突仍报错。脚本从这些清单读取本次批准对象的实际来源；整场齐备后，对未在本次清单中的其他当前采用段，自动从其工作稿链接的已完成留档记录补齐实际映射、API、画布及取回凭据。尚未形成整场留档时，从当前采用所关联的人工审核记录读取明确的任务映射和凭据，并复用同任务固定的`任务.api.json/任务.workflow.json`。只按完整采用身份关联，不扫描历史猜最新R版本；缺少来源或关联冲突时返回具体缺项。只批准`identities`；未获批其他段保持原状。部分批准后整场尚未齐备时只收尾采用；最后一部分批准使整场齐备时，一采、二采沿整场当前采用组合补齐来源后统一留档；后处理直接完成业务收尾。
- 批准结果通过`stage/sources`保存该阶段实际采用身份、映射、请求来源及选定文件；后处理从二采批准报告读取，旧`finalization`报告继续兼容读取。
- 留档时如来源AiMixer 导演台编辑区仍保存旧正文，工具在实际API与提交请求一致、选中范围明确且正文匹配冻结资料的前提下，仅将导出副本编辑区同步至实际执行根时间线，并在`restoration`留证；不回写原API、画布或请求，不接受实际正文与冻结文本不符。
- `edition`等导出参数只在下方独立导出请求中使用，不在批准时自动执行。
- `summary`可选，指定本集既有生成说明或分镜索引工作稿。项目进度使用既有`EP编号制作`行；旧项目缺少该行、分镜索引或模板字段时返回具体缺项，不猜写另一种结构。
- 常规采用、业务记录和网页核对在同一次调用完成，`timings_seconds`返回各段耗时；结果保存在请求旁的`请求名-结果.json`，保留失败经过，不新增效率台账。`--timeout`默认为30秒，约束网页请求及网页同步等待；“正在检查”和“正在更新”均结束后才判断同步错误并核对网页，期间有界等待，不让Agent接管轮询。

`state=completed`表示本场该阶段采用及网页核对完成，其中一采、二采还须完成定稿留档；只有`episode_completed=true`才表示正式分镜索引中整集各场的三阶段采用、一采二采当前版本留档及网页“已完成”均已核实。`adopted_partial`表示所批对象已采用、整场仍未齐备。成功后Agent依据报告交付，不再人工重复逐段核对、采用进度更新或网页核验；`episode_completed=true`后的业务收尾按[完集复盘](../../nora-drama-handoff/references/逐集目录与资产管理规范.md#完集复盘与经验维护)接续，该字段不表示复盘完成。此时同时返回`retrospective={status:"pending"|"completed",record:生成说明工作稿绝对路径}`：`pending`对应`next_action=episode-retrospective`，`completed`对应`next_action=deliver-completed`。完成判据与接续写法由上述复盘规则维护；同一批准重复调用复用当前复盘结论，采用身份变化时重新打开受影响的复盘待办。

异常返回失败阶段及结果文件：`needs_attention`交Agent处理真实缺项或冲突；`browser_pending`保留已完成的本地采用与定稿，同请求恢复时仅接续网页核对。成功结果重复调用会先核对本次交付及原整集完成判据所需的当前文件；缺项时停止并保留原批准与报告，不复用已失效的整集完成结论。核对通过后复用，不重复移动、导出或发起生成。完全一致且缺少`postprocess_delivery`的旧后处理成功请求仅返回`historical_receipt=true`历史回执，不改记录，也不表示重新核验当前完成状态。新的批准决定另存请求，不能改写已有请求覆盖原批准。采用替代影响已有下游、必要配置冲突、未授权拆批、旧记录无法确定来源等业务判断仍由Agent按用户授权处理；工具不能自行批准、改内容或重生成。

回归：`TMPDIR=/private/tmp python -B -m unittest discover -s .agents/skills/nora-drama-production/scripts -p test_video_approve.py -v`。使用临时项目和模拟导出／网页，覆盖12段新后台后处理格式的零导出收尾、独立任务分批批准后整场来源补齐、一采二采的首段及末段连续返修、自动002／003版和旧包保留、重复调用、网页失败接续、来源缺失、一采留档失败、二采留档依赖及阶段边界；不修改真实项目或提交生成。macOS使用上述物理临时目录；其他平台按本机实际临时目录运行。


## 视频批准后的采用收尾

常规批准走[一次收尾入口](#视频批准的一次收尾)。以下接口用于明确只做采用、旧资料适配及具体故障恢复；不再要求Agent为常规批准手写这些技术字段。

入口：[video_adopt.py](../scripts/video_adopt.py)。这是独立于通信客户端的短剧业务工具，Python 3.11+、仅标准库；复用客户端的严格JSON读取、JSON编码和本机带时区时间，不依赖 `tzdata`。用户批准具体视频后，用它移动文件、更新采用和审核记录；适用于已取回或本地修改完成的一采、二采、后处理视频。采用、替代和整集完成标准唯一从[逐集目录规范](逐集目录与资产管理规范.md#视频采用记录与批准依据)读取。

agent根据用户实际批准范围准备数据文件，不编写修改脚本。将计划命名为 `采用请求.json`，保存在对应真实执行附件；同一共同任务可以列多个获批分段，不要求它们全部获批。以下JSON示例的身份、实际执行映射、取回响应以及 `old` 原文须按项目现状替换：

```json
{
  "approval_text": "第7段通过了。",
  "approval_time": "2026-10-10T13:40:05+08:00",
  "items": [
    {
      "identity": "EP002-C001-P007-R005-二采",
      "mapping": "09-剧集制作/EP002/其他资料/执行附件/EP002-C001-P007-R005-二采/输入映射.json",
      "receipt": "09-剧集制作/EP002/其他资料/执行附件/EP002-C001-P007-R005-二采/取回响应-001.json",
      "execution_heading": "R005-二采"
    }
  ],
  "record_updates": [
    {
      "path": "09-剧集制作/EP002/其他资料/工作稿/EP002-生成说明-工作稿.md",
      "old": "- 当前状态：P007二采待审核；其他段见各工作稿。",
      "new": "- 当前状态：P007 R005二采已批准采用；其他段见各工作稿。"
    },
    {
      "path": "项目进度.md",
      "old": "| EP002制作 | 既有会话入口 | 待确认 | P007二采候选 | P007二采待审核 | 按实际决定采用 |",
      "new": "| EP002制作 | 既有会话入口 | 进行中 | P007 R005二采已采用 | 其余分段见工作稿 | 按已有授权接续 |"
    }
  ]
}
```

在工作区根目录运行（独立技能安装替换工具路径）：

```powershell
python .agents/skills/nora-drama-production/scripts/video_adopt.py --project 'projects/示例项目' --plan '09-剧集制作/EP002/其他资料/执行附件/EP002-C001-P007-R005-二采/采用请求.json'
python .agents/skills/nora-drama-production/scripts/video_adopt.py --project 'projects/示例项目' --plan '09-剧集制作/EP002/其他资料/执行附件/EP002-C001-P007-R005-二采/采用请求.json' --apply
```

参数与计划字段：

| 字段 | 含义及默认行为 |
| --- | --- |
| `--project` | 必填项目根；从当前工作目录解析。所有计划中的资料路径相对该项目根解析，也可传项目内绝对路径；资料越界路径拒绝。 |
| `--plan` | 必填采用计划JSON；相对路径按项目根解析，也可用绝对路径。正式计划存实际执行附件；只读检查可传项目外临时计划，计划中资料仍须位于项目内。默认只读预览，不写任何项目文件；`--apply` 才执行。 |
| `approval_text` | 必填用户批准原话。没有明确批准不能填；工具不推断批准范围。 |
| `approval_time` | 可选实际决定时间，带时区；省略时明确“实际决定时间未记录”，另记本次登记时间，不冒充历史决定时间。 |
| `items[].identity` | 必填完整 EP/C/P/R/阶段，阶段仅一采、二采、后处理；重复对象拒绝。不接受整集、全部、最新等模糊对象。 |
| `items[].postprocess_delivery` | 后处理必填`workflow`或`products`，语义及清单完整条件与上方一次收尾接口一致；一采／二采不填。独立采用入口不以旧请求缺字段为理由创建新采用。 |
| `items[].mapping` | 必填实际执行输入映射，关联对应 `generation_contexts[].identity` 及本段输出。ComfyUI执行需真实prompt ID；本地修改使用下述实际修改记录，不借用来源任务ID。支持 `outputs`、`runtime_retrieved`，或单段 `output`；不修改请求、生成上下文或技术状态。 |
| `items[].receipt` | 必填实际输出凭据。远端取回复用固定下载响应的 `data.bytes/sha256/remote`；本地修改用下述输出记录。共同目录外的凭据必须已在映射中明确关联；不新增批准哈希。 |
| `items[].approval_scope` | 可选实际批准范围，默认所列具体文件；用户限定画面、音频或接受已知缺陷时必须传入原意，不扩大批准。 |
| `items[].review_entry` | 可选实际网页审核入口，写可读链接；缺省如实标为未记录，不编造已展示事实。 |
| `items[].source` | 可选，默认本集 `其他资料/候选视频/{identity}.mp4`。其他实际格式或旧位置须传实际路径，文件名须为本身份加实际扩展名；保留原格式和文件名，不转码。目标按阶段采用目录确定。 |
| `items[].execution_heading` | 可选，默认 `R编号-阶段`。旧章节如 `R004后处理故障接续-001` 应明确传完整标题；标题须唯一，章节字段须标明本次阶段。 |
| `items[].related_mappings` | 可选父映射路径数组。仅同步 `current_execution.mapping/prompt_id` 明确指向本次执行的父记录；原prompt、旧终态、历史输出凭据保留。 |
| `summary` | 可选单集既有业务汇总入口，限本集生成说明或分镜索引工作稿；缺省使用生成说明。多集采用计划保持各集默认入口。 |
| `record_updates` | agent按当前事实准备的定点替换数组，字段为 `path/old/new`，只允许涉及集的业务汇总工作稿（默认生成说明，单集可由 `summary` 指定既有分镜索引工作稿）和项目进度。正式采用要求两类入口均有更新；事实无变化可 `old=new`。原文匹配须唯一；已是唯一新文时不重复更新；他人改动导致失配就停止。可列多处，包含移动后需要更新的链接。 |

本地直接修改视频时，实际输入映射的 `local_edit` 记录 `tool/source/source_file/parameters`（工具、完整来源身份、项目内来源文件及实际参数），与 `generation_contexts` 的来源保持一致；本段输出记录 `path/bytes`，已有 `sha256` 时复用，没有不补造。`receipt` 可指实际输出响应，也可指含单段 `output` 的本地映射本身；不填ComfyUI prompt ID。仅采用已生成的文件，不执行视频修改。目录迁移后，实际文件、原输出凭据及现有批准关联一致时，可同步映射中的当前位置，保留原批准时间，不新增审核决定。

工具按现有格式自动更新：阶段选定行、具体审核章节及决定、该阶段执行条目的审阅引用、输出入口和取回核对状态、移动／替代记录、输入映射的 `adoptions`。审阅正文直接读取[现有模板](../templates/视频人工审阅区模板.md)，不另维护一份结构。每个分段的其他阶段保留；不更换R、不把生成成功当审核通过。返回JSON包含逐项 `adopt/already_adopted`、移动清单、受影响工作稿／映射、各阶段已采用数量；预览的 `required_record_updates` 列出缺少的收尾入口。标准输出供当轮留证，不为保存结果再运行一次。退出0表示预览或执行成功，退出1表示检查或I/O错误。

执行前完成本批所有检查。已采用同一文件且记录齐备时调用不会重复移动或新增审阅；目标文件与取回字节不同、候选／采用两处同时存在同名文件、记录失配或替代影响已选定下游时停止。磁盘写入使用同目录临时文件替换单个记录；跨文件操作不构成数据库事务。移动或写入期间I/O错误可能已有部分动作，按实际文件位置核对后收尾：例如视频已移入采用目录但文字未写完，同计划可完成登记；旧版本退回候选发生冲突时需先定点处理。不能因此重生成或覆盖冲突文件。

本工具始终离线，不调用ComfyUI、不处理媒体内容、不自动采用整集、不更新定时器。返回 `browser_sync=not_checked`，网页读取核对仍按[项目浏览入口规范](../../nora-serial-drama/references/项目浏览入口规范.md)执行，不能把本地成功写成网页同步成功。独立采用工具的工作稿计数不代表整集完成；常规批准的进度与完成判断由[一次收尾入口](#视频批准的一次收尾)按正式范围及批准事实处理。

后台格式的输入映射未内嵌任务ID和成果时，采用与定稿工具读取同一执行附件的`后台任务状态.json`和`提交响应.json`，核对实际提交、目录、分段身份及指定取回凭据。原生 AiMixer 导演台按后台分段结果关联；后处理等普通保存节点按后台输出选择器的节点、输出类型及序号关联`执行结果.json`中的真实远端文件，核对成功任务ID与下载凭据，不要求普通下载响应包含AiMixer 导演台分段字段。旧映射内嵌格式继续支持；读取时关联执行元数据，不将派生字段补写到历史输入映射，只按既有规则追加采用或定稿记录。

参数及输入格式：

| 字段 | 含义 |
| --- | --- |
| `--project` | 必填项目根，相对当前工作目录；数据中的路径均相对项目根，也可填项目内绝对路径。拒绝越界。 |
| `--plan` | 必填留档请求；相对项目根，也可用绝对路径。默认只读预览，预览不联网、不写项目；正式请求放既有共同执行附件。 |
| `--apply` | 保存汇总API、场次画布及来源记录，不调用 `/prompt`、上传、队列操作、缓存操作或媒体后处理。 |
| `episode/scene/stage` | 必填完整EP、C编号和阶段名，阶段只允许一采、二采。 |
| `items[].identity` | 必填完整EP/C/P/R/阶段。与正式索引及当前选定表逐一对应；脚本读取所链接的具体人工批准决定，未获批、重复或缺段即停止。 |
| `items[].mapping/api/canvas/receipt` | 模型原片填写实际执行映射、实际API、配对画布和该段取回凭据。映射旁的 `请求.json` 和 `提交响应.json` 必须对应真实任务。取回凭据位于共同执行附件，或由输入映射明确关联到分段附件。远端文件身份和采用文件字节均须一致。整段静音衍生填写本地映射及输出凭据，`receipt` 可指向包含单段 `output` 的映射本身。 |
| `items[].generation_source` | 已采用的本地整段静音衍生填写原模型视频的 `identity/mapping/api/canvas/receipt`。本地映射的 `operation` 为 `local-video-audio-removal`，`local_edit.source` 与生成资料的 `source` 使用同一个完整来源身份字符串。按实际处理记录填写 `source_file`、`parameters` 及输出的 `path/bytes`。工具分别核对采用文件和原生成文件，留存两套身份、原模型正文、参考素材与输入参数。二采仍核对原生成缓存。 |
| `edition` | 可选三位留档序号，如 `002`。省略时自动匹配已有相同来源的留档；来源变化则取该场、该阶段及同配置批次已占用序号的最大值加一，无序号首版视为001。画布、准备API及留档记录共用此序号；已有中断记录也占用原序号。显式填写时按指定序号另存，保留原附件；不增加生成R编号。 |
| `summary` | 可选已有的本集业务汇总工作稿路径，默认 `其他资料/工作稿/EP编号-生成说明-工作稿.md`；已有项目使用分镜索引工作稿汇总时明确指定它，不创建第二份记录。 |
| `configuration_batches` | 仅用于用户明确允许的按配置分批例外，数组中每项为 `{"name":"标准版","parts":["EP001-C001-P001"]}`。各批合计必须完整覆盖该场全部P段且各段仅归属一批；同批必要配置仍须一致。批次名只允许字母、数字、汉字、下划线和连字符，用于定稿文件名及记录章节。默认不分批。 |
| `configuration_batch_authorization` | 使用上述分批时必填本次用户明确允许的依据；脚本不能自行填写授权。先核对全部批次，再逐批保存场次画布及来源，已有批次按原中断恢复机制核对复用，不自动重导。 |

准备和核对全部成功后，整场汇总只保留实际获批各P；根时间线、r2v编辑工作区、组序和计划帧数同步。公共正文／引用不同而其他配置兼容时，把原公共正文和媒体移入各自组，保留绝对标签和本组覆盖公共同槽的对应关系。模型链、SIGMAS、Refine、种子、尺寸或其他必要控件冲突时，返回具体来源身份并停止，不自动统一。当前支持原生r2v分组；带源视频或关键帧时间轴的工程、旧公共referenceVideo差异不自动改造，需先解决说明中的具体缺项。

目录和文件名按业务真源确定。`--apply` 将场次画布放入阶段目录，汇总 API 和留档记录留在最前分段的共同执行附件。来源记录保留逐段身份、任务ID、种子、采用文件和批准入口，并在输入映射登记 `scene_finalizations`。相同来源复用原档，新来源递增留档序号。已有不同内容的资料拒绝覆盖，重复调用只补齐同一版本。

### 从已采用二采生成后处理清单

常规整集后处理使用[video_postprocess_plan.py](../scripts/video_postprocess_plan.py)准备清单和逐段画布。先完成二采采用留档，并用既有修改轮次入口登记本次后处理组合；Agent只提供该轮次、已完成的批准收尾报告、已选定配置与执行授权，不再手工逐段提取来源、拼执行目录或填写画布控件。

请求保存在本次共同执行附件，字段示例：

```json
{
  "episode": "EP001",
  "round": 3,
  "video_postprocess": {"resolution": [1920, 1080], "fps": 30, "fit": "crop"},
  "authorization": "用户本次实际后处理授权及范围",
  "approval_reports": ["09-剧集制作/EP001/其他资料/执行附件/EP001-C001-P001-R001-二采/批准收尾请求-结果.json"],
  "output_root": "E:/实际服务/output"
}
```

```sh
python .agents/skills/nora-drama-production/scripts/video_postprocess_plan.py \
  --project projects/项目名 \
  --request 09-剧集制作/EP001/其他资料/执行附件/本轮后处理/装配请求.json \
  --output 09-剧集制作/EP001/其他资料/执行附件/本轮后处理/任务清单.json
```

- `round`指定已登记且各P均为后处理的本轮组合；按其中场次、P顺序装配，不猜最新轮次或R。当前工具针对常规整集批次，不代替局部返修或定制后处理方案。
- `approval_reports`为`video_approve.py`输出的已完成二采收尾报告，可含多个场次。工具将报告中的准确来源与当前采用身份对应；当前采用变化、报告未完成或源文件缺失时停止，不以最高R代替采用决定。
- `video_postprocess`按[共用调用接口](../../studio-video-processing/references/视频技术处理规范.md#调用接口)填写，不含source；工具对每段准确采用来源执行ffprobe，再按目标规格装配，并在任务中绑定source。原规格使用`original`；不同比例须明确fit，不能默认裁切。旧请求的profile/orientation仍可接续，但不用于新问答。
- 已满足规格的片段写入清单`reused_sources`，不创建画布或任务；全部可复用时返回state=reuse。复用项沿原文件交回业务记录；任务清单的expected_video_count仅计实际待处理任务，业务轮次仍须核对复用项与处理项全部齐备，不把空任务清单送入队。
- `output_root`填写本次服务已有真实输出目录。成功仅表示本地清单及画布已生成，未上传、未入队、未批准任何视频。随后将生成的清单交`comfyui_dispatch.py --plan`执行既有准备检查及批量入队；不另做一次人工逐节点装配或例行重复预检。
- 清单或任何目标画布已存在时，在写入前停止；沿已有清单和装配结果接续，不能覆盖已执行证据。

回归：`TMPDIR=/private/tmp python -B -m unittest discover -s .agents/skills/nora-drama-production/scripts -p test_video_postprocess_plan.py`。临时项目覆盖不同R的准确采用来源、两种配置及横竖屏实际API导出、未完成／失效批准、缺失源文件和已有文件保护；不调用生成服务。


### 视频资料自动保存

一采、二采、后处理继续使用同一个提交命令，不增加手动关联命令。业务规则真源为[生成版本的资料关联](逐集目录与资产管理规范.md#生成版本的资料关联)，保存代码为[内部资料保存模块](../scripts/generation_context.py)；网页自动读取其输出的同一 `generation_contexts` 字段。

调用前在 `--record-dir` 指定的共同证据目录准备 `输入映射.json`。以下是输入接口示例，路径与编号必须换成实际任务值；`segments` 保留AiMixer 导演台完整原组序，`selected_indices` 仅列本轮实际选择的零起始组序号，不压缩未选组：

```json
{
  "scene": "EP001-C001",
  "scene_storyboard_version": "v21",
  "selected_indices": [0],
  "segments": [
    {"segment": "EP001-C001-P001", "round": "R004", "local_execution_dir": "09-剧集制作/EP001/其他资料/执行附件/EP001-C001-P001-R004-一采"}
  ],
  "uploads": [
    {"file": "03-人物资料/CH001/参考图/CH001.png", "input_path": "本轮实际上传目录/CH001.png"}
  ]
}
```

映射中的本地路径以项目根目录解析，也可使用项目内绝对路径；不得越出项目。`uploads`记录素材的本机来源映射；清单准备阶段可由`references`自动建立`planned/...`占位来源索引，上传后由后台关联真实远端路径及凭据。本轮新上传素材由后台依据下方上传绑定及实际响应补充到资料保存模块，`input_path` 分别与API的 `imageFile`、`videoFile`、`audioFile` 对应，复用旧上传也须记录本轮真实本地输入版本。它与下方 `--uploads` 的节点输入上传接口不同，不能相互替代。正式一采／二采沿用原生r2vAiMixer 导演台，公共开关 `global.commonEnabled` 显式填写；API实际选择状态、公共／本组正文及三类素材槽位决定保存内容。按 `refs`、`refVideos`、`refAudios` 依次保存图片、视频、音频，各类型按index排序且编号独立；本组同类型同槽位覆盖的公共素材不记作本段实际输入，公共开关关闭时不保存公共素材或正文。既有单视频 `referenceVideo` 兼容为视频index 0，存在原生同槽位时采用原生项，与[节点实际输入规则](../../studio-h3/references/ComfyUI-AiMixer导演台节点使用规范.md)一致。

二采在每个实际执行组中另填 `source`，指向同P获批来源的完整执行身份；二采保存自己的当次输入并保留来源。后处理只需场次、实际组序及含 `segment`、`round`、`source` 的分段项，来源为本次实际使用的完整执行身份，不另生成空提示词或参考素材。

可选的 `storyboard_file` 指定项目内已冻结分镜，仍核对 `scene_storyboard_version`；不填写时读取正式分镜。同R尚无完整结果的故障恢复按[修订与过程规则](逐集目录与资产管理规范.md#视频修订编号与执行过程)使用阶段目录内 `执行-YYYYMMDD-HHmmss/`，`--record-dir` 及各选中组的 `local_execution_dir` 对应该次位置；提交命令、文件名和防重检查不变，建立新位置不能代替旧任务的活动／接受核对。

每个 `segments` 项可选填写 `materials_from: {"mapping": "项目内原输入映射.json", "identity": "EP001-C001-P001-R001-一采"}`，引用同分段原关联的分镜、提示词与实际参考素材。工具按当前实际输入逐项核对正文、文件字节与槽位后引用旧冻结文件，差异时报错，不冒充沿用；新工作流/API仍单独保存。若素材有修改，不填写整套复用字段，按新输入冻结。复用不继承视频批准，也不递归推断最新资料。

无需填写 `materials_from` 也会自动复用相同PNG：POST前保存时，在同项目 `09-剧集制作/*/其他资料/执行附件/**/输入素材/` 查找大小及完整字节相同的PNG，排除历史版本目录，匹配后将本次 `references[].file` 指向该冻结文件，`original_file` 仍记录本次实际来源。只共享图片文件，不共享分镜、提示词、身份或批准；其他媒体仍按原方式冻结。已有 `generation_contexts` 或已有本任务副本优先保持原关联，重试不因出现另一份相同图片而改变路径。没有相同PNG时照常新建副本；保存或复用的任务输入PNG去除文件写权限，冻结资料不允许原地修改。

分镜版本、执行身份及正文对应在准备检查中确认，资料未变复用结论。后台完成素材上传后，在POST前按实际输入保存：正式场次分镜全文冻结为共同目录 `分镜脚本.md`；各P按[语言适配](../../nora-video-prompts/references/视频提示词制作规范.md#h3模型正文的语言与命名)编写的实际公共＋本组正文保存为其执行目录 `模型提示词.txt`；参考PNG按上段规则自动复用或首次冻结，其他图片、视频和音频参考素材冻结于共同目录 `输入素材/`；中文按[生成版本的资料关联](逐集目录与资产管理规范.md#生成版本的资料关联)从本组已核对文档自动提取、冻结为各P执行目录内的 `中文提示词参考版.txt` 并关联；历史冻结或复用资料保持原来源，无依据的旧任务不补译。最后自动补齐共同映射的 `generation_contexts`、记录时间与依据，保留原字段值。缺文件、映射不符或试图覆盖不同冻结资料时暂停任务并保存原因，不发送生成POST；同一准备输入重复检查不改写快照。保存资料不代表服务器已经接受任务，仍以提交结果的真实prompt_id为准。

图片任务不执行视频资料保存。原任务的防重复提交检查继续生效；已有历史缺项按业务规则核实证据后补记，不通过重新提交或从现行文档猜测恢复。


## 视频阶段编号迁移

编号规则由[逐集目录规范](逐集目录与资产管理规范.md#视频修订编号与执行过程)维护。已有记录须有明确迁移授权；固定工具 `../../scripts/video_revision_migrate.py` 只整理本地身份和引用，不联网、不生成、不变更审批。请求JSON包含 `episode` 和 `identities` 数组，每项填写完整的 `old`、`new`，下游另填写真实上游 `source`；先核对修订沿革，不以执行次数自动推算版本。

```powershell
python .agents/skills/nora-drama-production/scripts/video_revision_migrate.py --project "projects/项目名" --request "项目内的迁移请求.json" --database "工作区浏览服务/runtime/workspaces/nora/comfy-tasks.sqlite"
```

默认只读预览，返回身份对应、文件移动、记录及后台任务数量。确认预览与授权一致后，停止本工作区浏览服务，再用相同参数加 `--apply --report "项目名/99-综合资料/其他资料/历史版本/编号迁移-实际时间.json"` 执行；数据库参数指向该已停止服务的真实任务库。脚本拒绝活动任务、越出本集的身份、跨片段／阶段修改及覆盖无关目标。保留迁移前文本与任务行、旧新身份和路径对照；视频及原请求、工作流、响应、下载凭据只移动、不改字节。生成资料关联、当前取回映射、工作稿、审批链接、网页修改意见、后台当前结果入口随身份更新，原通知和事件不重发。导演包及画布是已导出的执行档案，保留原字节，来源引用按旧新身份对照追溯。

返回 `state=completed` 才表示本地迁移完成；恢复服务后还须核对网页各阶段候选号、原审批状态、来源资料与下载入口。失败按报告中的原记录和移动对照恢复，不再次执行同一迁移报告。不使用该工具迁移仍在运行的任务。验证命令：`python -m unittest discover -s .agents/skills/nora-drama-production/scripts -p test_video_revision_migrate.py`，覆盖跨阶段来源、编号重叠、原媒体／请求字节、审批／备注保留和活动任务拒绝。

将旧候选下某一次重复执行单独归为新候选时，在请求中只列这一项`identities`，并增加`execution`对象：`record_dir`为旧身份下`执行-YYYYMMDD-HHmmss`目录，`new_record_dir`为新候选执行目录，`source_output`和`target_output`为旧新视频路径（均相对项目根），`task_id`为这一条已结束后台任务的本地ID，`scene_modification_round`为新候选对应轮次。仍先预览，再停止服务后`--apply`；只移动指定执行及视频、更新其当前映射与这一条任务，并在输入映射的`identity_migration.report`关联完成的迁移报告；批准工具据该报告核对原凭据旧身份与新候选身份，不改写原取回凭据。原候选、批准、素材来源、请求、工作流及取回凭据字节保留。项目工作稿中的候选条目、轮次和下游计划按已授权对应关系同步，不对所有旧身份作全局替换。测试使用`TMPDIR=/private/tmp python -m unittest discover -s .agents/skills/nora-drama-production/scripts -p test_video_revision_migrate.py`（macOS使用物理临时目录），包括拆出一次执行且不影响原候选采用状态。

编号迁移完成后，有原任务清单的执行目录自动保存`迁移后来源清单.json`，仅供批准收尾的`submission_plans`指向实际当前执行目录；它链接原提交清单及完成的迁移报告，不用于提交生成。普通编号迁移和单次执行拆分均在当前输入映射中关联`identity_migration.report`，原请求及下载凭据不改字节。
