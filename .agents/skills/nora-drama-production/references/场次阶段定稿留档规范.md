# 场次阶段定稿留档

## 5. 保存与交付

正式制作的定稿包、配对画布及保存范围执行[第5.1节](../../nora-h3/references/ComfyUI-MiniMaxH3导演包制作规范.md#51-场次各阶段定稿留档)。导出响应、汇总准备API及来源记录按[共同证据归属](逐集目录与资产管理规范.md#多组任务的共同证据与状态)留在既有执行附件，不另存一份定稿包或配对画布。

单独获授权的测试导出沿用任务准备／执行附件或既有技术测试目录，文件名沿用本任务附件前缀，添加 `-导演包.mmxpack.zip` 与 `-导演包-导出响应.json`；测试包不登记为阶段定稿，也不要求从定稿目录复制一份。再次导出使用新的明确版本或序号，需要对比或复用的独立测试工程保留已有包；仅为下载或导入核验产生的重复副本及解压副本，核验后按[下载核验包清理](../../nora-serial-drama/references/文件版本与工作稿规范.md#下载核验包清理)收尾。导出本身不增加生成R编号。源画布/API和原素材映射保留，不能用包取代生成记录。

在既有准备或执行记录注明来源文件与版本、导出时间及服务地址、实际导演台ID、组与P映射、公共／本组标签、包与响应入口、文件完整性和缺失检查结论。记录当次事实，不另建同一任务的进度台账。

交付提供可下载包、匹配画布和简短导入说明。无需用户解压后逐张上传；素材随包导入。通用规范不保存真实项目媒体、服务器地址、任务ID或单次测试流水。

### 5.1 场次各阶段定稿留档

各阶段不主动或自动生成导演包及其配对整场画布；仅在用户明确要求本场、本阶段或指定范围的导演包时执行。导演包不作为进入二采、后处理或本集完成的前置条件。明确请求整场定稿包时，核对该范围的实际批准与来源，不把局部批准写成整场批准。后处理不导出导演包或另做整场定稿配对画布，保留实际后处理工作流、参数、输入来源、结果和[自动采用记录](逐集目录与资产管理规范.md#后处理自动采用)；后处理导演包不作为场次或本集完成条件。批准和导出不授权重新生成视频、切换执行阶段或清理缓存。

常规批准通过[视频批准一次收尾入口](固定脚本接口规范.md#视频批准的一次收尾)完成采用、来源汇总、业务记录及网页核对，不调用导出。用户明确要求导演包后，才使用[固定场次阶段留档脚本](固定脚本接口规范.md#场次阶段批准后的定稿留档)核对指定范围、原生导出、保存配对画布及完成导出记录。Agent理解用户的范围与授权，脚本处理明确来源的装配和技术核对。单独技术测试仍按第4节的原生导出入口执行。

用户明确要求导出时，每个场次的一采、二采分别依据各段的获批来源整理一份整场汇总工程，再原生导出一个该阶段的整场定稿导演包，并保存同版本的两项附件：

- **导演包**：`EP编号-C编号-阶段名定稿-导演包.mmxpack.zip`，阶段名填写一采或二采；按分镜顺序包含本场全部P段在该阶段最终采用版本的正文、素材、时长、衔接与包内配置。汇总工程的根时间线和编辑工作区保持一致，不夹带未采用版本或其他批次的历史整场草稿。不另造一种配置文件格式。
- **已配置画布**：`EP编号-C编号-阶段名定稿.workflow.json`，保存与该阶段整场定稿包配对的已配置节点、连线、模型链、SIGMAS、控件及导演台内容，不能用空白画布或通用基准代替。由多个执行来源整理时明确标注为整场汇总工程，不声称它是某一次实际执行的原始画布。

一采、二采按该阶段获批任务的实际配置汇总，配对画布保留实际生成配置；不将另一阶段的包和画布直接改名当作本阶段定稿。

定稿包与配对画布只保存到[逐集目录规范第4节](逐集目录与资产管理规范.md#4-视频执行输出审核与采用)规定的对应阶段定稿目录，不在执行附件、其他阶段或另一套正式目录重复保存。导出时将包的目标直接指定为该定稿位置，导出响应及汇总准备API按既有执行附件和共同证据归属留存；实际来源画布仍作为原任务证据保留，与新整理的配对定稿画布分别记录用途。在既有记录中逐P关联该阶段获批版本、实际来源API／画布、素材映射、任务ID、种子及批准依据，并登记整场包与画布的配对入口。原始请求和记录保持完整；核对整场包覆盖全部已获批P段且每段只出现一次，正文、素材标签、时长和配置与其获批来源对应。原生包内路径与服务端路径可不同，按素材映射核对对应关系。

分批执行或局部返修产生多个获批来源时，仍汇总为一个整场定稿包，历史来源工程用于追溯，不按来源批次分别导出多个场次定稿包。单段返修重新采用后，按正式分镜顺序重新汇总本场该阶段全部当前采用版本：返修段使用新批准版本，未返修段从其当前采用所关联的留档记录或人工审核记录自动补齐实际执行来源。不得按最大R编号、文件时间或其他未采用候选猜选来源；缺少明确依据或来源冲突时报告具体分段并停止留档，不撤销已经完成的视频采用。汇总只在新建的任务API／画布副本中进行，不改写来源文件，不重新生成视频；重排组序或重映射素材标签后核对其语义和实际媒体对应不变。缺少来源画布时依据其实际API与配套画布恢复并注明依据；来源无法确定时记录缺项，不猜填。

不同来源的公共设置、种子或其他控件存在差异时，按节点实际能力核对整场工程能否准确表达。无法在同一包及配对画布中保留必要配置时，说明具体冲突和受影响P段，待用户确定处理方式；不静默统一参数，也不自行拆成多套定稿包。未解决前不登记整场定稿留档完成。

这两项附件用于以后打开、调整和重新测试该场该阶段内容，不携带或恢复一采潜变量缓存。二采仍按各获批来源的原始组序、P映射和缓存接续，整场汇总工程不作为二采缓存命中的依据。后续编辑使用副本。用户再次明确要求导出、且当前采用来源变化后，递增本场该阶段的三位留档序号，另存新版整场导演包和同序号配对画布，保留原包、画布、留档记录及批准事实；来源变化本身不触发导出。无序号首版视为001，后续使用002、003等序号；已有更高序号时继续递增。实际来源与已有留档一致时复用对应版本；中断恢复沿用已分配序号和既有记录，不因重复调用再增加版本，也不自动重试失败的原生导出。明确指定的另存序号继续适用，不能覆盖已有不同来源的文件。包和配对画布均已导出、文件核对通过且记录入口可用后，才登记该阶段定稿留档完成；留档缺项不改变视频已获批的事实，问题在既有记录中注明并处理。定稿配对入口和详细完成经过保留在各P及本集既有工作稿；项目进度仅按[当前阶段字段边界](../../nora-serial-drama/references/会话与进度管理规范.md#4-项目进度文件)同步对应阶段行，不追加留档历史章节。
