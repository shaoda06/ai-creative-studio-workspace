# ComfyUI-服务配置与任务提交规范

### 视频执行分工

适用于已完成内容准备的一采、二采、后处理及视频返修执行。已有任务的局部返修在装配前按[执行快照与素材路径](../../studio-h3-aimixer/references/ComfyUI-AiMixer导演台节点使用规范.md#611-局部返修的执行快照与素材路径)确定实际来源，并在任务清单中落实远端素材复用及新上传范围。Agent只提交任务清单、读取入队结果和最终报告，完成结果按[整轮汇总规则](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md#3-跟进与通知)向用户汇报；不把剧本／分镜创作、语义判断或用户批准转成脚本推断。内容输入变化时返回对应内容环节；无变化的纯执行不重新读取整套创作技能和技术映射。

| 环节 | 脚本负责 | Agent负责 |
| --- | --- | --- |
| 提交前 | 导出API／画布；装配素材绑定、候选路径与下载凭据；新一采按已核定时长装配帧数、起点、总帧数及编辑区；为本次语义核对记录绑定输入／中文／依据指纹；准备检查复用同一份文件读取；建立或补空白的分段阶段条目，自动填实际参数、计划数值及证据入口 | 标准版先按[共用配置选择与装配前询问](../../studio-h3-aimixer/references/参数与基准规范.md#标准版配置选择与装配前询问)确定本次有效配置及其来源；把已备正文、素材用途、分段／轮次／阶段、内容判断与实际授权作为输入提交；不手算帧数、不抄指纹、不平行编辑API／画布、不手建技术条目 |
| 入队后 | 保存本地ID、上传、核对真实素材返回值及当前阶段缓存、冻结当次资料并跟踪；来源画布、节点ID、原组序及种子保持原接续关系 | 读取入队成功结果，汇报数量即结束本轮；不补记录、进度或查网页 |
| 生成后、通知前 | 按已确定身份取回本批成果；读取一次实际容器信息并记录尺寸、帧率、时长、视频轨／文件总码率和音轨；更新各P本R本阶段结果和待审区；合并同步并核验网页，保存可直接汇报的报告 | 无常规工作；不量视频、不抽帧、不写技术摘要、不再登记待审 |
| 收到通知 | 一次report读取并确认收到，返回视频数、阶段身份、成果绝对路径、实测信息及可直接打开的链接 | 按[正常视频结果](进度查询与结果处理规范.md#正常视频结果)处理 |

新一采的帧数装配必须在新的执行副本中显式选择；二采、返修及已有来源保持原任务画布和缓存输入，不能为同步技术字段改写来源或重算已获批一采。已有内容核对指纹不自动刷新；脚本只能绑定新提交的实际判断及原文依据，不能生成passed。当前远端缓存、队列与文件变化核验保护不同执行时点，由后台保留，不转交Agent人工复查。

已准备的正文、分段身份与参考来源在内容阶段一次写入任务清单和实际内容画布；提交不再从文件名猜P编号，不另抄上传位置或来源索引，也不平行补写API。准备失败后只处理报告指出的缺项。尚未登记的本地清单按[重新准备接口](../../studio-comfyui/references/固定脚本接口规范.md#未登记清单的重新准备)原地修正并重查，保留失败依据；已有本地任务ID的资料修正按[原任务重新准备与恢复](../../studio-comfyui/references/ComfyUI-服务配置与任务提交规范.md#重新调度与失败恢复)处理。依赖修正成功的同步和提交必须顺序执行，前项失败不继续提交旧输入；已通过且未变化的内容核对不重做。

媒体信息读取仅检查文件可读取性与客观容器／视频轨事实，不扫描画面、不做ASR、口型／连续性／质量评分，不按推荐码率或请求值判定画面通过。结果与请求目标分开保存；缺失信息如实记未提供，读取失败或文件变化报告技术异常，不自动重生成。正常报告读取不再探测媒体或写记录。历史已接受任务及旧报告不追溯补测；异常按报告的具体失败阶段处理。

默认登记为排队中；已获授权、需要先手动转移的任务可通过统一入口的 `--start-paused` 登记为暂停中。初始状态与任务一起保存，恢复前不上传或提交，暂停中的转移与恢复仍使用既有按钮规则。


### 准备资料的集中同步与检查

版本组合及其与执行时间线的职责按[修改轮次](../../nora-serial-drama/references/场次版本组合规范.md#场次修改轮次)维护。新视频任务必须在准备阶段填写`scene_modification_round`，字段名兼容保留，值使用该单集共用轮号，并核对任务所属场次在该轮的组合；同批多场只登记一次轮次。未选中执行组不作为播放版本来源，局部修改使用明确基轮登记。既有已登记任务继续保留旧场次轮次引用、原执行事实和兼容恢复，不借旧报告为新登记省略轮次关联。

准备报告在`prepared_input.scene_composition`保存所引用轮次的编号、剧本／分镜引用及完整分段组合，引用文档纳入既有文件状态比较；不把整份轮次JSON的修改时间作为任务依赖。追加其他轮次、修改轮次备注不使本任务准备结论失效；被引用组合或相关输入改变时停止并返回准备阶段。关联检查只合入已有准备及开工比较，未变复用，不另加提交或通知前的整套复查，不重查远端缓存或重复上传。

新视频任务由后台登记状态保存`scene_round_required`，恢复和重启继续执行轮次关联要求，不从请求参数或报告缺失推定旧任务。原登记没有此标记时保留其兼容范围，即使它已有`preparation_required`也不强加新轮次要求；原有准备、素材、身份和防重校验仍保留。显式修订并重新准备成功的未提交任务可启用新要求，不自动回填历史输入映射或审核。

内容准备、文件同步和工具检查分开处理。先根据当前授权及上游变化确定需要转写、修订或只核对的范围，不把“核对资料”默认扩大为整套重写；确需重写时说明具体受影响内容，不能为省时沿用已失效的正文。必要的剧情、人物、声源、动作因果、起止状态、对白、参考差异和段间设置核对仍按[模型正文的内容核对](../../nora-video-prompts/references/视频提示词制作规范.md#模型正文的内容核对)完成，格式通过不能替代内容通过。

同一批先完成正文、素材映射、实际分支所需API／画布、计划文件和相关来源说明的集中写入；已获授权提交时，由[统一装配入口](../../nora-serial-drama/references/固定脚本接口规范.md#一次装配与批量入队)一次完成检查与入队，本轮只准备时才加`--prepare-only`。检查成功且所覆盖输入未变时复用报告，不因更新通知、队列状态或无关说明再次检查。是否影响报告以工具记录的依赖范围为准，不自行排除实际使用的来源文件。发生具体内容变化、技术失败或依赖变化时修正对应部分，再检查受影响输入；不为证明完成而反复运行。

工作稿当前正文转为正式文件，使用[固定文档同步工具](../../nora-serial-drama/references/固定脚本接口规范.md#工作稿当前正文集中同步)，集中处理章节边界、标题层级、相对链接和换行，保留旧正式文件及原审阅记录。任务参数和新正文仍由Agent编写；不逐任务重写已有工具覆盖的解析、归档、链接换算或发布代码。实际模型英文由既有资料保存工具从本次API生成，不提前手写另一份冻结英文再反复比较；已有冻结文件继续执行原有对应和防覆盖检查。中文参考版仍须在准备阶段完成，不能在提交阶段临时补译。

读取范围及已读内容复用按[主入口的读取范围](../../nora-serial-drama/references/业务工作约定.md#读取范围)执行；写入后的网页核验按[交付前同步检查](../../nora-serial-drama/references/项目浏览入口规范.md#交付前同步检查)集中完成。固定工具失败时读取具体错误和所指文件后修正，不从头重读已满足且未变化的规则或整批资料；工具说明缺口在获授权维护中补齐，不用临时替代流程绕过。


## 业务准备、显示标题与旧报告补项

Agent准备提交时，按 `{对象编号} · {简短任务描述}` 编写标题，并显式传入统一入口的 `--task-title`。对象编号采用项目已有编号：整场任务使用EP/C编号，单段任务使用完整EP/C/P编号，资产任务使用对应人物、场景或道具编号；不为标题新增编号。描述说明本次具体要做什么，例如 `EP002-C001 · 首次生成`、`EP002-C001-P003 · 返修动作`、`CH001 · 调整发型`。

准备阶段完成剧本、分镜、实际模型正文与中文参考版的内容核对，在任务清单提供素材用途、来源／批准、成果用途和执行授权；固定技术副本与映射由工具装配。AiMixer 导演台的基准选择、固定参数继承、任务字段填写及历史来源复用，统一按[任务参数来源与准备提交](ComfyUI-H3视频执行规范.md#12-任务参数来源与准备提交)处理。默认`--plan`由工具在本次入队前执行技术检查；只需准备时使用`--prepare-only`，报告保存在同一执行附件的`执行检查报告.json`，不上传、不入队、不生成。Agent读取成功／失败及具体缺项，处理内容问题；报告不代替内容审核或用户授权。H3一采、二采的准备入口同时执行[正文检查](../../nora-video-prompts/references/固定脚本接口规范.md#h3正文与内容核对检查)，结果保存在同一报告的`content_checks`；具体内容核对顺序和证据要求只由[模型正文规则](../../nora-video-prompts/references/视频提示词制作规范.md#提示词编写与检查顺序)维护。
