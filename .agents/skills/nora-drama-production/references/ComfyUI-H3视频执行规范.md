# ComfyUI-H3视频执行规范

版本：v1.100；更新日期：2026-10-25。

本规范管理视频工作流的填写、执行与记录。制作顺序及审批读取[开发流程第二部分第7节](视频阶段与返修执行规范.md#7-生成视频验收与衔接修改)，后处理与其他视频修改的阶段归属读取[阶段与当前版本修改](视频阶段与返修执行规范.md#视频阶段与当前版本修改)；提示词正文读取[视频提示词制作规范](../../nora-video-prompts/references/视频提示词制作规范.md#6-分段视频提示词文档)及 `h3-prompt-writing`。准备资料、实际任务和人工审核按[逐集目录规范](../../nora-serial-drama/references/逐集目录与资产管理规范.md)保存，不把技术成功写成内容获批。

## 0. 制作策略与工作流配置

视频生成的默认入口为“Minimax-H3-导演台-视频生成-标准版”，使用同一画布，按“一采确认与二采”分轮执行。一采按[共用配置与装配映射](../../studio-h3/references/参数与基准规范.md#标准版配置参数)落实六步输入及关联预置；后处理在对应阶段按实际源片另行装配。正式生成使用原生MiniMax H3导演台，一采与二采通过同一画布分轮执行，输入模式默认为r2v / Ref2VA。准备或修改节点内容时按[导演台任务阅读路径](../../studio-h3/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#任务阅读路径)选读，覆盖本次组与P映射、素材、正文、时间线及执行所需条件。

| 工作流 | 当前用途 |
| --- | --- |
| Minimax-H3-导演台-视频生成-标准版 | 正式默认多功能画布，DMAD与343常开，Mystic和打戏组按本次选项启用；502为导演台，407为Refine；首次只一采，人工确认后再次执行二采；默认分段导出，403报告驱动执行 |
| [共用视频后处理工作流](../../studio-video-processing/references/视频技术处理规范.md#实际装配) | 逐段输入选定二采，按[后处理交付规格](#后处理交付规格)确定本次输出。插帧、超分、缩放与裁切由共用工具按实际源片和目标装配。开始条件见[整场后处理安排](视频阶段与返修执行规范.md#7-生成视频验收与衔接修改)。 |

标准版生成前先按[共用配置选择与装配前询问](../../studio-h3/references/参数与基准规范.md#标准版配置选择与装配前询问)确定本次有效配置。一采参数和工作流确认不等于具体视频获批，也不授权下一批任务。二采与后处理仍需指定获批来源和对应执行授权；各阶段尺寸、Refine设置与执行端条件见第2节。

## 1. 当前固定基准与任务副本

技术正文见[H3参数与基准](../../studio-h3/references/参数与基准规范.md#1-当前固定基准与任务副本)。

### 1.2 任务参数来源与准备提交

执行责任见[视频执行分工](ComfyUI-服务配置与任务提交规范.md#视频执行分工)。新建首次一采的内容准备从第1节对应的现行本地 `.workflow.json` 基准配置本次内容画布；通过[任务清单入口](../../nora-serial-drama/references/固定脚本接口规范.md#一次装配与批量入队)由工具导出配套API、装配上传／成果映射、执行检查并入队，不由Agent平行编辑两份技术副本；不是从空白重建节点、凭记忆重写固定参数，或直接提交含样例内容的基准。固定生成参数以第2节及配套基准保存值为准，不以远端节点出厂默认值、网页临时显示值或旧项目副本替代。

| 参数类别 | 任务副本的处理方式 |
| --- | --- |
| 固定生成配置 | 继承第2节规定的模型链、采样及SIGMAS连接、帧率、参考图处理尺寸与性能控件；LoRA开关、采样步数、生成尺寸、Refine的MP和后处理分支按本次配置及横竖屏表处理；其他参数未经明确变更不重新选择或估算 |
| 本次内容与素材 | 根据本次已核对资料填写公共／本组提示词、素材与音色绑定、主体标签、组与P映射；替换样例正文和空素材，保持对应编辑工作区同步 |
| 时间线与运行范围 | 内容准备确定各组时长、接续和选择范围；新一采可由工具按核定时长生成帧数、start、总帧数并同步编辑区；接续保留来源；按[导演台第5–7节](../../studio-h3/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#5-时长帧数与编辑状态同步)同步根字段、output和编辑工作区，不沿用样例组数或选择范围 |
| 种子、缓存与输出身份 | 种子按本规范的[种子策略](#场次基准种子与实际任务种子)，缓存名、导演台ID及原组位置按[缓存规范](../../studio-h3/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#75-缓存检查与清理接口)，输出按本次P／R／阶段填写；不随机换种子或另换缓存身份以绕过匹配 |
| 历史一采接二采及原任务恢复 | 使用指定来源的一采任务副本、原一采尺寸和实际输入，不重新从现行基准覆盖；局部返修先按[执行快照与素材路径](../../studio-h3/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#611-局部返修的执行快照与素材路径)选择实际执行后的来源并落实素材绑定，配置变更涉及缓存时按[来源保护](../../studio-h3/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#751-制作变更时的缓存保护)处理 |

入队成功汇报数量即结束本轮，不继续补ID、技术记录、进度或查网页。准备阶段一次完成上述内容填写，由工具在既有输入映射、分段条目及API副本中保存配对基准或历史来源、实际参数及获准配置差异，不另建参数台账。画布自身控件与API内部时间线／编辑状态按各自规则处理，不进行画布与API比较；技术检查交固定工具完成。任务副本需要改变时回到准备阶段；仅提交已核对资料时不再重写副本或重跑未变化的检查。

任务清单从本次指定内容画布导出实际API；旧式逐项入口读取`--workflow`指向的最终API副本。两者不自动加载最新基准、填补未授权配置或升级旧任务。后台按上传绑定将真实素材路径同步到受影响的API／画布字段后提交；其余已准备的生成配置沿用任务副本。准备报告复用、入队及执行时点核验读取[执行前检查与复用](../../studio-comfyui/references/ComfyUI-服务配置与任务提交规范.md#执行前检查与复用)，不在提交阶段增设人工逐项复查。基准变更不追溯更新已准备、入队或已提交任务；确需变更尚未提交的登记任务时按[准备检查与提交复用](../../studio-comfyui/references/固定脚本接口规范.md#准备检查与提交复用)显式重新准备，已有提交证据的任务不重写或重发。

## 2. 参数边界

技术正文见[H3参数与基准](../../studio-h3/references/参数与基准规范.md#2-参数边界)。

### 标准版任务准备与配置记录

所有配置的一采、二采及局部返修，准备时均须按[生成分段时长规则](../../nora-serial-drama/references/层级编号与时长规范.md#1-层级编号与时长)核对本批各P的请求时长。提交已备任务时，原结论已覆盖现行制作上限且输入未变则复用；尚未覆盖时只补核对该项，超限须先处理分段及关联资料，再按既有流程重新准备，不重复整套检查。

旧一采请求超过现行制作上限且本次仅授权二采接续时，先说明上限与保持来源输入之间的冲突；已有授权覆盖调整分段或重做方案时按其范围执行，否则先取得相应方案授权。不能为满足上限擅自缩短二采或重做一采，也不自动给予历史来源豁免；原请求和批准事实保留。

配置选择与询问统一读取[共用H3装配规则](../../studio-h3/references/参数与基准规范.md#标准版配置选择与装配前询问)。Nora项目默认保存于项目`00-项目定位/项目基本定位.md`的“制作规格 → 视频生成默认配置”，记录字段按共用规则填写。

在本次任务清单的`authorization`写明六步配置的确认来源（本次选择或项目默认及其决定入口）及本次执行授权；六步答案通过共用`h3_first_pass`字段装配，脚本写入已有`mapping.baseline.fixed_configuration`，记录实际比例尺寸、步数、戏型、速度、附加LoRA及采样关联；二采按[共用分辨率询问](../../studio-h3/references/参数与基准规范.md#二采分辨率询问)接续，h3_second_pass装配结果写入已有mapping.baseline.refine_configuration，保留一采配置事实。技术参数和执行事实继续由固定工具保存，不新增配置台账。

### 后处理交付规格

本节维护常规规格处理参数；定制项目及授权范围按[后处理范围](视频阶段与返修执行规范.md#视频阶段与当前版本修改)执行。透明交付须使用支持Alpha的编码及像素格式，例如ProRes 4444 MOV；下文H.264／yuv420p仅适用于不透明常规视频，不能据此输出或声称具有透明通道。去绿等定制处理按既定顺序完成后，记录实际尺寸、帧率、时长、编码、像素格式及透明通道技术结果；技术核对不替代内容审核。

后处理推荐分辨率不低于1080P、帧率30fps；横屏16:9基准为1920×1080，竖屏9:16对应1080×1920，其他画幅按实际比例选择，不拉伸凑尺寸。这是制作建议及基准默认值，不是所有平台的硬性门槛；其他明确选定的规格可用于实际任务。平台发布入口、合同或项目另有已确认要求时，记录其依据并采用对应值，不把支持的最高帧率当作最低要求，也不默认把所有视频补到60fps。

视频码率12～16Mbps可作为1080P交付的推荐参考，不作强制区间或最低值。实际码率还受帧率、画面复杂度、编码器及质量设置影响。基准使用H.264、CRF 19按画质编码，不保证成品落在该区间；只有本次交付确需限定码率时，才按已确认要求配置码率控制。准备记录区分平台硬性要求、推荐参数与实际选定目标；结果记录区分视频轨平均码率与含音频、封装的文件总平均码率，注明测量来源，不把推荐值填写为实测结果。

源文件已满足本次选定规格时，无需仅为套用基准再次插帧或超分；需要处理时保持原播放时长及音画同步，并保留真实切镜，不跨切镜生成混合过渡。任务副本按实际画幅与交付目标调整，画布和API同步；基准更新不改写历史任务、视频、审批或采用记录，不构成重新处理的授权。

后处理准备与提交前按[开发流程第二部分第7节](视频阶段与返修执行规范.md#7-生成视频验收与衔接修改)核对整场开始条件、指定来源及执行授权；每个后处理任务使用该P选定的二采原文件。先按[共用后处理询问](../../studio-video-processing/references/视频技术处理规范.md#后处理分步询问)确定输出规格；超分、缩放与裁切由源尺寸及目标计算，不由文戏／打戏或旧配置编号决定。技术节点、连线、编码与装配参数见[视频技术处理](../../studio-video-processing/references/视频技术处理规范.md)。成果按本阶段自动采用规则接续，技术工具不决定批准。

正式工作流更新不修改历史任务副本、视频、审批或采用记录，不自动重新处理其他视频。

任务中的素材、公共／本组正文、时长与编辑状态按[导演台节点使用规范第2–5节](../../studio-h3/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#2-素材排序与编号)填写；实际种子按下节保存到502的seed，画布control_after_generate固定为fixed。逐组导出使用导演台报告的实际路径并按组与P映射归位。精简基准只使用分段导出，不依赖外接视频保存节点；分段交付与本集收尾读取[逐集目录规范第5节](../../nora-drama-handoff/references/逐集目录与资产管理规范.md#5-分段交付与本集完成)。明确改用全部导出时须在任务副本补齐对应的视频保存连接，不能只改exportMode后声称已保存合并视频。

### 场次基准种子与实际任务种子

同一EP/C首次一采先查已有场次基准种子；没有时采用用户指定值，未指定则生成一次允许范围内且可精确序列化的整数。后续同场首次一采沿用。内容返修默认沿用来源任务的实际种子，便于比较提示词、素材或时间安排的修改效果；新增R编号或选择部分分段本身不触发换种子。固定种子用于控制随机因素，不保证保留原构图、表演或动作，也不保证正确执行修改后的提示词。

**主动建议换种子尝试的条件**：在处理用户反馈、制定一采返修方案时，出现下列情况应主动提出，不等用户先提种子：

- 已对照该次冻结请求，确认相关描述清楚、参考输入无冲突、动作时间与构图可见范围合理，但用户反馈仍有漏动作、表演不合适等生成偏差，建议保持方案不变、更换少量种子作对照。
- 根据用户反馈及既有记录，同类问题连续返修仍存在，重新判断原因，并将换种子列为备选；发现文本、素材、时间或配置的明确问题时先处理，不以换种子代替修正，也不只反复叠加同义措辞。

提出建议时说明具体问题、已核对的依据、推荐候选数量及P范围，不将疑点说成种子已被证实有问题，不承诺换种子必然修好。沿用用户已有的明确选择和执行授权；尚未覆盖换种子或追加候选时，先确认该范围。仅换种子的对照保持提示词、素材顺序、时长和其他生成配置不变，保存各次实际种子与来源；候选完成后交用户审核，不自动追加尝试。不要求每次返修都先跑固定种子、再跑新种子两轮，也不因正常结果通知触发主动审片或生成。

上述选择用于新的一采返修；获批一采接续二采仍保持其来源种子，不以换种子绕过缓存问题。换种子的修订编号及留存按[视频修订编号规则](逐集目录与资产管理规范.md#视频修订编号与执行过程)处理，不改写场次基准、历史请求或批准事实。

场次基准和来源在本场首个任务的 `输入映射.json` 保存，后续记录引用该入口并记录本次实际值；不另建种子台账。每次导演台提交只有一个全局seed，作用于该批实际运行的各组；选择运行不会自动创建分组独立种子。一轮生成七组时，七组使用同一实际种子；选择其中三组时，这三组仍共用该任务的seed。画布control_after_generate保持fixed，不在轮次结束后自动随机或递增。另行探索改变全局种子时，说明其他组后续缓存匹配也受影响；历史获批来源确有不同实际种子时按各自来源核对，不用一个值覆盖历史。恢复查询及故障恢复保持原任务种子，不因查询重复提交。画布/API内7503308486466147是示例，不能直接当作其他项目的场次基准；不得在执行后读取前端下一次种子冒充本次实际值。

准备时逐P核对请求秒数符合[生成分段时长规则](../../nora-serial-drama/references/层级编号与时长规范.md#1-层级编号与时长)，并核对一采与二采一致；超限且无该规则规定的专项测试授权时，不照搬画布示例或历史请求提交，先调整分段和关联资料。请求时长、17k+5帧格及时间线同步按[导演台节点使用规范第5节](../../studio-h3/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#5-时长帧数与编辑状态同步)处理；保存请求秒数、计划帧数和真实输出时长，严格时长要求需明确方案，不默默裁切或变速。

标准版的预览与保存接线：502.images_pre_refine（槽位6）→503 CreateVideo→504 SaveVideo；502.images（槽位0）→505 CreateVideo→506 SaveVideo。两条CreateVideo均连接502.audio（槽位1）和502.fps（槽位2），使用8位sRGB；SaveVideo使用MP4／H.264，任务中分别使用[远端输出目录](../../nora-serial-drama/references/ComfyUI-服务配置与任务提交规范.md#远端输出目录与命名)的项目辅助预览前缀，提供播放预览和下载，不代表全部分段成果或采用状态。

首次一采确认时最终images口被阻断，只能由504保存一采；人工批准后沿用同一任务副本、缓存名、导演台节点ID、实际种子和一采输入再次执行，命中一采缓存后执行二采，由506保存二采。二采轮可能同时输出一采对照视频，不能把504的对照文件登记为新一采或二采成果。缓存缺失或不匹配按[远端缓存复用与缺失处理](../../studio-h3/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#752-获批一采缓存的远端复用)处理，不改关闭确认来绕过审批。

默认segments导出时，外接保存仅用于最后实际运行组的辅助预览，完整逐组文件仍由403最终报告驱动后台取回；不替代逐组P映射。明确使用all导出时，两条保存分支接收相应阶段的合并画面，保存为合并视频，不能当作所有P的独立文件。任务完成后再取回全部预期成果。

### 2.1 已批准的输出前缀公式

R的分配、阶段转换、失败恢复及完整结果后的再次生成读取[视频修订编号与执行过程](逐集目录与资产管理规范.md#视频修订编号与执行过程)，不由任务ID或提交次数分配新R。

可配置保存节点统一按[远端输出目录与命名](../../nora-serial-drama/references/ComfyUI-服务配置与任务提交规范.md#远端输出目录与命名)填写，包括标准版504／506辅助预览、需要外接保存的任务、历史任务副本中的264／214及后处理16。导演台插件内部的分段保存和缓存目录保持其原有规则，不由外接前缀控制。下载只认实际返回的filename/subfolder/type。

多组任务的共同证据位置、任务状态与各P输出记录读取[多组任务的共同证据与状态](逐集目录与资产管理规范.md#多组任务的共同证据与状态)；合并文件不冒充每个P的独立输出。正式场次/整集保存与计数按逐集目录规范；已有用户明确指定的技术测试位置可沿用。不因导演台一次导出多组就自行创建一套正式目录或计数规则。

既有二采使用265的可选外部加载器时，以其画布映射与 `_meta.nora_optional_reference` 为准，填写实际文件并接入目标槽位，删除所有未用加载器。保留结构不等于已获新二采执行授权。

## 4. 提交、恢复与结果取回

服务配置、选端与恢复地址执行[工作区ComfyUI配置](../../studio-comfyui/references/ComfyUI-服务配置与任务提交规范.md#工作区-comfyui-配置)。新任务的准备与入队按[服务与任务提交入口](../../studio-comfyui/references/ComfyUI-服务配置与任务提交规范.md)执行，不向远端发布基准。已有后台任务按[查询与结果处理入口](../../studio-workspace-browser/references/进度查询与结果处理规范.md#进度查询与结果处理)选择[状态查询](../../studio-workspace-browser/references/固定脚本接口规范.md#后台状态查询)、[通知确认](../../studio-workspace-browser/references/固定脚本接口规范.md#后台通知确认)或[取回重试](../../studio-workspace-browser/references/固定脚本接口规范.md#后台取回重试)，无需加载上传、提交或完整comfyui-api说明。

1. **准备**：内容已备时，工具从指定内容画布制作任务副本并自动建立分段阶段技术条目；内容尚未准备时先从正式基准配置当前内容，替换全部业务占位符，保存组与EP/C/P映射、获批资料版本、完整模型正文、实际素材、种子和输出范围。冻结任务按[逐集目录规范第4节](逐集目录与资产管理规范.md#4-视频执行输出审核与采用)保存，05不维护运行流水。
2. **准备核对**：内容合理性由Agent在准备阶段完成，可程序判断的格式和执行条件调用工具生成报告；按[执行前检查与复用](../../studio-comfyui/references/ComfyUI-服务配置与任务提交规范.md#执行前检查与复用)复用本地工具报告，不预查远端节点／模型能力；由工具按所选标准版配置检查实际启用节点的API结构、素材身份和数量/时长、标签、时间线与输出位置；按[模型提示词长度规则](../../nora-video-prompts/references/视频提示词制作规范.md#模型提示词长度)核对各分段最终正文并记录结果；内容与格式分别核对、分别记录结论，语言适配读取[语言与命名](../../nora-video-prompts/references/视频提示词制作规范.md#h3模型正文的语言与命名)，检查要求及结论留存直达[模型正文的内容核对](../../nora-video-prompts/references/视频提示词制作规范.md#模型正文的内容核对)，资料包的其他交付项按[交付核对](../../nora-drama-review/references/交付核对规范.md#交付核对)执行。不能用UI注册或上传成功证明全组合可运行。
3. **入队**：本次生成获授权后，按[任务组提交范围](../../studio-comfyui/references/ComfyUI-服务配置与任务提交规范.md#任务组提交范围)将已核对的独立任务放入同一清单，通过统一入口登记，不重新通读内容或手工重跑技术检查；登记只做必要边界校验并保存本地任务ID；轮到执行时由工具统一比较准备依据并复用未变结论，上传后只核对实际改写的素材绑定，不比较画布与API，具体边界按[执行前检查与复用](../../studio-comfyui/references/ComfyUI-服务配置与任务提交规范.md#执行前检查与复用)执行。Agent只提交已备内容及语义映射；脚本导出API、装配绑定和成果目标、自动维护执行条目；后台轮到任务时上传，在POST前按[生成版本的资料关联](逐集目录与资产管理规范.md#生成版本的资料关联)冻结当次资料，保存实际地址与远端ID。参数见[视频资料自动保存](固定脚本接口规范.md#视频资料自动保存)。
4. **跟进**：后台按[任务监控规范](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md)监听、重连及核对，Agent不另开定时器。收到结果通知后按[整轮汇总规则](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md#3-跟进与通知)处理交付时机，只调用report并在同次读取中确认收到；不再读常规记录或补写；失败从具体失败阶段复查，不自动安装、重启、清队列或替换模型。

   原ID丢失时执行[故障后的视频接续](ComfyUI-任务监控规范.md#51-后端故障后的视频接续)，保留证据和已有文件，核对状态与来源缓存，不自动补做。
5. **取回**：由后台执行。默认分段导出按导演台报告中的本轮运行目录和逐组文件核对，按[逐组输出规范](../../studio-h3/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#731-导出方式与逐组文件)区分一采、二采及P映射，403报告为逐组文件依据。明确采用全部导出时须核对本任务实际接入的保存节点；历史独立一采任务认264、独立二采任务认214，后处理认16。只用本任务真实文件身份，不把旧预览作为结果。缺少完整逐组文件时报输出异常，不把执行成功当作全部交付。
6. **交付**：后台成功后将最终文件保存到指定候选路径，按[成果保存与已有文件](逐集目录与资产管理规范.md#成果保存与已有文件)保留已有文件与记录。后台按[精简收尾](ComfyUI-任务监控规范.md#视频完成通知后的精简收尾)自动登记待审和核验网页后再通知，Agent读取现成报告，按[整轮汇总规则](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md#3-跟进与通知)集中交用户人工审核；成功生成和保存均不等于内容获批。

实际送入模型的文字限制执行[视频生成全程无字幕](../../nora-serial-drama/references/画面文字与字幕规范.md#视频生成全程无字幕)；字幕问题的修订优先级及获授权的省略例外按[提示词对照](../../nora-serial-drama/references/画面文字与字幕规范.md#生成字幕问题的提示词对照)处理，准备核对覆盖本次方案的完整正文与中文参考版，不以格式通过代替结果要求。

## 5. 人工审核与轻量记录

执行、候选/选定、人工审阅及场次/整集交付统一按[逐集目录规范](../../nora-serial-drama/references/逐集目录与资产管理规范.md)维护，不另建运行台账。结果只由用户人工审核，不进行agent内容初审、自动重生成或未经批准切换处理阶段。

获批一采的远端缓存复用执行[导演台第7.5.2节](../../studio-h3/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#752-获批一采缓存的远端复用)。一采、二采明确获批后，以及后处理满足[自动采用](逐集目录与资产管理规范.md#后处理自动采用)条件时，走[一次收尾入口](固定脚本接口规范.md#视频批准的一次收尾)，依据报告及实际授权接续下一环节；各阶段均不主动或自动导出导演包；只有用户明确要求时，才按指定范围导出并保存配对画布。包是否存在不影响阶段接续；一采来源和缓存仍按下文核对。

正式画布407.confirm_first_pass保持开启。一采与二采共用工作流不合并制作阶段；按开发流程的整场审批顺序推进，分别保存两阶段任务ID、输出及用户决定。首次执行只生成一采；用户批准后，沿用同一任务副本、缓存名、导演台节点ID、实际种子与一采输入再次执行。逐一核对本轮选中组与获批一采的缓存匹配，命中后只做二采；缓存缺失或不匹配时先说明，不把重新一采冒充二采。局部返修与不同获批输入的分轮执行按[返修选择运行操作](../../studio-h3/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#711-返修选择运行操作)处理。Refine参数可按已批准二采方案调整；清理缓存按[节点缓存操作](../../studio-h3/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#75-缓存检查与清理接口)执行，不在两轮之间自动清理。
