# 缓存与返修接续

#### 6.1.1 局部返修的执行快照与素材路径

已有视频的局部返修在装配任务前，必须以指定EP／C／P／R／阶段**实际执行后的快照**为起点：依据实际提交API／请求、上传响应和输入映射确认来源，再在新执行副本中修改本轮获授权的内容。不能直接沿用上传前的内容画布、含占位路径的准备副本或从现行基准重填一套输入。配对画布可用时使用其中已回填的真实路径；未回填时先依据实际API及上传记录恢复新执行副本中的真实引用，再交固定工具装配，不能把占位值当成当次已执行输入。

- **未变素材保留实际路径**：图片、音色、参考视频及其他原生媒体输入，核对来源文件、具体版本、用途、顺序和原上传身份；内容与用途未变时沿用原远端`input_path`及其`name/subfolder/type`，同步根时间线和对应编辑工作区。同一文件重新上传到新任务目录仍会改变缓存输入身份，不能以“素材内容相同”认定前段缓存可用；新执行目录不要求重新上传未变素材。确需换素材时使用新版本的真实路径，并按第7.5.1节核对影响范围，不覆盖原文件冒充沿用。
- **把路径保留落实到装配输入**：任务清单按[视频装配与素材绑定](../../nora-serial-drama/references/固定脚本接口规范.md#一次装配与批量入队)区分已核实的远端引用与本次需上传素材。复用依据写入既有输入映射；不伪造上传响应或建立跨任务上传缓存。只在来源和远端文件身份可核实的范围内复用，运行时的文件与缓存核验仍由后台执行。
- **核对实际前组**：未选中的前组也须保持其实际素材路径及原输入，记录本次引用的具体版本和批准或使用依据；缓存存在、缓存名相同、种子相同或有旧MP4都不代替匹配检查。原服务、缓存身份、组序及未改组按[制作变更时的缓存保护](../../studio-h3/references/ComfyUI-AiMixer导演台节点使用规范.md#751-制作变更时的缓存保护)保持，只替换获授权的返修内容。
- **失配先定位，不扩大生成**：先区分缓存不存在与素材路径等输入失配。能够恢复已核实的原路径时，使用原任务的[重新准备与恢复](../../studio-comfyui/references/ComfyUI-服务配置与任务提交规范.md#重新调度与失败恢复)处理；不通过改种子、关衔接、清理整场缓存或补生成未授权前段绕过检查。原输入或缓存确实无法恢复时，说明缺项与受影响段，取得相应方案授权后再继续。

### 7.5.1 制作变更时的缓存保护

原结构内常规返修先按[执行快照与素材路径](../../studio-h3/references/ComfyUI-AiMixer导演台节点使用规范.md#611-局部返修的执行快照与素材路径)确定来源及未变素材的绑定，再沿用原服务、场次缓存名、AiMixer 导演台ID及完整原组序，只选择需返修组。实际重新一采时替换对应组的缓存，历史MP4及执行记录仍保留供比较；输入未变且缓存匹配时会接续二采，不将再次提交当作强制重新一采。未返修组不加入本轮采样范围，不为局部返修清理整场缓存。

拆分、插入、删减、重排或修改段长时，按[模型时间线同步](../../studio-h3/references/ComfyUI-AiMixer导演台节点使用规范.md#5-时长帧数与编辑状态同步)同步根时间线、编辑工作区、组与P映射及选择状态，再按[缓存技术检查](../../studio-h3/references/ComfyUI-AiMixer导演台节点使用规范.md#75-缓存检查与清理接口)核对当前输入与远端缓存。前后段衔接按[模型衔接](../../studio-h3/references/ComfyUI-AiMixer导演台节点使用规范.md#61-局部返修时的前后衔接)处理，不把组位置变化后的缓存直接认作同一P的获批来源。

二采仍依据指定获批一采的原任务副本、原始组序及输入快照，按[第7.5.2节](../../studio-h3/references/ComfyUI-AiMixer导演台节点使用规范.md#752-获批一采缓存的远端复用)核对并接续；新时间线不替代原来源快照。

### 7.5.2 获批一采缓存的远端复用

一采缓存保留在实际执行端，制作流程仅查询和复用远端缓存。已有本地备份、历史记录和批准事实保持原样。

二采依据指定获批一采的原执行快照，沿用原服务、缓存名、AiMixer 导演台节点ID、完整时间线、组位置、真实输入及模型链，按第7.5节核对远端缓存。需要前组接续时，同时按第6.1节核对所需的具体来源；制作变更按第7.5.1节核对时间线及来源。

缓存缺失、失配、被覆盖或来源无法确认时，在既有执行记录中说明缺项和影响，不把其他版本冒充获批来源，不将二采授权当作重新一采授权。实际执行是否命中缓存并跳过一采，以第7.5节规定的执行报告为准。整场审批依赖仍按[开发流程第7节](视频阶段与返修执行规范.md#7-生成视频验收与衔接修改)执行。


## 素材与业务对象约定

组与业务对象的对应由调用阶段提供。组内可包含多个Shot；这是项目制作约定，节点本身只识别素材组，不要求使用EP/C/P编号。`segments[]` 的数组顺序就是组顺序；每个组保留独立id，并在既有输入映射中记录对应EP/C/P。移动、复制或删除组后同步检查分镜顺序、时长、提示词、连续开关和输出范围，不把组显示序号当作永久P编号。

素材／主体定义按[参考定义与状态描述](../../studio-h3/references/ComfyUI-AiMixer导演台节点使用规范.md#41-参考定义与状态描述)填写。新增主体、场景状态或声音信息仍依据获批资料整理，不因技术拆分改写剧情。主体与说话者编号的含义和分配读取逐集内容规范。

主体名称按[语言与命名](../../nora-video-prompts/references/视频提示词制作规范.md#h3模型正文的语言与命名)填写。参考定义不写“已采用”“已批准”、候选版本、路径等管理信息；这些内容保存在素材映射及制作记录。参考对象的描述、当前画面约束与修改过程按[描述性正文与修改要求](../../nora-serial-drama/references/文件版本与工作稿规范.md#描述性正文与修改要求)区分。各节允许为标签对应、参考保留和状态延续作必要重复，不规定用途或特征只能表达一次，删除不增加有效信息的重复解释。

开启衔接且本组引用前组时，节点可读取同一AiMixer 导演台前一组的磁盘缓存，即使前组本轮没有重新采样。返修P002时，可用P001的已采用结果引导P002；它不是同时约束P002与P003的双向衔接。已有P003不会因P002重生成而自动更新，新的P002与旧P003是否接得上由用户人工审核，不能根据共用参考图或缓存匹配直接判断。

提交前在既有输入映射中核对前组缓存对应的具体版本及批准依据。节点为恢复衔接可能读取旧缓存，缓存存在不等于它就是当前采用版本；节点在前组没有可用缓存时可能跳过引导，须按实际报告记录为未接续，不能以此替代本次要求的前段引导；准备或开工发现缓存缺失、失配时按[执行快照与素材路径](../../studio-h3/references/ComfyUI-AiMixer导演台节点使用规范.md#611-局部返修的执行快照与素材路径)处理。

段间引导包含音视频上下文，不能将其视为只有画面。按[声景与配乐](../../nora-drama-storyboard/references/场次分镜制作规范.md#声景与配乐)确定允许的声源；无对白段需分别明确是否允许前段尾音、是否禁止新增可辨人声，以及明确需要的动作声或已指定环境声，并核对实际前组版本、衔接设置和第3.1节输出模式。独立Audio槽为空不等于没有音频条件；发现无台词段出现人声时，将前段上下文列为核对项，不直接认定它就是原因。不能自动关闭衔接、重做一采或整段静音；用户明确选择静音时，如实记录环境声与动作声也会随之移除，采用仅表示用户接受该处理范围。

缓存名由调用方提供；短剧约定使用`{项目目录名}-{EP编号}-{C编号}`，例如`示例项目-EP003-C001`；集号和场号沿用项目的EP、C编号。Agent在准备场次任务副本时填写并同步画布与API中的`cache_name`，脚本不自动生成场次缓存名。同一场次的一采、二采和常规返修使用同一个名字，不添加随机后缀、阶段、R编号或批次编号；实际工作流与既有输入映射保存此值，不另维护命名台账。完整名字保持在64个字符内；目录名含非法字符或过长时使用项目已确定的稳定合规简称，没有简称时先确认，保留完整集号和场号，不依赖服务端替换或截断来区分场次。实际目录取服务端规范化后的名字，记录实际缓存身份。
