# 导演台返修与输出业务接续规范

本文件保存从模型工具归回本业务阶段的约定；模型格式、槽位与技术操作仍由共用H3工具维护。

1. **落实本轮范围**：先按[同场反馈的返修范围与提交](视频阶段与返修执行规范.md#同场反馈的返修范围与提交)确定本轮P清单，再将镜头或时间点对应到组内Shot，按[制作返修的上游归属](../../nora-serial-drama/references/制作返修接续规范.md#制作返修的上游归属)维护剧本、分镜、提示词或素材。修改生成输入时同步既有准备资料、实际任务副本及中文参考版，历史请求不改写。
2. **核对缓存与时间线**：先按[执行快照与素材路径](../../studio-h3/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#611-局部返修的执行快照与素材路径)确定返修起点及素材绑定，再按[制作变更时的缓存保护](../../studio-h3/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#751-制作变更时的缓存保护)核对本轮组序与来源。原结构内返修保留完整时间线及各组原始位置与id，仅开启需返修组的选择运行，按[模型时间线同步](../../studio-h3/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#5-时长帧数与编辑状态同步)同步根时间线、编辑工作区及画布/API的选择状态；未返修组不加入本轮采样范围。
3. **核对将执行的阶段**：先比较选中组的一采缓存与本次输入。提示词、参考路径等一采输入改变后，该组重新一采；输入不变且缓存匹配时，再次执行会做二采，不会自动“换一次运气”。原输入不变但要求强制重做一采时，先明确实际重生成方案及缓存影响范围，再按授权执行；不把网页节点级清理按钮当作单组清理。缓存判定、ID和清理范围只在[第7.5节](../../studio-h3/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#75-缓存检查与清理接口)维护。
4. **核对输入及扩散影响**：实际seed按[种子策略](ComfyUI-H3视频执行规范.md#场次基准种子与实际任务种子)填写。公共提示词、公共素材和共同参数的变化可能影响多组，不声称只改了本组。替换参考文件内容时使用对应新版本的真实路径，不能覆盖原路径后假定缓存必然失配。被引用前组及返修后组的衔接按[第6.1节](../../studio-h3/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#61-局部返修时的前后衔接)处理；没有新反馈或相应授权，不自动扩大到后续分段。
5. **审核并接续二采**：取回本轮实际返修结果，记录新任务ID、各P的R编号和对旧版本的替代关系；送审安排及整场审批顺序按开发流程执行。二采分别依据当前获批一采的冻结输入；历史获批来源存在不同实际种子或共同参数时，不能用一套全局值宣称全部缓存匹配，按各自获批快照明确执行方案。未匹配组先处理来源问题，不让二采批次意外重新一采。
