# 完单复盘流程与规则

更新日期：2026-11-02。按用户已确认的业务决定和模板正式维护；业务复盘不自动授权修改共用规则或对外发送。

## 流程与接续

用户明确说明最终交付 → 核对事实与相关历史 → 整理问题及结果 → 每单检索已有经验并查重 → 提出适用规则建议 → 按实际维护授权处理 → 按需整理结项摘要。

只有用户明确最终交付后，统一做一次完单复盘；此前只在原业务记录保留必要问题，不在素材/草稿包交接后提前开展。没有打包需求时不以剪映包为前置，也不要求用户补填人工精剪过程。

## 执行要点

使用[项目复盘模板](../templates/项目复盘.md)，核对实际用户决定、有效阶段稿、真实输入与结果、采用及交接。会话标题/摘要用于定位，按问题补读相关分页；继承内容按实际turn去重，不为复盘全量复制附件或重读无关流水。缺少最终成片时据实写未收到/未记录，不补造路径和参数，不否定用户明确的交付说明。

有问题时列明证据、原预期、实际原因或未确定部分、修正与实际结果；未知机制不写成已证实结论，没有单变量验证的成功只说明整组结果，无问题不凑问题表。区分已验证做法、单单配置、未验证建议及未覆盖环节。

每单复盘检索已有同类规则并查重，提出值得补充的内容、适用条件及目标位置；没有新经验时说明无新增，不另建一套经验文件。品牌、角色、片长及模型参数等单单配置留项目，不推广成全业务默认值。

已有明确维护授权时，按[维护规范](../../iris-commercial-video/维护规范.md)落实所属规则；没有授权时保留建议，不把建议标成已落地，也不把聊天全文塞进技能。完成后更新原项目状态及必要入口，保留原始请求和历史。业务复盘通过不代表未测工具/模型模式或操作系统已经验收。

## 内部记录与填写时点

字段按实际发生填写，决定和交付事实引用项目状态，技术依据链接原档案。

| 字段 | 填写条件 | 最少需要什么 |
| --- | --- | --- |
| 项目、复盘版本、启动依据与范围 | 开始完单复盘时必填 | 引用用户明确最终交付说明及项目状态，说明本次覆盖哪些工作 |
| 实际产物与交付入口 | 必填 | 引用真实采用、交接和已有文件；用户已说明交付但未提供最终成片时注明未收到/未记录，不补造文件、参数或否定用户说明 |
| 资料覆盖范围 | 必填 | 实际使用的阶段稿、相关会话和记录入口，必要时说明继承内容去重；只按问题读取相关历史，不全量复制执行附件 |
| 问题与处理结果 | 有实际问题时填写 | 证据、原预期、原因/未确定部分、修正及实际结果；未知原因不写成已证实的模型机制，无问题不凑问题表 |
| 经验分类及查重结论 | 每单复盘核对 | 已验证做法、单单配置、待验证建议和已有相似规则；没有新增经验时说明无新增，不留一批空分类表 |
| 规则建议与适用范围 | 有值得补充的共用经验时填写 | 具体建议、适用条件、目标规则位置；客户品牌、角色及本单参数不泛化为所有订单默认值 |
| 实际规则维护结果 | 有相应维护授权且已执行时记录 | 引用真实维护记录；未实施就写建议，不把建议标成已落地 |
| 待验证及对外结项整理 | 有相关事项或实际整理需要时填写 | 下一单需验证什么；确有对外结项需要时引用模板6，不另建项目完成事实表 |

## 交付整理与完成

确有向甲方说明收尾的需要时，使用[交接与结项摘要](../templates/交接与结项摘要.md)从实际交接、用户说明和原生产资料整理。它是对外摘要，不是内部复盘报告；无需求不新建、不强制发送或新增确认环节。

| 字段 | 填写条件 | 最少需要什么 |
| --- | --- | --- |
| 项目名称、摘要版本、日期 | 使用本模板时必填 | 当前对外摘要的身份 |
| 实际完成范围 | 必填 | 依据项目实际交接和用户说明整理，准确区分素材、草稿与最终交付，不把技术完成当客户全部验收 |
| 交付内容索引或已有交接入口 | 有相关文件/交接内容时填写 | 实际文件/附件名称、对应范围、必要使用说明；已交接的内容可以说明已有交接，不重新制造附件；未取得的成片或规格不补造 |
| 已确认事项 | 实际存在且有说明必要时填写 | 只整理已有真实确认，不将用户说明交付自动扩大为甲方认可所有内容 |
| 后续安排与未决事项 | 有实际约定或真实未决项时填写 | 明确已约定安排和具体问题，不新增工期、费用、免费返修等承诺 |
| 本次需要核对事项 | 确有必要时填写 | 对具体交接范围/文件的真实核对点；没有则省略，不强制新增确认步骤 |

不加入内部失败、成本、模型参数或无依据承诺；实质修改先回生产来源。正式对外稿沿[跨阶段交付规则](../../iris-commercial-video/references/对外交付.md)批准Markdown具体版本后导出PDF，已有有效批准直接沿用，实际发送须在授权范围内。用户交付说明、甲方确认、整理完成及批准导出各记实际范围。
