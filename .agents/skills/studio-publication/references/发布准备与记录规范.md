# 发布准备与记录规范

## 人工剪辑与最终成片

制作素材交付沿所属业务；仍需人工剪辑时交接已采用素材及可用配套，说明实际导出位置。发布对象、成片来源和交付目录按[对象映射](../../studio-social-operations/references/运营与制作接续规范.md#业务范围与对象映射)确定，创建时机按同规范执行。后处理不代表人工剪辑已完成，不自动将某个分段或目录最新视频当作最终成片。

用户交接最终导出时，核对作品代号、文件、实际时长、分辨率及可读取性。已有明确的文件决定时沿用该版本，只有一份成片且没有其他版本决定时以该文件准备材料。多个候选无法确定时询问，不按修改时间猜测。内容检查按主技能现行授权单独核对。最终成片按所属业务指定的位置与资源版本保存。不安排社媒发布时只按业务规则交回成片资料，不建立空发布材料。

## 准备发布包

在调用方指定的本次发布资料位置准备材料，目录层级与命名沿所属业务；最终文件引用原件。调用方已有发布资料模板、页面交接和发布执行选择顺序时，沿该接续规则准备及展示，不再创建同用途的发布说明、文案或发布记录文件。下文模板及文件名表达材料职责，按调用方的实际位置映射；尚未选择手动或代发不阻塞资料准备，缺少账号配置仅补本次动作必要信息。

1. 读取调用方提供的项目运营配置或同等记录（包括[发布选项配置](../../studio-operations-setup/references/运营启用与账号连接规范.md#发布选项配置)）及[阶段06](../../studio-operations-guidance/SKILL.md)，确认目标账号、平台、本作品适用建议。先读[对应平台指南](#平台发布指南)确认需填字段，再核对本条确切的成片文件和已有资料。成片缺失或无法读取时说明文件缺项，继续准备可完成的材料。
2. 按调用方的记录映射填写各平台标题、正文、话题，未指定结构时使用[发布文案模板](../templates/发布文案模板.md)。文案依据本次成片和已核实的商品资料，参考既有复盘。成片已删减的内容不作为文案承诺，也不照搬前一作品的承诺。话题不能替代正文。具体字数／话题等平台限制按当前发布页核实，超限时调整。
3. 调用[封面阶段](../../studio-cover-images/SKILL.md)核对当前正式封面、本作品匹配和报告建议。已适用的封面和发布资料直接复用。需补充或修改时说明调整及依据，沿本次范围制作并取得实际采用决定。
4. 从项目配置和用户已确认的本条安排整理[本条发布设置](#本条发布设置)，按[排期建议与授权](#排期建议与授权)准备建议、确认实际排期。先从已有资料补齐，仍需用户决定的事项集中确认，可先交已有材料或按授权准备预览。
5. 在调用方指定的发布说明或等效记录中汇总确切成片、封面、文案入口、本条发布设置、建议与待办，未指定结构时使用[发布说明模板](../templates/发布说明模板.md)。成片、文案和封面等内容材料齐备后可以交接或按授权预览，列明待定的发布执行、设置或排期。正式代发须齐备本条必填设置和提交授权，按[提交前核对](#代为定时发布)执行。

## 本条发布设置

按本条作品、平台和账号填写下列设置，在进入正式发布表单前明确拟选值。沿用项目已确认的默认值时引用对应配置条目，写明实际要选的值。本条有例外时以用户的本条决定为准，写明取值与依据；只有用户确认长期沿用时才更新账号默认。缺少必需值时填待确定，可按授权继续准备或预览，待补齐后提交。平台预选值只供核对。

| 设置项 | 取值与填写依据 |
| --- | --- |
| 自主声明 | 依据作品内容与权利事实，按对应平台指南选实际适用的声明。事实或选项待核实时记录缺项。 |
| 可见范围 | 取本条决定或项目已确认的账号默认值，按对应平台的选项填写。 |
| 保存权限 | 取本条决定或项目已确认的账号默认值，按平台提供的下载或保存选项填写。 |
| 发布方式 | 记立即发布或定时发布；由谁操作另记在发布执行。Agent 代发适用[发布方式](#发布方式)的授权要求。 |
| 确认排期 | 定时发布记用户批准的具体日期、时间、时区和确认依据，注明本次代发授权。立即发布填不适用。建议时间和后台实际回显各归原记录。 |

其余选项按[发布资料与选项执行](#发布资料与选项执行)和平台指南处理，有明确填写要求时补入本条设置。某项确经实际入口核实未提供时记录不适用，并说明依据。

## 封面文件与版本

在本次发布说明中引用实际选用封面的资源版本及文件入口，明确平台与版式；抖音按实际入口核对横竖版，其他平台按实际常规主封面选择。跨平台同图引用同一文件，不为发布留档另存副本。用户明确需要自包含发布包时，才临时装入所需图并保留来源清单；交付名由调用方或本次要求确定，不形成第二个修改源。

## 发布资料与平台作品的变更

提交前按当前决定调整材料或拟填设置。调用方要求留存已引用的资料时，沿业务版本规则追加资料版本，同一次发布记录改为引用新版本，并保留旧引用、变更内容及依据。纯长度适配保留原意，实质改写、换图或换商品按本次授权处理。

提交后由 Agent 修改时须获本次授权，核对原平台条目保存结果后再回写。改文案、换图或换商品时保留前后对应的实际资料。仅改已提交条目的排期或设置时，在原发布事件下记录实际改动、回显及依据。重新发布形成新的平台作品时才新建发布事件。实际使用的文案、成片和封面按对应版本留档。

## 发布方式

发布支持用户手动发布和 Agent 代发。调用方约定先展示再选执行人时，内容材料齐备即可展示，待决的排期和发布设置随资料列出。未约定选择流程且用户未要求代发时，交付材料供用户手动上传。已明确的执行选择及有效授权直接沿用。发布包就绪、运营启用或技能维护本身不授权上传、提交或修改平台作品。

用户明确要求代发时，使用平台自身的定时发布功能；只有用户对本次作品显式要求立即发布时才使用立即发布。核对本次作品代号、平台账号、最终文件、文案、封面及批准排期；默认定时不等于对以后所有作品的持续发布授权。用户仅说“发布”“你来安排”不构成立即发布或具体排期的批准。

在本作品发布说明或等效记录中填写发布执行、本条发布方式及授权范围。手动发布分支交付材料和建议时间，收到用户的发布反馈或作品入口后按[发布后检查与临时跟进](#发布后检查与临时跟进)核验。

## 排期建议与授权

1. 先读项目运营配置中各目标平台的推荐时段及来源；再按来源读取相关运营报告，核对推荐的适用账号、日期、数据阶段及验证状态。配置没有单列时从最近适用报告提取，不能用其他项目、其他平台或通用“黄金时间”代替。
2. 结合本作品就绪状态、用户期望发布日期及平台原生定时限制，逐平台提出“具体日期＋时间＋时区”，同时列出推荐依据和待验证范围。粉丝活跃、观看时段和最佳发布时间分别判断；没有账号依据时写明无数据支持，提出供用户选择的测试排期，不能自行确定最终时间。
3. 在提交前向用户申请本次具体排期及代发范围的授权，说明平台定时提交后将按批准时间自动公开。各平台可以分别排期，不为方便统一时间。用户已显式确定本次平台和完整排期时直接沿用；只问缺失项，不重复确认已授权的同一排期。用户要求先看预览时，完成可检查的材料和预览后等待其提交决定。
4. 批准结果及依据写入[本条发布设置](#本条发布设置)的确认排期。日期已过、提前量不足或平台不接受该时间时，说明原因并提出新排期，重新取得调整授权；保留原批准记录。

### 发布资料与选项执行

- 账号和 Chrome 配置从调用方的项目配置取得。按调用方的资料映射，以作品、平台和账号定位本条发布资料，读取确切成片、标题、正文、话题、封面和拟选值。首次使用某平台时，按指南逐项核对当前账号实际表单，已获确认的账号默认值写回项目配置。
- 位置、关联人、合集、推广、商品、同步分发、封面实验等可选功能，仅在项目或本次明确指定时启用；未指定则不添加、不关联、不启用。新建发布时可选文本留空，预选开启的额外功能按本规则关闭；只读核查不操作开关，已有作品编辑时保留原有值，未经本次授权不删除已存在的合集、引用或其他关联。页面强制选择或不允许关闭时记录具体限制并请求决定，不猜分类、承诺或资质。列举的功能并不表示每个平台当前都提供。
- 具体声明根据内容和权利事实填写。AI制作不直接等于已具备原创声明所需全部权利；用户没有确认相关事实时不代勾。只在已核对的具体入口记录“不提供”；已发布编辑页省略字段，不等于新建页也不提供。字段含义、协议或页面入口与指南不符时，定点核实受影响部分并记录；核实完成前不带着不明选择提交。账号差异和本次实测记录留在项目，平台通用字段变动更新对应指南。

### 商品挂载与结果核对

本次明确带货或要求挂品时，按调用方提供的真实商品、款式或SKU、原始链接及授权执行；普通不挂品作品不增加商品字段问卷。准备资料中的链接只用于定位和交接，不等于平台已经挂载。

1. 在实际发布入口核对当前账号是否提供商品挂载、是否具备所需权限，以及目标商品能否选择。按实际界面定位商品，核对商品名称、店铺或商家、可见的商品标识与规格。原始链接与平台回显链接不一致时仍以商品身份核实。平台只支持商品级挂载时如实记录，不声称锁定了用户购买SKU。禁止仅凭相似标题换品或把链接粘入正文充当挂品。
2. 保存选择并返回发布表单，回读实际挂载的商品卡片或清单，核对与本次资料、视频展示商品一致；截图或回执引用原执行证据。入口缺失、权限不足、商品下架或不匹配时，停止依赖该挂品的提交并说明具体限制，交用户接管或等待调整决定，不擅自改成无商品发布。
3. 提交后从原作品管理条目核对挂载结果；公开后在可访问的作品入口再次核实商品入口及对象。视频公开状态与挂品结果分别记录，查不到挂品结果写待核实，确认未挂上写实际问题；不因挂品异常把已公开视频写成未发布，也不自动重发或换品。
4. 手动发布交付相同商品资料及核对要点，用户提供结果后回写原发布事件。计划挂载对象、平台实际挂载对象和差异写入调用方的发布说明或原核对记录，结果证据引用原附件，不再建立挂品台账。

平台指南只提供入口导航，未核实的商品控件名称或能力不写成通用事实；执行时按当前账号实际页面核对并保留限制。

### 上传核查与临时草稿

核查发布字段先利用现有作品的只读入口；需要新传文件才能显示字段时，按浏览器工具规则取得具体文件、目标平台及清理范围的授权。新建前记录待发布作品和草稿基线，仅操作本次临时表单，不点发布或提交定时。完成后先退出编辑，再检查自动草稿和“继续编辑”残留；关闭标签页不等于草稿已清理。只放弃或删除可确认为本次创建且获准清理的条目，工具要求不可恢复删除须在执行时确认的，保留该条目等待确认，不能绕过。清理后回读基线、原作品及原排期，证据留在项目执行附件，不能补成成功发布记录。

### 提交前截图

在主表单回读核对后截图，覆盖标题、正文、话题、采用的各版封面、本条发布设置和定时发布时回显的日期与时间。按页面实际提供且本条适用的字段留证，一张放不下时按表单顺序连续分张截，保证各处已填内容清楚可读。

用户要求先看预览时，交付截图并列出待定项，停在提交前等待确认。必填资料和发布安排已确认，且已获本次明确提交授权时，截图后直接提交，再按[定时提交后核对与汇报](#定时提交后核对与汇报)接续。

## 代为定时发布

1. **备料与核对账号**。按[准备发布包](#准备发布包)确定成片、文案、封面和本条设置。按[浏览器任务与收尾](../../studio-operations-setup/references/运营启用与账号连接规范.md#浏览器任务与收尾)进入正确 Chrome 配置并核对实际账号，使用本任务标签组。按页面核对定时功能、有效时间、时区及上传限制。页面不接受原排期时按[排期建议与授权](#排期建议与授权)接续，待用户确定调整。
2. **按表单顺序一次填写**。先确认表单加载的是正式成片，再按平台指南填写已备齐的文案、话题、封面和[本条发布设置](#本条发布设置)，核对话题和封面裁切。本次要求挂品时执行[商品挂载与结果核对](#商品挂载与结果核对)。涉及协议、实名、验证码或权限时按当前工具规则处理。必要的文案长度适配保留原意并同步发布包，实质改写或换素材按本次授权处理。
3. **核对、截图、提交**。确认视频处理完成，回主表单核对已保存封面及其他实际填写项，包括账号、作品、文件、文案、本条设置、定时时间和适用的挂品。按[提交前截图](#提交前截图)留证，并根据本次授权接续预览或提交。
4. **核实结果并统一汇报**。按[定时提交后核对与汇报](#定时提交后核对与汇报)查作品管理、截图和回写。按[记录与检查收尾](#记录与检查收尾)整理本次页面。

用户要求更改或取消已定时作品时，定位原条目操作，核实新状态并更新原记录，不能用重复新建作品代替修改。预约时间到后按[发布后检查与临时跟进](#发布后检查与临时跟进)核验。

## 定时提交后核对与汇报

1. **在作品管理定位本条。** 提交后进入当前账号的作品管理或平台对应入口。用标题和作品封面等信息确认是本次作品，页面提供作品ID时一并核对。回读平台显示的预约日期、时间和状态，对照用户批准的排期。后台明确确认预约且时间一致时记录预约成功，审核状态按页面原文另记。页面只显示「审核中」时记录审核中，预约信息有缺项就标为待核实。公开状态按[实际发布与记录](#实际发布与记录)核实。
2. **结果不明先查条目。** 遇到报错、超时或没有明确回执，先在同一账号的作品管理查看是否已生成条目。找到就沿原条目核对时间和状态。只有确认未生成条目，且本次授权和排期仍然适用时才重试。仍无法判断时记录待核实，暂停再次提交。多平台发布分别回读，只处理尚未完成的平台。
3. **截图并回写。** 在关闭页面前截取能识别本作品的管理条目，保留可见的预约时间和状态，一张放不下时分张留存。条目待核实时保留实际回执或查询结果截图。把截图、后台回显、作品ID或管理入口、保存选项与发布资料的对应关系写入调用方指定的记录。带货作品按[挂品结果规则](#商品挂载与结果核对)回读商品。异常按[审核状态与异常处理](#审核状态与异常处理)接续。
4. **一次汇报。** 同时交付提交前表单截图、作品管理结果截图、后台回显的预约时间和当前状态、管理入口。时间有差异或结果仍待核实的，写清实际回显及缺项。页面提供修改或取消入口时随结果附上。

## 审核状态与异常处理

提交成功、审核通过、已公开、推荐／搜索受限分别判断。遇到拒绝、限制展示或其他异常时，先读取该条目的具体处置、原因、时间及建议，保存必要证据；不把限制推荐等同于删除或未公开。审核状态变化时更新当前状态并保留历史处置，不推定申诉已通过或猜测变化原因。

平台要求补充编号、资质或材料时，核对所指字段，不能用普通作品代号替代另一类编号，也不编造缺失信息。是否适用于本条内容以实际提示及可核实依据判断；某作品的审核结果不能直接认定其他未审核作品也被拒绝。影响已确定排期或需修改、重发、申诉时，说明具体缺项与可用处理方式，按用户决定接续，不从发布授权自动推导这些额外动作。用户要求等待审核时保留条目和跟进状态。

## 实际发布与记录

按调用方的记录映射写入发布安排、实际进展和公开结果。发布事实包含平台账号、实际发布时间、作品标识及链接、实际发布包入口和核验证据。

- **核对状态与可见范围。** 从作品管理回读同一账号下的原条目，核对标题、作者或作品ID。作品页可访问时，核对作者与作品是否相符，并检查公开访问状态。后台明确显示已发布时，按事实记已发布，按已核实的页面证据另记可见范围及推荐／搜索限制。面向所有人的作品，使用可核实的公开作品页或后台明确的已发布与公开设置确认公开。媒体或可见范围暂时无法核实时说明核对范围。
- **记录时间与链接。** 实际发布时间取平台标明的发布时间，按可核实精度和时区记录。预约时间保留在计划字段。作品链接取平台提供的该作品入口或分享链接，打开后核对作者和作品。有可核实发布状态但缺少时间、作品ID或链接时，保留已核实状态，缺项按调用方规范标为待核实或未取得，公共模板使用N/A。管理入口和公开作品链接分别记录。
- **回写原记录。** 将实测状态、准确素材、后台截图或作品页证据按业务位置回写。授权依据与结果证据各自记录。手动发布的用户反馈作为接续依据，平台回读结果记在原作品的发布记录。公开后对照最终发布包核对实际内容。

用户手动提前发布、改排期或调整发布设置后，先定位原条目并核对实际状态，再更新同一次发布记录。改预约时更新计划时间并保留原排期及变更依据。设置变更记录平台实存值。各平台分别回写已核实的内容、发布进展和运营状态。

## 发布后检查与临时跟进

1. **定时发布到点核验。** 预约时间到后，由承接发布的 Agent 打开原作品管理条目，按[实际发布与记录](#实际发布与记录)核实。当前会话继续跟进时在到期后检查。到期前先交回预约结果时，在原记录留下预约时间、原作品入口和待核验事项，本条下次接续时优先核对已到期的作品。
2. **手动发布收到反馈后核验。** 用户告知已提交或已发布，或提供作品链接、平台回执后，沿原账号和作品核对平台结果。用户手动预约的作品按定时发布的时点核验。两种方式都把核验结果写回原发布记录。
3. **仍在审核时继续读原条目。** 已到预约时间或收到手动发布反馈后，后台仍显示审核中时，登记审核中和本次检查证据，实际发布时间及公开链接留待核实。当前跟进任务可继续时，后续回读同一条作品。出现拒绝或限制提示时按[审核状态与异常处理](#审核状态与异常处理)核实具体原因。

用户要求跟进某次发布直到完成时，在当前会话按实际可用工具继续检查，直到核实发布结果及目标可见范围，或确认失败、遇到需要用户决定的状态。无法持续检查或需要用户接管时，记录后续核验事项和原作品入口，在汇报中说明当前状态及可接续方式。单条发布的等待、完成通知和补录使用原会话与记录。用户另行明确要求长期周期性运营报告或独立提醒时，按实际授权和工具能力安排。

每次只处理尚未核实的结果与实际缺项。用户已手动发布或某平台已完成时，更新原执行记录及跟进提示，不按旧计划重放发布动作；无变化且无需行动时保持安静，仅完成、失败、明显异常或需要用户处理时通知。

对于既有且确属本次任务的一次性跟进，结果核实、记录更新且已向用户汇报后，按当前工具允许的管理操作删除其真实ID对应的定时器并核对删除结果，在原执行记录注明ID、完成结果及已删除；仅暂停不算收尾。尚未完成或需要用户决定时保留跟进，用户明确停止则按其要求处理。删除调度保留执行资料，不自动归档会话。

发布后将实际作品交[复盘模块](../../studio-operations-review/SKILL.md)。使用浏览器执行读取、上传核查或发布均按[浏览器收尾](../../studio-operations-setup/references/运营启用与账号连接规范.md#浏览器任务与收尾)完成收尾。
