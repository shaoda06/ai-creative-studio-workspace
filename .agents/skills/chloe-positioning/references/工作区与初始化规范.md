# 工作区与初始化规范

## 目录与归属

真实工作区位于`workspaces/Chloe Workspace/`，根目录README使用总层六章结构。每个项目直接放在工作区根目录，以用户明确提供的项目名称、项目代号或社交媒体账号名称命名，不另加品牌目录或自动编号。

```text
Chloe Workspace/
├── README.md
└── 用户提供的项目名/
    ├── README.md
    ├── 综合资料/
    │   ├── 账号定位.md
    │   ├── 选品记录.md
    │   ├── 运营复盘.md
    │   ├── 商品资料/
    │   ├── 共用素材/
    │   └── 资源/
    └── projects/
        ├── README.md
        └── V编号-视频名称/
```

所有项目使用相同结构。每个项目可以关联多个平台账号；定位、商品、资产、视频和复盘各归其项目，默认不跨项目共享。同一作品多平台发布沿用原视频资料，不另复制项目。项目内原有目录和文件名保持稳定；V、M、O等业务编号以及B、R、T等记录编号均在所属项目内解释，不凭编号跨项目寻找资料。

项目的`综合资料/`保存账号定位、选品记录、运营复盘、商品资料、共用素材及共用资源区。发布平台、人群和风格归账号定位。固定分类为`商品资料/`，以及`共用素材/AI模特/`、`服装/`、`造型/`、`场景/`、`声音/`。分类与资产说明只引用媒体，实际共用媒体归`综合资料/资源/图片、视频、音频`，按[资源规范](../../chloe-assets/references/资源存储与引用规范.md)管理。单条视频结构归[创意建档规范](../../chloe-creative/references/视频项目与脚本规范.md)。

## 项目名称与初始化时机

项目初始化之前，Agent必须取得用户明确提供或明确选定的名称。可以是项目名称、代号或社交媒体账号名称，没有固定命名前缀。用户尚未提供时询问；用户说没想好时先帮助拟名，等用户选定再初始化。不得替用户补全名称，不以“待命名”“未命名”“待确定”等占位值绕过此步，也不先建目录再问。已有明确名称直接使用。

脚本没有默认项目名，项目命令的`--name`必填；视频和资产命令的`--project-name`也必填。脚本拒绝空名、占位名、路径分隔符和工作区保留目录名。确认名称来自用户是Agent的职责，不能把脚本接受任意合法字符串当作用户已经命名。

固定目录由初始化脚本建立，包括暂时为空的分类；实际资产与视频只按明确任务建立。重复初始化只补缺，不覆盖已有正文、配置、版本和引用；编号已用于另一名称时停止，不借初始化改名。工作区初始化只建README，不创建任何项目、账号资料或资产索引。

## 初始化命令

从总工作区使用已有浏览服务Python环境，无需联网或启动服务：

```sh
工作区浏览服务/.venv/bin/python .agents/skills/chloe-positioning/scripts/chloe_init.py --workspace 'workspaces/Chloe Workspace' workspace
工作区浏览服务/.venv/bin/python .agents/skills/chloe-positioning/scripts/chloe_init.py --workspace 'workspaces/Chloe Workspace' project --name '用户提供的项目名'
工作区浏览服务/.venv/bin/python .agents/skills/chloe-positioning/scripts/chloe_init.py --workspace 'workspaces/Chloe Workspace' video --project-name '用户提供的项目名' --id V001 --name '视频名称'
工作区浏览服务/.venv/bin/python .agents/skills/chloe-positioning/scripts/chloe_init.py --workspace 'workspaces/Chloe Workspace' asset --project-name '用户提供的项目名' --kind 模特 --id M001 --name '模特名'
```

命令中的名称与编号只是用法，须替换为真实已确认值，不据此自动创建对象。`--workspace`指向实际或隔离的Chloe Workspace目录；`--project-name`指定该目录下已建档项目，不包含路径。视频编号为V001等，资产前缀为商品G、模特M、服装O、造型L、场景S、声音A；Agent核对当前项目已有目录后明确传入。脚本输出实际目录JSON；参数缺失、格式错误及编号冲突直接失败，不生成媒体、不提交任务、不登记采用、不安装依赖。

## 登记、分发与验收

浏览空间和任务连接按[运行资料规范](../../studio-workspace-browser/references/任务运行资料维护规范.md)管理。Chloe登记使用`project_layout:"nested"`；工作区初始化与登记分开；只有明确传入workspace的`--register`才尝试登记，不启动或重启服务。资料迁移涉及浏览或任务路径时先核对当前任务与接口支持，在路径接入完成之前不切换真实资料。不复制任务库、原请求、媒体或其他项目凭据来创建项目。ComfyUI节点连接配置保留在工作区根目录，各项目复用该技术配置；它不承载账号定位或业务资产。

技能、脚本和模板归总仓库；实际项目及其README、账号事实、媒体、执行记录和本机配置全部留本地。工作区README只负责项目入口，项目README承载本项目约定及会话入口；不把某个实际项目的名称预填进公共模板。项目README及其模板保留定位、目录索引、项目专用例外与规则链接，不复制技能中的通用制作步骤、技术规格或页面布局。规则变化更新所属技能；仅当入口或项目真实约定变化时同步README，保留已有项目决定及事实。

## 固定文件的填写与检查

固定文档按[固定资料写法](固定资料写法规范.md)填写。不同资产使用独立模板；更新格式时保留原有实际决定及记录，不用初始化强制覆盖。检查与资源脚本的`--project-root`明确指向具名项目根目录，文档相对路径及共用引用的路径都以该项目为基准。

```sh
工作区浏览服务/.venv/bin/python .agents/skills/chloe-positioning/scripts/chloe_documents.py check --project-root 'workspaces/Chloe Workspace/用户提供的项目名'
工作区浏览服务/.venv/bin/python .agents/skills/chloe-positioning/scripts/chloe_documents.py read --project-root 'workspaces/Chloe Workspace/用户提供的项目名' --file '综合资料/账号定位.md'
工作区浏览服务/.venv/bin/python -m unittest discover -s .agents/skills/chloe-positioning/scripts -p 'test_*.py'
工作区浏览服务/.venv/bin/python -m unittest discover -s .agents/skills/chloe-assets/scripts -p 'test_*.py'
```

check检查本项目固定资料、共用及视频资源、引用和实际剪映清单；read返回同一规则解析的数据，不保存第二份业务记录。验证使用独立临时目录，核对缺名拒绝、项目隔离、重复初始化保留正文、旧引用不随新版变化、越界与重复导入拒绝及并发保存；不能用测试资产填入真实projects。

## 项目归档

整个具名账号项目的归档与恢复调用[共用归档](../../studio-archive/SKILL.md)，不按内部 V 视频分别归档。其标记放在项目 README“项目接续与相关资料”中，保留原会话表和视频制作进度；工作区浏览列表读取该根目录标记。
