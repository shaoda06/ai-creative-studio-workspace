# H3参数与基准

## 1. 当前固定基准与任务副本

工作流基准与任务副本的维护边界统一读取[维护规范](../../studio-entry/维护规范.md#工作流基准与任务副本)。正式与非正式文件的目录归属按[维护规范第1节](../../studio-entry/维护规范.md#1-目录分类与文件归属)执行。画布保留UI布局、导演台公共/本组编辑状态及说明；API只保留正式输出所需的服务端依赖。标准版节点标题使用“中文解释名｜英文原名”，英文原名保留节点实际类型名（例如`二采前馈分块｜MiniMaxChunkFeedForward`）；标题不写节点编号、权重、步数、块数、尺寸、设备或开关状态等实际配置，参数保留在控件与执行规则中。API的`_meta.title`沿用同一格式，实际节点ID及类型标识不改。

画布按“模型加载组、LoRA组、实际工作组”分区；LoRA区内分出常驻LoRA组、可选附加LoRA和专用打戏LoRA组，布局分组不改变节点启用状态或执行接线。

### 1.1 离线API检查与回归测试

[workflow_baselines.py](../../studio-comfyui/scripts/workflow_baselines.py)使用Python 3.9及以上标准库，只读取API，检查必要输出、连接引用、RTX必填参数、后处理链路及API内部导演台时间线和编辑状态。不读取画布，不做画布与API一致性或差异比较。

```sh
python3 -B /实际技能目录/scripts/workflow_baselines.py
python3 -B -m unittest discover -s /实际技能目录/scripts -p test_workflow_baselines.py -v
```

可选`--directory /待检查目录`，扫描其中API及统一目录入口登记的直属分类，不递归扫描其他目录。默认覆盖6份正式API，非正式目录当前为空；每份输出一行JSON，成功输出PASS并退出0。空目录也可返回成功，须确认目标有被覆盖。修改API或相关脚本时运行；普通提交不重复跑整套测试。不使用`-O`。

后处理报告列出宽高、目标帧率和编码参数；低于交付建议只提示，不强制改写用户已确认目标。正式RIFE同时检查随包ZIP的必需文件、完整性和Python语法，不加载模型、不运行GPU。测试不连接远端，不证明实际生成或用户批准。

标准版画布完整接线为192 → 331 → 53 → 128 → 507 → 342 → 344 → 345 → 343 → 405，默认将128、507、342、344、345旁路，实际执行链为192 → 331 → 53 → 343 → 405。LoRA、采样步数、生成尺寸与后处理按下节选择，其他生成参数和时间线保持不变；405直接接261和502；二采独立支路为405 → 408 → 409 → 407.refine_model。执行端须提供上述两个分块节点及对应参数接口，不用Refine的时间／空间分块开关替代模型分块。331选择完整注意力计算后端，一采与二采均沿用Kitchen；不串接Sage补丁或332稀疏注意力。407连接502.refine；没有SelfLift、FaceRefine或语义桥连接。两轮实际步数按外部SIGMAS及一采补零后的结果记录，不能把261显示的总步数登记成两轮实际总步数。

Refine先按一采比例及 `megapixels × 1024²` 计算目标宽高，再分别对齐32；仅填写width/height不会覆盖这一计算。一采1024×576时，MP=1.265625得到1536×864，MP=1.9921875得到1920×1088；竖屏576×1024使用相同MP分别得到864×1536和1088×1920。任务副本同时填写MP与目标宽高，执行依据是实际API中的MP；不要只改宽高控件。打戏二采受32对齐影响，比例略偏离16:9／9:16，后处理按短边方向裁掉8像素得到标准画幅；不拉伸二采原片，也不改写一采缓存。

参考图片尺寸由各组 `refImageSize="1536"` 控制，保持原比例；该设置与生成画布尺寸及 `ref_max_size / refMaxSize` 分开，不通过修改后者替代。正式基准各组与output回退值均保存1536；准备、新增、复制或导入任务分组时逐组落实，并同步根时间线及对应编辑工作区。插件“新增分组”会生成自己的尺寸值，不能宣称仅修改基准JSON就改变了插件默认行为；手动画布可复制已设1536的组，新增空组则须选择1536。

执行端的清理实现须在模型GC／卸载前清空动态显存预取队列，按阶段保留／卸载模型，并支持 `precise_segment_memory`。精确调度按模型权重大小与物理内存总量的比例选择策略，不是按当前内存占用率决定。节点缺少所需接口时报告兼容性问题，不静默删掉参数、覆盖插件或更改启动配置。

基准更新及版本选择用于后续获授权任务，不自动改写已有任务副本、请求或批准来源。已有一采的二采接续沿用原工作流版本和原一采尺寸，不自动改用当前基准或其他LoRA配置；需要切换时先核对模型链与缓存影响。参考图策略属于一采缓存输入；已有一采接续二采时按[制作变更时的缓存保护](ComfyUI-MiniMaxH3导演台节点使用规范.md#75-缓存检查与清理接口)保留来源配置并核对缓存，不套用新基准导致重新一采。不同分辨率的一采即使使用同一种子也可能产生不同构图和动作，既有内容批准不自动转用于另一尺寸的新结果。

### 标准版配置选择与装配前询问

本节适用于所有业务及独立技术任务调用H3标准版，配置询问是装配输入的确定步骤，由使用共用工具的Agent执行。脚本接收已确定的配置和方向，按下方参数表装配。内容、生成范围、一采审阅、二采及后处理的执行授权仍由调用方提供，配置选择本身不代表获准生成。

标准版采用“项目默认配置＋每批允许临时覆盖”。新批次依次采用用户本次明确指定的配置、适用且由用户确认过的项目默认配置；已有本批选择直接沿用。沿用项目默认时简短告知实际配置，不逐批弹窗或要求再次确认。单批覆盖只作用于该批，不自动变成项目默认；只有用户明确要求修改项目默认时，才由调用方写入其既有项目资料，记录配置编号与名称、适用范围及用户决定入口。未设置默认或独立技术任务没有项目默认时，不从画布初始状态推断。

既没有本次选择也没有适用的项目默认、用户主动要求选择或比较配置，或已确认配置无法满足本次明确要求且需要用户取舍时，才问“本次生成使用哪一种工作流配置？”。优先使用当前可用的选项弹窗；弹窗不可用或无法完整展示四项时，使用聊天正文询问。逐字展示以下四条选项，保留编号和顺序，不缩写配置名、不省略尺寸和后处理、不将“8步+归零”改写成“9步”，也不用技术表替代询问内容；具体适配冲突须说明原因，不以一般性担忧恢复逐批询问：

```text
1. 文戏默认，一采8步+归零（1024x576）二采4步（1536x864），后处理（1920x1080）
2. 文戏+去油，一采8步+归零（1024x576）二采4步（1536x864），后处理（1920x1080）
3. 打戏默认，一采8步+归零（1024x576）二采6步（1920x1088），后处理（短边两侧各裁4像素）
4. 打戏+去油，一采8步+归零（1024x576）二采6步（1920x1088），后处理（短边两侧各裁4像素）
```

每次展示四条配置选项时，结合项目已确认偏好与本次明确需求，在一个完整选项之后标出“（推荐）”，并简短说明理由，不改写选项正文或调整顺序。尚无项目默认且没有打戏、去油或其他明确适配需求时推荐选项1；有打戏适配需求时推荐选项3；有成人内容表现或人物去画面油腻需求时推荐选项2；两类需求同时存在时推荐选项4。推荐不代替用户选择，不因剧情或观感自动开启配置，也不增加单独的推荐审批。

四条选项保留横屏基准尺寸，9:16适配不改写以上展示内容。画幅优先沿用项目或本次已明确的选择；未确定时只补问“本次使用16:9横屏，还是9:16竖屏？”。若本次同时需要选择配置，将画幅问题放在四条选项之后；不为询问画幅重复选择已确定的配置。用户选择竖屏后，告知按9:16适配执行，实际尺寸和裁切按下方横竖屏表换向。

配置及方向明确前可准备资料和做离线预检，实际上传、入队和生成须等待相应选择确认及本次执行授权。「继续做」「参考图可以」、画布保存的文戏默认与16:9初始状态、预设名中的「默认」、弹窗预选项或未回复都不能代替配置确认。

查询、结果通知和原任务故障重试不重新选配置。已有一采接二采沿用该来源已选配置及实际步数、尺寸、方向和噪声表；用户要求换配置时先说明一采来源和缓存影响，不把切换后的二采当作原一采的直接接续。项目默认只用于后续新批次，不随默认变化改写历史请求、批准或缓存。

将实际采用的配置编号、来源（本次选择或项目默认及其决定入口）、方向和执行授权写入调用方已有任务记录；具体字段及项目默认保存位置由调用方维护，不新增配置台账。按[标准版配置参数](#标准版配置参数)在任务副本中落实模型链、步数、尺寸、Refine及后处理，不把本次选择写回共用基准。
