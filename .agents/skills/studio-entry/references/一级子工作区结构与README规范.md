# 一级子工作区结构与README规范

## 归属与边界

本规范由AI Creative Studio总工作区维护，只规定Nora、Iris等一级子工作区的命名、基础结构和说明入口。项目编号、业务阶段目录、项目README及建档方法由对应业务维护，不在本规范复制。总入口只登记和引用规范。

## 工作区结构

- 一级子工作区位于总目录的`workspaces/`，使用英文女生名开头，目录名为`名字 Workspace`。工作区名字确定后，其一级、二级业务技能使用同名英文小写前缀。
- 工作区根目录使用`README.md`作为定位、独有约定和资料导航入口，不另建工作区级AGENTS.md。AI Creative Studio根AGENTS.md及开发工具自身的局部指令不受此约定替代。
- `projects/`保存独立业务项目；`综合资料/`保存该工作区跨项目资料，首次需要时建立。已有配置、历史归档及独立Git按实际用途保留，不据此自动创建空目录。
- 技能、业务规范、模板和共用工具统一在总目录`.agents/skills/`维护。资料区不复制技能库、不另启浏览后台或任务监控器。
- 新建工作区按本规范及[模板](../templates/一级子工作区README模板.md)填写真实名称、业务入口和路径；空间登记及数据库位置按共用浏览服务的[运行资料维护规范](../../studio-workspace-browser/references/任务运行资料维护规范.md)执行。后台自动在总服务内建立独立任务库，不在业务资料区创建服务目录，不把创建资料目录视为已完成登记。

## README固定写法

一级标题为工作区英文名与业务说明。以下六个二级标题按顺序保留；其下可用三级标题展开，已有外部引用的章节锚点继续保留。

| 二级标题 | 内容 |
| --- | --- |
| 工作区定位与业务范围 | 名字、所属总工作区、业务范围及必要边界 |
| 一级业务入口 | 本工作区实际负责的一级业务及其技能链接，不抄业务流程 |
| 目录结构与资料存放 | 实际项目、综合资料、配置和历史目录的用途；不规定业务阶段目录 |
| 项目索引入口 | 链接已有索引，或说明按projects实际子目录查找；不复制项目进度表 |
| 工作区专用约定 | 仅本工作区有效的约定；通用约定引用根AGENTS，实际任务授权和状态仍归项目 |
| 项目接续与相关资料 | 进入项目时读取其README及状态文件，提供能力状态、接续及历史说明入口 |

README是需要Agent主动读取的业务说明与规则文件，不宣称由Codex默认自动注入。新增业务时更新真实业务入口；项目状态变化不要求重写工作区README。

## 项目层的维护入口

- Nora连续短剧：项目结构沿定位建档阶段及其引用的业务结构规范，项目README使用该阶段的[规范](../../nora-drama-positioning/references/项目README规范.md)和模板。
- Nora社媒运营：沿用所属创作项目README；实际独立运营项目按[运营项目规范](../../nora-operations-setup/references/运营项目README规范.md)建档。
- Iris商业视频：项目结构与README由[需求建档阶段](../../iris-commercial-brief/references/项目建档与README规范.md)维护。

新增一级业务必须明确自身项目结构与README的维护入口，不直接套用另一个业务的阶段目录。已有项目专用约定继续在其适用范围内执行。
