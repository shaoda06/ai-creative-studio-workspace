# 项目整理与技术测试规范

## 旧结构转为正式项目

仅在用户授权项目整理或旧结构迁移时执行。目标目录、初始化、编号、正式产出和状态文件由所属业务的建档及阶段规范决定；只读检查、普通接续或技能维护不授权迁移真实资料。

1. 明确目标项目、范围和内容归属，区分目录整理与创作扩展。归属不明且影响归位时，提出具体建议交用户决定，不补造作品编号、增加内容或重做素材。
2. 盘点当前正文、在用素材、历史版本、执行证据、配置和引用方，明确旧新位置；已有正式位置的资料按原分类保存，不将全部旧资料塞入综合资料。
3. 按所属业务留存整理前状态和必要旧版，用其初始化入口补齐获授权范围内的结构。已有不同内容不覆盖；不为填满目录补写尚未开展的阶段。
4. 移动资料并同步当前引用，保留原始请求、响应、已提交工作流、任务标识和批准原文。历史位置通过既有迁移记录追溯，不把路径调整登记成新生成或新批准。活动任务依赖待移动路径时，保留有效入口并明确暂缓范围和接续条件，不擅自中断或重新提交。
5. 同步所属业务的唯一进度、项目入口、索引和任务当前路径，复用实际会话及已确认成果。已接入网页的资料按[业务接入检查](../../studio-workspace-browser/references/业务接入规范.md#资料变更与解析接入检查)及所属业务映射核对；项目整理不自动授权修改公共代码。
6. 完成前核对现行入口唯一、资料和批准事实完整、旧新位置可对应、在用链接及下载可达，归档不再作为现行来源。退役文件和空目录按本次授权收尾；仍有依赖或未归位内容时列明位置及剩余动作，不以标准目录已创建宣称迁移完成。迁移完成不等于制作完成。

## 技术测试资料归属

- 创建目录或派发任务前，按实际用途区分业务制作与工具验证。正式业务项目列表不登记独立工具验收、工作流验证、性能测试或演示项目；使用业务模板、编号或目录不能改变测试性质。
- 需要长期保留的跨业务测试资料归总层`综合资料/<测试事项>/`；仅属某业务的跨项目测试归该资料区`综合资料/<测试事项>/`。明确属于真实项目的试验沿该业务的项目内规定位置保存，不能借测试之名改写正式来源或批准状态。集中保留必要输入、独立成果、请求、证据和结论；代码、缓存及已有专用验证附件位置不因此迁移。
- 模拟项目结构或验证网页、后台、生成链路时，执行[技术测试与隔离验证](../维护规范.md#技术测试与隔离验证)。媒体准备使用[隔离测试媒体入口](../../studio-workspace-browser/references/存储与测试媒体维护.md#隔离测试媒体准备)，复用相同内容并收尾本次中间文件。

## 下载核验包清理

“重复包”指仅为本次下载核验生成、下载或复制，结束后没有独立交付或复用用途的包，不要求二进制字节相同。这是本次测试收尾，不是历史去重，不据此扫描其他目录；原件、独立测试成果、正式交接包及依赖安装包按各自规则留存。

- 使用[临时核验入口](../../studio-workspace-browser/references/存储与测试媒体维护.md#隔离测试媒体准备)。核验结束并记录结果后，清理本次重复ZIP、剪映包及仅供核验的解压副本，成功或失败均不默认长期留包；仍在核验或用户要求保留的文件按实际范围处理。
- 在既有记录写明包身份、所测版本和范围、检查项、结果或失败原因，以及清理情况和时间。历史包路径注明已清理，不再作为下载入口，不另建清理台账。
- 只清理本次重复文件；正式媒体、制作记录、原始输入、用户主动保存的下载文件及其他任务资料不在范围内。结束前核对重复包已移除、记录仍在，服务临时包自动清理不替代核验副本收尾。
