# 固定脚本接口规范

共用[提交工具](../SKILL.md)和[任务后台](../../studio-workspace-browser/SKILL.md)只处理调用方已明确的请求、参数、路径及技术事实。内容、业务目录、来源资格、记录和采用由调用业务及登记适配负责，模型正文由Agent编写；不要求所有调用方具备短剧资料卡、EP编号或六列进度表。

# 通用 ComfyUI 执行工具

入口：[comfyui_client.py](../scripts/comfyui_client.py)。Python 3.9+，仅标准库；实现归本共用工具，旧短剧位置仅兼容转调。与 `comfyui-api` 技能结合使用：技能提供连接、接口与安全规则，脚本执行上传、提交、单轮查询和下载。节点／模型检查仍按 `comfyui-inventory`；故障按 `comfyui-troubleshooter`。


## 使用边界

工作区任务的调用入口和授权边界统一见[固定通信工具与证据](ComfyUI-服务配置与任务提交规范.md#固定通信工具与证据)；按该规范使用下方队列入口或工作区认证适配入口。本文原生客户端命令用于独立通信和底层接口说明。

业务关联更新由登记的业务适配预检和写入；共用工具只检查技术请求、路径、文件与提交边界，不决定业务进度表或采用范围。

- agent 按当前业务规范准备最终 **API 格式节点 JSON**、参考素材映射和全部参数；脚本不修改提示词、种子、节点或连线，不转换画布 JSON，不内置工作流模板。
- 上述已有能力必须复用此脚本，不按任务新写 Python／shell／内联 HTTP 实现。准备 API JSON 和人工审核仍由 agent 完成；批准、采用及业务收尾使用调用业务自己的固定入口。发现脚本缺陷先报告并集中修复，缺少接口则明确缺口后处理，不悄悄回退成一套临时执行器。
- 只处理当前获得授权的任务；不启动下一阶段、不自动重试提交、不管理定时器、不操作队列删除／中断／卸载／服务器配置。
- 通信客户端本身不决定项目路径、命名、审批或归档，不生成或维护项目工作稿，不移动候选至选定。Agent核对实际技术结果；内容审阅、看图权限、批准后处理及采用由调用业务和本次授权决定，工具不自动重试或启动下一阶段。
- 五个命令相互独立。已有远端素材可以复用；新本地素材由后台上传并把实际返回路径写入声明的API输入。接口验证／节点发现等不在这些命令内的只读操作仍可按对应技能执行。


## 独立通信调用

以下相对路径示例在本 README 所在目录执行；跨会话优先使用脚本绝对路径。每个命令的参数以 `python3 comfyui_client.py COMMAND --help` 为准。

所有命令支持 `--url`、`--timeout`、`--result`：

- `--url` 优先，其次 `COMFYUI_URL`；均未提供就报错。脚本没有默认服务器。agent 从当前任务或 `comfyui-api` 配置确定地址再传入，不自行改全局设置。
- `--timeout` 默认30秒，表示网络阻塞操作超时，不是整个生成任务的时限。大素材可按实际情况明确设置更长值；不自动重试 HTTP。禁止带凭据的 URL，不跟随 HTTP 重定向。
- `--result` 可指定一个**尚不存在**的 JSON 文件。调用前独占创建，避免网络操作成功后才发现目标冲突；异常结果也会保存。省略时仅写标准输出，agent负责留存。文件不得覆盖；是否落盘由调用方的留档规则决定。
- 除 `--help` 外，标准输出为 JSON；退出码0表示本次工具操作成功，1表示工具错误。`status` 返回 `state=failed` 仍可能退出0，意为“查询成功、任务失败”，不是生成成功。


### upload：上传原始字节

```sh
python3 comfyui_client.py upload --url 'http://SERVER:8188' \
  --file '/absolute/path/reference.png' --subfolder 'unique-task-inputs' \
  --result '/absolute/path/upload-response.json'
```

通过 `/upload/image` 的 multipart `image` 字段提交文件，`type=input`、`overwrite=false`；不限制扩展名，但是否能由工作流加载需另行核对。使用临时磁盘流构建请求，不把整个视频读入内存；不转码、裁剪或处理媒体。

返回 `data.remote`（服务器的 name/subfolder/type）、`data.input_path`（正斜杠输入相对路径）、上传字节数及SHA-256。同名文件服务器可能重命名或复用，必须使用实际返回值，不按本地文件名推断。上传结果不明时先查已有响应／服务器文件，不能宣称文件未上传或无限重传。


### submit：只提交一次

```sh
python3 comfyui_client.py submit --url 'http://SERVER:8188' \
  --workflow '/absolute/path/task.api.json' \
  --record-dir '/absolute/path/execution-record'
```

接收节点对象，不接受画布格式或已经包了一层 `prompt` 的请求。只做JSON及基本结构检查，节点／模型存在性、允许参数、素材批准和生成授权由agent预先确认。原节点对象作为 `prompt` 原样封装，额外生成唯一 `client_id`。JSON数字使用Python整数，不把大种子转换成浮点。

后台的工作流基础结构、提交证据名称合法性及名称冲突属于准备阶段固定检查，资料未变复用既有报告，入队和本工具发送时不再重复检查；独立文件调用在本工具入口检查一次。提交证据存在性与独占保护统一在本工具执行，上层不重复扫描三份提交证据。提交前先独占保存防重标记、完整请求，随后只发送一次 POST；返回 `data.prompt_id`、`data.client_id`、实际响应和记录目录。记录默认名称：

| 文件 | 内容 |
| --- | --- |
| `submit-attempt.json` | 服务地址、时间、client ID、请求哈希；保留即阻止重复提交 |
| `request.json` | 实际发送的完整请求 |
| `response.json` | 原始成功响应，或拒绝／不明状态及错误证据 |

agent 可通过 `--attempt-name`、`--request-name`、`--response-name` 指定当前业务规定的文件名（均为单个文件名，不能是路径）。例如视频使用 `提交尝试.json`、`请求.json`、`提交响应.json`；图片使用该任务规定的带编号附件名，**不要求新建额外管理目录**。这些名称只是调用参数，不是脚本内置业务规则。`--result` 不可与上述文件重名。

**同一逻辑提交必须沿用同一记录目录与文件名。** 发现任一证据已存在即拒绝提交，包括超时和先前被拒绝的请求；独占创建发生冲突也停止。两者返回`submission_guard`及`submission_state=not_sent`，表示本次未发送生成POST。后台记录拦截，待执行任务暂停，已有终态／未知状态和原始错误保留，不把拦截误记为新的远端拒绝或提交结果未知。不要换目录、换证据文件名或删除防重标记绕过检查；这是本地记录范围的保护，不是服务器全局幂等，也不能保证跨目录“恰好一次”。

请求超时、响应丢失、无有效prompt ID或服务器5xx时视为提交状态不明；用已保存client ID／请求核对队列及必要历史，不自动重发。正常 `status` 需要真实prompt ID；尚未找回ID时按 `comfyui-api` 做只读核对。只有确认原任务未接受且获得相应方向后才建立新的提交尝试。明确4xx拒绝也保留记录，修正后的新尝试不可覆盖旧证据。


### status：单轮查询

```sh
python3 comfyui_client.py status --url 'http://SERVER:8188' \
  --prompt-id 'REAL-PROMPT-ID'
```

先查指定history，非明确终态再核对queue。只返回本任务证据，不保存其他任务的提示词。状态为 `queued`、`running`、`success`、`failed`、`unknown`。`running`仅表示在运行队列，不证明采样步数正在推进；`success`须服务端明确completed与success且无错误／中断事件，**不等于业务要求的输出齐备或内容获批**。

`data.files`列出返回文件的node_id/output_key/index及原始文件信息；不替agent选择输出。agent核对本次预期节点及具体文件后再下载。原始任务history保留于返回JSON。网络故障是工具错误，不把任务标成失败。不自动等待、定时或启动下一阶段。


### 只读诊断与重启证据

CLI的status已查询history／queue，诊断不要为保存响应重复调用。其他只读核对复用本模块的`Client(url, timeout)`：`client.json(route)`读取JSON，`with client.open(route) as response`读取有界原始日志／响应头；不提供data时为GET，不写另一套HTTP通信。保存当轮返回和本地观察时间，重复错误沿用既有证据。具体次数、间隔及判定由[监控规范](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md#31-异常检查与连接恢复)维护，客户端自身不循环或判断是否补做。

`/system_stats`是连通性／设备快照，没有本工具保证的进程ID、启动时间或每次启动变化的实例标识；相同GPU、版本、URL不能证明同一实例或发生重启。`/internal/logs/raw`及`/vhs/getpath`属于执行端可选接口，仅在实际已确认可用时读取；目录列表限任务已绑定绝对目录，不扫描猜目录。原始日志读取限定大小（例如最多1 MiB），接口缺失如实报告，不安装节点、修改服务或臆造启动标识接口。没有直接进程证据时，按[原任务证据核对](../../studio-workspace-browser/references/进度查询与结果处理规范.md#后端故障后原任务无法确认)核对组合证据，不能由客户端的请求成功代替业务判定。


### download：明确指定文件

```sh
python3 comfyui_client.py download --url 'http://SERVER:8188' \
  --filename 'actual-file.mp4' --subfolder 'actual/subfolder' --type output \
  --output '/absolute/path/candidate.mp4' --result '/absolute/path/download-response.json'
```

三个远端字段来自上传响应或指定任务的输出。`--type`必须显式为input/output/temp；支持服务器返回的Windows子目录分隔符及Unicode、空格，按真实值URL编码。不得猜测文件名或替换成别的任务输出。

流式下载至目标同目录临时文件，核对HTTP长度（如提供）并计算SHA-256；可用 `--sha256` 核对已知传输哈希。完整后采用不可覆盖的原子发布；中断／失败清理本次临时文件，不留下伪装完成的目标。目标已有文件则拒绝，不自行替换、比较后采用或重命名。文件系统不支持原子硬链接时报告错误，不退回覆盖写入。

这些是传输完整性检查，不读取媒体内容、不调用ffprobe／ASR、不解码视频、不进行图片视觉审核。返回 `data.path/bytes/sha256/remote`；业务元数据及审批由agent维护。


## 回归测试与验证边界

纯函数／文件安全回归测试（不启动本地服务、不访问远端）：

```sh
python3 -B -m unittest discover -s '/absolute/path/comfyui-scripts' -p 'test_*.py' -v
```

覆盖请求不改写、大整数种子、重复提交、POST超时不重试、状态分类、不泄漏其他任务、半下载清理及并发落盘防覆盖。POST响应丢失和并发下载边界使用单元测试注入，不通过破坏远端制造故障。真实任务排队中／运行中状态、长时间网络中断、任意自定义节点和认证网关不据此宣称全部实测。


## 工作区认证通信

服务配置与任务地址绑定读取[工作区ComfyUI配置](ComfyUI-服务配置与任务提交规范.md#工作区-comfyui-配置)。新任务经下方统一入口调用本工具；本工具不另维护业务配置规则。新记录使用执行机器本地时区及偏移，协议原始时间戳如实保存。

明确获授权直接查询、取回或诊断时，使用[配置适配入口](../scripts/comfyui_config.py)，复用本客户端的命令、输出及错误语义，并从指定工作区为实际地址读取认证，不在命令行传账号密码：

```powershell
python -X utf8 '.agents/skills/studio-comfyui/scripts/comfyui_config.py' --workspace '.' status --url 'https://comfy.example.com' --prompt-id '实际任务ID'
```

命令从工作区根目录执行；`--workspace` 相对当前目录，必须显式提供。支持 `status`、`download`、`inventory`；子命令参数分别与原通信工具、库存工具说明一致，`--url` 必填。调用范围及地址处理按[固定通信工具与证据](ComfyUI-服务配置与任务提交规范.md#固定通信工具与证据)。适配入口只加载凭据并调用原工具，不改配置、不自动重试。独立通信的Python接口为 `Client(url, timeout, basic_auth=(username, password))`，HTTP和WS可复用实例的 `headers`，不将其写入证据。正常后台队列已使用共用配置，无需每个任务另传认证。

获授权盘点库存时使用以下命令；输出与退出码见[库存工具](../dependencies/comfyui-inventory/SKILL.md)。默认缓存仍在该库存工具的 `state/inventory.json`，可用 `--output` 指定本次保存位置：

```powershell
python -X utf8 '.agents/skills/studio-comfyui/scripts/comfyui_config.py' --workspace '.' inventory --url 'https://comfy.example.com'
```

配置与入口回归使用临时工作区和本机模拟HTTP服务，不读取真实凭据、不调用远端：

```powershell
python -X utf8 -m unittest discover -s .agents/skills/studio-comfyui/scripts -p 'test_comfyui_config*.py'
```

退出0且报告OK表示通过；覆盖跨项目共用配置、逐节点认证、凭据不泄露、禁用直接上传／提交、强制实际地址、库存失败保留旧缓存。

任务准备、查询和取回时，读取[监控规范的精简留档规则](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md#执行附件精简留档)，据此确定附件留存及当前检查时间的维护。


## 统一分配与提交

入口：[comfyui_dispatch.py](../scripts/comfyui_dispatch.py)。Agent调用此入口登记后台本地队列，不向远端上传或提交，不等待生成。工作区配置及调度、按钮语义读取[服务配置与任务提交规范](ComfyUI-服务配置与任务提交规范.md)。上方comfyui_client.py为后台复用的通信模块，调用边界见该规范的[固定通信工具与证据](ComfyUI-服务配置与任务提交规范.md#固定通信工具与证据)。

同项目、同来源且可同时执行的任务放在一份JSON的tasks数组，可选group_title指定组名。每项的业务或technical适配字段按[任务输入分流](#已备资料的逐项参数入口)提供；未获生成授权可只准备，正式登记时每项须写明authorization依据。

```sh
python /实际技能目录/scripts/comfyui_dispatch.py \
  --project /实际项目目录 --plan 执行附件/本次任务/任务清单.json --prepare-only
```

返回prepared后核对内容及授权；实际获准执行时复用原命令、移除--prepare-only登记队列，不另复制工作流或重建任务清单。返回enqueued及group_id/成员ID只表示登记成功。短剧的业务字段及自动记录见[业务装配](../../nora-serial-drama/references/固定脚本接口规范.md#一次装配与批量入队)，其他调用方不为使用共用接口创建该业务结构。



#### 未登记清单的重新准备

准备失败或仅准备后修改内容时，先在原任务清单及独立内容画布中修正输入，再显式重新准备：

```sh
python /实际技能目录/scripts/comfyui_dispatch.py \
  --project /实际项目目录 \
  --plan 执行附件/本次任务/任务清单.json \
  --prepare-only --reprepare
```

`--reprepare`仅与`--plan --prepare-only`合用，不上传、不入队、不生成。限同一来源会话、整份清单尚无已登记任务；即使装配记录漏存已接受ID，只要后台存在对应执行目录，也拒绝重装。新装配记录在原记录中保存字段差异及检查摘要，重复配置/API正文和长文修改按[精简装配接口](../../studio-workspace-browser/references/固定脚本接口规范.md#精简装配记录读取)保存并完整还原；旧式装配记录保留原准备归档行为。从原始输入重新装配并在原执行目录检查，不因重新准备增加候选轮次。任一原准备文件被其他会话修改时停止，不覆盖。原地重装失败仍不入队；缺少原装配记录时按常规命令准备。重新准备返回`status=prepared`后，复用未变化的授权依据，以不带两个准备参数的原命令正式入队；本轮仅获准准备时保持不入队。已有本地ID的资料修正按[原任务重新准备与恢复](ComfyUI-服务配置与任务提交规范.md#重新调度与失败恢复)处理，不用此参数重装清单。


### 已备资料的逐项参数入口

图片清单按显式适配分流：未指定adapter的原清单继续由Nora图片业务装配；纯技术图片指定`image_plan.adapter:"technical"`，直接使用共用Qwen/图片工具已装配的API，不要求短剧kind、人物卡或EP。技术清单每项提供task_type、title、workflow（API对象）、record_dir、outputs及image_plan，参考上传按实际提供uploads；image_plan.images明确实际结果路径/宽高。授权沿用任务清单的authorization要求。技术分支不写业务资料或自动采用，本地尺寸处理直接使用共用图片工具，不传业务local_processing。通用视频可使用`video_plan.adapter:"technical"`清单。

上述清单复用`--plan --prepare-only`准备、不带准备参数登记及原任务恢复入口；已有完整文件也可使用下方逐项参数入口，不另造业务模板、重复API或新的任务后台。

```sh
python /实际技能目录/scripts/comfyui_dispatch.py \
  --project /实际项目目录 --task-type image \
  --workflow /实际执行附件/本任务-工作流.json \
  --record-dir /实际执行附件 --task-title '当前对象 · 首次生成' \
  --attempt-name 本任务-提交尝试.json --request-name 本任务-请求.json \
  --response-name 本任务-提交响应.json --history-name 本任务-执行结果.json \
  --output-plan /实际执行附件/成果取回映射.json \
  --image-plan /实际执行附件/图片收尾计划.json
```

| 参数 | 含义 |
| --- | --- |

### 准备检查与提交复用

同一命令在准备阶段加`--prepare-only`，由后台检查并在原`--record-dir`写`执行检查报告.json`，不上传、不入队、不生成。参数、计划文件与正式提交相同；准备命令不要求已有生成授权。返回`dispatch_state=prepared`和`prepared=true`才表示工具检查成功；失败报告写具体错误，不等于内容审核通过。

```sh
python /实际技能目录/scripts/comfyui_dispatch.py \
  --project /实际项目目录 --task-type image \
  --workflow /实际执行附件/本任务-工作流.api.json \
  --record-dir /实际执行附件 --task-title '当前对象 · 首次生成' \
  --output-plan /实际执行附件/成果取回映射.json \
  --image-plan /实际执行附件/图片收尾计划.json --prepare-only
```

用户授权后调用相同命令、移除`--prepare-only`即可登记队列。准备报告的复用、开工时文件变化处理和旧报告补项统一按[执行前检查与复用](ComfyUI-服务配置与任务提交规范.md#执行前检查与复用)执行；固定检查、输入映射、上传绑定和防重复提交由该规范的[固定检查与动态条件](ComfyUI-服务配置与任务提交规范.md#固定检查与动态条件)维护，不由Agent重复核验。底层提交错误字段见[submit调用说明](#submit只提交一次)。

准备时的已知RTX输入检查按[RTX节点共用必填输入](../../studio-image-processing/references/ComfyUI-图片超分执行规范.md#rtx节点共用必填输入)；普通准备不查询远端库存，出现真实接口错误时按[远端能力与错误返回](ComfyUI-服务配置与任务提交规范.md#远端能力与错误返回)定点处理。

尚未提交的已登记任务需要修正资料时，先按[重新调度与失败恢复](ComfyUI-服务配置与任务提交规范.md#重新调度与失败恢复)核对可重新准备的范围，再使用同一命令加`--prepare-only`。成功响应包含原`local_task_id`，任务仍保持暂停；之后从网页恢复原任务。普通恢复按钮不会重读修改后的JSON。失败、已有提交证据或远端ID的处理，以及重启、队列变化后的阶段复用，均沿该恢复规则，不改目录绕过原任务。

`执行检查报告.json`保留实际登记输入、准备时的源文件大小／修改时间、API结构、H3各组字符数／标签／容量结论，不保存私有桌面连接信息。它是本次工具技术报告，不能占用提交／下载凭据名称。后台任务详情的记录列表可直接打开该报告。准备中的内容判断及审批依据仍在既有业务文档；报告不替代它们。


### 节点输入上传

有新本地素材时增加 `--uploads '/实际附件目录/本任务-上传映射.json'`。数组每项对应一次文件上传及一个既有节点输入，例如：

```json
[
  {
    "file": "/实际目录/已批准参考图.png",
    "node": "2",
    "input": "image",
    "subfolder": "本任务输入目录",
    "response-name": "本任务-上传响应-001.json"
  }
]
```

节点编号、输入名及上传来源按实际API填写。后台向任务当前归属节点上传后使用真实返回的input_path连接；响应保存在record-dir内，成功响应的url必须与该任务实际节点一致才可复用。节点归属及手动转移读取[服务配置与任务提交规范](ComfyUI-服务配置与任务提交规范.md#本地队列与按钮)。上传状态不明、响应为空或失败时停止并核对，不自动重复上传；原上传证据不覆盖。映射属于生成前准备或技术执行附件，不改变现有生成／审阅记录模板。此映射不是视频模型的Picture／Audio／Video标签表，业务标签仍须按既有规范核对。

标准输出为JSON。退出0且data.dispatch_state为enqueued表示本地入队成功，保存local_task_id；不代表远端已经接受或任务完成。接口或配置错误退出1，先查询后台记录，不自动重试远端POST。

工作流仍按本次声明的任务类型校验；原生H3技术任务核对明确模式、素材/输出映射和运行组计划；短剧任务由其业务适配额外核对阶段与业务输入映射，不读取远端其他任务的工作流判断是否可提交。

后续查询、取回重试及通知确认使用[后台任务查询与结果处理](../../studio-workspace-browser/references/固定脚本接口规范.md#后台任务查询与结果处理)中的对应接口；后台负责原远端地址、提交证据和防重复。

调度回归测试使用模拟响应及临时目录，不连接服务器、不生成媒体：

```sh
python3 -B -m unittest discover -s '/实际技能目录/scripts' -p 'test_comfyui_dispatch.py' -v
```

退出0并报告OK表示通过。Agent入口测试覆盖纯入队、主节点配置、素材绑定、本地ID和不访问远端；后台队列、通知及取回测试在工作区浏览服务/tests维护。真实模型兼容性仍需实际任务验证。

AiMixer 导演台素材藏在timeline_data JSON内时，上传映射可加json-path数组；每个组件为字段名或数组下标，绑定必须已经存在。例如：

```json
[{"file":"素材/参考.png","node":"502","input":"timeline_data",
  "subfolder":"本次任务","response-name":"上传-001.json",
  "json-path":["global","refs",0,"imageFile"]}]
```

后台使用实际返回的input_path替换这一字段，保持原工作流副本和大整数种子。新上传素材的本机来源同时交给资料冻结模块；已有远端素材仍按输入映射uploads核对来源。


## 聚合执行凭据读取与导出

工作区新任务默认将技术凭据保存在原执行目录的`执行档案.json`，`提交尝试.json`继续独占保存。调度与留存职责见[精简留档规则](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md#执行附件精简留档)。旧独立JSON保持可读，`legacy`仅用于存量兼容。

使用Python 3.9+、标准库；从工作区根目录运行。`path`可以是实际档案，或“执行目录/原逻辑凭据名”；相对路径按当前目录解析。read仅返回所选JSON，不写文件、不联网。

```sh
python .agents/skills/studio-comfyui/scripts/execution_records.py read 'projects/项目名/执行附件/任务/结果收尾报告.json'
python .agents/skills/studio-comfyui/scripts/execution_records.py read 'projects/项目名/执行附件/任务/执行档案.json'
```

明确需要给外部程序一份独立JSON时才使用export，输出必须是明确的新位置，不覆盖既有凭据；不把导出副本作为新的技术真源。

```sh
python .agents/skills/studio-comfyui/scripts/execution_records.py export 'projects/项目名/执行附件/任务/结果收尾报告.json' --output '综合资料/本次交接/结果收尾报告.json'
```

格式为`format:1`，`records`按原逻辑文件名保存完整JSON，`versions`按条目更新用于恢复核对。档案不内嵌图片/视频本体；真实媒体仍按输出位置保存。读取或导出失败直接报错，不以空记录代替。准备、生成和重试仍走既有任务接口，不能用写档案代替真实执行。
