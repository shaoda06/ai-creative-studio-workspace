# ComfyUI-服务配置与任务提交规范

版本：v1.42；更新日期：2026-10-27。

本规范维护工作区ComfyUI配置、准备与提交分工、选端、提交接续、任务地址绑定及固定通信要求；具体工作流、模型参数、审批与监控策略仍由对应专项规范维护。按当前任务读取：

- 初始化项目或调整服务地址：读取[工作区配置](#工作区-comfyui-配置)。
- 准备或提交新任务：读取[执行前检查](#执行前检查与复用)、[选端与提交](#新任务的选端与提交)、[任务显示标题](#任务显示标题)及[固定工具](#固定通信工具与证据)，再按实际媒体类型进入执行规范。
- 推进已授权待提交任务：读取[待提交推进](#已授权待提交任务的推进)及其链接的监控方式。
- 查询、取回或恢复已提交任务：读取[地址与恢复](#已提交任务的地址与恢复)，按[查询与结果处理入口](../../studio-workspace-browser/references/进度查询与结果处理规范.md#进度查询与结果处理)选择具体后台工具及监控规则，不重新选端或提交。


## 工作区 ComfyUI 配置

本节是服务配置、主节点提交和任务地址绑定的唯一规则入口。整个工作区共用根目录 `comfyui-config.json`；Agent与浏览后台复用同一[配置读取工具](../scripts/comfyui_config.py)。后台按实际资料工作区定位配置，不按代码目录或启动目录定位。项目内不另建配置，不读取项目覆盖或回退配置。

```json
{
  "remote-nodes": [
    {
      "url": "https://comfy.example.com",
      "auth": {"type": "basic", "username": "", "password": ""}
    },
    {"url": "http://127.0.0.1:8188"}
  ]
}
```

`remote-nodes` 为非空有序节点数组，第一项为主节点，其余为备用节点。节点包含 `url` 及可选 `auth`，地址支持IP或域名及HTTP／HTTPS，不重复、不含URL凭据、查询参数或片段。无需认证时省略 `auth`；需要HTTP Basic认证时填写上述类型及该节点自己的账号密码，用户名不得含冒号，凭据不得含控制字符。空凭据表示等待本机配置，工具不登录或提交；不支持用此设置替代网页表单登录或交互式登录。HTTP上传、提交、查询、下载及WebSocket使用同一节点凭据；HTTPS对应WSS，校验证书，不跳过TLS验证。账号密码保存在本机配置，不写入Git、任务参数、执行证据或日志；仅节点编辑页经工作台管理范围与同源检查后读取账号密码，普通节点、队列及任务响应不返回凭据；URL及任务地址记录不包含账号密码。修改凭据后，节点监听自动重新连接。

Agent登记的新任务默认进入主节点本地队列；各节点有独立本地队列，网页顶部只显示当前配置节点，切换时同步切换远端及本地排队／暂停列表，本地历史统一查询全部节点。备用节点只接收用户从网页手动转移的任务，不自动分流或故障改投。主节点不可用时，其本地任务等待恢复。

工作区首次配置时检查该文件，合法则复用，不擅自覆盖。完整工作区已运行浏览服务时，项目初始化即可从“任务进度→编辑”添加、修改或排序节点，用户点击保存后写入同一份工作区配置；没有配置时编辑页提供添加入口，不自动创建默认节点。用户也可提供实际服务地址或有序节点列表，由Agent按确认内容维护；缺少配置且用户尚未选择网页填写时，询问实际地址，并告知默认地址 `http://127.0.0.1:8188`，确认后才创建，未回答不视为同意。独立技能或浏览服务不可用时继续使用Agent配置方式，不以网页作为文本创作或客户端使用的前提。新项目复用工作区配置，缺少不阻塞纯文本创作或浏览，但生成任务须先完成配置。`127.0.0.1` 指执行脚本的机器。配置不保存时区、模型、库存、项目状态或运行状态。

网页节点列表第一项为默认节点，其余按顺序为备用节点，通过上移／下移排序，增删和编辑仅在保存后生效。保存复用现有格式及地址／认证检查，至少保留一个节点，不把连通性或模型库存查询作为保存条件。编辑页预填现有账号密码，可直接修改；密码默认遮挡，可切换显示／隐藏。勾选“无需认证”时禁用账号和密码框，尚未保存时保留框内草稿，取消勾选可继续编辑；保存无认证配置时省略认证字段。“还原”仅撤销未保存修改，恢复最近一次读取或保存成功的表单，不写配置文件。改变已认证节点地址时清空原凭据，须重新填写认证或明确选择无需认证，不把原凭据带到另一个地址。配置在编辑期间被其他页面或Agent改动时，停止保存并提示重新载入；写入失败保留原文件。未保存离开时提示处理修改。网页保存采用工作台管理范围与同源写入检查，普通查看不传递凭据。

排序只改变后续新登记任务的默认目标，不移动已入队或已提交任务，不改写原地址、最初入队地址和历史记录。网页禁止删除或替换仍有本地排队、暂停、准备、提交、远端排队／运行、取回中、取回失败待处理、提交结果待核对或状态待核对任务的地址；远端观察到的排队／运行任务同样保护该地址。调整排序仍可执行。保存后后台更新节点监听和网页状态，无需为普通配置编辑重启服务。

工作区文件兼容仅含 `remote-urls` 地址数组或 `remote-url` 单地址的无认证格式；普通读取不自动改写，用户从网页保存时统一写入`remote-nodes`格式。获授权迁移时先核对旧项目实际地址及排序，建立工作区配置，再将旧配置完整留档退出项目根目录。旧项目文件不构成运行入口；不同项目的冲突配置不得静默合并。真实工作区配置不随技能或仓库分发，迁移本机工作区时须单独保存。


## 新任务的选端与提交

所有会话的新任务使用[统一分配与提交入口](固定脚本接口规范.md#nora统一分配与提交)，所有类型均提交到工作区主节点。准备阶段完成内容核对，获得当前执行授权后使用同一份任务清单一次调用；同批任务先全部通过工具准备检查，再逐项登记本地队列。不直接绕过入口向远端批量提交。

完整工作区中，默认使用统一入口的`--plan`。Agent确定本次内容、实际素材与用途、执行授权和必要业务字段；模型工具按明确模式装配API、上传与成果映射，后台执行共用准备检查及登记。共用清单和technical字段见[统一分配接口](固定脚本接口规范.md#nora统一分配与提交)；Nora短剧的种子登记、工作稿及模板记录由[业务装配](../../nora-serial-drama/references/固定脚本接口规范.md#一次装配与批量入队)负责，其他业务不因此初始化短剧。生图原画布只在工具workflow目录原样保存，不生成任务画布。工具不替代内容核对、素材批准、二采批准或下一阶段授权。

**本轮结束条件**：返回`status=enqueued`、真实`group_id`及成员任务ID后，Agent简要汇报已入队的组和任务数量并结束本轮；不再补抄ID、刷新网页或等待远端提交。新后台清单先检查全部成员，再原子登记一组；登记失败不留下半组，回执丢失沿原清单恢复，不整组重提。历史`partial`记录仍按原已接受ID接续，不能改作新组覆盖。正常完成由后台按[任务组通知](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md#3-跟进与通知)等齐汇报，异常提前报告问题成员；技术字段及动态状态由后台维护。

旧式逐项参数入口只用于原任务接续或本次明确独立的单项提交；已有完整技术资料不构成拆开同组任务的理由，范围仍按[任务组提交范围](#任务组提交范围)确定；只做内容／技术准备而未授权生成时加`--prepare-only`，不入队、不上传、不生成。新入口在同一次工具调用中先装配并完成准备、再调用既有入队；入队及实际开工不因此重跑固定检查。

### 本地队列与按钮

队列归属、顺序和分类保存到后台SQLite，网页关闭不影响调度。每个节点独立调度，仅在该节点连接正常、已读取实时队列且进行中和队列中均为0时，自动取出该节点本地第一项。WS队列事件触发检查，另每30秒补查；上传准备结束、POST之前再次读取队列。若检查后其他来源抢先提交，本任务正常进入远端队列，不撤回或重复提交。同一节点串行提交，不同节点的上传、排序和调度互不阻塞。

- 排队中：立即提交、插队、暂停、取消。
- 暂停中：立即提交、插队、恢复、取消。
- 立即提交解除暂停，忽略远端任务数量，仍检查连接、资料和防重复证据；不打断远端任务，也不保证远端第一位。
- 插队解除暂停，移到本地第一位等待自动提交；恢复移到本地末尾。取消只作用于尚未提交的任务，保留记录并进入历史。
- 转移到：只能选择工作区配置的其他节点，只移动任务，不创建副本。排队任务移到目标节点队尾；暂停任务仍暂停，恢复后进入目标队尾。保留本地ID、来源会话、工作流、本机保存路径及记录，取消原立即提交标志。开始准备、上传或提交后禁止转移，已结束或结果待核对的任务也不能转移。
- 卡片除按钮和选择框外可抓取排序。抓取前取得该节点的后台排序租约，只暂缓该节点取出下一项；保存该节点完整顺序后释放。网页每5秒续租，关闭或失联15秒后租约失效。已开始准备或提交的任务不能再排序、暂停或取消。源节点或目标节点正在排序时不能转移。
- 历史包括取回中、已完成、生成失败、取回失败、提交被拒绝、提交结果待核对、状态待核对及已取消。历史不显示本地操作按钮；Agent可请求只重试取回。

一采、返修及二采须满足执行地址、缓存名与导演台节点ID的缓存接续要求。旧一采在备用端执行时，新增返修或二采仍须核对主节点的来源缓存及输入是否具备；未具备时停止，不照搬其他节点的路径，不把MP4当作潜变量缓存。技术缓存条件执行[导演台缓存规范](../../studio-h3/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#75-缓存检查与清理接口)；Nora的阶段批准与来源资格另由[短剧制作](../../nora-drama-production/references/ComfyUI-H3视频执行规范.md#5-人工审核与轻量记录)维护，不作为其他业务的默认阶段。同一地址不证明缓存名、节点ID、具体版本和生成输入匹配；新场次任务的缓存名能力与填写要求读取上述导演台缓存规范，目标端不支持时停止，不退回共用缓存。

后台复用本地准备报告，不预查目标端节点或模型能力。导演台任务向实际执行端查询当前工作流对应的缓存：二采必须能确认一采，局部执行所依赖的前段缓存必须匹配；一采工作流若会因目标已有缓存进入二采也暂停。接口不可用或条件不满足时暂停，不自动迁移、清理缓存或改为重做一采。原始入队地址保留作重复登记核对，技术通信和成果取回绑定转移后的实际节点。

后台调用固定客户端上传并按实际返回路径替换声明的素材绑定，随后只发送一次生成POST。已有上传凭据核对后复用；原请求、上传响应、提交尝试及响应由后台写入现有执行附件。防重复、异常处理及重启接续统一按[监控规范](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md)执行；Agent不再维护另一套文件锁、定时提交或自动重发规则。


### 任务显示标题

Agent提供能辨认本次动作的明确标题，并显式传入`--task-title`；技术工具不规定业务编号或命名公式。调用业务已有标题格式时由其适配提供。

标题不重复卡片顶部的项目名及图片生成、图片超分、视频一采、视频二采、视频后处理类型，不把排队、执行或下载状态写进标题。Agent遵守上段标题格式；后台只要求标题为非空文字，原样保存，不用目录名补标题。显示标题不改变记录、文件名称或生成序号。


## 已授权待提交任务的推进

授权和资料准备完成后即登记后台本地队列，保存本地任务ID与记录入口；远端ID在实际提交成功后由后台补充。尚未授权或资料未准备完的事项仍留原会话，不登记成可执行任务。

入队后所归属节点不可达时留在该队列等待后台重连，不自动改投其他节点；轮到任务才发现素材、资料或缓存问题时暂停并记录原因。Agent收到问题通知后从记录复查，修正资料后恢复或按实际问题安排新的获授权任务；不另开heartbeat查空位或重复提交。


## 已提交任务的地址与恢复

任务在现有执行记录中绑定实际服务地址、任务ID及对应提交证据；实际地址及远端执行结果注明于既有生成／执行记录，不另维护一份调度状态库。后台任务的查询、通知确认与取回重试使用[专用工具](../../studio-workspace-browser/references/固定脚本接口规范.md#后台任务查询与结果处理)的本地任务ID或通知批次ID，后台沿用该任务提交尝试中的真实地址，Agent不传 `--url`。获授权直接使用 `comfyui_client.py` 查询或取回时，使用[带工作区认证的通信入口](固定脚本接口规范.md#nora-工作区配置与分享边界)，把记录中的真实地址显式传给其 `--url`；两种方式都不从当前地址列表第一项覆盖旧任务地址。旧记录缺少地址时核对当时请求、上传或响应依据，无法确定先沟通，不猜测。

调整地址顺序或备用列表只影响新任务，不取消、移动或重提旧任务；原备用端任务继续按提交时的实际地址跟踪。停止监控不等于取消生成。对已提交任务服务不可达、提交状态不明或失败的处理执行[监控与异常规则](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md)，不自动更换执行地址。


## 执行前检查与复用


### 任务组提交范围

同一次授权、同一项目及来源会话中可同时提交的任务，默认统一写入一份`--plan`清单，不需用户另行要求或确认分组。支持跨场、跨P及不同执行阶段，允许单任务组；可选`group_title`作为组名，不填写时使用清单文件名。导演台组、来源批次与后台任务组不是同一概念：素材容量、不同来源缓存或工作流限制需要拆成多个独立远端任务时，仍作为同一清单的多个成员，不拆成多份清单逐项调用；逐段准备、不同场次或提示词分别保存也不是拆组理由。用户明确分组、项目／来源会话不同，或后续阶段须等待前置结果时分别成组，不提前提交依赖未满足项。已登记的多组不追溯合并，按原ID接续。清单内的任务仍独立进入远端队列；组只管理固定成员、进度和通知，不改变工作流、素材、seed或执行顺序策略。旧式单任务入口新登记时自动建立单成员组，已登记任务保留原组；同步本地规格处理与后台清单分开。具体调用见[共用清单入口](固定脚本接口规范.md#nora统一分配与提交)；短剧业务字段另读[业务装配](../../nora-serial-drama/references/固定脚本接口规范.md#一次装配与批量入队)。


## Agent与工具的职责

Agent负责内容准备、内容合理性判断、工具调用和读取报告／结果；工具负责实际上传、提交、技术核验、状态维护及执行报告。技术检查不转交Agent逐项人工重复，工具报告不再由Agent抄写成另一份报告。

调用方先完成本次实际内容、输入和授权。工具按明确模式装配技术副本、上传绑定和成果目标；默认`--plan`在入队前检查，单独准备使用`--prepare-only`。报告保存为`执行检查报告.json`，只准备不上传、不入队、不生成。技术检查不代替Agent的语义判断或用户授权；业务检查由已登记适配执行。

提交阶段仅使用准备好的资料和当前明确授权调用同一入口，不重新编写或审查业务内容，不重跑已通过且输入未变的配置检查。入队只确认本次调用身份、项目／路径范围、后台登记记录占用及重复登记，不解析工作流或重查固定节点／素材绑定、分段与输出身份关系，也不读取或比较准备报告；轮到实际执行时，工具统一比较一次登记输入与准备依据、相关文件的存在性／大小／修改时间，未变则复用准备结论。变化时停止并指明需返回准备阶段，不上传、不提交、不边执行边修稿。显式再次调用准备检查才更新准备结论。新登记任务保存必须先准备的标记，入队仍不读取准备报告；开工时在同一次报告比对中要求报告已通过、覆盖当前准备要求并与输入和文件状态一致，缺失、失败或缺项即暂停并指明使用`--prepare-only`完成准备，不在上传或发送阶段补跑固定检查。报告的`new_task_ready`只表示新登记准备要求已覆盖，不代表内容批准或生成授权。旧任务仅指启用此要求之前已登记、原持久化状态未记录必须先准备标记的任务；不根据报告缺失、旧报告版本、重启、恢复或请求参数把新任务转为旧任务。旧任务没有工具准备报告时，才允许后台在实际开工时调用同一套固定技术检查并标明`checked_during=execution`；历史缺少显式分段目标时继续按原映射取回，不借兼容为新任务省略目标。失败即停止上传／提交，后续未变复用，不补造历史准备事实或要求Agent人工补查。旧报告未覆盖资料关联固定检查时，先确认报告通过、登记输入一致且原记录文件状态未变，再复用已覆盖项目，只补未覆盖项并在同一报告标明实际检查时点。开工补检只适用于上述旧登记任务；新任务须在准备阶段补齐，旧报告也只有在准备阶段补齐新任务要求后才可标明`new_task_ready`。已有分段计划的旧报告，其导演台数量、组序、分段数量、执行身份及目录归属结论直接复用，不为补资料关联重新调用整套分段检查；分镜版本、正文对应、生成模式、来源及素材关联等缺项继续检查，旧分段检查未覆盖的场次格式和执行子目录名称要求也只在补检时完成。没有分段计划检查依据的任务仍检查该缺项，不把旧报告通过当作全部项目都已覆盖。准备入口和开工补检遵循同一范围，保留已有配对等结论；补查失败暂停，不重跑整套固定检查。准备入口补齐旧报告、旧任务开工补项时，原来源核对与新增资料关联共用本次实际读取的文件状态；重合文件直接复用，仅读取新增文件，不以旧报告中留存的状态代替本次读取。复用只在同一次补项调用内有效；后续调用重新核对，上传期间及结束后的变化检查保留。资料变化后显式进行完整准备时，检查结束重新取得文件状态，不沿用此前比较旧报告时的读取。新增文件缺失或补项失败时记录失败，不写成通过。


### 远端能力与错误返回

正常准备与提交默认目标ComfyUI可以执行所提供的工作流。本地工具不查询节点库、模型清单或参数注册表，不刷新能力库存，也不把远端能力核验作为入队条件；Agent不人工比较远端能力。转移到工作区其他已配置服务也遵守此边界。

节点缺失、模型不可用、参数不支持等由远端实际接收／执行时判断。工具保存真实请求、远端响应、原始错误详情和失败阶段，并将报告返回Agent；Agent读取后说明具体问题。远端拒绝与结果未知分别记录，不自动改配置、换服务、重发生成或安装依赖。用户明确要求盘点远端能力或诊断依赖时，才独立调用[库存工具](../dependencies/comfyui-inventory/SKILL.md)，该操作不是正常提交的固定步骤。

已出现必填字段缺失、枚举不支持等接口差异时，可针对报错节点定点读取 `/object_info/{类名}`，核对必填项、取值和默认值；不因此查询整份节点库。接口差异不等于已证明远端升级，没有版本或变更记录时不推断新增时间。相同配置影响同批其他待提交任务时，先暂停这些任务，避免继续提交已知不兼容的副本。

获准修复共用基准时，更新受影响的执行API、参数规则和引用、固定准备检查及回归测试；原始文生图和图生图画布不修改，不能只补单个项目副本。已知接口要求由本地准备工具检查，普通入队继续复用通过的报告，不增加逐任务远端能力盘点。RTX超分共用输入由[RTX节点共用必填输入](../../studio-image-processing/references/ComfyUI-图片超分执行规范.md#rtx节点共用必填输入)维护。历史请求、错误及批准记录保留；已入队或已提交任务继续按[重新调度与失败恢复](#重新调度与失败恢复)处理，不因更新基准而改写。


### 固定检查与动态条件

工具检查本地API结构、素材路径与绑定、输入标签、数量／时长／字符数、分段与输出身份等可程序判断的准备事项；节点／模型是否存在、远端参数及连接类型是否支持由远端执行时判断，复用同一执行副本的结果。内容是否符合剧情、动作和表达要求由Agent在准备阶段判断；两者不能互相代替，未覆盖的分支如实说明。

固定技术检查各设一个执行位置，统一在准备阶段由同一工具执行：标题等固定登记字段、明确模型模式与输出目标，业务依据与内容关联由登记适配检查；通用工具检查上传映射的必填字段／类型／json-path格式、上传目录及源文件名合法性、各类证据名称合法性／重名／保留名称冲突，以及基础JSON结构、节点与素材绑定、标签／数量／时长／字符数、分段对应与输出身份关系，以及新分段任务逐段显式提供成果目标的要求，并写入既有准备报告；入队和发送阶段不再调用这套固定检查。开工时只比较准备依据与文件状态，未变直接复用，变化返回准备阶段。后台每次接收输入统一解析一次实际路径并检查项目范围；调用端只传递资料，准备、上传及内部格式转换直接使用解析结果，不重新解析或判断同一路径是否绝对。通用检查负责文件名。H3阶段合法性由同一函数维护：有分段计划时由分段检查调用，无分段计划时由通用准备检查调用，同一次准备只执行一次并保留明确的阶段错误。逐段成果目标是否提供在准备时检查，登记和开工不重查；旧报告没有覆盖该项时，显式准备只补该项并记录完成状态，已有结论不重跑。导演台数量、选中组序、分段数量、执行身份及目录对应关系由共用分段检查一次完成，取回计划与生成资料检查共用其结果，不分别再查；独立生成资料调用也使用同一检查实现。同一轮共用已解析的时间线、映射和唯一文件状态。独立调用通信工具、从文件读取工作流时，由该入口检查一次基础结构。入队和后台通信不再重复这些格式或名称检查；通信使用准备后对象和源路径，不新增外部跳过检查开关。真实上传响应的filename／subfolder／type仍按新返回内容核对。登记仅保留调用身份和实际路径范围的安全边界，以及后台登记记录的占用；不在上层扫描提交尝试、请求和响应三份提交证据。相同任务的本地ID复用和已有远端ID的状态路由继续由后台负责。

目录占用按实际职责处理：入队按SQLite中的执行目录身份复用同任务ID，不同任务不得共用；没有匹配任务时，已有固定的后台任务状态／过程记录则阻止覆盖。准备用的API、画布、输入映射和自定义执行凭据不作为入队目录占用依据。准备报告匹配之后，上传环节按真实端点和文件指纹恢复已有上传凭据；提交环节发现已有终态记录或下载凭据则停止并要求核对原执行，不覆盖、不发送新生成。实际取回继续保护已有成果。执行检查报告位置已有非报告资料时停止，不覆盖该资料。

实际发送的防重复保护统一由底层通信工具执行：提交尝试、请求或响应任一已存在则停止；独占创建提交标记和请求文件，只有取得独占权的调用才能发送POST。已有证据或独占冲突统一返回`submission_guard`和`submission_state=not_sent`。后台记录“已拦截、未发送”；待执行任务暂停，已有拒绝／未知等结果和原始错误保持，不误记为本次提交结果未知，不覆盖旧证据或自动重发。

临执行仍由工具核对真实端点和当前队列；上传期间队列可能变化，最终POST前再次检查队列。H3一采／二采均在实际上传绑定后由工具查询阶段缓存和所依赖的前段缓存，同端任务也不省略。保留用户明确授权的一采／二采范围、未知提交不重发、已有输出不覆盖等边界。瞬时队列、缓存、进展和显存不由静态能力清单证明。

同一任务按唯一文件复用读取结果。新上传在读取传输字节时计算文件指纹，不为重复槽位重新读取；同一服务进程内，端点、目标目录和源文件状态未变时复用已核验的上传结果；重启后首次恢复已有上传凭据时，每个唯一文件核验一次。每份凭据在该恢复过程只核验一次；源文件按必要时间点统一读取大小和修改时间，不按槽位重复读取。任一凭据指纹不符或文件在过程中变化则停止。开工报告比对实际读取的唯一文件大小与修改时间，在本次调用内直接传给上传环节作为比较基准，不再次读取同一基准；旧任务首次补检实际取得的文件状态同样复用。报告比对未读取的素材才在上传环节读取一次，不把报告中的历史状态或其他次调用的状态冒充本次读取结果。每个实际上传完成后的变化核对、全部上传及资料保存结束后的变化核对均保留，发现变化即停止。复用范围限本任务及实际端点／目标目录，不引入跨任务上传缓存。素材JSON字段路径及末级字段存在性在准备时检查一次；实际上传绑定直接向已确认的字段写入返回路径，不再次读取末级字段确认存在。上传后只核对本次素材绑定与真实上传响应的对应，包括正确分组／槽位、实际路径、filename／subfolder／type，以及导演台根时间线与公共／分组编辑区的对应字段。未变化的API检查结论复用准备报告，不比较画布与API，不重建整张工作流、不重查未改的节点、模型和固定参数。工具只同步受影响的API输入；视频、超分及历史任务存在任务画布时，同步其受影响的控件。文生图和图生图不创建任务画布，也不回写原画布；绑定未变时不读取或改写API／画布副本。输入映射的实际素材关联与当次生成资料仍由工具保存，不能用上传前计划替代。

执行记录的路径转换复用同一任务已解析并核验范围的项目根目录、输入及成果路径；事件、数据库状态和状态文件共用转换结果，不重复解析同一路径。首次出现的记录路径仍解析实际目标并核对项目范围，不能只凭字符串前缀放行。复用仅用于记录中的绝对／相对路径转换，不作为文件访问授权，不替代新请求、文件读写入口及必要的范围检查；明确重新准备后按新输入重建，服务重启时先重新核验载入资料，再建立任务内复用。各项目和任务不共用转换缓存，远端路径、原始错误与历史证据的含义保持。共同任务的技术状态和执行报告由后台在既有共同执行附件维护，Agent只读取并说明完成数量、问题与审核入口。业务工作稿引用共同技术证据，不抄写整批动态状态；Nora的P段具体关联另按[短剧共同证据归属](../../nora-drama-production/references/逐集目录与资产管理规范.md#多组任务的共同证据与状态)执行。

提交前资料处理在同一轮内复用中间结果。准备阶段首次验证上传JSON字段路径时同时取得末级值，资料关联直接使用该值；独立资料关联检查或旧报告补项只解析尚未取得的绑定，不重复遍历已验证路径。

同一准备或资料保存阶段共用已解析且核验范围的项目根、执行目录和文件地址，素材映射整理及路径格式转换使用同一份结果；不在各辅助函数内重复解析相同地址。地址复用仅用于计算及格式转换，实际读写前仍核验当前真实目标和项目范围；路径转向、目录联接或符号链接变化导致目标不符时停止，不凭缓存放行。范围不跨任务或阶段，不替代后续调用的动态核验；独立工具入口仍自行建立核验范围。

保存上传映射时保留首次读取的原文和解析对象，用该原文判断新内容是否需要写入，不为同一次比较再次读取文件。后续阶段需处理已经保存的新资料时仍按实际文件读取，不将旧对象当作后续文件状态。

冻结快照按唯一路径复用同轮存在性结果和内容，多个分段引用同一目标不逐段重查；不同来源拟写同一目标且内容不同仍拒绝。保存前重新检查每个唯一目标的状态，发现新增、删除、替换或内容状态变化即停止；新文件仍独占创建，已有冻结内容不得覆盖。复用不取消实际读写入口的路径范围核验、保存前的变化检查或防覆盖保护。


### 重新调度与失败恢复

上传及执行资料保存完成后，工具保留该阶段结果。因队列变化回到排队，或在同一进程恢复尚未提交的任务时，资料未变则复用实际工作流、上传核验、绑定结果和冻结资料，不重新上传、全文件计算指纹或写入相同副本。瞬时队列及H3阶段／接续缓存仍按本次实际执行时点核对。既有任务状态保存已完成阶段的文件状态，重启时核对恢复所需证据。恢复时，准备报告与已完成阶段的文件状态比对共用本次开工实际读取的结果，API、画布及其他重合文件不重复读取；同一实际状态仍须分别与准备报告和阶段记录的对应依据比较，任一不符即停止。报告比对未读取或仅阶段记录涉及的文件，按需读取一次；该结果也供本次上传恢复作为基准复用。复用仅限同一次开工，不跨重新调度或恢复调用；上传期间、每次实际上传后及整轮准备结束的必要变化检查仍在各自时点重新读取，不借阶段复用绕过变化检查。不引入跨任务、跨端点的上传缓存。

暂停任务的“恢复／插队／立即提交”只恢复调度，不重读被修改的工作流。尚未提交且没有提交、终态或取回证据的同一来源任务，可显式使用同一准备入口重新准备：阶段、端点和成果范围保持，检查前暂停原任务，成功后更新原任务输入和准备报告、清除受影响的阶段复用结果，仍保持暂停；失败保留原输入和具体报告。然后显式恢复原任务ID。已有远端ID、提交证据、拒绝或未知结果不得借重新准备清除证据或重发；范围变化另按授权登记任务。

节点队列只保留一个常规定时刷新来源，同节点同时发生的刷新共用一次请求；最终发送前仍须取得本次实际执行时点的队列结果。原任务的并发状态核对共用正在进行的查询；调度确认旧任务终态后，将取回交给后台，不等待下载及下载重试完成才安排下一项。

取回重试只重新下载失败成果。同一进程复用已核验且文件／凭据状态未变的成功项；重启恢复或文件状态变化时重新核对，不能继承不匹配的下载凭据。取回、监听及重连均不回到生成提交。

本地证据写入失败且尚未发送POST时，报告“未发送”；已发送而响应无法确认时，报告“结果未知”。底层保存原始错误，上层补充阶段及状态，同一次失败不重复生成多份同义报告；同一次状态转换集中持久化状态和事件。必要的独占创建、原始请求／响应及失败证据保持，不为了减少写入而延迟提交证据。


## 固定通信工具与证据

准备新任务或获授权直接调用远端接口时，读取 `comfyui-api` 及[固定工具说明](固定脚本接口规范.md)的对应章节；操作后台已有任务直接按[进度查询与结果处理](../../studio-workspace-browser/references/进度查询与结果处理规范.md#进度查询与结果处理)进入专用工具，不加载完整通信和提交说明。

新生成任务及其普通输入素材上传统一经 `scripts/comfyui_dispatch.py` 登记，由后台调用通信模块执行。明确获授权的直接查询、下载、导演包导出或库存诊断，经[工作区认证适配入口](固定脚本接口规范.md#nora-工作区配置与分享边界)执行；显式提供工作区及本次实际服务地址，认证仅从工作区共用配置加载，不用环境变量或localhost替代实际地址。适配入口不提供upload／submit命令，不能用诊断入口提交生成任务。底层客户端和依赖技能的curl／原生CLI示例用于独立通信及协议说明，不是Nora项目绕过队列或工作区配置的另一条路径。

通信复用本工具 `scripts/comfyui_client.py`（旧references/comfyui-scripts路径仅兼容转调），不逐任务重写通信代码，不使用会重写审批状态的旧执行器，也不在单次制作中修改comfyui-api技能本身。工具故障或缺口先报告并集中修复；额外只读核对按相关技能处理，不静默另写临时替代工具。

Agent准备内容、素材顺序与用途、必要业务参数、标题和授权依据；工具装配API／画布、技术映射与模板记录，后台负责通信、调度及技术证据，不决定审核、候选采用或下一阶段。SQLite是后台队列状态真源，项目附件保存可复查的阶段记录和原始响应；不另建Agent调度台账。

技术证据的保存与复用统一按[执行附件精简留档](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md#执行附件精简留档)，业务阶段引用共同技术证据；Nora的多P关系按[短剧共同证据与状态](../../nora-drama-production/references/逐集目录与资产管理规范.md#多组任务的共同证据与状态)维护；不在准备阶段另造后台证据副本。实际必需的模型正文、任务映射及冻结文件仍按各自格式完整保存。

## 远端输出目录与命名

调用方提供本次实际输出前缀，或由已登记的业务适配按其目录与编号规则装配；公共工具不从业务示例补造CH、SC、EP、C等身份。技术任务使用已明确的输出目标。

前缀相对执行端ComfyUI的`output/`，不再加`output/`，不带扩展名。目录各段不得含分隔符、`..`、控制字符或Windows禁用字符；存在不合法名称时先明确合规名称，不随机替换业务身份。可配置输出与节点固定的缓存／逐组保存目录分别处理。

取回只使用真实响应的filename、subfolder、type；保持远端产物与本地资源版本的对应。远端文件存在或前缀文字不构成批准或采用。远端前缀、本地证据文件名、素材上传路径分别按各自接口使用，不互相替代。
