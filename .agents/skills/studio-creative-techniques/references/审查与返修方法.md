# 审查与返修方法

按当前范围读取目标版本、相关上游依据、已确认要求和允许保留或改动的内容。结构问题用现有校验或可复核事实检查。判断创作问题时引用当前原文、画面区间、文件或工具证据，并说明已观察的范围。仅有审阅意见时引用该意见，未查看的效果按未知处理。制作限制、事实冲突和风格偏好分别表达。

## 说明一个问题

写明所在文件和版本、章节或镜头／时段、实际证据、对观看或后续制作的影响、期望结果及保留项。涉及事实冲突时同时指向上游依据和冲突位置。相同原因可归为一项，相关位置分别列出。只需提供审查时把问题交给负责该内容的阶段，沿现有审阅或制作记录处理。

## 选择修订与复核

先找实际出错的层，例如脚本事实、分镜起点、参考绑定、执行配置或后期处理。先修实际来源，再同步受影响的下游。已采用内容按原业务规则处理。局部调整可以保住所需内容且能检查接缝时优先考虑局部处理。问题影响多个接点、身份或动作逻辑时评估重做有关段落；符合已确认要求的版本也可以保留。

修后按相同证据和已确认要求复核，连看受影响的前后接点、时码、视听连续性及保留项。记录问题是否解决、是否出现副作用及仍缺什么依据。实际修改、重做、媒体查看和采用由调用业务按授权决定；复核结论写回现有记录。

## 视频候选的返修接续

业务收到审阅意见后，先对照候选与当次实际请求，确定问题来源及需修改的范围。涉及剧情、台词、客户要求、商品事实或资产设计时，回业务准备的对应阶段修订，再将有效版本交[共用视频制作入口](../../studio-video-production/SKILL.md#制作入口)接续。涉及镜头、分段、实际参考、提示词或请求参数时，回[共用视频制作流程](../../studio-video-production/SKILL.md)的对应环节处理。原任务异常走该流程的结果恢复入口。

同步受影响的下游，沿用仍然有效的结果。按已有授权完成修订后的执行或局部处理，将新候选与原意见关联，交回同一业务审阅。业务按实际决定继续返修、接续执行或登记采用并交付。
