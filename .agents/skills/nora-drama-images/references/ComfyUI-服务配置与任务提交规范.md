# ComfyUI-服务配置与任务提交规范

### 图片执行分工

适用于内容已经备好的ComfyUI图片及超分提交、正常结果接收。Imagegen原生任务使用[子代理与固定收尾分支](内置图片制作接续规范.md#子代理执行与父代理交付)，不适用下表的入队、远端取回和通知步骤。执行环节Agent只提交任务清单、读取提交结果及最终报告并向用户展示；脚本拥有固定技术检查和写入责任。提示词创作、设计取舍及用户新给出的审批决定是内容输入，不由技术检查推断；正常结果通知不附带一次新的创作或审批整理任务。

| 环节 | 脚本负责 | Agent负责 |
| --- | --- | --- |
| 提交前 | 读取类型规格与类别种子表；核对输入文件、批准关联及原始种子；同批同一输入只解码一次；文生图／图生图只组装执行API，超分按其入口保留适用的任务画布；装配素材绑定、目标和证据命名；从实际API填写模型、采样、缓存、预处理等技术记录；共用准备入口一次执行格式、任务参数和固定节点检查 | 将已备提示词、对象／状态、素材用途及授权作为本次输入调用统一入口；不再人工读取种子表、量尺寸、对节点或整理技术附件 |
| 入队成功 | 保存本地ID、调度、真实上传路径、实际请求／响应及状态；上传后同步受影响的技术副本 | 读取成功结果，汇报已入队数量并结束本轮 |
| 生成后、通知前 | 核对实际输出、尺寸／数量／可解码性、下载凭据及来源；写生成／审阅和实际上传绑定；获批超分按计划正式保存；合并核验网页并持久保存可直接展示的报告 | 无常规工作，不等图、不轮询、不补记录 |
| 收到通知 | 一次report读取并确认收到，直接返回成果绝对路径、真实规格、数量及审核入口；完整证据保存在原附件 | 普通图片读取报告并展示；超分复用技术核验，按原批准补齐未完成的正式登记和同步后汇报，不再次请求批准 |

技术检查各有一个执行位置；准备通过且输入未变时复用既有结论，正常通知不重跑。上传后核对真实返回值、文件变化检查、下载后解码／凭据核对和正式替换的批准／历史保留分别保护不同阶段，保留由后台执行；不把必要检查再转给Agent。结果异常时由报告指出失败阶段及具体缺项，按异常分支处理，不先要求Agent通读整套记录。纯提交不加载提示词创作技能、完整工作流映射或无变化的素材资料；需要改内容时再进入对应创作分支。
