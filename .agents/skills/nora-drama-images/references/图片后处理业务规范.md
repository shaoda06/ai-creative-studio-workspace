# 图片后处理业务规范

版本：v1.35；更新日期：2026-10-24。

适用于生产图片获批后的像素处理与正式保存。Qwen分支中需超分的类型包括人物正面半身图、服装正背面图、道具三视图、资产状态参考图（服装／场景／道具）、虚拟道具基础界面、场景参考图、首帧参考图及新生成的剧集专用参考图：按对应送审尺寸生成、用户批准后，以原图执行一次2倍超分，核对正式尺寸后保存，不裁切、拉伸或换图。Imagegen原图单独执行下方[指定尺寸处理](#imagegen原图的指定尺寸处理)。两种分支均不重新生成提示词或调用生成模型重画内容；修改后的新候选须重新审批。

| 图片类型 | 送审／正式尺寸及比例的规则入口 |
| --- | --- |
| 人物半身、人物六视图、服装正背面、角色六视图 | [人物专项规则](人物参考图制作与记录规范.md#2-规格背景与布局) |
| 道具三视图、道具状态参考图、虚拟道具基础界面 | [道具规范第3节](道具图片制作规范.md#3-三视图与状态规则) |
| 场景参考图 | [场景规范第4节](场景图片制作规范.md#41-画面要求) |
| 资产状态参考图 | [统一资产状态规则的对应规格入口](Qwen-Image-2.1-提示词规范.md#27-资产状态参考图统一规则) |
| 新生成的剧集专用参考图 | [集内素材规则](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#21-剧集专用参考图) |
| 首帧参考图 | [首帧规范第1节](../../short-drama-storyboard/references/首帧参考图规范.md#1-制作复用与画面要求)，区分新生成与已有图／视频取帧来源；仅对该入口要求超分的图执行本规范 |

2倍指宽、高各为输入的2倍，总像素为4倍，画幅比例保持不变。新任务先核对本类型送审尺寸和节点约束，取回后核对真实输出；不将节点可填写的尺寸视为已经实测成功。不将高分辨率旧图缩小再放大冒充低分辨率原生生成。

Qwen人物本体六视图与穿衣角色六视图的规格及直接原图保存要求读取[人物专项规则](人物参考图制作与记录规范.md#2-规格背景与布局)，不进入2倍超分流程，直接复制前按[批准后保存核对](图片批准后处理规范.md#图片批准后处理)处理。Imagegen六视图的正式尺寸仍按该专项，实际处理见下方指定尺寸分支。画风验证样例保留原图作为风格依据，不进入资产超分流程。导入的剧集专用参考图按其专项规则记录实际处理，不因本规范要求补做生成或超分。

## 指定尺寸处理的方式选择

调用[图片处理工具](../../nora-image-processing/SKILL.md)比较真实输入与目标，选择原字节保存、本地等比适配或RTX放大。业务明确本图正式尺寸和裁切授权，不改变已批准图的内容或明显画幅；源图和处理结果分别保留。

业务脚本在成功后维护规格处理/超分子记录、原批准、正式资产和索引、必要归档及网页核验。只准备不处理、不替换；重复调用恢复已完成结果。技术方式、参数、真实尺寸和凭据由工具交回，不伪称实际用户审核了处理细节。

## Imagegen原图的指定尺寸处理

- **适用输入与目标。** 先按[Imagegen规范](内置图片制作接续规范.md)保存原生图并取得对该具体候选的批准。目标宽高取上表资产专项中已规定的正式尺寸或当前用户明确指定的尺寸；不用原图乘2推导正式目标，也不把Imagegen原生图的像素不符当作处理失败。
- **处理方式**：按[指定尺寸处理的方式选择](#指定尺寸处理的方式选择)比较原图和目标，选择本地处理或RTX放大，不将所有指定尺寸任务都交给RTX。不任意改变已确定正式尺寸；涉及裁切时按实际授权执行，明显改变画幅或构图的任务另按用户授权，不属于轻微尺寸适配。
- **已经达到目标。** 原图已为正式宽高时，用户批准后直接核对保存，不为了流程凑一次放大。需要减少像素时如实记录尺寸调整，不把缩小再放大写成原生达标或无损超分。原图与实际处理输出均保留。
- **输出核对。** 正式结果必须符合本次规定的宽、高及格式；允许的轻微比例适配发生在获批源图到正式结果之间，不是允许正式文件偏离规定像素。记录原生尺寸、目标尺寸、实际输出、实际方式与工作流／请求，源图批准、后处理与正式保存分别关联。不额外要求用户重审同一内容，也不在处理完成前登记已采用。
- **RTX固定工具调用**：仅限上方方式选择中需要RTX放大的任务。统一任务清单使用`task_type:"image-upscale"`，明确`size:[目标宽,目标高]`（正整数像素）以及原图、原批准章节和正式目标路径。工具在任务副本中将RTX节点设为`target dimensions`，同步画布／API的`resize_type.width`和`resize_type.height`及成果计划；共用质量、强度和编码保持不变。未传`size`仍走原2倍模式，不根据图片来源或比例自动猜测目标。后台按明确目标核验真实输出，保留批准、上传与取回证据，并按原规则正式保存和静默收尾。调用格式见[超分条目](../../nora-ai-short-drama/references/comfyui-scripts/README.md#一次装配与批量入队)。

以下固定2倍节点参数、原生尺寸与2倍关系核验适用于Qwen分支；Imagegen指定尺寸分支不套用倍数断言。批准原图身份、正式路径、归档、证据、源文件保留及通知要求仍共用。

## 1. 触发与输入

- 先在原生成／审阅记录确认用户已批准的对应审批尺寸具体版本，核对实际文件、来源和可解码性。用户批准即接续本规范的超分，无需再问一次执行许可；尚未批准、仅部分认可或未明确版本时不提交。
- 输入必须是被批准的审批原图；不使用另一张同人物／同道具／同场景的其他图或中间预览。已有远端素材按原凭据核对，本轮新素材交后台上传并使用实际返回路径。审批原图与其请求、批准记录完整保留。
- 历史已批准的其他尺寸资产保留，不批量补超分、不因规格变化撤销批准。明确技术测试可以使用指定测试输入，测试结果不登记为正式资产。
- 按[工作区选端及任务地址规则](../../nora-generation/references/ComfyUI-服务配置与任务提交规范.md#工作区-comfyui-配置)选择新任务服务或恢复原任务；准备检查与远端能力诊断按[执行前检查与复用](../../nora-generation/references/ComfyUI-服务配置与任务提交规范.md#执行前检查与复用)执行，不将库存查询作为常规任务步骤。节点缺失或执行异常时保留实际错误，不自动安装依赖、切换放大器或重提；获授权的节点部署沿用[节点与安装包规则](../../nora-ai-short-drama/维护规范.md#comfyui节点与安装包)。

## 2. 配套工作流与参数

技术节点、模式和参数由[图片处理工具](../../nora-image-processing/SKILL.md)维护。业务提供本图正式目标和已批准源图，不修改共用固定配置。

## 3. 执行与恢复

新任务使用[统一入队入口](../../nora-ai-short-drama/references/comfyui-scripts/README.md#nora统一分配与提交)，任务类型image-upscale。Agent在[任务清单](../../nora-ai-short-drama/references/comfyui-scripts/README.md#一次装配与批量入队)提供已批准原图、原批准章节、正式目标及必要适用内容；工具装配API／画布、节点2的image上传绑定、节点3的一张PNG成果映射及本机候选目标，不由Agent手工逐份填写；超分附件沿用原前缀追加超分序号，不另建调度目录。后台上传批准原图、按队列提交并留存真实路径、请求、远端ID和响应。

工具在提交前自动准备[图片收尾计划](../../nora-ai-short-drama/references/comfyui-scripts/README.md#图片及超分收尾计划)，关联批准输入、原批准章节、正式路径及正式资产表和关联入口的更新。入队成功汇报数量即结束本轮，不补ID、进度或查网页。后台按[监控规范第4节](../../nora-generation/references/ComfyUI-任务监控规范.md#4-图片处理)完成下载、下节规格与来源核对、正式保存和网页同步；发送行为执行[正常超分静默规则](../../nora-generation/references/ComfyUI-任务监控规范.md#图片批次通知与超分静默)，保留本地报告，不另通知或展示。异常仍及时提醒，不重复检查或补常规记录。下载失败使用browser_tasks.py retry-collection请求原任务只重试取回，不重新超分。生成失败、状态未知及提交不明均保留原批准事实，不自动再POST。

预期输出为节点3的一张正式PNG，本机候选按原候选名追加超分序号保存，下载凭据位于原执行附件。后台只按已批准原图及收尾计划完成正式采用；需要替换已有正式图时必须提供归档入口，不覆盖历史文件。异常报告保留真实完成范围，未完成正式保存时不记已采用；原批准事实不因技术异常撤销，下载完成不等于正式收尾完成。

新处理任务沿[素材命名与保存](../../nora-ai-short-drama/references/共用规则/文件版本与工作稿规范.md#素材与执行附件)核对批准候选与`formal`同名主体，输出只按原候选追加本次`超分-NNN`或`规格处理-NNN`。显式指定`output`不免除核对；不一致时先报告需整理的源记录，不通过扩大文件名匹配或改写原批准继续处理。既有任务按原身份恢复，不追溯改名。

## 4. 文件核对、保存与记录

原生成条目的当前采用字段与批准依据保留在原处，填写格式读取[开发流程8.5.1](核心参考图制作规范.md#851-图片交付与用户审核)。批准后尚未完成时保留批准；等待、处理中和异常写入执行结果及原因与依据。完成规定核对及正式保存后更新采用状态，原因与依据按实际分支记录“批准后2倍超分”或“批准后指定尺寸处理”，关联审批原图、超分子记录及正式文件。未送审、待确认及候选结束状态读取[开发流程8.5.1、8.5.2](核心参考图制作规范.md#851-图片交付与用户审核)，不因后处理改写用户决定。

由后台核对实际宽高符合准备计划及上表对应正式尺寸、PNG、数量1、可解码性及来源：工作流确为批准的审批原图→节点1按本次模式处理→节点3；Qwen核对2倍关系，Imagegen核对指定目标宽高，复用已接受任务及终态成果关联，核对实际请求、上传及下载响应。正常通知后Agent直接使用报告，不重复读取这些证据。默认不调用看图能力，不宣称细节或身份的视觉保真已经验证。需要视觉分析时按[看图边界](../../nora-ai-short-drama/SKILL.md#看图能力调用边界)取得明确授权。

超分不增加第二轮默认画面审批。文件与记录核对通过后，将对应正式尺寸结果作为已批准版本的正式交付文件保存；通知与展示按[正常超分静默规则](../../nora-generation/references/ComfyUI-任务监控规范.md#图片批次通知与超分静默)处理；批准依据仍指向审批原图，处理方式按上方实际分支记录，不能伪称用户另行审核了超分细节。若用户要求再审超分结果则先送审。超分尚未完成时不将审批原图冒充正式尺寸图，不替换旧正式文件，不开始依赖该新正式图的下游制作。

人物、道具、场景及首帧分别沿用[人物](人物参考图制作与记录规范.md)、[道具](../../nora-drama-assets/references/道具资料与参考图规范.md)、[场景](../../nora-drama-assets/references/场景资料与参考图规范.md)及[首帧](../../short-drama-storyboard/references/首帧参考图规范.md)中的生成／审阅模板：原生成条目保留审批原图、参数及用户批准，在同条目补充超分子记录。子记录依次编号`超分-001`等，实际超分提交次数与原生图次数分开，不重置历史、不为后处理另算一次Qwen生成。机器附件沿用对应资产专项规范规定的原生成前缀，追加`-超分-001-*`，不在此另定义各类型的原生附件命名；候选超分文件为`{原候选名去扩展名}-超分-001.png`，存放位置按[工作稿管理规则](../../nora-ai-short-drama/references/共用规则/文件版本与工作稿规范.md#工作稿管理规则)执行。当前正式表登记对应正式尺寸文件，采用版本写原候选版本及超分编号，审阅入口指向原批准记录；正式文件名和层级不变。按[采用后收尾](核心参考图制作规范.md#852-图片采用替换与归档后的状态收尾)同步引用及浏览页。

画风验证样例的保存及展示读取[定位画风验证流程](../../nora-drama-positioning/references/项目定位与画风规范.md#项目画风展开示例验证与复用)，本规范不另维护样例尺寸。

## 5. 维护验证

修改配套工作流或节点映射时，在技能目录执行离线API检查及回归：

```sh
python3 scripts/workflow_baselines.py
python3 -B -m unittest discover -s scripts -p 'test_workflow_baselines.py' -v
```

检查应包含本图片超分API，执行节点为2、1、3；静态通过不证明服务端执行成功。实际验证须使用明确的技术测试输入，保存请求、结果和真实尺寸，不修改业务批准或自动替换项目资产。
