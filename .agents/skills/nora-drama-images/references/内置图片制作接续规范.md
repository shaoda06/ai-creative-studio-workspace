# 内置图片制作接续规范

版本：v1.15；更新日期：2026-11-08。

适用于已明确选用 Codex 内置 `imagegen` 的图片生成和编辑。这里的“本地生图”指当前会话可调用的内置工具，不表示模型运行在本机GPU。各类型的默认能力、备用能力及切换条件由[主入口选型](图片提示词规范.md#当前参考图生成选型)决定，本规范不自动改变选型。

固定交接、`prepare/complete`及脚本登记／网页核验步骤适用于人物、场景、道具、剧集素材和封面；社交媒体头像与主页背景图使用[社交图片生成与记录](../../studio-profile-images/references/个人页视觉制作与管理规范.md)的用途分支，不借用旧类型。本规范的能力边界、固定执行代理、真实调用、参考图输入、原生结果和单次执行要求仍适用；社交图片的尺寸处理与保存按该专项执行。

## 1. 任务与提示词

先按[源图资格与业务修订](图片提示词规范.md)准备本图内容、实际参考图、用途和授权。Agent复用本类型模板的主体、画风、构图及保留/变化要求，完整引用已确认画风，不将Qwen专有JSON、种子或采样强加给Imagegen。固定视图和正式目标仍按本业务规范，不另建Imagegen资产分类。

编写或实质修订正文时，按[图片提示词](图片提示词规范.md#图片提示词)选用适用的静帧镜头和表情技法。首次使用说明和具体效果反馈沿该节的共用规则处理。

实际工具调用、参考容量及原生文件处理进入[Imagegen工具](../../studio-imagegen/SKILL.md)。Agent编写提示词，业务脚本建立原对象的生成/审阅记录；执行Agent原样调用已备正文，不重新创作。

### 子代理执行与父代理交付

按Imagegen工具的执行代理要求交接。父代理提供完整已备内容、参考顺序和业务脚本返回的命令，执行方交回固定报告。生成完成后复用已做文件核对与登记，父代理只处理报告未覆盖的业务摘要和实际交付；导演表按其网页交付规则，不自行另建一套通知。

已有原生图但登记或网页核验失败时，只修复原登记或同步，不再次生成。用户尚未采用时保留候选状态。

## 2. 生成规格与原图送审

1. **先确定比例与正式尺寸。** 正式宽高沿人物、道具、场景或首帧专项，不因改用Imagegen另定像素标准。生成时明确目标比例和后处理后的正式分辨率，但不把请求值当作工具保证值。方图可请求1:1，服装正背面请求4:3；专项使用“16:9推荐尺寸”时，Imagegen可请求16:9，正式像素仍沿专项的既定宽高；项目另有画幅按已确认要求处理。
2. **接受预期的原生尺寸差异。** Imagegen返回的原生像素可能不同于请求值，通常低于正式目标；比例相近而非数学上完全相等也可作为候选送审。记录真实宽高、请求比例及正式目标，不因这类预期差异认定生成失败、自动重试或改换能力。不承诺某个固定原生尺寸、严格比例或“输入尺寸就是输出上限”。
3. **送审保留原图。** 保留完整原图，不为了凑严格比例或Qwen送审像素而先裁边、拉伸、缩放、补边或再次生成。仅展示、复制保存、读取尺寸和解码不改变画面。用户明确要求裁切、扩图等另按该授权制作，分别保留原始与处理后文件，不能混称原生输出。
4. **区分轻微误差与更换画幅。** 原图与目标近似比例的轻微差异允许随获批后的指定尺寸处理适配；这不授权把横图强行变成竖图、改变重要构图或接受明显变形。比例明显不符或用户指出构图问题时说明实际情况，按本轮授权处理；不自定通用误差百分比、补做次数或新的审批门槛。

文件与记录核对、用户采用状态、展示去重及计数沿[图片交付与用户审核](核心参考图制作规范.md#851-图片交付与用户审核)。文件核对通过只指可解码、来源及实际规格已如实记录，不代表画面已通过用户审核。尚未获批时不处理成正式资产。

## 3. 来源与记录

- 实际原生输出由固定脚本原字节保存到本项目资源版本，返回准确编号／版本和文件链接。修订携带原资源编号及真实base_file；新目标建立新编号。工作稿引用该版本，采用时不再另存正式PNG。来源、真实尺寸和用户决定仍按本类型模板登记。
- 使用原类型的生成／审阅模板，在现有字段填写实际工具名称、完整实际提示词、编辑输入及具体版本、生成用途、原生文件、真实宽高与格式、正式目标及当前用户决定。提示词与实际调用参数可保存到同前缀执行附件；未暴露的模型版本、种子、采样、client_id及prompt_id如实填未提供或不适用，不借用ComfyUI的值，不伪造后台任务ID。
- Imagegen原生阶段由固定脚本维护候选、文件核对、记录及网页解析核验，再由子代理向父代理回传现成报告。它不建立ComfyUI远端任务或后台取回通知，不调用ComfyUI的report伪装原生收尾；固定脚本自己的report只读取本次现成报告。失败恢复仅处理原收尾，不重新生成。超分阶段仍沿实际远端任务、后台记录及完成通知接续处理。
- 原生尺寸不同于Qwen送审尺寸是本分支正常事实；不得把缩放后的图登记成原生送审图。下游引用正式图时，同时保留Imagegen原图、原批准章节与实际尺寸处理的来源链；非公开种子不编造为Qwen种子。

## 4. 获批后到正式尺寸

用户批准具体原图后，按[图片后处理的方式选择](图片后处理业务规范.md#指定尺寸处理的方式选择)及[Imagegen指定尺寸分支](图片后处理业务规范.md#imagegen原图的指定尺寸处理)接续：以该原图为输入，选择本地等比缩放及获授权裁切，或确实需要的RTX放大，到达专项正式尺寸。不按原图机械乘2，不重新调用Imagegen或Qwen生成内容，不通过拉伸适配比例。

画风验证样例等原本无需资产超分的用途仍按相应专项保留原生图，不因本规范新增一次放大。

人物本体六视图与穿衣角色六视图的正式目标仍是人物专项规定的尺寸；Qwen分支的“原生即正式、不超分”不代表较低分辨率的Imagegen原图可以直接冒充正式图。原图已经达到正式尺寸且不需处理时，用户批准后按[直接保存核对](图片批准后处理规范.md#图片批准后处理)保存；其他情况按实际需要的指定尺寸处理记录，不缩小再放大以凑一次超分。

需要RTX放大的指定尺寸提交使用超分规范中的统一任务清单`size`参数，不得省略目标而落入默认2倍模式；本地处理不装配为RTX任务。两种方式均不改正式目标或绕过原图批准关联。仅在真实处理结果达到规定宽高、来源及正式保存核对通过后登记已采用；用户批准、实际处理与正式保存分别留证，不新增默认二次画面审批。
