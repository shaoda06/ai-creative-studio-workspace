# 固定脚本接口规范

## Imagegen子代理交接与固定收尾

全剧共用片头、片尾在09下使用固定制作对象，其目录和编号见[共用制作规则](../../nora-serial-drama/references/逐集目录与资产管理规范.md#全剧共用片头与片尾)。立项时随已选配套建立目录，按[初始化脚本说明](../../nora-drama-positioning/references/项目初始化规范.md#项目与单集目录初始化脚本)传入选择参数；仅补齐某个共用对象的准备目录时仍可使用 `project_init.py --project 'projects/剧名' --episode 片尾`（片头同理）。制作对象命令的 `--episode` 参数及JSON的 `episode` 字段继续使用。场次轮次、准备与入队、视频采用／定稿、图片收尾均沿原命令，仅将EP前缀替换为“片头”或“片尾”。图片使用 `kind=剧集素材` 和对应的 `片尾-专用素材制作-工作稿.md`；同样执行真实来源、批准依赖及网页条目核验。

入口：[imagegen_results.py](../scripts/imagegen_results.py)。生图能力选型及每批确认仍由[统一分流入口](图片提示词规范.md#当前参考图生成选型)负责；固定代理、实际调用及父子交付边界见[Imagegen规范](内置图片制作接续规范.md#子代理执行与父代理交付)。本脚本不生图、不超分、不远端入队、不发消息，也不自动批准；复用共享图片记录应用、审核模板和项目网页解析核验。需要完整工作区及浏览服务Python运行环境，独立技能包缺少该运行环境时说明限制，不伪装已同步网页。

使用当前工作区浏览服务的Python环境，macOS／Linux为`工作区浏览服务/.venv/bin/python`，Windows为`工作区浏览服务/.venv/Scripts/python.exe`。以下示例解释器和技能路径替换为当前安装的实际绝对路径。主控在该项目既有执行附件保存一份请求JSON，字段如下；图片类型、目录、名称和创作字段仍沿原专项，不由脚本决定设计。

```json
{
  "kind": "场景",
  "object": "SC001",
  "image_type": "场景参考图",
  "title": "办公室工位无人总览",
  "purpose": "总览／基础图",
  "draft": "04-场景资料/其他资料/工作稿/SC001-参考图-工作稿.md",
  "output": "04-场景资料/其他资料/工作稿/素材/SC001-EP001-C001-V001-场景参考图-候选-v01.png",
  "formal": "04-场景资料/SC001-办公室/参考图/SC001-EP001-C001-V001-场景参考图.png",
  "prompt": "本次准备好的完整实际提示词",
  "ratio": "16:9",
  "formal_size": [2752, 1536],
  "authorization": "本批Imagegen选择、生成范围及一次调用的真实授权",
  "fields": {"场景编号与名称": "SC001 办公室", "视图编号与名称": "V001 工位总览"},
  "references": []
}
```

封面新请求先在`10-社交媒体资料/封面资料/封面索引.md`登记对象；`fields`填写`封面编号:"COV001"`、`修订轮次:"R001"`及`轮次名称:"初稿"`。编号固定对应用途、平台和版式，后续修订沿用；横竖分别编号，同一轮可包含多次生成。新Imagegen与Qwen请求均检查这一归属，既有清单恢复保留原参数。旧记录补录使用索引的历史归属表，不改写旧清单。详见[封面对象与版本归属](../../nora-cover-images/references/封面制作与管理规范.md#封面对象与版本归属)。

`kind`为人物、场景、道具、剧集素材或封面。封面使用 `10-社交媒体资料/封面资料/其他资料/工作稿/封面制作-工作稿.md` 和封面工作稿模板；`prompt`自由编写，只记录本次实际正文，不套固定封面提示词模板。`prompt`为最终正文，不是要求子代理继续编写的任务描述。`ratio`为请求比例，`formal_size`仅记录获批后正式目标，不限制原生结果像素。`output`必填且不得占用已有文件；不自动推断用户想覆盖哪个候选。`fields`可填原模板创作字段；`references`按既有清单的`file/purpose/approval`或`user_reference/basis`提供项目内真实输入，原批准及来源要求保持，不要求Imagegen提供种子。`record_dir`可选，默认沿原工作稿的既有执行附件及对象／生成序号；`record_updates`可选，原记录须同步的关联内容用`path/old/new`明确提供，支持`{{outputs}}`和`{{specs}}`，不让子代理手写更新。

有对应正式图片的新请求须填写`formal`，与`output`一起按[素材命名与保存](../../nora-serial-drama/references/文件版本与工作稿规范.md#素材与执行附件)填写；它只声明对应正式图片身份，不创建或批准正式图。固定入口在写入工作稿及交接前核对目录、候选名与正式名，不合规时报错停止；已有执行清单的恢复保留原路径，不追溯改写。`complete`按清单复制原生文件，新清单再次核对同一身份，执行代理不改目标名。画风验证填写`image_type:"画风样例"`，不虚构`formal`，候选按专项固定对象名检查；手绘导演分镜表以`formal`中的场次及页码核对专项候选名。命名检查可在工作区根目录运行`工作区浏览服务/.venv/bin/python -m unittest discover -s .agents/skills/nora-drama-images/scripts -p test_imagegen_results.py`；使用独立临时项目核对新请求拒绝、标准命名交接及历史交接复用，不调用生图。

```sh
/实际浏览服务/.venv/bin/python /实际技能/scripts/imagegen_results.py prepare \
  --project /实际项目目录 --request 相对执行附件/请求.json
```

`prepare`只准备既有生成条目和Imagegen执行清单，不调用工具或创建ComfyUI任务。新交接返回`manifest`、`executor`、`generation`、`candidate`、`generation_call`、`result_store_key`、`report`入口及`complete_command`参数数组；实际提示词只在清单的`request.prompt`保存一次，不另写TXT或JS。主控将执行清单、调用正文和此数组交给固定子代理；执行时只追加`["--source", 实际原生输出路径]`，用参数列表启动，不重新拼写项目、清单或提示词长路径。相同请求复用交接，不重复分配生成编号。已交接请求改变时另存新请求，不覆盖原调用依据。未执行条目保留待执行，不记生成成功。

`generation_call`是返回的代码正文，供子代理原样提交到functions.exec，不在shell或Node中调用真实生图。正文包含实际提示词和按用途清单排序的绝对参考图路径；同次exec先`store(result_store_key, 完整返回值)`，再`generatedImage(完整返回值)`。不按MCP的`content`数组解析、不打印base64。恢复显示只执行`generatedImage(load(result_store_key))`。旧清单有`prompt_file/generation_call_file`时仍可读取原文件；旧任务恢复不新增生图。

子代理取得原生PNG后，使用上述`complete_command`数组追加`--source`并执行。以下仅展示`complete`的参数含义，不作为手工重拼路径的步骤：

```sh
/实际浏览服务/.venv/bin/python /实际技能/scripts/imagegen_results.py complete \
  --project /实际项目目录 --manifest 相对执行附件/请求-Imagegen执行清单.json \
  --source /工具实际返回的原生输出.png
```

`--source`为实际工具原生文件的绝对路径，保持原文件并复制原字节，不裁切、缩放或转换。脚本从执行清单的`request.prompt`读取本次逐字提交的正文；旧清单仍读取原`prompt_file`并核对准备正文。执行者须原样使用返回的调用正文，不重新改写。已有命令仍可显式传`--actual-prompt-file`，但它是兼容选项而非默认步骤；不把重新改写的文本登记为原请求。固定脚本保存真实来源凭据、实际尺寸／数量、原生候选与待确认审阅，核验该项目解析后确实含本候选，再返回`user_message_ready=true`和交付入口。普通生产项目使用其真实项目根目录；隔离测试项目只核验其独立项目解析结果，不表示生产网站新增该测试项目。

生图失败时使用`fail --project ... --manifest ... --error-file /实际错误.txt`，只记录错误，不追加生图。收尾失败时子代理回传错误；获授权修复后重新调用原`complete`只恢复未完成的登记／网页核验，不再次生成。候选已存在不同内容、提示词不符或记录并发改变时停止，不覆盖用户反馈。已完成结果重复调用复用原报告；不借收尾入口替代已有候选或新一轮生成。

父代理收到完成消息后读取子代理报告即可。报告入口也可用`report --project ... --manifest ...`读取；该命令不重新测图、登记或扫描网页。失败报告返回实际问题，未完成时不能以已有文件推断可交付。超分沿原批准后处理入口执行，不交给本脚本重画。


### 图片的只读命名核对

社交图片手工保存，以及获批生成图无需尺寸处理、由Agent通过共用PNG入口保存到正式位置前，复用同一脚本的`check-name`。它只读核对命名，不写文件、不调用生图、不建立任务，也不核验图片内容、尺寸或批准。请求JSON已有实际`kind`、`formal`、`draft`、`output`，路径均相对项目根目录；普通图片的`output`是对应候选，社交图片使用`kind:"社交媒体"`并沿[专项候选标识](../../nora-profile-images/references/个人页视觉制作与管理规范.md)。该子命令不增加社交图片的生成登记能力。

```sh
/实际浏览服务/.venv/bin/python /实际技能/scripts/imagegen_results.py check-name \
  --project /实际项目目录 --request 相对执行附件/请求.json
```

成功返回`status:"valid"`及核对过的正式／候选路径；不合规时报错并以非零状态退出。手工保存须使用核对过的`output`原样复制，不能把此报告当作生成或收尾成功。


### 图片及超分收尾计划

`--plan`由工具装配本节计划及既有生成条目；下列为旧式参数入口和异常定位所用格式，正常新任务不手填。与API、上传及成果映射一起在准备阶段写入原执行附件；`--prepare-only`与正式入队使用同一计划。技术及审批分工以[监控规范第4节](ComfyUI-任务监控规范.md#4-图片处理)为准。路径相对项目根目录，宽高单位为像素。`images`必须与output-plan一一对应；`kind`选择人物、场景、道具、剧集素材或封面，引用对应既有工作稿模板，不改变图片画风。工作稿须已有本次生成条目及审阅区；后台在成功取回后建立实际审阅记录。

```json
{
  "draft": "03-人物资料/其他资料/工作稿/CH001-参考图-工作稿.md",
  "kind": "人物",
  "generation": "生成记录-001",
  "review": "审阅-生成记录-001-001",
  "formal": "03-人物资料/CH001-人物/参考图/CH001-日常-服装参考图.png",
  "images": [{"path": "03-人物资料/其他资料/工作稿/素材/CH001-日常-服装参考图-候选-v01.png", "width": 1152, "height": 864}],
  "record_updates": []
}
```

新登记图片计划的`formal`声明对应正式路径，`images`逐项按该正式名核对；超分可从下方`upscale.formal`取得同一身份。旧任务收尾或恢复保留原计划，不为补字段改写原执行依据。`record_updates`可选，默认空数组；需要同步本批项目进度、资料卡或索引时，在生成前提供实际Markdown的`path`、唯一`old`原文和`new`目标文字，后台在结果成功后执行，不在通知后让Agent补写。支持`{{outputs}}`、`{{specs}}`、`{{evidence}}`、`{{time}}`；超分还支持`{{file}}`。链接按每个目标文档的位置计算。原文不唯一、并发改变或未知占位符停止对应更新，不覆盖其他修改。项目进度只填写本批对象对应的阶段行；资产入库之外已获授权的剧集进度另行同步，不混入资产收尾计划。异常接续按[已有授权的登记修复](../../studio-workspace-browser/references/进度查询与结果处理规范.md#已有授权的登记修复)，先修正计划，不以放宽保护或重做图片解决。

获批超分使用原生成及批准章节，images填写超分候选路径和正式尺寸，并增加`upscale`对象：

```json
{
  "number": "超分-001",
  "source": "03-人物资料/其他资料/工作稿/素材/CH001-日常-服装参考图-候选-v01.png",
  "approval": "03-人物资料/其他资料/工作稿/CH001-参考图-工作稿.md#审阅-生成记录-001-001",
  "formal": "03-人物资料/CH001-人物/参考图/CH001-日常-服装参考图.png",
  "archive": "03-人物资料/其他资料/历史版本/CH001-日常-服装参考图-归档-实际时间戳.png",
  "record_updates": [{"path": "03-人物资料/其他资料/工作稿/CH001-参考图-工作稿.md", "old": "实际待替换的唯一正式资产表行或表头", "new": "实际更新后的表行，正式文件使用{{file}}并引用原批准章节"}]
}
```

此对象填入计划的`upscale`字段；示意文字及路径须替换为当次真实值。`source`必须是原批准章节明确批准的具体候选，并实际绑定节点2上传；节点1按实际计划执行2倍或指定宽高、节点3保存PNG。指定尺寸API使用`resize_type:"target dimensions"`及`resize_type.width`、`resize_type.height`，与`images`计划宽高一致；倍数模式仍为`scale by multiplier`和`resize_type.scale:2`。`formal`为实际正式路径；首次保存可省略archive，替换已有正式图时必须给出真实、未占用的历史路径。`upscale.record_updates`必填，准备当前正式资产表及受影响卡片／索引的实际更新，不改写用户反馈、批准或旧版本事实。后台补超分子记录，保留原审批图，不增加默认画面审批；用户明确要求超分后再审时不得使用自动正式采用计划。

正常结果直接读取report。缺少计划的旧任务只报告缺项，不自动搜索或猜测；明确核对原关联后，可将`{本地任务UUID: 完整计划}`写入原附件，通过`browser_tasks.py register-results --notification-id 通知UUID --image-plans 旧图片收尾关联.json`显式修复。此命令仅允许本通知中的图片任务，不覆盖已有不同关联，不重新生成；返回真实登记及网页结果，不改写已发送的历史报告。是否可直接修复沿[已有授权的登记修复](../../studio-workspace-browser/references/进度查询与结果处理规范.md#已有授权的登记修复)判断，不为命令本身增加用户确认。

新prepare只保存一份执行清单中的实际提示词和参数，返回`generation_call`供原样执行，不再为每张图另存相同TXT或调用JS。旧清单仍可读取原`prompt_file/generation_call_file`；实际工具返回值和原生PNG继续保留，参数及来源核对不省略。


## Nora图片关联更新范围

项目进度的写入只覆盖本批制作对象或资产类型对应的既有六列阶段行；定点更新不能在阶段表外追加历史记录或改动其他阶段。当前问题与动作的填写语义读取[会话规范第4节](../../nora-serial-drama/references/会话与进度管理规范.md#4-项目进度文件)。图片关联更新、视频采用和后台业务登记共用这一阶段行范围核对。图片与超分的全部关联更新在准备阶段预检字段、Markdown路径、原文唯一性、支持的填充标记及进度阶段范围，先于远端入队、Imagegen交接及本地图片处理；实际登记仍核对范围和当前原文，防止执行期间的变化被覆盖。
