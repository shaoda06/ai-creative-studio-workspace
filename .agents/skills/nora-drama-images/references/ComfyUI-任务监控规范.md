# ComfyUI-任务监控规范

## 4. 图片处理

提交前通过[图片收尾计划](固定脚本接口规范.md#图片及超分收尾计划)明确工作稿、生成及审阅章节、图片用途和目标规格。计划随实际入队资料保存，后台不按文件名猜测身份或来源；需要正式保存的超分还须关联具体批准原图、原批准章节、正式路径及预先准备的资产表与关联入口更新。

后台按[取回与收尾](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md#2-留档与收尾)选择真实输出并保存，随后核对实际PNG、尺寸、数量、压缩数据可解码性、完整性、下载凭据和已接受的实际请求。核验通过后，普通图片更新原生成条目，按对应既有模板建立审阅记录并登记网页待审；保留已有反馈和决定，不把生成目标当成画面验证结论。超分按[超分规范第4节](图片后处理业务规范.md#4-文件核对保存与记录)核对批准输入、实际上传及所选倍数／指定尺寸处理链，完成正式保存及已准备的关联更新，沿用原图批准，不追加默认审批。

后台沿用原执行附件的`结果收尾报告.json`保存技术结论、成果、文档变更及可恢复进度；网页同步按项目合并核验，确认对应候选或正式资产已收录后，按[公共批次通知规则](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md#图片批次通知与超分接续)发送；正常超分仍保存原执行附件的收尾报告和正式记录。网页失败只接续核验，不重复解码图片或写已登记的记录；证据或源文字变化则报告冲突。暂时性写入／网页失败沿用[公共结果收尾](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md#后台结果收尾与通知)的持久重试额度，耗尽或需人工处理时发送真实异常，不重新生成。


### 图片完成通知后的精简收尾

Agent收到本批普通图片的完整正常通知后，只调用一次`report`，使用`delivery.tasks[].images[].file`中的绝对路径、实测规格及`review_url`展示成果和审核入口，不再计算根目录或拼接地址。正常图片CLI只返回这份展示清单；异常自动保留完整报告，显式追溯可加`--details`。未带展示清单的历史报告仍使用原`closeout.display_outputs`及其所属项目路径，不重跑收尾。展示去重仍按[图片交付规则](核心参考图制作规范.md#851-图片交付与用户审核)执行。复用报告中的技术结论，避免重复读媒体规格、请求／响应和工作稿，避免补常规记录、查状态或刷新网页。返修图按[图片交付规则](核心参考图制作规范.md#851-图片交付与用户审核)完成业务复核再送审。异常才按报告指出的失败阶段及证据入口查缺项，旧任务缺计划时使用工具的显式关联修复，不猜测、不自动重生成。采用仍由用户决定。

### 超分结果业务接续

收到超分结果后，按[图片后处理业务规范](图片后处理业务规范.md#4-文件核对保存与记录)沿用原图批准和本次处理授权，复用后台完成的正式保存及关联更新，补齐未完成的采用与展示同步后汇报；不重复技术核验或增加默认审批。异常按[本阶段恢复](进度查询与结果处理规范.md#异常与恢复)执行。
