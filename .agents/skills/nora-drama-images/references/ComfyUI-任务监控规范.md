# ComfyUI-任务监控规范

## 4. 图片处理

提交前通过[图片收尾计划](固定脚本接口规范.md#图片及超分收尾计划)明确工作稿、生成及审阅章节、图片用途和目标规格。计划随实际入队资料保存，后台不按文件名猜测身份或来源；需要正式保存的超分还须关联具体批准原图、原批准章节、正式路径及预先准备的资产表与关联入口更新。

后台按第2节选择真实输出并保存，随后核对实际PNG、尺寸、数量、压缩数据可解码性、完整性、下载凭据和已接受的实际请求。核验通过后，普通图片更新原生成条目，按对应既有模板建立审阅记录并登记网页待审；保留已有反馈和决定，不把生成目标当成画面验证结论。超分按[超分规范第4节](图片后处理业务规范.md#4-文件核对保存与记录)核对批准输入、实际上传及所选倍数／指定尺寸处理链，完成正式保存及已准备的关联更新，沿用原图批准，不追加默认审批。

后台沿用原执行附件的`结果收尾报告.json`保存技术结论、成果、文档变更及可恢复进度；网页同步按项目合并核验，确认对应候选或正式资产已收录后，按下方批次通知与超分静默规则决定发送；正常超分仍保存原执行附件的收尾报告和正式记录。网页失败只接续核验，不重复解码图片或写已登记的记录；证据或源文字变化则报告冲突。暂时性写入／网页失败沿用第2节的持久重试额度，耗尽或需人工处理时发送真实异常，不重新生成。


### 图片批次通知与超分静默

新登记任务统一按第3节任务组边界通知，图片、视频和超分混合组也不拆开正常通知。以下image_batch关联仅用于历史无组图片任务的兼容恢复；正常超分静默和图片集中展示继续适用。

1. **历史无组图片按明确批次集中通知。** 一次已确认提交清单中的普通图片生成任务（image）构成一批；同清单的超分和视频任务不计入图片数量。装配入口在准备时记录批次标识及预期任务数，随入队、清单恢复和服务重启保留；不同项目、来源会话或提交清单互不补足数量。只有本批全部图片取回、技术核验、记录更新及网页核验完成后，才保存一次完整通知报告并集中发送，Agent读取一次report后集中展示。部分正常成功由后台继续登记，不逐张通知，也不发送“已收到几张”的对话进度。用户主动询问进度或指定查看部分成果时，按实际范围回答。
2. **正常超分静默。** image-upscale完成正式保存、关联记录和网页核验后，只保留本地报告、正式文件及状态，将通知记为not_required，不发送完成消息、不唤醒来源会话，也不重复展示图片。收到升级前已经发出的正常超分通知时，只读取report并确认收到，不发处理进度、完成回复或图片；异常不适用静默。用户主动要求展示或查询时可回应。
3. **异常交接与修复。** 生成失败、异常暂停、提交状态不明、取回或正式保存／登记／网页核验失败等需处理的问题，沿本规范第3节合并交接Agent并先静默修复，不等待整批成功；需要用户决定或确实受阻才汇报。其余正常图片继续取回；问题在原任务恢复并完成后，再集中交付本批全部图片，不重新生成来凑齐数量。

没有组或批次关联的历史任务按原单任务记录处理，不靠标题、时间相近或同一会话猜测历史批次。新提交统一执行[任务组提交范围](../../nora-comfyui/references/ComfyUI-服务配置与任务提交规范.md#任务组提交范围)，旧式入口新登记的独立单项也属于单成员组。通知合并、静默和技术成功均不改变用户审批或下一阶段生成授权。


### 图片完成通知后的精简收尾

Agent收到本批普通图片的完整正常通知后，只调用一次`report`，直接使用`delivery.tasks[].images[].file`中的绝对路径、实测规格及`review_url`展示成果和审核入口，不再计算根目录或拼接地址。正常图片CLI只返回这份展示清单；异常自动保留完整报告，显式追溯可加`--details`。未带展示清单的历史报告仍使用原`closeout.display_outputs`及其所属项目路径，不重跑收尾。展示去重仍按[图片交付规则](核心参考图制作规范.md#851-图片交付与用户审核)执行。不得再读媒体、请求／响应和工作稿来重复核对，不再补常规记录、查状态或刷新网页；`report`读取不触发这些工作。异常才按报告指出的失败阶段及证据入口查缺项，旧任务缺计划时使用工具的显式关联修复，不猜测、不自动重生成。默认不调用看图能力，图片是否符合设计和是否采用由用户判断；技术成功不授权下一阶段。
