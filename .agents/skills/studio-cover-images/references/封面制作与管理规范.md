# 封面制作与管理规范

## 1. 用途与制作

封面用于项目展示、片头、介绍或视频发布；按实际需求制作项目通用或单作品专用封面。由运营封面阶段负责画面、文案、排版和素材依据，生成执行负责调用、结果登记及规格处理；不新增独立制作阶段。

业务对象、会话和资料位置由调用方提供，按[运营接续](../../studio-social-operations/references/运营与制作接续规范.md)读取；是否制作封面依实际展示或发布需求，不要求补其他业务的定位表。

按需讨论用途、文案、比例和目标尺寸，需求已清楚时直接制作。默认使用内置Imagegen，Qwen Image 2.1为备用，已明确工具选择时沿用本次要求；执行方法见[运营图片规范](../../studio-social-operations/references/运营图片制作与采用规范.md#生成与记录)。请求尺寸与模型参数按实际共用工具说明，正式成品按本次目标处理。

不设固定封面生图提示词模板。根据本次目标自由组织完整实际提示词，写清文案原文、画面与排版、参考图逐张用途和保留／变化范围，沿用项目已确认画风、人物及服装。保存实际提示词与真实输入，修改和重新生成沿[参考与修订](../../studio-social-operations/references/运营图片制作与采用规范.md#参考与修订)。用户选定某图并指定据此延展时，记录该源图、版本和范围；新横竖版分别送审，不继承源图批准。

### 成套交付

封面默认以套组制作和交付，每套包含一个横版和一个竖版。先制作或先批准其中一版，不代表另一版无需制作。同套使用共同的画面设计、人物、文案及视觉风格，按横竖比例调整排版；用户明确要求的差异按实际记录。

套组名称固定表示同一用途，例如“账号通用”或调用方的实际作品代号，不随平台、方案名称或改图轮次变化。同一用途下的每个平台及版式登记固定封面编号，方案和修改进入该封面的修订轮次，不因换风格另建对象。每张图片仍保留真实候选文件版本、生成、批准及处理记录。同套缺少尚需交付的版式时，如实记为未完成；已获批单张的状态保留，不因整套未完成而撤销。套组完成按本次所选平台逐一核对；所有仍需交付的成品均已获批且规格达标，才记为本套交付完成。

## 2. 平台选择、规格与后处理

### 平台字段与多选

成品必须绑定适用平台。使用公共模板时固定使用以下字段和写法；调用方已有固定结构时按[业务记录映射](#业务记录映射)表达同等信息，不重复建表。平台与项目通用／单作品专用的适用范围分别记录，不互相代替。

| 字段 | 固定填写方式 |
| --- | --- |
| 封面编号 | 调用方指定的封面索引范围内固定编号COV001起；登记后不复用或随文件名变更，横竖版各有一个编号；适配多平台且共用同一设计与文件时可绑定多个平台 |
| 套组名称 | 同一用途的横竖版共用固定名称，例如“账号通用”或调用方的实际作品代号；平台单独登记，方案名称放在轮次名称中 |
| 修订轮次 | R001起；一次用户反馈或新方案为一轮，同一轮的抽卡与故障恢复记录可以共用轮次；横竖同步修改时使用相同轮次，仅改单版时不为另一版伪造新记录 |
| 轮次名称 | 简短说明本轮变化，如“初稿”“视线调整”“配色整合”；不使用原始文件名作为页面标题 |
| 目标平台 | 本批制作的平台选择，允许多选；平台标准名称为“通用”“抖音”“快手”“小红书”，后续平台按其正式中文名称补充，不使用别名或缩写 |
| 适用平台 | 每条成品实际适配的平台；单平台填标准名称，多平台用顿号连接，如“抖音、快手”，按抖音、快手、小红书的顺序填写，其他平台依本批选择顺序追加 |
| 版式 | “横版”或“竖版” |
| 规格依据 | 对应平台及版式的依据，区分平台要求、工作区交付预设和用户指定规格；引用核实依据时注明链接及适用日期 |

“通用”表示不针对具体发布平台，按明确用途及目标规格交付，不表示已经适配全部平台。“通用”单独选择，不与具体平台混选；具体平台可以同时选择多个。不明确目标平台时先询问，不自动填通用或沿用上次平台。需要用户选择时优先使用可多选的选项弹窗；弹窗仅支持单选时，用同一问题接收顿号分隔的全部平台，不将多平台需求压成单选。已有明确选择直接沿用。

### 封面对象与版本归属

使用公共封面索引时，当前表逐项登记固定“封面编号”，即使尚无正式图也先登记对象及目标规格，成品和原图尚不存在时如实填待处理／待生成。生成前明确编号、修订轮次、轮次名称；准备记录应包含这些字段；使用支持fields的执行适配时传入同名字段并核对与索引一致，不假定所有模型接口都有相同字段。同一对象后续沿用其正式图片身份及候选命名，不因修改风格重新从v01建立另一个对象。

页面按平台和用途展示横竖各一张对象卡片，优先预览当前正式版；没有正式版时展示最新候选。新版候选不自动替换正式版，有待确认更新时给出提示。详情按轮次从新到旧列出候选及执行记录；同轮多次生成是候选／执行附件，不平铺成独立封面。原生图及本地缩放、裁切或超分后的成品属于同一轮，尺寸处理不新增设计版本。历史成品引用本轮保留的处理输出或归档文件，不能引用会被新采用覆盖的当前正式路径。

旧记录缺少编号或轮次时，在同一封面索引的“历史归属补录”表按生成记录逐项关联。只补经旧请求、修改链或原采用索引核实的归属，保留原执行清单、提示词、生成编号及批准原文。没有明确归属的资料留在“待归类资料”，不按文件名相似、文件版本号或比例猜测。不得把制作时未登记的平台追写成历史真实发布平台；补录表示当前图库的版本归属。

### 规格确定与成品处理

按以下顺序处理每批封面：

1. 确定套组名称、适用范围、目标平台。每套需要横版和竖版；实际上传数量与版式由平台规则确定。
2. 以本规范的统一交付预设确定横竖版目标宽高、比例和格式；通用及各目标平台均以此为默认起点。逐平台核对实际发布入口，明确需要其他规格或用户另有要求时再适配；未核实的官方限制如实注明，不将工作区预设或用户指定值标为官方要求。
3. 先确定共同设计，再制作横竖版和所需平台延展。平台之间画面、排版、宽高、比例及格式完全相同，且分别满足各平台已确认要求时，可共用同一成品文件，索引一条记录列出全部适用平台，无需重复生成或复制。任一项不同则分别处理和登记；仅同属一个套组不能推定文件可共用。
4. 以各成品已定目标执行下方后处理，保留原图和实际处理记录。比例变化需要重新排版或明显改变构图时按修订处理，不能仅凭尺寸达标视为完成。
5. 按实际适用平台及版式逐项核对成品与批准依据，再更新索引、工作稿及套组待办。某平台尚未确认规格或尚缺一版时保留对应未完成项，不影响其他已完成成品的真实状态。

每个封面在制作时注明适用平台、用途、规格依据、目标宽高、比例和格式。

### 平台官方口径与适用入口

按[平台封面规格库](平台封面规格库.md)读取当前入口；比例依据与交付像素依据分开记录。

### 工作区选用的交付预设

每套制作以下横竖两版，适用于“通用”及抖音、快手、小红书等目标平台的初始交付。比例和像素均为工作区制作选择，不代表各平台统一强制要求；默认交付PNG。本次用户明确另行指定时按当次要求执行；旧成品保留实际规格，不将旧制作尺寸自动沿用为新标准。

| 默认版式 | 比例 | 交付尺寸 |
| --- | --- | --- |
| 横版 | 4:3 | 1440×1080 |
| 竖版 | 3:4 | 1080×1440 |

其他比例仅在实际发布入口明确需要或用户指定时适配，不按平台名称自动另做一套。例如入口需要16:9横版或9:16竖版时，可选1920×1080或1080×1920；这两组像素仍是工作区自选尺寸，入口另有明确像素、格式或文件大小限制时按其要求处理。官方列出的可选比例或推荐比例，不自动成为本批必须交付的规格。

首次用于某个平台时，在实际发布环节核对封面上传预览、列表或主页裁切效果，确认标题、人脸和关键信息完整；只有入口需要时再从保留的原图适配，必要时重新排版。

规格依据固定区分“比例依据”和“交付像素依据”：分别注明官方强制／官方推荐／工作区预设／用户指定；引用官方要求或建议时附对应官方链接、适用入口和核实日期，入口裁切或上传未验证时如实注明。文件达到交付预设不等于已验证所有平台入口的显示效果。

平台预设更新不自动改变已采用封面、用户指定规格或历史批准。已有4:3／3:4等组合可以保留为其明确用途或用户指定规格；新增平台用途或改动现有画面时，再按本次授权适配，不批量裁切、扩图或重写原记录。

生成原图完整保留，真实尺寸以文件为准，不把请求比例或文件名当作实际规格。候选送审与用户决定沿[审阅与采用](../../studio-social-operations/references/运营图片制作与采用规范.md#审阅与采用)。

后处理只用于使分辨率、尺寸和比例达到本次目标；明确目标宽高后，沿[公共尺寸处理](../../studio-social-operations/references/运营图片制作与采用规范.md#尺寸处理)处理，Qwen备用封面同样适用，不套用其他资产的固定2倍要求。不为尺寸处理重新生图。裁切按本次用户授权执行，明显改变构图的裁切、补画或扩图作为修订处理。

用户批准的是具体原图。后处理完成后核对实际宽高、比例、格式和可解码性，记录原图、处理方式、结果及批准依据，再登记正式成品。原图与成品都保留，不把“画面已批准”写成“成品规格已达标”。项目原有不超分约定不免除目标尺寸和比例核对。

### Qwen封面默认生成尺寸与后处理

使用Qwen Image 2.1文生图或图生图制作上述默认横竖封面时，按下表填写原生输出宽高。两组生成尺寸均满足[Qwen工具](../../studio-qwen-image/SKILL.md)的32像素对齐要求；原生生成尺寸与最终交付尺寸分别记录，不将交付尺寸直接填入生成请求。

| 版式 | 原生生成尺寸 | 最终交付尺寸 | 默认后处理 |
| --- | --- | --- | --- |
| 横版4:3 | 1536×1152 | 1440×1080 | 本地等比缩小 |
| 竖版3:4 | 1152×1536 | 1080×1440 | 本地等比缩小 |

保留真实生成原图，核对实际宽高后，按[公共图片处理](../../studio-image-processing/references/图片处理工具规范.md#输入与分流)使用Pillow与LANCZOS等比缩小，两边缩放比例均为15/16；不裁切、不拉伸，不执行RTX或固定2倍超分。处理结果保存为PNG新资源版本，保留原图、来源关系及处理记录；候选审阅与采用仍按本规范执行。

本预设只用于Qwen生成默认4:3／3:4封面，Chloe及其他调用业务直接沿用，不在各业务重复维护尺寸。用户指定或实际平台入口需要其他规格时，另行确定符合Qwen对齐要求的原生宽高及处理目标，按实际原图与目标选择处理方式；不把本表扩大为所有图片的生成尺寸，也不为已采用的历史封面补做缩放。

## 3. 项目级保存与记录

封面索引、工作稿、执行附件、媒体归属和文件命名由调用业务提供。创建时机沿其建档规则，不由公共封面技能决定项目层级或是否预建目录。索引记录业务对象、用途、平台和版式，实际媒体保存到调用方指定资源区。

调用方未提供固定映射时，使用[封面索引模板](../templates/封面索引模板.md)维护编号、套组、平台、目标规格、采用原图、当前成品、审阅和处理入口；使用[工作稿模板](../templates/封面制作工作稿模板.md)保存真实生成、讨论和采用记录。保持模板字段与既有解析约定，状态与版本由原记录提供，不另建一套批准台账。

“正式文件”“成品文件”均表示采用版本的入口，不要求复制到正式封面目录。原生、处理、采用、发布和历史通过具体版本关联，不因用途或阶段变化另存相同媒体。替换当前采用时保留原审阅与旧版本；已有发布引用保持不变。实际迁移按明确授权和共用资源规则处理，不重写原请求、响应或批准。

### 业务记录映射

已有固定业务记录时，由调用方明确以下信息的原记录位置：稳定封面对象及用途、所属套组、平台与版式、目标规格、候选与修改链、真实输入输出、审阅依据和当前采用。对象可用调用方已有的业务身份与用途槽位组合表示；修订可沿已有执行、上游与返修记录关联，不强制增加COV编号、R轮次或公共封面索引／工作稿文件。公共模板中的R轮次不得与调用方已有的同名审阅编号混用。

首次制作前在原准备或执行记录中明确对象、目标和修改关系；尚未获批的候选保留在原输出记录，不为占位写入当前采用。采用与发布引用准确资源版本，历史版本沿原审阅与修改链追溯。采用现有固定结构的页面只按已支持的映射展示，不要求额外接入公共索引页面，也不把候选自动显示为正式封面。

## 4. 固定工具与浏览入口

按[运营图片规范](../../studio-social-operations/references/运营图片制作与采用规范.md)调用共用生成和图片处理工具；调用业务提供实际对象、输入版本、记录位置及已支持的登记适配。固定种子类别、图片kind、命名检查和专用收尾属于具体适配，不作为公共封面的统一接口。

浏览适配读取索引、工作稿及真实规格，解释对象、修订轮次、候选和采用关系；其支持目录与资源范围由调用方登记。已支持的页面保持当前表头、审阅标题及状态字段。未支持的对象或路径交付实际文件入口并说明限制，不将公共模板可填写视为网页已经接通，也不复制媒体以满足固定目录。

## 5. 类型、复盘与发布接续

通用封面表达账号、项目、品牌或系列气质，可用于多作品；单作品封面表达当前内容看点、主题或产品重点，关联调用方实际作品身份。两类均按本次所需套组制作，不强制每条作品重做。文字承诺与实际内容一致，主要信息易辨认；横竖分别排版，不拉伸，不预设强冲突、大字标题或固定表情布局。

制作、更新及发布选用时按[阶段06](../../studio-operations-guidance/SKILL.md)筛选相关报告，记录建议、实际采用和验证目标。复盘不主动触发改图；每次发布即使复用通用封面，也核对与当前作品匹配。

[发布阶段](../../studio-publication/SKILL.md)引用本次实际选用的文件、资源版本和采用依据，不再保存一份封面副本。发布后引用不随当前通用封面更新；新采用只影响后续选择，不自动修改已发布作品。
