# 参数与基准规范

本规范维护 AiMixer 导演台标准版的画布、参数与装配接口。
## 1. 当前固定基准与任务副本

工作流基准与任务副本的维护边界统一读取[维护规范](../../studio-entry/维护规范.md#工作流基准与任务副本)。正式与非正式文件的目录归属按[维护规范第1节](../../studio-entry/维护规范.md#1-目录分类与文件归属)执行。画布保留UI布局、AiMixer 导演台公共/本组编辑状态及说明；API只保留正式输出所需的服务端依赖。标准版节点标题使用“中文解释名｜英文原名”，英文原名保留节点实际类型名（例如`二采前馈分块｜MiniMaxChunkFeedForward`）；标题不写节点编号、权重、步数、块数、尺寸、设备或开关状态等实际配置，参数保留在控件与执行规则中。API的`_meta.title`沿用同一格式，实际节点ID及类型标识不改。

画布按“模型加载组、LoRA组、实际工作组”分区；LoRA区内分出常驻LoRA组、可选附加LoRA和专用打戏LoRA组，布局分组不改变节点启用状态或执行接线。

| --- | --- | --- | ---: |
| 标准版：正式默认一采确认与二采 | [画布](../../studio-h3/references/workflows/Minimax-H3/Minimax-H3-导演台-视频生成-标准版.workflow.json) | [API](../../studio-h3/references/workflows/Minimax-H3/Minimax-H3-导演台-视频生成-标准版.api.json) | 默认18；全开23 |

该原生标准版一采不使用外部图片、音频、视频加载节点；素材通过AiMixer 导演台的 `timeline_data` 传入原生公共区和本组区。502是基准节点编号，任务副本的缓存身份填写、来源身份保持与缓存定位按[节点缓存规范](ComfyUI-AiMixer导演台节点使用规范.md#75-缓存检查与清理接口)处理。画布中的三组、11/15/14秒和种子是填写样例，不是所有任务的规定；执行前按调用方明确输入替换提示词、素材、组序、时长、实际种子及输出标识。执行参数以实际API为准；连接输入覆盖控件默认值。

原始项目画布、实际请求及历史批准保存在项目中，不写回可分发基准。基准中的空素材和正文占位符不得原样提交。历史独立二采任务副本中的15个可选加载器及其 `_meta.nora_optional_reference` 不能照搬到现行AiMixer 导演台一采。

新建首次一采使用本节现行基准与本次确认配置；接续二采或恢复任务使用指定来源的一采副本、实际输入及缓存身份，不用新基准覆盖历史来源。业务批准、分段与输出编号由调用方提供，技术装配按本规范及AiMixer 导演台规则执行。

### 1.1 离线API检查与回归测试

[workflow_baselines.py](../../studio-comfyui/scripts/workflow_baselines.py)使用Python 3.9及以上标准库，只读取API，检查必要输出、连接引用、RTX必填参数、后处理链路及API内部AiMixer 导演台时间线和编辑状态。不读取画布，不做画布与API一致性或差异比较。

```sh
python3 -B /实际技能目录/scripts/workflow_baselines.py
python3 -B -m unittest discover -s /实际技能目录/scripts -p test_workflow_baselines.py -v
```

可选 `--directory /待检查目录`，扫描其中 API 及统一目录入口登记的直属分类。默认覆盖登记的正式 API，每份输出一行 JSON，成功输出 PASS 并退出 0。空目录也可返回成功，须确认目标有被覆盖。修改 API 或相关脚本时运行，保持断言启用。

后处理报告列出宽高、目标帧率和编码参数；低于交付建议只提示，不强制改写用户已确认目标。正式RIFE同时检查随包ZIP的必需文件、完整性和Python语法，不加载模型、不运行GPU。测试不连接远端，不证明实际生成或用户批准。

辅助预览一采为 `502.images_pre_refine → 503 CreateVideo → 504 SaveVideo`，二采为 `502.images → 505 CreateVideo → 506 SaveVideo`。两条合成支路读取 502 的 audio 和 fps，使用 8 位 sRGB，保存为 MP4/H.264。保存路径与前缀由调用业务确定，产物和阶段按[AiMixer 输出规则](ComfyUI-AiMixer导演台节点使用规范.md#731-导出方式与逐组文件)核对。

标准版画布完整接线为 192 → 331 → 53 → 128 → 507 → 342 → 344 → 345 → 343。默认旁路 128、507、342、344、345、343，实际执行链为 192 → 331 → 53。导出时，最后一个启用的 LoRA 节点接调度器 261、导演台 502 和二采模型支路 408 → 409 → 407.refine_model。LoRA、采样步数、生成尺寸与后处理按下节六步输入装配，其他生成参数和时间线保持不变。执行端须提供上述两个分块节点及对应参数接口，不用Refine的时间／空间分块开关替代模型分块。331选择完整注意力计算后端，一采与二采均沿用Kitchen，不串接Sage补丁或332稀疏注意力。407连接502.refine。SelfLift、FaceRefine或语义桥均未接入。两轮实际步数按外部SIGMAS及一采补零后的结果记录，不能把261显示的总步数登记成两轮实际总步数。

Refine先按一采比例及 `megapixels × 1024²` 计算目标宽高，再分别对齐32；仅填写width/height不会覆盖这一计算。一采1024×576时，MP=1.265625得到1536×864，MP=1.9921875得到1920×1088；竖屏576×1024使用相同MP分别得到864×1536和1088×1920。任务副本同时填写MP与目标宽高，执行依据是实际API中的MP；不要只改宽高控件。打戏二采受32对齐影响，比例略偏离16:9／9:16，后处理按短边方向裁掉8像素得到标准画幅；不拉伸二采原片，也不改写一采缓存。

参考图片尺寸由各组 `refImageSize="1536"` 控制，保持原比例；该设置与生成画布尺寸及 `ref_max_size / refMaxSize` 分开，不通过修改后者替代。正式基准各组与output回退值均保存1536；准备、新增、复制或导入任务分组时逐组落实，并同步根时间线及对应编辑工作区。插件“新增分组”会生成自己的尺寸值，不能宣称仅修改基准JSON就改变了插件默认行为；手动画布可复制已设1536的组，新增空组则须选择1536。

执行端的清理实现须在模型GC／卸载前清空动态显存预取队列，按阶段保留／卸载模型，并支持 `precise_segment_memory`。精确调度按模型权重大小与物理内存总量的比例选择策略，不是按当前内存占用率决定。节点缺少所需接口时报告兼容性问题，不静默删掉参数、覆盖插件或更改启动配置。

基准更新及版本选择用于后续获授权任务，不自动改写已有任务副本、请求或批准来源。已有一采的二采接续沿用原工作流版本和原一采尺寸，不自动改用当前基准或其他LoRA配置；需要切换时先核对模型链与缓存影响。参考图策略属于一采缓存输入；已有一采接续二采时按[制作变更时的缓存保护](ComfyUI-AiMixer导演台节点使用规范.md#75-缓存检查与清理接口)保留来源配置并核对缓存，不套用新基准导致重新一采。不同分辨率的一采即使使用同一种子也可能产生不同构图和动作，既有内容批准不自动转用于另一尺寸的新结果。

### 标准版配置选择与装配前询问

本节适用于使用 AiMixer 导演台标准版的业务和独立技术任务。Agent 逐项确定装配输入，脚本将确认值写入任务画布并导出 API。配置选择与本次生成授权分别确认。一采审阅、二采与后处理按各自的授权推进。

按字段依次采用本次用户明确选择、适用且经用户确认的项目默认值；只询问缺项或确需重新取舍的项。已有明确选择直接沿用，不为完成六步而重复询问；用户要求完整演示时可逐步展示，但演示答案不成为真实任务或项目默认。项目默认的保存位置及决定入口由调用业务维护，单批覆盖不自动回写项目默认。画布初始值、预选项、未回复、“继续做”或“参考图可以”均不替代尚缺的参数确认。

#### 一采六步询问

每次只弹出一个问题，等待回答后再展示下一步。不添加“推荐”字样，按表中顺序展示选项。弹窗不可用时使用相同文案在聊天中询问。

| 步骤与标题 | 问题 | 选项 |
| --- | --- | --- |
| 第1步：比例 | 请选择画面比例，或输入其他比例。 | 16:9 横屏；9:16 竖屏 |
| 第2步：分辨率 | 请选择分辨率，或输入宽×高。 | 16:9只展示1024×576（默认）；9:16只展示576×1024（默认）；不显示MP |
| 第3步：采样步数 | 请选择步数，或手动分配一采、二采步数。 | 一采：8步 + 二采：4步（文戏默认）；一采：8步 + 二采：6步（打戏默认） |
| 第4步：文戏／打戏 | 请选择文戏或打戏配置。 | 文戏；打戏 |
| 第5步：动作速度 | 逐字使用 [Studio H3 共用动作速度询问](../../studio-h3/SKILL.md#动作速度询问) | 只显示第4步戏型对应的选项，可直接手填 |
| 第6步：附加 LoRA | 请选择附加 LoRA，多选请输入编号，如“1,2”。 | 0. 不启用附加 LoRA；1. 去油（MysticXXX，默认权重0.35）；2. 口型修正（Natural Face & Speech V2，默认权重0.8） |

自定义比例使用宽:高；未定义默认分辨率的其他比例，第2步只请用户填写宽×高，不冒充已有默认值。自定义宽高须为正整数、32的整数倍且与所选比例一致；有冲突只返回对应一步说明具体问题，不静默裁切、拉伸或取整。第3步同时展示两条步数选项，用户也可填写“一采10步，二采6步”等明确分配；两个值均须为正整数，缺少任一值只补问缺项。问题与选项不提示归零，由内部装配处理。第4步的文戏／打戏选择不覆盖第3步已确认的任何步数；“文戏默认”“打戏默认”只是选项标签，不将所选步数组合反推成戏型。

附加LoRA当前使用单选弹窗加自由填写入口。Agent将“1和2”“1,2”“1，2”等明确多选表达转换为编号列表；0表示空列表，不能与1或2同时出现，未知编号或含混回答先澄清。附加LoRA与打戏组独立，未选的附加LoRA保持旁路。权重使用列出的默认值；用户另有明确权重要求时按已授权的任务画布调整并记录，不丢弃自定义权重，也不将其混入当前六步字段接口。

完成后汇总比例、分辨率、一采与二采步数、戏型、速度 LoRA 开关及启用时的数值，以及各附加LoRA的开关和权重。已有授权覆盖所示方案时直接准备。二采分辨率和后处理方式在各自阶段确定，不夹在一采选项中，也不将一采六步答案记为后续阶段执行授权。

查询、取回和原任务恢复不重新询问。二采从获批一采来源接续，保留一采输入及噪声表；确需改变关联参数时说明缓存和重做影响，按相应授权处理，不把重新一采当作直接二采。

#### 二采分辨率询问

正常二采接续先明确获批一采来源及本次执行范围；来源已明确则不重复询问。按来源实际width/height确定比例，不用当前基准或戏型猜比例。步数沿用一采时已确定的两段分配与实际噪声表；一采输入、LoRA及速度均保留，只询问二采分辨率。已有明确目标或适用且经用户确认的二采默认时直接沿用；原任务恢复沿用原目标，不重新弹窗。

**标题**：二采分辨率

**问题**：请选择二采分辨率，或输入宽×高。

| 来源比例 | 按顺序同时展示的选项 |
| --- | --- |
| 16:9横屏 | 1536×864（文戏默认）；1920×1088（打戏默认） |
| 9:16竖屏 | 864×1536（文戏默认）；1088×1920（打戏默认） |

只展示来源比例对应的两项，不标推荐；“文戏默认”“打戏默认”是尺寸选项标签，选择另一项不改变戏型、步数或任何LoRA。其他来源比例只请用户手填宽×高，不套用横竖屏选项。手填值须为正整数且两边均对齐32，并能按来源比例经Refine计算得到；不自动将1920×1080改成1920×1088，不因尺寸不匹配改写一采比例。32像素对齐造成的轻微比例偏差由后处理阶段按授权决定是否裁切。

收到选择后汇总来源与二采目标，按本次已有授权准备，不将尺寸选择本身当作执行授权。配置通过下方[二采装配接口](#二采装配接口)落实；后处理选项另行确定。

### 标准版配置参数

#### 六步答案与实际装配

一采任务清单提供`h3_first_pass`，由共用[装配脚本](../scripts/h3_workflow.py)的`configure_first_pass`处理。technical与Nora业务适配均在导出API前调用同一函数；新六步任务使用该入口，不再由Agent逐项平行编辑API。输入完整且明确后才调用，脚本不根据预选项补答案。

| 六步答案 | 实际写入 |
| --- | --- |
| 比例、宽、高 | 502的width/height、timeline根width/height、output的fixed模式/width/height/aspectRatio/longEdge/megapixels/multiple；MP仅用于内部计算，不显示为选项 |
| 一采步数N、二采步数M | 261.steps=N+M、289.step=N、502.steps=N；与scene_type无关；保留原SIGMAS前段到502、后段到407及一采自动补零 |
| 文戏／打戏 | 342／344／345整组旁路或启用，权重依次0.65／0.35／0.35；不改变已确认的一采、二采步数，不控制去油或口型修正开关 |
| 动作速度 | `speed` 为 `null` 时 343 旁路。有数值时 343 启用，`strength_model` 使用该值 |
| 去油 | 128开关独立，选中mode=0，未选mode=4；默认权重0.35 |
| 口型修正 | 507开关独立，选中mode=0，未选mode=4；默认权重0.8，位置在128之后、342之前 |

53 DMAD 沿用基准配置。画布保留完整串联接线，关闭 LoRA 时使用 mode=4 旁路。文戏默认 API 有 17 个节点，去油、口型修正和速度 LoRA 各增加 1 个，打戏组增加 3 个，全开 23 个。导出自动跳过旁路节点，API 只保存执行参数。

用户填写的一采N步、二采M步分别写入`steps`和`refine_steps`。总步数设置为N+M，在N处分割噪声表；一采末尾自动补零，实际为N步＋归零，补零不占用用户填写的N或M，也不计入261的总步数设置。二采后段使用M步。文戏8+4与打戏8+6仅是第3步的默认组合，用户选择交叉组合或手动分配时原样执行；脚本不再根据戏型推算二采步数。

Beta噪声表依赖总步数，因此N与M都在一采前明确，并与实际任务一起保存。步数选择不代表获准执行二采；二采仍接续获批来源，不能临时重算总步数或更改分割位置，否则一采噪声序列可能改变。需要调整时先明确对来源及缓存的影响。自定义分配同步三个节点，不仅修改502的显示步数；离线装配通过不等于已验证该组合的生成效果。

407仍连接502，confirm_first_pass=true。一采装配保留Refine关联预置：文戏MP=1.265625、打戏MP=1.9921875，按本次一采比例分别对齐32计算其width/height。它们是关联画布的预置值，二采正式执行前按来源与已确认二采方案核对。后处理从实际选定源片另行装配，本接口不选择、创建或提交后处理任务。

原配置编号1／2／3／4仅用于理解已有记录，分别对应文戏无去油／文戏去油／打戏无去油／打戏去油，不再作为新的询问列表或完整配置身份。新任务记录六步实际字段、确认来源及授权；口型修正、自定义尺寸、步数和速度不能只用旧编号代表。历史请求、项目已有默认及旧缓存不随此规则重写，适用且经用户确认的项目默认可逐字段复用。

#### 任务清单字段与调用

Python 3.9及以上。`h3_first_pass`是每个新一采任务的可选字段；使用六步装配时以下字段全部必填。`aspect_ratio`为正整数比例字符串，width/height单位为像素，steps是一采步数，refine_steps是二采步数，两者均不含一采自动补零；scene_type为dialogue或combat，speed按[共用动作速度询问](../../studio-h3/SKILL.md#动作速度询问)填写，loras为附加编号列表，未启用时为`[]`。默认权重由共用参数确定。本接口限标准版新一采；二采和后处理携带该字段会报错，未传字段的已有任务仍沿用已配置画布。新清单缺少refine_steps时明确报错，不从文戏／打戏或旧默认猜测；已准备、已登记任务的原请求和缓存保持原样，恢复不自动改写历史清单。

```json
"h3_first_pass": {
  "aspect_ratio": "16:9",
  "width": 1024,
  "height": 576,
  "steps": 8,
  "refine_steps": 4,
  "scene_type": "dialogue",
  "speed": null,
  "loras": [2]
}
```

将该字段加入现有任务清单的对应task，其余canvas、输出、适配和业务字段按[共用提交接口](../../studio-comfyui/references/固定脚本接口规范.md#统一分配与提交)提供。canvas与record_dir均以实际项目根目录为基准；新一采使用本次内容画布、独立执行目录及新缓存身份，不能把此字段塞入已获批来源的二采任务。准备命令：

```sh
python3 .agents/skills/studio-comfyui/scripts/comfyui_dispatch.py \
  --project /实际项目目录 --plan 执行附件/本次任务/任务清单.json --prepare-only
```

脚本在内存中装配画布副本，再由既有文档事务保存任务.workflow.json、任务.api.json及装配记录；原内容画布和共用基准不改写。technical任务的六步输入保存在既有任务清单及装配记录source中；Nora同时更新既有mapping.baseline.fixed_configuration。确认来源、用户指定值和执行授权由调用方写入既有记录，不新增配置台账。

本装配函数不联网、不上传、不入队。输入不合法会明确报错，返回对应问题修正；prepare-only返回prepared仅表示准备完成，真实提交仍按授权使用既有入口。检查新尺寸同时覆盖502、timeline和output；检查采样前后段、LoRA开关和实际导出链，不比较画布与配套基准API。

离线回归：`python3 -B -m unittest discover -s .agents/skills/studio-h3-aimixer/scripts -p test_h3_configuration.py -v`。退出0且报告OK表示六步输入装配、technical/Nora接入、自定义值及非法输入处理通过，不表示远端生成或审阅通过。

#### 二采装配接口

任务清单的二采task可提供`h3_second_pass`，只含实际目标像素宽、高：

```json
"h3_second_pass": {"width": 1920, "height": 1088}
```

`task_type`必须为`video-second-pass`，`canvas`使用获批一采的实际来源画布，`record_dir`使用本次二采执行目录；两项路径均以项目根目录为基准。新一采、后处理不能传此字段；同一任务不同时传h3_first_pass和h3_second_pass。缺省仍沿用已配置来源，原任务恢复不自动添加或替换字段。prepare-only命令、文档事务、授权与入队方式沿用上方[任务清单字段与调用](#任务清单字段与调用)。

共用configure_second_pass在technical与Nora适配导出API前执行，仅读取来源502的宽高，确认407采用upscale、跟随AiMixer 导演台及一采确认模式；其他模式需另行明确处理，不擅自切换。尺寸选择只写407.width、407.height和407.megapixels，并同步该节点控件值。总步数261、分割位置289、502全部输入及timeline、所有模型与LoRA、种子、缓存名、节点ID和连接均不改写，也不清理或创建缓存。

Refine按来源比例和`MP × 1024²`计算两边，再分别对齐32。标准两档MP分别为1.265625和1.9921875，横竖屏相同。自定义目标由宽高各自能对齐到目标的像素面积区间求交，优先使用width×height对应的MP；面积不在交集时选交集内部值。无交集就明确报错，不提交不同于用户选择的尺寸。width/height和MP必须同时装配，不能只改控件宽高。

technical任务在既有清单、装配记录source及实际API中保留目标；Nora另写已有mapping.baseline.refine_configuration，不覆盖fixed_configuration中的一采事实。脚本只装配本地任务副本，不联网、不上传、不提交生成、不证明远端缓存存在。实际二采前仍按[获批缓存复用](ComfyUI-AiMixer导演台节点使用规范.md#752-获批一采缓存的远端复用)核对来源缓存，不把缓存缺失后重新一采登记为二采。

离线测试沿用test_h3_configuration.py，覆盖四个预设尺寸、跨文戏／打戏选尺寸、自定义尺寸、非法输入、两个实际适配入口及来源参数保持不变。生成后的实测尺寸和缓存命中仍以实际执行报告为准。
