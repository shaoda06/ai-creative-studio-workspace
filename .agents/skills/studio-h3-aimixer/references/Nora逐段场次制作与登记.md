# Nora 的 AiMixer 逐段场次制作与登记

适用于沿原 AiMixer 执行接续，或用户本次明确指定 AiMixer 的短剧任务。已登记的原请求、逐段阶段、来源、文件身份和批准记录按实际事实接续。

## 阶段名称和记录格式

按[生成阶段标签](ComfyUI-AiMixer导演台节点使用规范.md#生成阶段标签)填实际阶段。Nora 逐段后处理使用该 P 已批准的二采原片。工具读取完整的 `EP编号-C编号-P编号-R编号-阶段` 身份，例如 `EP001-C001-P001-R001-一采`。工作稿执行与审阅分别使用 `### R001-一采` 和 `### 审阅-R001-一采-001` 形式，阶段替换为实际值。交付组合引用二采原片时，「阶段」填「二采」。


```text
06-阶段采用视频/
├── 01-一采/
│   └── C001-场次/
│       ├── EP001-C001-P001-R001-一采.mp4
│       └── 导演包/
│           └── EP001-C001-一采定稿.workflow.json
├── 02-二采/
│   └── C001-场次/
│       ├── EP001-C001-P001-R001-二采.mp4
│       └── 导演包/
│           └── EP001-C001-二采定稿.workflow.json
└── 03-后处理/
    └── C001-场次/
        └── EP001-C001-P001-R001-后处理.mp4

```

媒体统一按[项目资源与版本管理](../../studio-workspace-browser/references/项目资源与版本管理.md)保存在项目资源区。同一P段的各次生成和后处理关联同一逻辑视频资源，各产出为独立版本；R编号及来源一采／二采身份继续保留。上方目录仅保留场次画布位置，不再新存MP4。采用更新原工作稿的准确版本及批准依据，不移动视频；目录或文件存在不代替采用。

**场次画布**按[场次阶段定稿留档](Nora场次阶段定稿留档规范.md)保存。表中的 `导演包/` 是现有画布路径，旧文件继续按原路径读取。

| 阶段 | 场次画布目录 |
| --- | --- |
| 一采 | `06-阶段采用视频/01-一采/C编号-场次/导演包/` |
| 二采 | `06-阶段采用视频/02-二采/C编号-场次/导演包/` |

## AiMixer 场次制作

本节适用于接续已采用 AiMixer 的任务，或用户明确指定使用 AiMixer 的任务。阶段名称、进入条件与缓存检查按[AiMixer 阶段接续](ComfyUI-AiMixer导演台节点使用规范.md#752-获批一采缓存的远端复用)办理。

1. **当前场次分段一采与统一审核。** 按[AiMixer 场次提交与分批](ComfyUI-AiMixer导演台节点使用规范.md#场次提交与分批)组织本场一采。单段超限按[分镜的参考输入规划与分段可执行性](../../nora-drama-storyboard/references/视频分段规划规范.md#参考输入规划与分段可执行性)处理。任务参数、种子及依据按[Nora 执行记录](../../nora-drama-production/references/ComfyUI-H3视频执行规范.md#12-任务参数来源与准备提交)保存，多组共同证据按[多组任务的共同证据与状态](../../nora-drama-production/references/逐集目录与资产管理规范.md#多组任务的共同证据与状态)归属。全部批次收尾后统一送审；未获批段按用户意见及授权处理，不将局部批准当作整场批准。
2. **当前场次分段二采与统一审核。** 本场各分段一采获批后，按[获批一采缓存的远端复用规则](ComfyUI-AiMixer导演台节点使用规范.md#752-获批一采缓存的远端复用)核对来源及远端缓存，再依据各段获批一采快照，保持各一采批次的原始组序、P映射及缓存来源，按[AiMixer 参数与基准](参数与基准规范.md)执行二采。每批执行终态核对，全部批次收尾后按[视频结果人工审核](../../nora-drama-production/references/逐集目录与资产管理规范.md#视频结果人工审核)统一交用户审核。二采执行不必等待其他场次的一采完成。
3. **当前场次统一安排后处理与自动采用。** 当前场次所有二采批次完成终态文件核对，且全部分段的最终二采版本均经用户明确批准采用后，依据已批准二采的实际来源准备后处理。按分镜索引核对本场全部P对应的选定二采文件及既有生成／审阅记录中的批准依据；仍有待审、返修、未采用或文件版本未确定的分段时，不因其他段已采用而提前后处理。再按[H3规范第0节的工作流用途](../../nora-drama-production/references/ComfyUI-H3视频执行规范.md#0-制作策略与工作流配置)、[后处理交付规格](../../nora-drama-production/references/ComfyUI-H3视频执行规范.md#后处理交付规格)及[第2节的参数边界](../../nora-drama-production/references/ComfyUI-H3视频执行规范.md#2-参数边界)核对方案、选定交付目标与实际输入，区分推荐值及已确认的交付要求；准备齐备且已获本轮执行授权后，按实际需要安排各段后处理；已达目标规格的获批二采原片按[交付采用组合](../../nora-drama-handoff/references/逐集目录与资产管理规范.md#交付采用组合)登记直接沿用，不先合并场次或整集。保留二采原文件；结果到达后进入[后处理自动采用](../../nora-drama-production/references/逐集目录与资产管理规范.md#后处理自动采用)。统一安排以场次为范围，不要求把整场帧装入一个任务，也不授权自动重试。用户已授权常规整集后处理时，复用[已采用二采后处理清单装配入口](Nora逐段任务固定脚本接口规范.md#从已采用二采生成后处理清单)，从已完成批准报告和本轮组合自动准备逐段来源与画布，再交固定提交入口；不手工重复拆来源或逐段填字段。
4. **当前场次收尾与下一场。** 按[逐集目录规范第5节](../../nora-drama-handoff/references/逐集目录与资产管理规范.md#5-分段交付与本集完成)完成本场分段交付与记录，再进入下一个场次，循环执行上述步骤；仍在本集会话内完成，不按场次新建会话。制作流程不设置场次合成、整集合成或对应的成片审批环节。
5. **本集分段交付与收尾。** 本集所有场次完成后，按该规范第5节核对本集交付范围与完成条件，交付各场次实际采用的分段及其播放顺序，再执行[完集复盘与经验维护](../../nora-drama-handoff/references/逐集目录与资产管理规范.md#完集复盘与经验维护)，完成后说明下一集入口。
- 各处理阶段的结果判断与记录按[视频结果人工审核](../../nora-drama-production/references/逐集目录与资产管理规范.md#视频结果人工审核)执行。
- 采用收尾执行[采用记录与依据](../../nora-drama-production/references/逐集目录与资产管理规范.md#视频采用记录与批准依据)；按对应收尾报告及实际授权接续上述阶段。
- 视频返修按[同场反馈的返修范围与提交](../../nora-drama-production/references/视频阶段与返修执行规范.md#同场反馈的返修范围与提交)确定本轮范围，再按[制作返修的上游归属](../../nora-serial-drama/references/制作返修接续规范.md#制作返修的上游归属)维护对应内容；AiMixer 导演台配置、缓存与衔接执行[返修选择运行操作](ComfyUI-AiMixer导演台节点使用规范.md#711-返修选择运行操作)。
- 获授权处理用户指出的构图、运镜、光影或焦点问题时，按[视觉表达方法](../../nora-drama-storyboard/references/视觉表达方法规范.md#视觉表达方法)参考镜头语言方法，修订对应文本或参考图；不将指南用作agent主动审核视频、自动返修或重生成的授权。
- 问题来自人物、场景或道具资料卡时，先修改对应资料卡，再继续后续剧集。若促使剧情发生变化，同步检查后续分集大纲。

## 完整场次方案

```json
{
  "note": "本批修改C001和C002",
  "script": {"file": "09-剧集制作/EP003/02-剧集剧本/EP003-本集剧本.md", "version": "v05"},
  "scenes": {
    "C001": {
      "storyboard": {"file": "09-剧集制作/EP003/03-分镜脚本/EP003-C001-场次分镜.md", "version": "v04"},
      "segments": [
        {"id": "P001", "duration": 14, "stage": "一采", "run": "R004"},
        {"id": "P002", "duration": 11, "stage": "一采", "run": "R003"}
      ]
    },
    "C002": {
      "storyboard": {"file": "09-剧集制作/EP003/03-分镜脚本/EP003-C002-场次分镜.md", "version": "v06"},
      "segments": [
        {"id": "P001", "duration": 9, "stage": "一采", "run": "R004"}
      ]
    }
  }
}
```

示例只演示结构，实际`segments`须覆盖该场本轮全部P，数组顺序即播放顺序。同轮只有一个共同`script`。未改场次沿用上一已登记轮，首次接旧记录时取该场最新完整记录，不从候选排序补齐。

## 局部替换方案

```json
{
  "note": "只改C002的P003，其余沿用第8轮",
  "base_round": 8,
  "scenes": {
    "C002": {
      "storyboard": {"file": "09-剧集制作/EP003/03-分镜脚本/EP003-C002-场次分镜.md", "version": "v07"},
      "segment_changes": [
        {"id": "P003", "duration": 10, "stage": "一采", "run": "R004"}
      ]
    }
  }
}
```

顶层`base_round`是单集基轮。场次内`segments`与`segment_changes`互斥；未提供的剧本、未改场次及P沿用基轮。首次从旧场次记录局部接入，在该场条目填原`base_round`，不在顶层冒充旧记录已是单集轮次。

## 逐段兼容任务清单

AiMixer 兼容条目使用已准备好正文、素材、时间线及运行范围的画布。标准版需要一采时，按[共用六步询问](参数与基准规范.md#一采六步询问)确定输入，并在任务清单传入[共用h3_first_pass字段](参数与基准规范.md#任务清单字段与调用)，由共用装配函数同步尺寸、采样与LoRA，不平行编辑技术API。Nora只补充业务映射和输出位置；未传该字段的已配置任务保持原处理方式。二采保留获批来源画布与实际参数，不传新一采配置；需要设置二采尺寸时使用[共用h3_second_pass字段](参数与基准规范.md#二采装配接口)，仅调整Refine目标。AiMixer 条目示例：

```json
{"task_type":"video-first-pass","title":"EP001-C001 · 一采","authorization":"用户明确授权本次一采",
 "canvas":"09-剧集制作/EP001/其他资料/执行附件/EP001-C001-P001-R001-一采/任务.workflow.json",
 "record_dir":"09-剧集制作/EP001/其他资料/执行附件/EP001-C001-P001-R001-一采",
 "output_nodes":["403","504","506"],"report_node":"403","output_root":"E:/实际ComfyUI/output",
 "h3_first_pass":{"aspect_ratio":"16:9","width":1024,"height":576,"steps":8,"refine_steps":4,"scene_type":"dialogue","speed":3.0,"loras":[]},
 "references":[{"file":"03-人物资料/CH001-男主/参考图/当前角色.png","placeholder":"planned/CH001.png"}]}
```
