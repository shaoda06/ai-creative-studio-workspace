# 剪映草稿与打包

Agent提供实际文件、播放顺序、包内名称和输出位置；脚本保留原媒体，生成一条不裁剪、速度1、音量1的原声视频轨道。可将其他版本仅放入素材箱。业务阶段决定哪些文件进入交付、哪些版本进入时间线。

使用现有Python环境中的`pyJianYingDraft==0.3.0`和`pymediainfo==7.0.1`；本工作区可复用浏览服务`.venv`，无需运行后台服务。调用[scripts/jianying_export.py](scripts/jianying_export.py)：

```json
{"name":"草稿名称","media":[{"file":"/绝对路径/视频.mp4","member":"视频.mp4","timeline":true}]}
```

```bash
python jianying_export.py manifest.json /输出路径/草稿.zip --format zip
python jianying_export.py manifest.json /输出路径/草稿.jypack --format jypack
```

输出位置须已存在，输出文件须不存在。文件按清单顺序排列；`timeline:false`只入素材箱。ZIP保存媒体原字节及三份草稿JSON，原生jypack只转换容器签名。包内路径必须相对且不越界。失败返回真实异常并清理本次CLI创建的残包；不覆盖已有输出。调用方直接使用`export_archive`时负责临时文件生命周期。

后台可调用同一工具并通过响应流提供下载；服务负责请求鉴权、文件访问边界、临时文件清理。工具不读取项目、EP编号、采用记录或网页状态，不自动添加字幕、音乐、转场、变速或最终成片。草稿结构检查和真实剪映导入验收分开报告，不将生成文件视为已在客户端导入。

登记项目空间可使用[共用浏览接入](../nora-workspace-browser/references/业务接入规范.md#项目媒体清单与剪映下载)保存一次明确媒体清单，由用户点击网页下载时调用本工具；不预生成或为每次点击新建清单。业务采用归调用方，Agent仅在用户明确要求时调用脚本生成并提供包。

## 客户端打开与核验

macOS剪映11.7.0已实测以下入口；其他版本和Windows仍按实际客户端核对，不沿用本机结论。

- **jypack**：先保存并返回剪映首页，再由系统“打开方式”交给已安装的剪映。获准系统辅助操作时可使用`open -a "/实际安装的剪映.app" "/绝对路径/草稿.jypack"`。等待客户端导入任务完成，再打开新增草稿；不要把包拖入编辑器的媒体导入框当作已验证入口。
- **ZIP**：先从客户端确认实际草稿根目录，将包内容解压到其中一个不存在的新草稿子目录，避免多套一层文件夹。仅在该新副本的`draft_meta_info.json`设置`draft_root_path`为实际根目录、`draft_fold_path`为完整子目录、`draft_name`为本次草稿名；保留媒体和内容JSON。返回首页刷新后从列表打开，不手改全局草稿索引。本机“文件→找回草稿”未能识别外部测试目录，不重复以该路径判断包损坏。

进入编辑器后核对实际素材、时间线顺序、总长和播放；测试副本做一项可见修改，保存、关闭并重开核对保留。声音须实际试听，电平与文件音轨只能算技术核对。出现“链接媒体”时先定位明确缺失文件，选择移走的同一原片，分别核对素材箱、时间线画面、已有编辑及保存重开。素材箱恢复不能代替时间线恢复。取消链接后仅放回文件未必恢复时间线；另建草稿不等于保留原有编辑，不能静默覆盖旧草稿。

本地视频素材对象的`materials.videos[].material_id`保持空字符串，由客户端建立素材库关联；对象`id`继续供`tracks[].segments[].material_id`引用，二者不能一并清空，也不把对象`id`复制到素材库标识字段。ZIP与jypack共用这份装配规则。此修正适用于新导出的草稿；已由客户端保存的旧草稿不自动改写。
