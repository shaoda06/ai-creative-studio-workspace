# Studio 项目归档

归档单位是整个项目：Nora 的整部短剧或其他具名项目、Iris 的整个订单、Chloe 的整个账号项目。用户要求实际归档或恢复时执行；讨论、建立机制和只读检查不改变项目或对话状态。归档不搬动、压缩或删除资料，也不改写制作进度、完成、交付和发布事实。

## 项目与原因

先读所属工作区 README、项目 README 及其指定的进度／状态文件，明确真实项目根目录和本次动作。Nora、Iris 位于各资料区的 `projects/项目名/`；Chloe 位于资料区的 `项目名/`，其中 `projects/V编号-名称/` 是单条视频，不是本技能归档对象。

原因采用用户的明确意思；缺少且无法确定时，用选项询问。常用分类：Nora 为已完成、暂缓制作、终止制作；Iris 为已完成、暂缓合作、停止合作；Chloe 为暂停运营、停止运营。用户明确其他原因时使用其分类，不强行改成已完成。不以闲置时间、任务成功或一次交付自动触发归档。

## 标记、索引与浏览页

使用[项目归档标记模板](templates/项目归档标记.md)。项目根 README 是项目管理状态的唯一来源：Nora、Iris 放在“历史与特殊事项”中；Chloe 放在“项目接续与相关资料”中。保留原有章节与表格，不另建归档文件或增加制作阶段。

- `项目管理状态`只取进行中、已归档，与原制作状态独立。旧项目没有这些字段时，页面按进行中显示；不为启用机制批量补写标记。
- `归档原因`保存本次或最近一次实际原因。`最近归档时间`、`最近恢复时间`使用带时区偏移的 ISO 时间；尚未发生填无。恢复时保留最近归档原因和时间，只改管理状态并填写恢复时间。
- 字段在 README 中只保留一组。操作经过用日期开头的简短普通条目追加在同一位置，保留过去的原因与结果，不重复上述字段名。
- 原有项目进度／项目状态文件注明“项目管理状态见 README 的项目归档标记”，并记录本次实际归档或恢复事项；保留原制作进度、待办和采用事实。Chloe 用项目 README 原会话入口及接续段落，不另建项目状态文件。
- 更新 README 后，按[共用项目总索引](../studio-workspace-browser/references/项目总索引规范.md#共用脚本)同步所属工作区索引，完成两表间移动、分类内编号和原因更新；本技能不复制表格格式或登记实现。同步完成后再核对浏览页并处理对话。
- 公共浏览页从 README 读取标记，每个工作区默认显示进行中项目；已归档页按原因筛选，原项目入口仍能打开。核对 `/api/workspaces` 中该项目的 `archive` 和页面分类，Nora 同时可用 `/api/projects`。接入细节见[业务接入](../studio-workspace-browser/references/业务接入规范.md#项目归档接入)。

已有 `.archived` 是历史迁移后的只读入口标记，不用它执行本机制，不移除它来恢复旧项目。仅改变归档标记不会取消后台生成、定时任务或停止账号服务；存在仍在执行的相关事项时如实保留并说明，需要停止时按实际授权另行处理。

## Codex 对话归档

归档项目包含处理已核实属于该项目的 Codex 对话，不因对话共用总工作目录就把整个工作区的对话归档。使用当前可用的 Codex 对话工具，不直接编辑 Codex 数据库或本地对话文件。工具属于[宿主平台能力](../studio-entry/维护规范.md#能力组成与分发范围)，按名称发现并读取本次实际参数，不在仓库固定工具安装路径或平台版本。

1. 从项目现有会话登记、进度与接续记录取得真实对话 ID／链接。用 `list_threads` 查找遗漏，按工具分页遍历必要范围；对缺少归属依据或名称相近的候选，使用 `read_thread` 核对内容与项目。标题、路径和当前任务状态共同判断，不能只凭标题或总工作目录。跨项目维护对话保持原状；仍无法确认的单列给用户，不猜测。
2. 在项目现有会话登记／接续位置记录本次要处理的真实 ID、所属 host（工具返回时）、项目归属依据及当前结果。不另建独立台账；已有会话表保留原表头，可在其后追加简短条目。不发送跨会话消息，不删除对话。
3. 更新项目标记、索引和实际执行记录后，对已明确归属、已结束运行的对话调用 `set_thread_archived` 归档。已归档的不用重复处理；正在运行或有未决审批／工具询问的对话保留待处理并说明（普通已结束、等待下一轮聊天的对话可以归档），不把归档当作中断任务的方法。
4. 根据工具响应核对结果；需要补查时用 `list_archived_threads` 的分页结果按真实 ID 检查。逐项记录已归档、失败或待处理；部分失败只接续失败项，不撤销已经完成的项目标记，也不宣称全部完成。工具不可用时完成项目标记并明确留下对话待办。
5. 如果当前对话本身只属于该项目，将其放在最后；先完成其他项目记录与结果说明，再调用归档工具。仅用于建立机制或跨项目维护的当前对话不随项目归档。

恢复项目时更新原标记与索引；按用户本次需要用 `set_thread_archived` 恢复选定的对话，不默认恢复全部历史对话，也不自动恢复生成或发布任务。

完成时说明项目状态、原因、浏览入口核对结果和对话实际处理数量；仍在运行、归属未明或操作失败的分别列明。未实际执行对话工具时，只能称流程已准备，不能称对话已归档。
