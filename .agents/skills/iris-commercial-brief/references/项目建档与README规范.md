# Iris项目建档与README规范

## 项目结构

本规范维护Iris商业视频项目的建档结构和README，一级业务只统筹阶段接续与项目状态。新订单在Iris资料区`projects/C编号-名称/`独立保存，不使用短剧EP结构，编号沿该资料区已有记录分配。

根目录保存 `README.md` 与 `项目状态.md`，建档时建齐下表十一个一级目录并初始化资源索引。阶段子目录及文件有实际内容时建立。阶段完成时保留对应主文件，空目录只提供存放位置。已完单项目按实际资料和批准记录追溯，旧订单整理按当次授权处理。

| 固定一级目录 | 阶段主文件或用途 |
| --- | --- |
| `01-客户资料/` | [需求与来源记录](../templates/需求与来源记录.md)及收到的客户原稿，媒体原件引用资源版本。 |
| `02-参考分析/` | [制作简报](../templates/制作简报.md)。复杂参考可另写分析稿，由简报引用。 |
| `03-创意脚本/` | [制作脚本](../../iris-commercial-creative/templates/制作脚本.md)，作为分镜所用的现行正文。 |
| `04-分镜声音/` | [分镜与声音制作稿](../../iris-commercial-storyboard/templates/分镜与声音制作稿.md)。 |
| `05-资产/` | [资产清单与制作说明](../../iris-commercial-assets/templates/资产清单与制作说明.md)。 |
| `06-视频生产/` | 每批一份[生产任务记录](../../iris-commercial-production/templates/生产任务.md)，引用分镜、提示词、执行记录、候选及审阅决定。 |
| `07-返修交接/` | 发生返修或交接时维护[返修与剪辑交接记录](../../iris-commercial-handoff/templates/返修与剪辑交接.md)。 |
| `08-完单复盘/` | 最终交付后维护[项目复盘](../../iris-commercial-retrospective/templates/项目复盘.md)。 |
| `资源/` | 资源索引、媒体原件及不可覆盖的版本文件。 |
| `归档/` | 封存项目树、迁移前入口及有留存依据的整批快照。 |
| `99-综合资料/` | 本项目无阶段固定位置的跨阶段资料、实验资料和待分类资料。 |

阶段的对外交付文件按实际需要准备，包括送审 PDF、展示用导演表、样片说明、剪映包和结项摘要。候选审阅随 `06` 的生产批次记录，面向交付的返修及采用组合归 `07`。媒体按准确的资源版本引用。

项目README提供说明、专用约定和导航；项目状态.md唯一保存当前阶段、现行版本、授权、待办和会话职责。需求原件、技术事实、客户反馈及采用保留原位置，不复制进README。

## 甲方来稿

在 `01-客户资料/` 按收到的文件或原文留档，在需求与来源记录中注明来源、版本及实际适用范围。新收到的版本另存。由[创意与音画阶段](../../iris-commercial-creative/references/流程规则.md#甲方来稿与制作脚本)在 `03-创意脚本/` 整理制作脚本，标明原稿版本及段落对应，项目状态指向实际采用的版本。

## 过程资料与综合资料

- 各阶段同一事项的讨论、草稿、审阅反馈和决定集中放 `其他资料/工作稿/`。被替换且仍需追溯的正式文稿放本阶段的 `其他资料/历史版本/`。有内容时才建分类，镜头、资产和生产段共用阶段分类。
- 工作流、请求、回执、日志和技术核验沿用各阶段既有 `执行记录/`，例如 `06-视频生产/执行记录/`。业务主文件引用实际凭据，同一份技术记录保留一个正式位置。
- `99-综合资料/` 按需建 `跨阶段资料/`、`实验资料/`、`待分类资料/`。有固定位置的资料由其他阶段链接引用。明确归属后按授权归位并更新链接。Iris 多项目共用资料归 Iris 资料区的 `综合资料/`。

## README固定写法

使用[模板](../templates/项目README模板.md)，一级标题写实际C编号与名称；固定六个二级标题依次为：项目说明、项目专用约定、目录与资料入口、进度与版本入口、接续要求、历史与特殊事项。

- **项目说明**用一两句话先写要制作的内容和用途，再按需注明暂名或测试范围。签单、客户批准及交付结论按已有依据填写。
- **项目专用约定**写本单已确认且接续时仍适用的要求。共用规范用链接引用。单轮生成、试听或交接授权记在项目状态及对应阶段。
- **目录与资料入口**按阶段顺序列实际可用的主文件。必要的客户原件、资源入口和归档按实际补充，每个入口一行。单张素材的采用记录归资产清单，每批候选、参数、回执和审阅过程归对应生产任务及执行记录。README 链接能查到这些明细的主文件。
- **进度与版本入口**集中链接 `项目状态.md`。当前阶段、有效版本、采用状态、授权、待办和负责人都从项目状态接续。
- **接续要求**先读 Iris 工作区说明、本项目 README 和项目状态，再按当前阶段进入对应技能，核对本次授权。已完单项目按复盘和归档查阅。
- **历史与特殊事项**简述实际归档、已停用方案或必要限制，并链接已有记录。没有则注明暂无。

现有文档可保留原章节标题作为三级小节，维持已引用锚点；相同信息合并为一处。当前采用、客户决定和历史快照不因入口整理改变。

### 保存前检查

1. 对照模板核对六节标题和顺序。读完项目说明，应能说清这个项目要做什么。
2. 对照项目状态和阶段主文件核对入口是否指向实际版本，检查每个相对链接能否在本地解析。项目目录内的资料入口同时在浏览页核对。网页入口使用项目内的相对路径，桌面文件路径留在执行或交接记录中。
3. 通读六节，项目用途、同一约定和项目状态入口各写一处。若整理前的 README 有独有的决定或执行事实，先核对依据，再归入项目状态或对应阶段记录。去掉 README 中已有出处的过程明细。

## 建档职责

新订单由Agent根据已知需求填写模板；编号、名称、范围及项目专用约定由Agent依实际资料确定，不能由脚本推定。按目录规范写入README并建立项目状态入口，后续阶段维护自己资料并更新唯一项目状态。项目已有README时按授权合并，不能用空模板覆盖。

项目建档时以实际订单根目录调用`studio-workspace-browser/scripts/project_resources.py --project <实际项目> init`建立资源索引。项目README连接[项目资源与版本管理](../../studio-workspace-browser/references/项目资源与版本管理.md)并说明原业务目录保留索引、工作稿与执行记录，媒体版本归`资源/`；已有项目先按明确授权迁移，不以建档命令直接启用未迁移旧流程。
