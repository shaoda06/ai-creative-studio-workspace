# Iris项目建档与README规范

## 项目结构

本规范维护Iris商业视频项目的建档结构和README，一级业务只统筹项目与作品的阶段接续及状态归属。新订单在Iris资料区`projects/C编号-名称/`独立保存，不使用短剧EP结构，编号沿该资料区已有记录分配。

项目根目录保存 `README.md` 与 `项目状态.md`，固定共享目录为 `01-客户资料/`、`作品/`、`08-完单复盘/`、`资源/`、`归档/`、`99-综合资料/`。每件作品放在 `作品/F编号-名称/`，从 F001 编号，编号在项目内唯一且不因改名改变。项目可以有多件作品；同片横版、竖版、长版和短版都作为该作品的交付版本。新增独立内容目标的片子才新增作品，不按生产轮次建作品。

作品根目录保存 `README.md` 与 `作品状态.md`，建齐下表的作品阶段目录。阶段子目录及文件有实际内容时建立。阶段完成时保留对应主文件。已完单项目按实际资料和批准记录追溯，旧订单整理按当次授权处理。

| 作品内固定目录 | 阶段主文件或用途 |
| --- | --- |
| `01-客户资料/` | 本作品的[需求与来源记录](../templates/需求与来源记录.md)，引用项目共享原稿及资源版本。 |
| `02-参考分析/` | [制作简报](../templates/制作简报.md)。复杂参考可另写分析稿，由简报引用。 |
| `03-创意脚本/` | [制作脚本](../../iris-commercial-creative/templates/制作脚本.md)，作为分镜所用的现行正文。 |
| `04-分镜声音/` | [分镜与声音制作稿](../../iris-commercial-storyboard/templates/分镜与声音制作稿.md)。 |
| `05-资产/` | [资产清单与制作说明](../../iris-commercial-assets/templates/资产清单与制作说明.md)。 |
| `06-视频生产/` | 每批一份[生产任务记录](../../iris-commercial-production/templates/生产任务.md)，引用分镜、提示词、执行记录、候选及审阅决定。 |
| `07-返修交接/` | 发生返修或交接时维护[返修与剪辑交接记录](../../iris-commercial-handoff/templates/返修与剪辑交接.md)。 |
| `99-综合资料/` | 只属于本作品、无阶段固定位置的资料。 |

项目 `01-客户资料/` 保存共享客户原稿，`08-完单复盘/` 保存用户明确最终交付后的[项目复盘](../../iris-commercial-retrospective/templates/项目复盘.md)，`资源/` 保存资源索引和全部媒体版本，`归档/` 保存封存项目树及整批快照。项目 `99-综合资料/` 保存项目内跨作品、无固定位置的资料。作品不另建媒体资源库或全单复盘。SH、P、R 和业务资产 A 编号各自在作品内使用，记录和工具输入必须同时明确 C 项目与 F 作品；资源编号仍由项目资源索引统一管理。

阶段的对外交付文件按实际需要准备，包括送审 PDF、展示用导演表、样片说明、剪映包和结项摘要。候选审阅随 `06` 的生产批次记录，面向交付的返修及采用组合归 `07`。媒体按准确的资源版本引用。

项目 README 提供整体说明、共用约定和作品导航；项目状态只保存跨作品事项、作品入口及整单结项。作品 README 提供本片说明和阶段入口；作品状态唯一保存本片当前阶段、现行版本、授权、待办、交付版本和会话职责。共用决定只在项目状态记录，作品状态引用其适用范围。需求原件、技术事实、客户反馈及采用保留原位置，不复制进 README。

启用社媒运营时，项目与作品的运营资料按[通用运营目录与接续](../../studio-social-operations/references/运营与制作接续规范.md)按需创建，并由原README、项目或作品状态引用；不因运营新增第二个制作项目或媒体库。

## 甲方来稿

在项目 `01-客户资料/` 按收到的文件或原文留档，媒体原件入项目资源库。在适用作品的需求与来源记录中注明来源、版本及范围；同一原件可供多件作品引用。新收到的版本另存。由[创意与音画阶段](../../iris-commercial-creative/references/流程规则.md#甲方来稿与制作脚本)在作品 `03-创意脚本/` 整理制作脚本，标明原稿版本及段落对应，作品状态指向实际采用的版本。

## 过程资料与综合资料

- 各阶段同一事项的讨论、草稿、审阅反馈和决定集中放 `其他资料/工作稿/`。被替换且仍需追溯的正式文稿放本阶段的 `其他资料/历史版本/`。有内容时才建分类，镜头、资产和生产段共用阶段分类。
- 新任务的工作流、请求、回执、日志和技术核验放所属作品阶段的 `执行记录/`。历史执行目录沿用原位置，不改写原请求、任务 ID 或缓存。确需从作品接续旧生产记录时，在作品 `06-视频生产/历史执行入口.json` 的 `records` 数组登记项目根相对的执行记录目录，在 `archives` 数组登记旧 Nora 制作归档目录；只登记实际属于该作品的来源，不扫描其他作品。业务主文件引用原凭据。
- `99-综合资料/` 按需建 `跨阶段资料/`、`实验资料/`、`待分类资料/`。有固定位置的资料由其他阶段链接引用。明确归属后按授权归位并更新链接。Iris 多项目共用资料归 Iris 资料区的 `综合资料/`。

## README固定写法

使用[项目 README 模板](../templates/项目README模板.md)，一级标题写实际 C 编号与名称。项目说明、项目专用约定、资料与接续依次排列，有追溯内容时加历史与特殊事项。已建档项目按授权整理，C001–C004 已采用此分工。

- **项目说明**用一两句话写项目内容、用途及长期范围。当前进度和本轮涉及的作品记在项目状态。
- **项目专用约定**是本单现行制作规格的正文来源。项目状态记录跨作品决定或授权的日期、范围、条件和依据，涉及规格时链接本节。单轮生成、试听或交接授权记在所属作品状态及对应阶段。
- **资料与接续**集中链接项目状态、客户原件、资源索引及本地接续说明。作品和各阶段从对应的状态与入口查阅。
- **历史与特殊事项**只记需要追溯的旧名、实际归档、已停用方案和必要例外，并链接已有记录。无内容时省略。

现有文档可保留原章节标题作为三级小节，维持已引用锚点；相同信息合并为一处。当前采用、客户决定和历史快照不因入口整理改变。

## 项目状态固定写法

使用[项目状态模板](../../iris-commercial-video/templates/项目状态.md)。先以「当前状态」写实际进度、本轮涉及的作品及下一步，再列「作品入口」。有实际内容时补「项目共用决定与授权」「项目待办」及「整单交付与复盘」。项目待办写具体事项与已知下一步，负责人明确时再填。跨作品决定引用现行规格和依据，单片授权与当前版本写入作品状态。

### 保存前检查

1. 对照适用模板核对章节和顺序。项目说明说清要做什么，项目状态说清目前做到哪里。
2. 对照项目状态和阶段主文件核对入口是否指向实际版本，检查每个相对链接能否在本地解析。项目目录内的资料入口同时在浏览页核对。网页入口使用项目内的相对路径，桌面文件路径留在执行或交接记录中。
3. 合读项目 README、项目状态与本次涉及的作品状态。每条制作规格、决定、授权或历史事实只在负责的文件里写正文，其他位置用引用。核对决定、授权和历史各自的日期、范围与出处。

## 建档职责

新订单由 Agent 根据已知需求填写模板；项目和作品的编号、名称、范围由 Agent 依实际资料确定，不能由脚本推定。项目使用[项目状态模板](../../iris-commercial-video/templates/项目状态.md)；每件作品使用[作品 README 模板](../templates/作品README模板.md)和[作品状态模板](../../iris-commercial-video/templates/作品状态.md)。各阶段维护本片资料并更新作品状态，跨作品事项更新项目状态。已有内容按授权合并，不用空模板覆盖。

项目建档时以实际订单根目录调用`studio-workspace-browser/scripts/project_resources.py --project <实际项目> init`建立资源索引。项目README连接[项目资源与版本管理](../../studio-workspace-browser/references/项目资源与版本管理.md)并说明原业务目录保留索引、工作稿与执行记录，媒体版本归`资源/`；已有项目先按明确授权迁移，不以建档命令直接启用未迁移旧流程。

## 作品 README 固定写法

一级标题为实际 F 编号与片名。固定六个二级标题依次为：作品说明、作品专用约定、阶段资料入口、进度与版本入口、接续要求、历史与特殊事项。说明写本片目标及交付版本关系；专用约定引用项目共用约定，只补本片差异；阶段入口按 01 至 07 顺序链接已有主文件；状态入口只链接本片作品状态。接续要求明确所属项目与作品，并引用项目共享资源。历史只链接原资料，不复制执行流水。保存前同样检查六节、真实版本、链接及信息重复。

## 作品状态固定写法

使用[作品状态模板](../../iris-commercial-video/templates/作品状态.md)。作品沿用项目 README 中适用于本片的项目或系列约定，在作品状态开头链接到规格正文。涉及共用决定的确认范围或依据时，引用项目状态的对应记录。

「当前有效决定与授权」记录本片的实际授权、对应轮次和版本、批准范围、单片例外及审阅或采用结果。若本片有规格例外，写清获准的差异及适用轮次或版本。某轮实际使用的参数及当时的规格留在对应生产任务和执行记录中，作品状态按需链接。

## 网页读取与相对路径

Iris 所有项目共用概况版式。浏览资料使用顶部对应栏目，作品从「作品入口」查看。

「资料与接续」「历史与特殊事项」及旧模板的「目录与资料入口」「进度与版本入口」「接续要求」留在本地 README，网页概况及章节导航默认省略。按模板编排后，网页依次读取「项目说明」「项目专用约定」「当前状态」「作品入口」，再按有记录的事项显示项目级决定、待办和交付结论。

项目概况、全部资料和项目资源读取整个项目；制作栏目统一跟随所选作品。交付成果按作品显示，整单复盘从项目层读取。阶段主文件的现行版本由作品状态中的 `对象 | 当前版本/文件` 表指定，文件值统一写项目根相对路径，例如 `作品/F001-示例/03-创意脚本/制作脚本-v01.md`。交付表与剪映清单同样以项目根为路径边界；正文中的普通 Markdown 链接按该文件所在目录计算相对路径。脚本接收明确项目、作品和输出位置；共用工具的项目参数仍传 C 项目根目录，作品阶段路径带 `作品/F编号-名称/` 前缀，媒体始终写回项目资源库。

视频生产目录同时按[整片轮次规范](../../iris-commercial-production/references/整片制作轮次与网页接入.md)维护一份明确审阅组合索引。未产生轮次时不预填候选。每批生产记录及原执行凭据继续保留，作品目录不因共用网页调整。
