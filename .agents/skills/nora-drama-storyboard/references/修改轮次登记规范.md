# 修改轮次登记规范

## 当前业务与调用时机

一次集中修改形成单集完整播放组合时使用；共同轮次、完整/局部沿用、来源冻结及旧记录边界见[版本组合](../../nora-serial-drama/references/场次版本组合规范.md#修改轮次)。Agent先确定获授权方案及准确剧本/分镜版本，填写[计划模板](../templates/场次修改轮次模板.md)；脚本只登记明确组合、保存源文档副本及编号，不创作镜头、不提交生成或决定采用。

Python 3.9+，仅标准库，不依赖浏览后台。在工作区根运行，project和plan均使用实际绝对路径：

```sh
python3 .agents/skills/nora-drama-storyboard/scripts/scene_rounds.py --project '/项目根目录' --episode EP001 --plan '/完整组合计划.json'
```

- `--project`：实际项目根目录；不指向工作区根或其他项目。
- `--episode`：实际EP编号，或既有固定对象片头/片尾。
- `--plan`：UTF-8 JSON，script与scenes按模板填写；局部修改使用base_round与segment_changes，完整重排给完整segments。
- `--scene`：旧单场兼容参数；日常集中修改用scenes一次登记，不逐场创建多个轮次。

经明确授权，将已完成的 Songssx 联调结果接入原项目供查看时，`--plan` 的顶层填 `"review_only": true`，提交该版完整剧本、分镜和所有场次的原执行附件关联。保留原执行凭据，项目内的展示关联明确来源。此轮可查看和下载，排除在新制作的工作流判断、基轮和执行准备之外。

独立提交整场后处理供审阅时，在对应场次的 `review_outputs` 按[共用整场后处理审阅](../../studio-workspace-browser/references/业务接入规范.md#整场后处理审阅)登记执行目录及源片。

参数路径由命令行从当前目录解析，计划内部文档位置从project解析。新组合写入该制作对象既有工作稿目录，源副本进入所属历史版本；原文、旧组合与媒体不覆盖。并发登记由既有独占锁处理；失败先核对是否已有登记结果，解决具体冲突后恢复，不猜轮号或重复追加。

成功标准输出JSON含file、number、scenes与segments；number为共同轮次，scenes为场次列表，segments为分段数量；非零退出或异常表示未完成，不掩盖错误。登记不提交后台任务，不代表输入已就绪、镜头已批准或视频采用。后续视频准备继续使用现行入口及原字段，实际执行/H3规则未在本规范重写。
