# 固定脚本接口规范

### 一次装配与批量入队

默认入口只传项目和一份项目内任务清单，提交范围按[任务组提交范围](../../studio-comfyui/references/ComfyUI-服务配置与任务提交规范.md#任务组提交范围)确定；不要循环调用旧式单项参数或逐场生成单成员清单来提交同一组；一份清单登记为一个固定成员任务组，相同授权且可同时提交的图片、超分或视频可混合放在`tasks`数组，支持跨场次及单成员。可选顶层`group_title`，不填使用清单文件名。先检查全组，再原子登记；返回`group_id`及子任务ID。重复提交原清单复用原ID，不能追加／替换成员。执行、排队和修复仍按子任务进行。同步本地规格处理与后台任务分开提交。提示词先按对应技能及固定模板完成内容核对，以下示例正文是字段示意，不可作为最终模型正文。

```sh
python /实际技能目录/scripts/comfyui_dispatch.py \
  --project /实际项目目录 \
  --plan 03-人物资料/其他资料/执行附件/首集角色提交/任务清单.json
```

执行职责读取[图片执行分工](../../nora-drama-images/references/ComfyUI-服务配置与任务提交规范.md#图片执行分工)。固定检查由共用准备入口执行一次，Agent不重读种子表或对工作流节点；同批重复输入共用元数据读取，记录中的模型、采样、缓存及预处理字段从实际API生成。

文生图和图生图只复制执行API，不读取、改写或复制原画布；视频沿用现行装配入口。所有类型取消画布与API一致性比较。可配置输出由工具按[远端输出目录](ComfyUI-服务配置与任务提交规范.md#远端输出目录与命名)填写；本地执行附件和上传input目录不跟随改变。

图片条目示例：

```json
{"group_title":"首集人物参考图", "tasks":[{
  "task_type":"image", "object":"CH001", "title":"CH001 · 首集角色六视图",
  "kind":"人物", "image_type":"角色多视角参考图", "state":"大学", "costume":"首集",
  "draft":"03-人物资料/其他资料/工作稿/CH001-参考图-工作稿.md",
  "formal":"03-人物资料/CH001-男主/参考图/CH001-大学-首集-角色多视角参考图.png",
  "authorization":"当前用户要求按已批准本体和服装生成首集角色六视图",
  "basis":"已确认人物资料、当前状态与服装批准记录", "description":"按已核对的完整提示词制作六视图",
  "references":[
    {"file":"03-人物资料/CH001-男主/参考图/已采用本体.png","purpose":"人物身份与体型","approval":"03-人物资料/其他资料/工作稿/CH001-参考图-工作稿.md#审阅-生成记录-003-001"},
    {"file":"03-人物资料/CH001-男主/参考图/已采用服装.png","purpose":"首集衣装","approval":"03-人物资料/其他资料/工作稿/CH001-参考图-工作稿.md#审阅-生成记录-004-001"}
  ],
  "prompt":{"rewritten_prompt":"这里填已完成内容核对的完整中文正文","wh_ratio":"1:1","ratio_follow":""}
}]}
```

- `kind`为人物／场景／道具／剧集素材／封面，沿用各自既有工作稿模板。封面不设固定提示词句式，Qwen备用调用仍遵守接口字段格式。有对应正式图片的新图片条目须填写`formal`，候选名和版本按该正式文件名分配，不从`image_type`拼接；同一正式图片独立累计v版本。画风样例保留固定对象名和样例身份，不虚构正式资产；手绘导演分镜表按正式场次及页码独立维护图表版本。工具自动建工作稿或追加下一生成编号、候选版本及同前缀执行附件；不另建人工调度台账。`fields`可提供该模板中特有的已确认业务内容，技术字段由工具填写。`record_dir`、`generation`、`output`只在明确指定既定入口时填写，显式`output`仍须与`formal`对应。
- 人物肖像默认1024×1024、本体六视图和角色六视图默认2048×2048、服装默认1152×864；其他类型或用户明确变更须填`size:[宽,高]`，沿用原规格。`prompt`仍按Qwen规则填写文生图两字段／编辑三字段及准确画幅；工具只注入正文，不优化或扩写。文生图`parameters`只接受已明确的`negative_prompt`；其模型、40步和TE加速等固定值按[文生图说明](../../studio-qwen-image/references/ComfyUI-文生图执行规范.md#2-提示词与参数映射)维护，配置变更另行授权。图生图`parameters`同样只接受`negative_prompt`；按[图生图说明](../../studio-qwen-image/references/ComfyUI-图生图执行规范.md#3-参数映射)保留40步、TE加速、参考条件缓存和每张1.5MP缩放。支持1–10张参考图，由工具按清单顺序生成加载、缩放及上传绑定，直接保存解码原图。
- 新清单全体后台任务统一登记任务组，`group_id`由工具产生，Agent不手填。正常结果等全组完成后通知，异常提前按组报告；见[组级通知](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md#3-跟进与通知)。历史`image_batch_id/image_batch_size`仅兼容已登记图片批次；无组历史任务沿原记录接续，不追溯猜测合批。
- 不传`seed`时由工具读取项目七类默认种子表；首次类别选定、登记并在同批复用，输入原始种子从批准记录读取。七类之外的图传`supplementary:true`，每次选择新种子，不新增类别默认值。来源／类别冲突停止，不暗中改已确认种子。用户指定参考图改用`user_reference:true,basis:"真实指定依据"`；可提供`source_seed`，非生成图写`source_kind:"非生成"`，生成来源种子未知须有`unknown_seed_basis:"用户明确允许按未知继续的依据"`。既有审批与未知来源处理规则保持。

超分条目只需关联已批准原图及正式目标，不手填RTX工作流、上传／输出映射、收尾JSON或正式表的整行替换：

```json
{"task_type":"image-upscale","object":"CH002","title":"CH002 · 首集服装批准后2倍超分",
 "kind":"人物","draft":"03-人物资料/其他资料/工作稿/CH002-参考图-工作稿.md",
 "authorization":"具体原图已获用户批准，按既定流程2倍超分",
 "references":[{"file":"03-人物资料/其他资料/工作稿/素材/CH002-大学-首集-服装参考图-候选-v01.png","purpose":"获批原图",
 "approval":"03-人物资料/其他资料/工作稿/CH002-参考图-工作稿.md#审阅-生成记录-008-001"}],
 "formal":"03-人物资料/CH002-女主/参考图/CH002-大学-首集-服装参考图.png",
 "adoption_fields":{"适用范围":"首集"}}
```

图片后处理继续使用`task_type:"image-upscale"`及可选`size:[目标宽,目标高]`，单位为像素，须为两个正整数；未传时沿用原图宽高各2倍。工具按[图片后处理的方式选择](../../nora-drama-images/references/图片后处理业务规范.md#指定尺寸处理的方式选择)读取原图真实宽高并自动分流，本地处理不装配RTX工作流。进入RTX的指定尺寸任务在副本同步`target dimensions`及宽高控件、API和成果计划，基准仍保留2倍，画布与API保留ULTRA、strength=1.0、8-bit RGB。

需裁切时可选`crop_anchor:[水平位置,垂直位置]`，两个数均为0到1，默认`[0.5,0.5]`居中；例如`[0.5,0]`保持顶部、从底部裁去多余部分。必须符合本次已获授权的裁切范围。正式资产、原批准、`formal`、`archive`及`adoption_updates`仍按本节填写。本地分支同步完成处理与收尾，返回`status:"completed"`、`provider:"local"`、报告路径及空的`local_task_id`，不会产生ComfyUI任务或正常超分通知；`--prepare-only`不执行处理，`--start-paused`遇本地分支时整批停在准备阶段，去掉该参数再次调用才执行。

工具从原生成条目读取图片类型／状态等字段，生成既有“当前正式资产”表采用更新，版本指向原候选与超分编号，审阅仍指原批准；该表缺少的业务内容在`adoption_fields`按原表头补充，不猜适用场次／状态。需替换已有正式文件时提供`archive`原规则下的历史保存路径。确有额外关联文字须修改时，可选`adoption_updates:[{path,old,new}]`补充具体关联，常规正式表无需提供。原图、历史批准与超分后再审等特殊要求沿用原规则，不借精简提前采用。

视频条目复用已配置好内容、时间线、编辑状态及运行范围的导演台画布；技术API不再由Agent平行编辑。标准版先按[四种配置与生成前询问](../../nora-drama-production/references/ComfyUI-H3视频执行规范.md#标准版四种配置与生成前询问)确定项目默认与本批覆盖后的有效配置，按该节配置及横竖屏表设置采样步数、128及342／344／345启用状态、生成尺寸、407的MP与目标宽高，并选择对应超分或裁切后处理；53与343常开，343默认3.0。工具沿用已配置的画布，不根据LoRA开关或后处理名称自动推算步数、尺寸及方向。随包生成API对应选项1横屏；其他选项及竖屏从配置后的画布导出，后处理同样复制所选基准后填写源片及方向。已有一采接二采沿用来源实际参数，不套用新默认值。视频条目示例：

```json
{"task_type":"video-first-pass","title":"EP001-C001 · 一采","authorization":"用户明确授权本次一采",
 "canvas":"09-剧集制作/EP001/其他资料/执行附件/EP001-C001-P001-R001-一采/任务.workflow.json",
 "record_dir":"09-剧集制作/EP001/其他资料/执行附件/EP001-C001-P001-R001-一采",
 "output_nodes":["403","504","506"],"report_node":"403","output_root":"E:/实际ComfyUI/output",
 "references":[{"file":"03-人物资料/CH001-男主/参考图/当前角色.png","placeholder":"planned/CH001.png"}]}
```

已有视频的局部返修，先按[执行快照与素材路径](../../studio-h3/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#611-局部返修的执行快照与素材路径)选择实际执行后的内容来源，再装配本次任务；不直接将首次准备示例用于返修。

视频执行职责见[视频执行分工](../../nora-drama-production/references/ComfyUI-服务配置与任务提交规范.md#视频执行分工)。任务清单自动建立或补齐各P本R本阶段的技术条目，已有非空说明、用户反馈及决定保持；记录从实际API、语义映射和后台事实生成，不手填模型参数、ID、秒数／帧数或冻结资料入口。

- 新一采可传`sync_timing:true`，以内容画布中已核定的各组durationSec计算17k+5帧格、start、length、总帧数并同步根字段及r2v编辑区。使用新的执行目录保存副本，原内容画布不改写；二采、返修或带历史source／materials_from的任务不使用此选项，保持来源与缓存身份。
- 新核对可在任务条目的`content_review`传逐组语义注释：`groups`中每项含`index`、`chinese:{file}`、`subjects`、四类`checks`及各自真实note／prompt_quote／chinese_quote／sources的file和quote；单导演台可省node。**不手填input_sha256、中文或依据sha256**，脚本按本次实际API和文件绑定。既有已绑定记录继续在原mapping使用，不自动刷新，不由脚本补passed；未做语义核对仍会失败。详细字段含义见[内容核对检查](../../nora-video-prompts/references/固定脚本接口规范.md#h3正文与内容核对检查)。
- 标准单段H.264 MP4后处理可不传outputs，工具从唯一VHS_VideoCombine保存节点和已选P／R派生目标及取回凭据；其他保存结构须显式提供实际输出映射，不猜节点。
- 清单视频任务自动带媒体信息读取计划：通知前仅用本机ffprobe读取一次stream／container事实，将实测值写入原结果收尾报告和分段记录；网页重试复用未变化的测量，report读取不再测量。缺少ffprobe、无法读视频轨或文件变化返回技术异常，不转交Agent手测或自动重生成；不安装依赖、不抽帧或运行内容／质量评价。既有已接受任务不追溯补测。

新视频准备及开工时会核对目标阶段／R在候选和采用目录中的现有视频；已有结果不能借更改输出路径重复使用该R。候选分配及失败恢复读取[候选编号规则](../../nora-drama-production/references/逐集目录与资产管理规范.md#视频修订编号与执行过程)，工具只报出冲突，不自动改号或重新生成。

`output_nodes`为本次画布的实际执行输出节点；标准版示例的403／504／506不能照搬到不同工作流。`output_root`为已核实的远端真实目录。既有`输入映射.json`复用，不复制粘贴；新映射可在`mapping`传入既定语义信息。分镜版本、场次修改轮次、组与P／R对应、内容核对证据仍须准备；工具不替代这些内容决定。工具导出配套API，按已选原始组序、P／R／阶段派生候选路径与取回凭据，按`references`中的占位值定位图片／音视频素材槽位、组装上传映射；原映射和冻结资料仍由既有后台保存。二采使用指定来源画布及既有批准关系，不能换成新的基准。后处理或特定输出可显式提供原格式的`outputs`／`segment_plan`／`uploads`，仍共用本次装配、准备和入队。

`references`是本次**需要上传**的素材占位值到源文件的单一填写入口。工具同时建立技术上传槽位和`输入映射.json`的`uploads:[{input_path,file}]`来源索引；同占位值、同源文件只登记一条来源，重复的`references`条目复用同一套槽位绑定，同占位值对应不同文件则在写入前报错。已有来源索引保持兼容，不要求Agent重复填写。

H3局部返修复用已核实的远端素材时，内容画布保留来源实际路径，`mapping.uploads`保留`input_path`到本地源文件的来源索引；该索引不发起上传，未变素材不再重复列入`references`。`references`只列本次确需上传的新／已变素材，否则工具会将所列素材上传到新执行目录并改写路径，可能使未选前组的缓存失配；没有新上传项时可省略`references`。这是原素材的显式来源引用，不是跨任务上传缓存；后台文件与阶段缓存核验继续保留。

画布控件修改由工具同步`widgets_values`和`widgets_values_named`，保留预览等界面字段；执行范围按[视频执行分工](../../nora-drama-production/references/ComfyUI-服务配置与任务提交规范.md#视频执行分工)处理。

返回与接续：

- 成功：`status=enqueued,tasks:[{local_task_id,title,task_type,status,record_dir}],next_action=end-turn`。**立即汇报数量并结束本轮**，不再补ID、进度、技术记录或检查网页；后台保存动态状态和成果。
- 仅准备：同一命令加`--prepare-only`，返回`status=prepared`；不入队／上传／生成。内容不变时可只补充各条`authorization`再正式调用；模型正文、素材或范围变更属于新的准备，不能覆盖已接受清单。原逐项入口也保留仅准备能力。
- 异常：全组先完成准备，任一准备失败则不入队；新后台清单原子登记，失败不留下半组。`任务清单-装配结果.json`保存装配、group_id及成员ID；回执丢失沿原清单找回原组和全部成员，不重复POST。仅无组历史部分提交或同步本地处理保留`partial`兼容路径，按原已接受ID接续。已登记任务的内容或来源不能覆盖原装配记录；尚未登记的准备修正按下方接口办理。只在异常时查这些附件，不在正常成功后再读一遍。


### 工作稿当前正文集中同步

入口：[sync_current_documents.py](../scripts/sync_current_documents.py)，Python 3.9及以上标准库。用于将明确选定的工作稿“`## 1. 当前内容`”正文同步到对应正式文件；准备与检查时机执行[集中同步与检查规则](../../nora-drama-production/references/ComfyUI-服务配置与任务提交规范.md#准备资料的集中同步与检查)。仅同步已编写的内容，不生成或审核正文、不改变确认状态、不联网、不修改工作稿、任务库、凭证、媒体或执行记录。文档采用及工作稿接替仍按[工作稿管理规则](文件版本与工作稿规范.md#工作稿管理规则)处理；运行工具不等于采用。

```sh
python -X utf8 /实际技能目录/scripts/sync_current_documents.py \
  --project /实际项目根目录 --plan /本批同步计划.json \
  --archive-dir 09-剧集制作/EP001/其他资料/历史版本/正文同步-YYYYMMDD-HHmmss
```

计划为UTF-8 JSON数组，只填写本批需要同步的文件：

```json
[{"draft":"09-剧集制作/EP001/其他资料/工作稿/EP001-本集剧本-工作稿.md",
  "target":"09-剧集制作/EP001/02-剧集剧本/EP001-本集剧本.md"}]
```

`--project`为当前设备项目根；`--plan`文件地址相对当前工作目录或为绝对地址。计划中的`draft`、`target`和`--archive-dir`相对项目根，也接受项目内绝对路径，不重复`projects/项目名`。归档目录须位于项目的`其他资料/历史版本`，本批使用未占用的时间戳目录；旧正式文件按原项目相对目录完整保存。计划支持多文件，工具预先解析整批后再写入；任何缺章节、代码围栏不闭合、目标重复、越界或归档冲突均报错，不发布已预检但尚未写入的条目。实际写入时的IO失败须按错误及已有归档核对，不声称整个批次已完成。
