# 创意与音画流程与规则

阶段一至三按2026-10-30用户确认的统一口径执行。

## 流程与接续

读取制作简报 → 构思并选择方向 → 展开主线 → 设计视听 → 编写音画 → 核对 → 整理交付 → 回写反馈。

输入为当前简报、已选方向、有效反馈及已有原稿。阶段主文件为 `03-创意脚本/` 下的[制作脚本](../templates/制作脚本.md)。讨论使用创意与音画工作稿，对外方案按需整理。

## 甲方来稿与制作脚本

已有完整脚本时，直接按制作脚本模板整理。逐段写明原稿版本及对应位置，保留已给出的台词、动作顺序和客户要求。遇到缺项或原稿内部冲突，标明待确认；改台词、删减内容或调整已约定时长等实质修改，按项目确认流程处理。现行采用版本登记在作品状态，后续分镜引用该版本。补齐既有项目的入口时沿用已确认内容及其范围，保留已执行批次的当时输入。

### 当前制作脚本的命名与网页核对

- 供用户在「创意与音画」直接阅读的当前稿，包括当前送审稿，保存到本作品的 `03-创意脚本/制作脚本.md`。有版本号时用 `03-创意脚本/制作脚本-v03.md` 这样的格式。片名与创意标题写在文档一级标题中。
- 在 `作品状态.md` 的「对象｜当前版本/文件」表登记「制作脚本」，填写从 C 项目根目录起算的实际文件路径。当前稿的审阅或采用状态写在「状态及依据」列。网页先识别主文件名，再从作品状态选择当前版本。
- 新建或替换当前稿后，交给用户前核对该作品「创意与音画」上方直接显示这一版正文。若文件只出现在「其他资料」，先修正文件名或状态表的引用，再核对网页。网页核对沿用[工作区浏览服务](../../studio-workspace-browser/SKILL.md)的只读入口。

## 执行要点

从简报形成可比较的少量创意方向，说明每种怎样串联重点、采用何种角色/叙述关系及制作成本。选择后用[创意与音画模板](../templates/创意与音画工作稿.md)展开，画面、实际台词、发声者、屏幕文字和时间对应。客户只需简要介绍时不要把PPT逐页读成视频；完整覆盖还是突出部分能力由本单决定。

有角色交流或旁白时按[共用对白与场次表演](../../studio-creative-techniques/references/对白与场次表演方法.md)核对原话、必要反应及留白。先写核心视觉变化与动作因果：谁遇到什么问题、助手/产品如何介入、信息或行动发生什么变化。角色互动若是核心，不用纯旁白加图标替代。新增角色可在原结构内局部接入；保留用户批准的未受影响内容。

按[共用剧本的声源写法](../../studio-screenplay/SKILL.md#声源与正文写法)区分人物对白、内心独白与旁白。时长按段相加，跨段台词只读一次；旁白、人物提问、助手回答各有职责。声音数量和是否入镜由本单设定，需计时的台词以实际朗读或表演复核。

按[共用画面文字写法](../../studio-storyboard/references/分镜写作规范.md#画面文字与实现归属)区分场景内文字、叠字及对白字幕。经本单确认的产品界面原文、标识及口型窗口写入现有脚本及[文字与声音表](../templates/文字与声音表.md)，保持实现归属明确。

对外稿按[对外交付规范](../../iris-commercial-video/references/对外交付.md)。客户反馈先标出修改范围、上下游影响和保留项，再修正文；改稿不自动更新批准状态或重生成媒体。

完成：故事和重点表达准确，台词、画面与文字互相对应，时间完整，并指向当前选定方向。

## 交付整理与完成

本阶段交付整理、批准及导出顺序统一执行[跨阶段交付规则](../../iris-commercial-video/references/对外交付.md)，本节只补充所属阶段的交付内容与完成要求。

音画段落不是镜头。当前方向已明确时直接展开，不重复比较；已有视觉探索注明是方向示意还是具体方案。声音、文字分类及跨段统计可用[文字与声音表](../templates/文字与声音表.md)。
