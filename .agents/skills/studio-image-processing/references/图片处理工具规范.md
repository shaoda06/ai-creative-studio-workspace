# 图片处理工具规范

## 输入与分流

调用方提供实际源图、目标宽高、允许的处理和新输出位置。工具不根据图片名称、人物图种或业务目录推导规格，也不决定是否批准。

- 同尺寸直接保留原字节。
- 任一目标边小于原图，采用本地Pillow与LANCZOS等比适配；宽高一增一减也不交RTX。
- 目标两边均不小于原图且至少一边增大，实际需要超分时可用RTX。

比例不同的本地处理涉及裁切，调用方须先确定允许范围；不拉伸。crop_anchor为两个0到1的数，依次表示水平、垂直裁切位置，当前业务默认值由业务阶段提供。

## 函数接口

scripts/image_processing.py中的resize(source, destination, target, crop_anchor, project=实际项目根目录)只处理明确路径，target为宽高像素。返回真实工具版本、源图尺寸和裁切坐标；不覆盖已有输出，不写业务表、不联网。依赖浏览服务现有Pillow环境。

assemble_rtx(source, prefix=..., remote_output=..., size=...)只装配。size省略时使用既有2倍工作流，指定时为明确正整数宽高。返回画布、API、上传映射和输出节点3；实际任务由后台执行。调用前由调用方依据真实输入大小确认放大方式，保持[RTX参数要求](ComfyUI-图片超分执行规范.md)。

scripts/image_files.py的png(raw)核对PNG编码并返回真实宽高；inspect_remote(data, state, outputs, planned)核对实际请求、上传及下载凭据和明确目标，不读取业务模板，不作视觉判断。已有来源核对复用原证据，不扩大看图范围。

## PNG保存、复用与替换

原生结果、规格处理输出、正式保存及PNG旧版归档统一使用`image_files.py`的存储入口。图片的审核路径、原生输出、处理结果和采用记录各自保留；内容完全相同时，在同一项目内共用只读磁盘数据，不为不同用途或文件名再次复制。外部工具结果先原字节保存到实际项目，不跨项目硬链接，也不共享临时写入目录。比较实际字节，不新增哈希索引或另一套素材库。

共享PNG禁止原地编辑。内容变化时保存新版本；正式路径更新先保存原图归档，再通过临时文件原子替换目录入口，旧候选和任务输入保持原字节。不得使用`write_bytes`、`copyfile`等直接覆盖已有PNG，也不为修改一份图片解除其全部共享副本的只读保护。

有实际源文件时，从总目录执行下列命令；项目与输出路径由业务阶段确定，命令只保存图片，不登记采用或生成新图：

```sh
python3 .agents/skills/studio-image-processing/scripts/image_files.py \
  --project "/实际项目根目录" --source "/工具返回的实际原图.png" \
  --output "业务已确定的候选或正式路径.png"
```

`--source`可以是外部绝对路径或项目内相对路径；`--output`及可选`--archive`以项目根目录解析。输出不存在时保存，同字节已有文件可复用；已有不同内容时默认失败。明确替换正式图时添加`--archive "业务规定历史目录/旧图.png"`，先保留旧字节再替换；归档已存在不同内容则停止。成功输出真实宽高、字节数及PNG解码结果；不联网、不生成、不改审批。项目内作为原图保留的源文件也会成为只读版本，修订时另存新文件。

内部接口`store_png(project, destination, raw, source=实际原文件)`保存调用方已核对的PNG字节。`source`只用于复用明确原图；来源在项目外时只读入，不能硬链接。显式替换调用另传`replace=True, prior=[原大小, 原mtime_ns]`，目标变化时停止；采用及归档条件由业务调用方提供。正常生成、模型取回、尺寸处理和正式保存已自动接入，Agent无需在这些步骤之后再跑一次合并。

## 输出与使用边界

源图、处理结果、实际方式、宽高和凭据分别保留。正式资产、原批准关联和归档由业务阶段处理；技术任务只返回文件和技术事实。正常结果不自动生成新图、改变源图或增加视觉审查。

过程检查文件与实际输入/结果的保存边界按[临时资料生命周期](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md#临时资料生命周期)执行。只用于检查的中间文件在本次临时目录处理并随操作收尾清理，实际被提交的图像/音轨、候选和交付产物继续保留，不按“过程”名称自动删除。
