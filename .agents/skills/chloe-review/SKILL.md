# Chloe 视频复盘与调整

创建或更新固定资料前，读取[固定资料写法规范](../chloe-positioning/references/固定资料写法规范.md)及其对应模板；完成后运行其中的检查命令，保持章节、字段和状态写法一致。

开始或接续复盘时，先核对[项目专用约定](../chloe-commerce-video/references/会话组织与接续规范.md#项目专用约定的记录与执行)，再按用户所问进入[制作过程复盘](#制作过程复盘)或内容与运营复盘。内容与运营复盘读取实际成片、视频编号和已有发布或效果资料。登录、查看账号状态或采集后台按本次明确的任务与授权接续。没有效果数据时按[复盘来源与证据](#复盘来源与证据)完成内容分析。

做内容与运营复盘时，按[共用复盘分析](../studio-operations-review/references/数据采集与核对SOP.md#成片与此前采用记录)区分证据、假设与结果，分别分析内容、商品和账号阶段。成片范围与数据缺项按本阶段映射写入原记录。

## 制作过程复盘

从实际采用版本、制作轮次、审阅与返修、异常执行和用户决定定位卡点。分别核对素材生成、内容返修、技法试验和技术失败的实际次数。说明哪些改法已见效果、哪些因素同时变化、哪些只获得了本次反馈。纯制作复盘可以在发布前进行，结论和原记录链接写入本视频 README 的「单条复盘」，采集编号填「不适用」。

对照现行入口查重，已有规则覆盖的问题回到实际执行步骤改进。可复用的做法按适用范围归入项目约定、业务规范或共用方法。用户要求落地时按[规则真源与引用](../studio-entry/维护规范.md#规则真源与引用)更新，并复查调用入口。仅讨论的建议保留在原复盘记录。

## 公共方法与输出映射

分析指标与成片、筛选建议或核对后续效果时，查[社媒运营与发布](../studio-entry/references/能力目录.md#社媒运营与发布)的复盘及建议查用条目。按[公共输出映射](../studio-social-operations/references/运营与制作接续规范.md#复盘输出映射)接入；本节是 Chloe 的固定记录映射。

| --- | --- |
| 实际发布对象及媒体版本 | 本视频README的发布记录，引用原成片、封面和发布资料 |
| 原始指标、采集时间与口径 | 本视频README的效果数据；已有采集快照不覆盖 |
| 单条内容判断、原因假设、限制及建议 | 本视频README的单条复盘；近似时间点及范围写内容判断或局限 |

按[共用数据核对](../studio-operations-review/references/数据采集与核对SOP.md#采集节点与对比)记录实际可得且适用的观看、互动、商品曝光或点击、订单、退款及佣金指标，预估与结算佣金分别保留原口径。缺项词和表格结构沿固定资料规范。仅做内容分析时无需建立效果数据行，也无需逐项追问指标。

默认直接完成上述记录。按用户要求分享时，按[公共输出映射](../studio-social-operations/references/运营与制作接续规范.md#复盘输出映射)从原记录导出，并注明实际记录编号与采集时点。

## 建议接续与验证回填

1. 在原单条或跨视频复盘的调整建议中写明问题依据、适用条件、具体改动及接收阶段。选品承接商品与资料问题，创意承接开场和镜头安排，资产承接构图与展示细节，制作与剪辑承接动作节奏，发布承接封面文案和时间建议。只交接本次相关建议，不自动改动这些阶段的产出。
2. 交接时提供Chloe规则入口、来源R记录链接及已有T编号。接收方按[共用建议选用](../studio-operations-guidance/references/复盘参考与采用规范.md#读取与采用)判断本次是否适用。
3. 一次独立验证使用一条T记录。复盘来源必须已有具体调整建议；采用依据记录本次选择、原因及授权，验证对象链接实际作品或待调整原资料，验证方法说明核对内容或数据口径。尚未决定时保留待决定；不采用且影响本次决策时在采用依据说明原因。已有明确授权直接沿用，需要新的业务决定时由接收阶段确认。
4. 采用表示决定实施，不代表已经落实。接收方按自身原记录维护具体改动和版本，只引用T编号及来源链接；复盘侧通过验证对象链接实际修订记录、准确版本或成片核对记录，不抄写制作过程。验证对象的每个链接须指向具体文件或原外部记录，不能只指向目录。
5. 后续复盘按[共用记录与验证](../studio-operations-guidance/references/复盘参考与采用规范.md#记录与验证)核对落实和实际效果，在T行分别填写两项结论并关联原核对或采集记录。只有落实依据时可写“内容调整已落实，效果未取得”，尚无验证结果时填未取得。
6. 同一验证的后续进展回填原T行，分期结果保留对应采集编号和判断范围，不把后来的数据改写进旧快照。另一次独立验证使用新T编号，继续引用同一R来源；明确共同验证计划中的多个作品可列在同一验证对象中。原验证行及其结果保留，不因开始下一轮而覆盖。

## 阶段记录落点

各阶段开始或继续相关任务时，先读与本次对象、问题和条件有关的R建议及已有T记录，按上一节选择采用。需要开展独立验证时，在原运营复盘文件建立T行后再从阶段记录引用；没有适用建议就正常推进，不创建空T行或虚构变更。相同任务、建议和决定未变化时复用原T编号。

阶段记录使用`[T001](<相对路径/运营复盘.md#建议验证>)`链接当前具名项目`综合资料/运营复盘.md`中的真实行；相对路径从当前文档计算，链接文字为准确T编号。阶段记录只写本次具体动作及版本，不抄建议全文、采用状态或验证结果。T链接用于追溯建议，不能替代原授权、审阅、采用或交接依据，不改变各阶段的批准与生成流程。

| 接收阶段 | T编号的现有记录位置 | 完成后交回的落实依据 |
| --- | --- | --- |
| 账号定位 | 账号定位.md的决定与变更／依据 | 实际B编号、调整字段及原确认依据 |
| 选品与商品资料 | 选品列表／选择依据；已有选择改变时另按原规则记录选择变更／依据；商品事实修正写商品说明的事实变更／依据 | 商品对象、选择或事实变更行及原始事实来源 |
| 创意与分镜 | 脚本修订记录／依据；首次建档无修订时，在视频README实际建档的阶段变更／依据中引用 | 脚本版本、U或B编号及实际修改的镜头或章节 |
| 共用资产与镜头图片 | 有实际执行时写资产说明或本视频制作记录的执行记录／结果说明；仅修改说明时在资产来源说明补充调整依据并保留原素材来源 | 实际对象、修改说明；有产出时带E编号、准确资源版本和实际审阅或采用依据，候选注明尚未采用 |
| 视频制作与返修 | 制作记录的执行记录／结果说明；实际返修按原X记录关联，不以T链接代替用户审阅 | 实际E、X、分段与轮次、准确输出及原用户审阅或采用记录；技术完成不等于内容落实 |
| 剪映交接与人工成片接续 | README剪映交接／依据补T链接；收到成片后的实际核对在制作记录的交接与成片核对／核对项目引用T | J清单及原采用组合；有实际成片核对时交K编号、原成片与核对证据，仅交付清单不称人工修改已落实 |

阶段完成或发现无法落实时，交回原T链接、本次动作、上表的具体文件与记录编号、实际状态及缺项；由本轮实际维护者把落实文件补入原T行的验证对象，保留原目标作品及已使用的来源引用。与相关阶段的交接仍依已有会话规范，不自动新建会话或发送跨会话消息。后续复盘沿原记录核对落实情况和效果，结果按上一节回填，不另建回执或验证台账。

## 复盘来源与证据

效果数据按[共用作品定位](../studio-operations-review/references/数据采集与核对SOP.md#定位作品与读取)和[采集日期规则](../studio-operations-review/references/数据采集与核对SOP.md#采集节点与对比)核对作品、发布时间及指标来源。D行关联本视频实际公开过的P行，撤回后仍保留历史数据，已知采集时间不得早于已知实际发布时间。发布字段依已有记录和实际来源引用，缺项沿[发布提交记录与既有事实](../chloe-positioning/references/社媒运营接入规范.md#发布提交记录与既有事实)据实标注。指标来源填写原附件或原记录的Markdown链接，或实际HTTP(S)来源URL。来源缺失时填未取得。脚本只检查记录关联和本地文件存在，证据判断由Agent完成。

纯内容复盘在内容判断或局限中链接实际成片或已注明成片版本、分析范围的原分析记录，采集编号填不适用，转化和收益结论留待实际指标。跨视频结论的“视频与证据”逐项链接当前具名项目内视频README中的实际采集或单条复盘记录，使用`[D001](<../projects/V001-名称/README.md#效果数据>)`或`[R001](<../projects/V001-名称/README.md#单条复盘>)`，多个链接用顿号分隔。单条或跨视频复盘引用的D编号下至少已有一项实际指标，原始证据沿被引用记录追溯。

“建议验证”的“复盘编号”可填本文件跨视频结论的R编号，也可直接填写上述单条复盘R编号链接。编号以文件和章节区分；单条建议直接关联原复盘，不为进入验证表另建跨视频结论。其余采用、对象、方法及结果要求按下一节执行。

## 时间与建议验证

效果数据按统计起始时间≤统计结束时间≤采集时间填写；跨视频结论按观察起始时间≤观察结束时间≤记录时间填写。各时间使用带时区的实际值，比较时按同一时间轴判断，允许相等。未取得的时间如实填未取得，只比较已知时间，不把未知时间补成零点或当前时间。

建议的采用与验证分开记录。采用状态为采用时，填写采用依据、验证对象及验证方法；验证对象用Markdown链接指向实际作品或被调整的原资料，可附具体发布编号、镜头或多个对象。验证方法说明准备比较或核对什么、使用何种口径或内容判断依据。只是提出建议、尚待决定或不采用时，不强求验证对象和结果。

尚未取得验证结果时，验证结果和结果证据填未取得，不为补齐字段生成资料或采集后台。一旦填写实质验证结果，无论采用状态如何，必须填写验证对象、验证方法，并用Markdown链接引用原始证据或原核对记录；本地链接指向原文件，外部证据使用实际来源链接，不另抄数据或复制附件。证据不足时保留局限，不把采用建议写成已验证有效。后续作品复盘时把真实结果补回原建议验证行。
