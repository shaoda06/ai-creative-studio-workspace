# 整稿接入适配规范

用户提供多集整稿、需要精确回读时使用。Agent判断真实集界、剧情与现行EP对应；脚本只记录字节定位、切片及明确的处理进度，不生成故事。先按[原稿接续](../../nora-serial-drama/references/原稿接续规范.md#用户原稿的读取复用与确认)定位实际来源，不改写原文迎合标题识别。

## Nora保存位置与调用

原稿沿项目实际来源保存，通常在`99-综合资料/其他资料/原稿/`；已在其他有效位置的原稿不自动搬迁。索引、临时切片及必要处理文件存`06-分集大纲/其他资料/执行附件/`，不新建外部`输入/`或`项目开发/`，不把技术JSON索引当成正式分集索引。

Python 3.9+，仅标准库，无网络或后台调用。在工作区根运行；以下文件名是调用示意，替换为本次实际来源和未占用附件名。相对路径均从当前工作目录解析，`--source-ref`填写项目内实际相对来源。

```sh
python3 .agents/skills/nora-drama-episodes/scripts/episode_intake.py index \
  'projects/项目名称/99-综合资料/其他资料/原稿/整稿.md' \
  --source-ref '99-综合资料/其他资料/原稿/整稿.md' \
  --out 'projects/项目名称/06-分集大纲/其他资料/执行附件/整稿-候选索引.json'

python3 .agents/skills/nora-drama-episodes/scripts/episode_intake.py verify \
  'projects/项目名称/06-分集大纲/其他资料/执行附件/整稿-候选索引.json' \
  'projects/项目名称/99-综合资料/其他资料/原稿/整稿.md'

python3 .agents/skills/nora-drama-episodes/scripts/episode_intake.py slice \
  'projects/项目名称/06-分集大纲/其他资料/执行附件/整稿-候选索引.json' \
  'projects/项目名称/99-综合资料/其他资料/原稿/整稿.md' EP001 \
  --out 'projects/项目名称/06-分集大纲/其他资料/执行附件/原稿EP001-切片.md'
```

`index`只自动识别短独立行`第N集`、`第N集 标题`及Markdown的`# EP N`。Agent先读候选定位中的未归属材料及每集首尾，辨别目录、正文、集间说明和尾注；`unmapped_spans`不能代替语义检查。非标准结构由Agent提供JSONL边界文件，每行明确`episode_id`与从1开始的`line_start`，必要时给`line_end`，再执行`manual-index SOURCE BOUNDARIES --source-ref REF --out INDEX`。这些JSONL只作技术附件，不新增业务必填档案。

任何切片前验证实际来源；检查字节长度、跨度、顺序和行定位。原文件变化后重建索引，不沿用旧定位。验证不能识别所有等长内容替换，不能据通过结果推定原文完全未改；Agent仍依据实际来源及版本回读。原稿集号仅作来源定位，不自动替代现行EP。

## 可选分批处理及结果

| 子命令 | 参数及用途 |
| --- | --- |
| `index SOURCE --out INDEX [--source-ref REF]` | 建候选索引，保留原始字节；省略source-ref时使用源文件名 |
| `manual-index SOURCE BOUNDARIES --out INDEX [--source-ref REF]` | 按Agent明确的集界建立索引，不判定剧情归属 |
| `verify INDEX SOURCE` | 只读核对结构；发现变化先处理来源与索引 |
| `slice INDEX SOURCE EP --out FILE` | 先核对索引，再原字节保存指定来源集切片 |
| `progress INDEX SOURCE MAP --batch-size N [--checkpoint FILE]` | 从实际已处理记录推导pending；N为本轮明确的正整数集数，checkpoint仅为可选缓存 |
| `merge INDEX SOURCE BATCH MAP --out NEXT --batch-size N [--checkpoint FILE]` | 将Agent已写记录合并到独立候选，拒绝覆盖输入或冲突重写；不自动发布或批准 |

`progress`和`merge`仅在本轮明确需要机器可读处理记录时使用，MAP/BATCH/NEXT存同次执行附件；记录每行含实际来源`episode_id`及Agent已核对的字段，不自动转换为正式七章大纲。缺失的MAP按尚无已处理记录计算；恢复以实际MAP推导缺项，不凭last_completed猜测。批量大小由来源跨度、复杂度和上下文确定，不设固定配额。是否更新候选及既有工作稿按本次实际授权处理，不调用原生指南中的外部发布框架。

标准输出为JSON：index返回output、episode_count及必要problems，verify返回verified和problems，slice返回output、episode_id、byte_length，progress返回completed、pending、next_batch、complete，merge返回output、added及progress。退出0表示该机械动作完成，不表示剧情或阶段获批；index/manual-index退出2表示候选已写但有结构问题，其他运行错误退出1，参数错误退出2。检查实际错误后处理原步骤，不重写来源或伪造完成记录。

原生[整稿方法参考](multi-episode-intake.md)只提供边界判断和分批回读方法，路径及发布示例不直接执行。正式交付仍由Agent填写分集索引与七章大纲，并按[分集大纲规范](分集大纲规范.md)完成接续。
