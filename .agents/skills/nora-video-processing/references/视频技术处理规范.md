# 视频技术处理规范

按调用方选定的超分或裁切方案装配，不自行决定目标或业务来源。两种基准均先在源视频尺寸下以RIFE插帧到30fps。节点12为`NoraRIFEInterpolationCutTest`，使用已安装的原`RIFEInterpolation`及已有`flownet.pkl`；节点包与安装验证统一见[节点与安装包](../../nora-video/维护规范.md#comfyui节点与安装包)，固定接口名不因正式使用而改变。默认`target_fps=30`、`scale=1.0`、`scene_cut_threshold=0.15`、`batch_size=1`、`use_fp16=true`。节点在内部用64×64 RGB相邻帧差异检测切镜，按整段目标时间表将跨切点的插值改为源帧保持，其余位置使用原模型；不按手填切点拆片，不跨切镜混合，也不按镜头分别四舍五入帧数。阈值0表示关闭保护，仅在本次任务明确选择时填写；闪光、快速运动和相近构图可能影响检测；技术结果交回调用阶段，由其处理采用与返修。

文戏RTX-RIFE基准节点1为`RTXVideoSuperResolution`，使用`target dimensions`、横屏`width=1920,height=1080`／竖屏`width=1080,height=1920`、`quality=ULTRA`，显式填写[RTX共用必填输入](../../nora-image-processing/references/ComfyUI-图片超分执行规范.md#rtx节点共用必填输入)。画面连接为`7.images → 12.images → 1.images → 16.images`。打戏RIFE裁切基准节点1为`ImageCrop`，画面连接为`7.images → 12.images → 1.image → 16.images`，按上表填写裁切位置及目标宽高，不接RTX、不缩放、不拉伸；只用于对应横／竖屏打戏二采尺寸，历史或其他尺寸来源另行确认处理，不能默认裁切到所选交付尺寸。

两种基准均将`12.source_fps`连接`7.fps`，`16.frame_rate`连接`12.fps`，`16.audio`直接连接`7.audio`原音轨，`trim_to_audio=false`。源帧率到目标帧率的整数帧量化可有不足一帧差异，不用修改播放速度代替插帧；默认H.264／yuv420p／CRF 19。任务完成后按[任务监控规范](../../nora-workspace-browser/references/ComfyUI-任务监控规范.md)取回成果，由后台核对尺寸、帧率、时长、码率和来源，将技术结果交回调用阶段。安装或模型缺失时报告实际错误，不自动下载、升级或替换方法。

节点16的`VHS_VideoCombine`画布控件`widgets_values`使用按字段名保存的对象，不使用位置列表；任务副本修改输出身份时保留对象格式。编码设置为`format=video/h264-mp4`、`pix_fmt=yuv420p`、`crf=19`、`save_metadata=true`、`trim_to_audio=false`、`pingpong=false`、`save_output=true`，API按同名输入填写。手工导入画布后，输出名称中的编号占位符须替换为本次实际身份；源视频、目标尺寸和插帧设置按本次已确认要求填写。

过程检查文件与实际输入/结果的保存边界按[临时资料生命周期](../../nora-workspace-browser/references/ComfyUI-任务监控规范.md#临时资料生命周期)执行。只用于检查的中间文件在本次临时目录处理并随操作收尾清理，实际被提交的图像/音轨、候选和交付产物继续保留，不按“过程”名称自动删除。
