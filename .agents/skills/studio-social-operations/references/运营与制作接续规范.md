# 运营与制作接续规范

## 业务范围与对象映射

本规范适用于Nora连续短剧、Iris商业视频及已明确归属的独立运营项目。先读实际资料区与项目README、唯一状态入口；涉及Iris作品时继续读作品README与作品状态。项目专用约定优先，已有资料不因启用运营迁移或重命名。

运营任务明确项目、作品、交付版本及目标账号。下表中的发布对象代号标识本次独立发布的内容：Nora通常沿用EP编号；Iris使用F作品编号，存在横竖、长短等独立发布版本时加已有版本用途名，例如`F001-横版`。代号只用于运营关联，不替换原作品身份、素材版本或平台作品ID，不为Iris虚构EP集号。

| 归属 | 制作与内容依据 | 状态入口 | 发布交付目录及最终成片 |
| --- | --- | --- | --- |
| Nora | 项目定位、对应剧集正文及采用记录；制作资料仍在`09-剧集制作/EPxxx/` | 项目`项目进度.md` | 沿用`98-成片交付/EPxxx/`；最终成片在其`成片/`，保持既有路径 |
| Iris | 项目共用要求、`作品/F编号-名称/`内的制作脚本、资产和交付版本；结构按[Iris建档规范](../../iris-commercial-brief/references/项目建档与README规范.md) | 共用账号与跨作品事项记`项目状态.md`；本片授权、发布及待办记其`作品状态.md` | 发布资料按需放在作品`07-返修交接/发布资料/{交付版本代号}/`；成片引用原交付记录中确认的准确资源版本或已有文件，不另建Nora的98号成片目录 |
| 独立运营项目 | 用户已明确的运营对象、原始内容和采用依据 | 沿用唯一状态文件；新项目由运营建档明确 | 沿项目约定；尚无位置时在`10-社交媒体资料/发布交付/{发布对象代号}/`建立发布资料，引用实际最终文件 |

项目级运营资料统一使用`10-社交媒体资料/`，供账号配置、个人页、封面、发布记录及复盘使用；已有项目专用位置直接沿用。首次启用时在[项目运营配置](../../nora-operations-setup/templates/项目运营配置模板.md)登记业务归属、状态入口和发布对象映射。配置引用原状态及采用记录，不复制批准事实。账号及客户资料按项目隔离，不因共用技能默认复用其他项目的账号或授权。

## 接续入口

定位、需求建档或首次提出运营需求时进入[阶段01](../../nora-operations-setup/SKILL.md)。阶段明确时只处理当前动作；无运营需求时不建立采集、发布包或报告任务，封面等展示需求仍可独立调用。

| 时点 | 读取与落实 |
| --- | --- |
| 开始或继续剧本、商业脚本、分镜、剪辑、封面等制作 | 读取[阶段06](../../nora-operations-guidance/SKILL.md)，筛选与当前对象有关的报告结论，记入原工作稿；相同报告与任务未变化时复用已有判断 |
| 已采用制作素材交接 | 由原制作业务核对素材与实际交付状态；尚待人工剪辑时如实记录，不把分段或草稿当最终成片 |
| 最终成片交接与准备发布 | [阶段04](../../nora-publication/SKILL.md)按对象映射核对最终文件、文案、封面、排期及适用建议，整理发布包 |
| 发布包就绪并确定发布方式 | 按阶段04的[发布方式](../../nora-publication/references/发布准备与记录规范.md#发布方式)交付手动发布或执行获授权代发，当前执行状态写本次发布说明 |
| 作品发布后 | [阶段05](../../nora-operations-review/SKILL.md)依据实际数据及成片复盘；建议由相应制作或发布阶段使用，不主动启动改图改片 |

商业客户验收、订单完单复盘与社媒公开发布、传播效果复盘分别记录；其中一项完成不代表另一项获授权或完成。

## 项目目录与创建时机

| 创建时机 | 位置及内容 |
| --- | --- |
| 项目或作品初始化 | 按所属业务建档；Nora沿[初始化工具](../../nora-drama-positioning/references/项目初始化规范.md#2-创建项目目录)，Iris沿原作品建档，不为运营补造短剧结构 |
| 首次启用运营 | 项目`10-社交媒体资料/项目运营配置.md`；项目与作品入口引用它，不重复维护账号表 |
| 首次落地个人页或封面 | 运营目录下`个人页资料/`、`封面资料/`，索引与工作稿按阶段02、03创建；非发布用途也可单独启用 |
| Nora初始化单集 | 提前建立`98-成片交付/EPxxx/成片/`，告知人工剪辑导出位置；片头、片尾交付沿Nora原约定 |
| 准备发布包 | 在对象映射确定的交付目录补齐`发布说明.md`、`发布文案.md`与`封面/`；不再按平台或时间分层 |
| 首次实际发布 | 项目运营目录`发布记录.md`按发布对象、平台、账号记录实际公开事实 |
| 采集与复盘 | 项目运营目录`运营复盘/{发布对象代号}/`保存报告及`采集资料/`；报告与快照按实际日期时间区分 |

只有首次有实际内容时才创建运营文件。未启用运营不预填空配置、发布材料或报告。Nora已有EP报告路径保持；Iris同片不同发布版本分清采集对象，不能混为同一条平台作品。

## 运营会话与制作接续

- **建立与复用**：启用运营后优先复用项目适合的运营会话。需要新建时按用户明确授权创建“项目名或代号｜运营”；发布意向、配置或建档不自动授权新建会话。跨平台、跨集或跨作品共用一个项目运营入口，不按每次报告拆会话；用户另有安排时沿用。
- **职责与交接**：承接账号配置、个人页、封面、发布包与记录、采集和复盘。接续材料包括项目规则、原状态入口、运营配置、对象映射、索引、报告、采用记录和当前任务。创建或收到交接不自动启动采集、生成、发布或定时器。
- **既有职责**：实际获授权交接时，将原封面或个人页会话的待审候选、决定与待办一并核对，保留原会话与历史依据；片头片尾和商业制作仍由原制作业务承接。不因主技能改名自动移动会话或改写项目进度。
- **状态登记**：真实会话入口与当前动作按上表状态归属登记。首次交接完成只表示本次接续完成，未来运营任务分别记实；已有视觉对象保留各自状态与采用。无当前动作时不将长期职责写成持续进行中。
- **制作闭环**：运营报告交原制作业务按当前任务筛选，采用与验证目标写原工作稿；后续复盘核对实际修改和数据。报告产出不主动触发返工，跨会话以项目文件接续。

## 素材、状态与展示

分段完成、待人工剪辑、最终成片确认、客户交付、发布包就绪、定时待发布、已公开分别维护，不能用一个“完成”代替全部状态。

最终媒体沿原业务的准确版本保存，运营只引用；项目已启用[资源版本管理](../../studio-workspace-browser/references/项目资源与版本管理.md)时，图片候选与采用也引用同一资源版本，阶段目录保存索引与记录。只有明确交付需求才将实际文件装入自包含发布包，不建立第二个可编辑源。发布包保留当次实际封面、文案及成片版本关系，后续通用封面更新不覆盖已发布记录。

运营图片使用共用[Imagegen](../../studio-imagegen/SKILL.md)、[Qwen](../../studio-qwen-image/SKILL.md)及[图片处理](../../studio-image-processing/SKILL.md)能力。Nora可沿其已支持的业务适配；Iris使用实际C项目根、作品身份和运营输出路径，不能伪造EP或调用仅接受短剧对象的适配来填缺项。工具输入、输出及采用记原运营工作稿；品牌素材依据仍由Iris原资产记录提供，不新增一份制作资产真源。

资料同步使用[共用浏览服务](../../studio-workspace-browser/SKILL.md)。Nora沿[项目浏览核验](../../nora-serial-drama/references/项目浏览入口规范.md#交付前同步检查)，Iris沿[项目与作品入口](../../iris-commercial-brief/references/项目建档与README规范.md#网页读取与相对路径)。现有页面未提供的运营专栏直接交付实际文件入口及状态链接，说明展示范围；不以规则接入声称已实现专栏，不为单个项目修改共用网页。
