# 固定脚本接口规范

## 后台任务查询与结果处理

入口：[browser_tasks.py](../scripts/browser_tasks.py)，Python 3.9+、仅标准库。下面各命令共用本节的调用条件，再按实际动作读取对应小节；无需读取上传、提交和素材映射章节。

依赖已启动的[本机浏览服务](../../../../工作区浏览服务/README.md#日常启动)。脚本自动读取工作区 `工作区浏览服务/runtime/task-service.json` 中的本机接口地址与内部凭证，不手填或输出凭证；各命令均不接收 `--url` 或 `--project`，远端绑定由后台按原任务记录处理。将示例中的技能目录和ID替换为本次真实值。配置缺失、服务不可达或接口拒绝时命令非零退出并输出错误，按[异常处理](ComfyUI-任务监控规范.md#31-异常检查与连接恢复)核对，不改走重新提交。


### 后台状态查询

新任务优先按提交返回的真实组ID查询：

```sh
python .agents/skills/nora-workspace-browser/scripts/browser_tasks.py status --group-id 真实任务组UUID
```

返回组名、`expected_tasks/completed_tasks`、成果取回计数、`status/terminal/review_ready`、缺项及各子任务的状态和错误。一个子任务可能生成多段，任务数不当分段数；具体问题仍用下方`--task-id`查询。查询不轮询远端、不重新提交。


适用于用户主动查询已有任务进度，或处理结果时核对最新后台状态。读取原入队响应的 `local_task_id` 或后台记录的本地任务 `id`；它不是远端 `prompt_id`。

```sh
python "实际技能目录/scripts/browser_tasks.py" status --task-id 本地任务UUID
```

此命令只读本机后台，单次返回任务JSON，不启动监控或轮询。核对 `status`、`updated_at`、`progress`、`collected`／`expected`、`error` 及 `record_dir`；失败阶段存在时读取 `failure_stage`。退出0表示查询成功，生成和取回是否完成仍看任务状态与实际成果。跟进方式见[查询规则](ComfyUI-任务监控规范.md#11-待提交跟进方式与间隔)。


### 后台最终报告读取

收到后台通知先读取[后台通知接续](ComfyUI-任务监控规范.md#后台通知接续)，再按下面接口读取最新报告；通知中的简短摘要不作为成果齐备或已交付的依据。

正常结果先按[整轮汇总规则](ComfyUI-任务监控规范.md#3-跟进与通知)判断用户交付时机，报告仍按收到的任务通知逐条读取；部分正常成功静默接收。

收到真实后台通知后，在真实来源会话执行；参数是通知批次UUID，脚本读取`CODEX_THREAD_ID`并由后台核对归属。只访问本机后台，不查询远端、不生成、不触发登记或网页扫描：

```sh
python "实际技能目录/scripts/browser_tasks.py" report --notification-id 通知批次UUID
```

后台在发送前已自动完成图片、超分及视频的技术收尾和网页核验，或保存具体失败结果。通知只提供任务身份和报告入口；命令按后台已有的最新任务状态刷新持久报告并自动记录收到，异常修复后的旧通知也返回当前结果，不重新收尾、扫描或发送。原通知和错误经过保留在过程记录。正常图片及超分默认返回通知身份、接收回执、交接信息及`delivery`，避免展开重复的状态／收尾内容；`delivery`包含完成任务数、图片数，以及每项标题、任务类型`task_type`、本地任务ID、成果绝对路径、候选路径、实际宽高／格式／字节数、工作稿／收尾报告绝对路径和可直接打开的`review_url`。普通图片按[批次通知规则](../../nora-drama-images/references/ComfyUI-任务监控规范.md#图片批次通知与超分静默)集中展示，不再拼路径、数文件、翻记录或查网页；正常超分不发送通知，历史正常超分通知只读确认，不输出进度、完成消息或图片。`user_message_ready=true`表示本报告所含成果的入口可审；整轮汇报仍须满足上述交付条件，成功读取不表示用户批准。历史图片／超分缺少展示字段时保留完整报告，按任务类型处理，不补做收尾。正常视频同样返回这些精简字段及`delivery`：`video_count`为本报告所含实际完成数量，`tasks`含标题、阶段身份、文件绝对路径、媒体信息及可直接打开的审核链接；达到整轮交付条件后，一采、二采对话只汇报汇总数量和审核入口；后处理沿[自动采用](../../nora-drama-production/references/逐集目录与资产管理规范.md#后处理自动采用)完成收尾，并按[后处理完成汇报](../../nora-drama-production/references/ComfyUI-任务监控规范.md#后处理完成汇报)汇总实际处理及配套交付；精简报告没有处理明细时复用本任务执行记录，必要时用下述--details读取现成完整报告。异常仍返回完整`tasks/results`，据失败阶段定位；显式追溯时可加`--details`读取完整报告，不触发重新核验或补做制作登记；仍按上方规则刷新报告并记录接收回执。未带展示清单的历史报告保留原格式。重复读取`reused=true`且不重复确认事件。

新组报告的`groups`为数据库固定成员范围，正常完成和异常通知均包含全组状态；`tasks/results/delivery`包含全组现有结果，终态交付不能只取new_task_ids。历史无组视频报告的`rounds`为原任务清单范围汇总，直接使用`rounds[].delivery`中的成果及审核入口，不根据最后一份通知重复数文件。字段与整轮／已读／已交付边界见[跟进与通知](ComfyUI-任务监控规范.md#3-跟进与通知)。原清单来源不完整时返回`status=needs_attention`及具体原因，不猜测合批。新任务的原清单关联由统一装配入口保存，Agent不手填后台字段；历史已登记任务不自动回填。报告读取只刷新已有任务事实和接收回执，不上传、生成、补登记或发送通知。

`business_sync.entries[].updated_fields`列出工具维护的字段；`actions`列出需Agent处理的具体字段、原因及责任方，`next_action=resolve-business-fields`时只处理所列项。正常自动事实同步及正式说明引用方式见[技术记录与业务记录分工](../../nora-serial-drama/references/会话与进度管理规范.md#技术记录与业务记录的分工)。


精简及完整组报告保留`handoff={receipt_only:true,scope:"task-group",next_action:"resume-group-delivery",record_dirs:[项目相对执行附件路径]}`；历史无组报告保留scope=notification及resume-round-delivery。它提供原记录入口，不建立新的交付台账。`should_notify_user`及`new_task_ids`只标识本次新接收结果，不能决定整轮是否可交付，也不能证明用户已收到；`false`或空列表仍需核对共同工作记录中的未交付范围。达到整轮条件时合并此前静默已读的结果，完成交付后在原共同记录注明范围与时间，已交付结果不重复汇报。

各任务收尾保存`business_sync`，report按`[{task_id,...business_sync}]`汇总；状态可为`needs_attention`、`not_current`或`updated`。`entries`逐项给出`episode`、现有业务文件`paths`、`status`及`reason`；`updated_fields`列工具维护的字段，`actions`列需接手的具体字段。`not_current`表示历史任务不覆盖当前摘要；`entries[].status=preserved`表示保留已有制作完成决定，事实仍在原结果报告。技术成功与业务摘要已同步分别判断，接续按上方记录分工处理，不重复已完成的核验和登记。

旧通知没有持久报告时返回已有摘要、`legacy_report=true`和`user_message_ready=false`，不会在读取时补做收尾；核对具体缺项后才使用兼容修复入口。


### 后台通知确认

仅供旧通知兼容；正常通知只调用上方report，不另调用ack。使用真实通知批次ID；主动查询没有通知ID时不调用。必须在真实来源会话内执行，脚本读取当前 `CODEX_THREAD_ID`，后台核对通知归属；不伪造会话上下文。

```sh
python "实际技能目录/scripts/browser_tasks.py" ack --notification-id 通知批次UUID
```

成功返回`notification_id`、`status=acknowledged`和本批`tasks`摘要。正常流程读取report已同时确认，不再调用此命令。重复确认返回`reused=true`，不重复追加事件。它只确认Agent收到，不表示用户已批准；图片、超分及视频统一按[监控规范](ComfyUI-任务监控规范.md)的对应结果分支交付，异常才展开证据。


### 后台视频待审登记

供旧任务兼容或明确登记／同步异常修复，在真实来源会话内显式调用；正常完成已由后台执行，不需要Agent调用。异常时按[已有授权的登记修复](进度查询与结果处理规范.md#已有授权的登记修复)由Agent接续，不为内部命令重复询问用户。不提交、下载或生成，不作内容审批：

```sh
python "实际技能目录/scripts/browser_tasks.py" register-results --notification-id 通知批次UUID
```

工具复用取回结果中的本批身份与资料关联（普通保存节点缺少身份时，仅按[精简收尾](../../nora-drama-production/references/ComfyUI-任务监控规范.md#视频完成通知后的精简收尾)补取已有检查依据），集中更新既有各P工作稿的成果／凭据入口，不重读固定映射；当前文件／凭据存在性和最终替换前的源文档变化仍核对，并用既有视频审阅模板登记待审；已有审阅决定和旧版本保留。共同状态归共同入口，各P不重复登记共同摘要。工具沿用原执行附件中的`结果收尾报告.json`保存处理进度；中断和重复调用按[收尾规则](../../nora-drama-production/references/ComfyUI-任务监控规范.md#视频完成通知后的精简收尾)恢复，不新建临时收尾脚本。

常规成果及待审事实由后台自动登记。异常修复确需本批项目进度行、制作前检查或生成说明的精确业务更新时，可准备UTF-8 JSON数组，在兼容修复调用提供`--record-updates 实际更新文件.json`。每项为`{"path":"项目根相对路径","old":"唯一原文","new":"准备好的替换文字"}`；仅限本批剧集既有对应资料，不支持跨项目混合更新，不修改正式剧本、提示词或批准事实。工具保存这份精确更新的处理进度，恢复调用可不重传；不同方案不能覆盖尚未完成的更新。源文字变化／不唯一时报告`registration_failed`，保留已完成登记及用户文字，不全文件覆盖。

摘要与登记共用稳定成果条目，状态／错误实时读取；取记录目录不展开完整入队参数。网页同步冷启动复用首次扫描，热缓存按本批更新扫描一次，规则见[精简收尾](../../nora-drama-production/references/ComfyUI-任务监控规范.md#视频完成通知后的精简收尾)。成功返回本批`results`、每项登记报告和`browser`核验结果；`user_message_ready=true`才表示本批视频网页入口核验通过。报告含登记开始`recorded_at`、完成`registered_at`及`browser.verified_at`。只有网页同步失败时返回`browser_pending`及原报告／源文件入口，重复调用只接续未完成环节。退出0表示接口调用成功，不代替报告中各项状态；登记不齐或异常须说明缺项，不声称全部可审。图片返回`image-review-workflow`，不改变图片审核及展示方式。


### 已有图片成果的登记修复

授权边界由[已有授权的登记修复](进度查询与结果处理规范.md#已有授权的登记修复)维护。以下入口只接续已有结果的记录，不上传、生成、超分或重新处理图片。`--image-plans`仍只补缺失关联，不能更换已接受的生成关联；登记文字修复使用本节入口。

每项修复JSON统一为：

```json
{
  "reason": "本次实际失败原因及如何保留用户修改",
  "expected_updates": [{"path":"原关联文件.md","old":"原计划的唯一原文","new":"原计划的目标文字"}],
  "updates": [{"path":"原关联文件.md","old":"当前文件的唯一原文","new":"保留用户修改后的完整目标文字"}]
}
```

`expected_updates`须逐项匹配当前生效的关联更新：原计划顶层`record_updates`在前，`upscale.record_updates`在后；已修复任务读取上次报告／任务状态中的`registration_updates`或`image_registration_updates`。`updates`只允许原关联文件的子集，填写实际链接和规格文字，不再保留`{{...}}`填充标记。只修正失败的业务更新；系统生成条目、取回凭据、正式路径、尺寸、原批准图和审批证据不能借此更换。工具保存`*-登记修复前-NNN.json`，其中包含原报告、原更新和请求；原提交清单不改。修复后仍按当前原文及批准依据完成登记与网页核验，不能把修复请求已接受当作成果已入库。相同修复可重复接续，不重复登记；已经登记只差网页时直接用原收尾命令核验，不再修改更新计划。

- **ComfyUI已有图片或超分**：在原附件保存`{本地任务UUID: 上述修复JSON}`，调用`browser_tasks.py register-results --notification-id 原通知UUID --image-repairs 修复映射.json`。只处理真实来源通知中的已取回图片任务；修复记录覆盖项另存后台状态，不改原已接受任务。没有收尾报告、已有报告但未登记的情况均可接续。
- **Imagegen原生结果**：沿原`complete_command`及真实`--source`追加`--record-repair 修复请求.json`。保留原执行清单、提示词及实际调用凭据；已有图但尚未建立收尾报告时也可修复，不新增生成。
- **已有本地规格处理结果**：在原附件保存`{原执行附件record_dir: 上述修复JSON}`，调用`comfyui_dispatch.py --project 原项目 --plan 原任务清单 --record-repairs 修复映射.json`。仅接续原清单、原来源且已有本地收尾报告的指定任务；不执行清单中的其他任务，不重新处理图片，也不重新入队。不能与`--prepare-only`、`--reprepare`或`--start-paused`混用。


### 后台取回配置修复

仅当原生H3视频生成成功、后台为`collection_failed`，且错误确认来自登记的output根目录时使用。原来源会话准备JSON，填写原`expected_prompt_id`、已核实的`output_root`和具体`reason`，保存到原执行附件；通过以下入口修复，不改任务清单、原报告或数据库。

```sh
python "实际技能目录/scripts/browser_tasks.py" repair-collection \
  --task-id 原本地任务UUID --repair 原执行附件/取回配置修复.json
```

后台核对来源会话、远端ID、生成成功终态、全部选中分段的实际导出路径及文件身份，只单独保存取回根目录覆盖值和修复前后事件，保留已接受生成输入。重复同一修复不增加事件；不会上传、生成、下载、改变批准或自动重试。返回`status=repaired`后，用下方`retry-collection`接续原取回及正常登记。已有成功文件和凭据沿原规则复用；人工独立取回的文件不得覆盖，保留原件及凭据后按原取回规则接续。


### 后台取回重试

后台在整项生成成功后取回全部成果；暂时性下载故障最多自动重试3次，间隔10、30、60秒，HTTP 429遵从有效Retry-After。自动重试期间保持 `collecting`，不重复唤醒Agent；达到上限或发现资料、HTTP权限／缺项、本机文件等不可重试问题后，才进入 `collection_failed` 并通知。次数、等待时间、每轮原因及成功凭据持久保存，后台重启接续原周期，详见[异常处理与授权](ComfyUI-任务监控规范.md#31-异常检查与连接恢复)。

以下入口仅用于后台状态为 `collection_failed` 的原任务。Agent核对并处理原因后，用原本地任务ID请求新一轮取回（重新获得最多3次自动重试）：

```sh
python "实际技能目录/scripts/browser_tasks.py" retry-collection --task-id 本地任务UUID
```

成功返回 `local_task_id` 和 `status=collecting`，仅表示后台接受了取回重试，最终结果由后台状态和通知确认。后台复用原终态结果及成功下载凭据，不上传素材、不重新生成；其他状态会被拒绝，不换ID绕过。需要主动核对时用[后台状态查询](#后台状态查询)。


### 后台异常结案

适用条件及业务边界读取[监控规范的异常结案](ComfyUI-任务监控规范.md#已核查旧异常的结案)。本机Agent通过以下入口提交已核查的结案请求，不直接编辑运行中的SQLite。

```sh
python "实际技能目录/scripts/browser_tasks.py" resolve --task-id 本地任务UUID --resolution "实际执行附件/异常结案请求.json"
```

`--resolution` 为UTF-8 JSON文件，其路径相对当前目录；字段如下：

| 字段 | 含义 |
| --- | --- |
| `expected_prompt_id` | 原远端任务ID，提交时与后台再次匹配 |
| `summary` | 本次结案说明，分别说明恢复与补齐的范围 |
| `outcome` | `recovered`（原成果已取回）、`superseded`（后续任务已补齐）或`recovered_and_superseded`（两者并存） |
| `evidence` | 已核对的本项目内文件路径数组，相对项目根目录或项目内绝对路径；至少一项 |
| `replacement_task_ids` | 后续补齐任务的本地ID数组；后两种outcome必填，要求同项目且已完成 |

成功返回`status=resolved`；相同请求重复调用返回`duplicate=true`，不再追加结案事件。任务不在适用状态、原ID不符、依据文件缺失／越出项目或替代任务未完成时拒绝，不覆盖既有不同结案决定。工具只写本地任务状态、结案事件及原执行附件中的后台摘要和过程记录，不连接远端，不修改批准记录，不触发通知。原请求、异常和原成果计数仍可在任务详情核对。


### 浏览服务监控接入

`--record-dir`、上传绑定的`file`、普通成果的`path`及分段`targets.path`共用项目根目录基准，与当前工作目录无关。例如`--project /工作区/projects/示例项目`时，执行目录填写`09-剧集制作/EP001/其他资料/执行附件/本任务`，不能填写`projects/示例项目/09-剧集制作/...`或再次加上项目名。也可填写该项目内的完整绝对路径。Agent入口和后台在入队前拒绝重复前缀及越界路径，明确报错，不猜测或自动剥掉前缀；失败时不会登记任务、创建执行目录或开始上传。`--workflow`、`--output-plan`、`--uploads`等JSON文件参数仍按当前工作目录定位，计划文件中的本机素材和成果路径才按项目根目录解析。已有历史证据兼容读取，不把新入队校验用于改写原始响应。

先启动[浏览服务](../../../../工作区浏览服务/README.md#日常启动)，在真实Codex执行环境调用入口。Node、已安装桌面适配器、CODEX_THREAD_ID及CODEX_APP_TOOLS_PIPE_PATH用于来源会话通知，不伪造。连接上下文只存本机runtime，不暴露到项目证据或网页。专用接口接受本机Agent凭证，不接受浏览器Origin。SQLite、runtime及本机连接不随技能分享；缺少完整工作区后台时不能执行这条入队流程。

普通成果映射示例：

```json
[{"node_id":"实际保存节点ID","output_key":"images","index":0,
  "path":"候选/CH001-本次版本.png",
  "response_name":"本任务-取回响应.json"}]
```

path是Agent指定的项目根目录相对路径及文件名，不是远端路径，不放执行附件。当前设备的项目内绝对路径仍可作为入队参数，但后台转换为相对路径保存；上传映射file及分段targets.path使用同一规则。节点、output_key和从0开始的index选择真实结果；后台完成后再从history取得远端filename／subfolder／type。普通任务不得空映射；导演台原生分段使用output-plan空数组并提供如下segment-plan。文件名与路径须换成真实项目值：

```json
{"director_node":"502","report_node":"403","output_root":"E:/实际ComfyUI/output",
 "targets":[{"index":0,
  "path":"09-剧集制作/EP001/其他资料/候选视频/EP001-C001-P001-R001-一采.mp4",
  "response_name":"P001-最终取回.json"}]}
```

targets必须逐一对应输入映射selected_indices，保留原始组序，不压缩未选组。report_node必须连接director_node的report槽位5；output_root按远端实际配置核实。后台按[任务完成后取回全部成果](ComfyUI-任务监控规范.md#2-留档与收尾)读取成功任务的最终报告，将全部预期文件保存到targets指定位置；不使用运行日志或猜测目录，不覆盖已有文件。

入队成功返回dispatch_state=enqueued、local_task_id（UUID4）、monitor_id及status=local_queued（使用--start-paused时为paused）；此时还没有远端prompt_id。对同一执行附件、相同入队资料重复登记返回原ID；资料不同拒绝，不能改目录绕过原任务。后台真正提交后保存远端ID和实际请求。完成、失败、重启与通知规则读取[任务监控规范](ComfyUI-任务监控规范.md)。

入队后的Agent操作直接进入[后台任务查询与结果处理](#后台任务查询与结果处理)，按当前动作只读对应工具小节。
