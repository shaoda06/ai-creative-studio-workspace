# 业务接入规范

业务阶段维护内容、类型、规格、来源资格、记录格式和采用。后台接收明确请求及结果适配，只维护执行、持久化和展示机制。业务接入模块是代码模块，不是三级技能。

图片结果适配由backend/services/image_tasks.py明确分发：technical只核对请求和文件；serial-drama及未指定adapter的既有计划调用短剧图片业务接入。未知适配快速报错，不执行任意传入脚本。

图片任务清单准备由backend/services/submission_plans.py按同一显式适配分流：technical复用调用工具已装配API及技术映射；原短剧计划调用D06的drama_image_plans，不在后台再实现图种、布局或资料卡规则。技术清单接口见[统一分配](../../studio-comfyui/references/固定脚本接口规范.md#统一分配与提交)。

短剧图片的准备、候选、批准、正式保存和业务投影在[图片阶段](../../nora-drama-images/SKILL.md)维护。backend中的image_closeout、imagegen_results、local_images是同一业务实现的兼容入口，不保留第二份可编辑规则。

技术完成、业务登记、网页同步和用户采用分别处理。业务登记失败恢复原记录；网页只读取实际资料，不以文件存在或任务成功推断批准。共用参数和文件路径保持验证，不能借业务解耦移除来源、认证或不可逆写入保护。

调用方没有业务展示记录时，后台可返回技术成果及文件链接，不强制创建短剧结构。现有业务展示接入的字段含义按所属业务规范，公共组件及交互由浏览服务统一维护。

项目总索引的格式、登记、分类排序及读取统一按[项目总索引规范](项目总索引规范.md)及其脚本执行；业务只提供项目根目录和创建时机。

## 项目媒体清单与剪映下载

登记项目空间的资料树识别以`.jianying.json`结尾的显式剪映媒体清单，在文件旁复用公共下载按钮提供jypack及按需ZIP。列资料、打开预览不生成包；用户点击下载时后台调用提供端studio-jianying的同一export_archive，返回下载并清理本次临时包，不另建业务打包器。

清单沿用共用剪映工具的name/media结构；文件路径由后台在当前项目内解析，包内名称及时间线由调用业务明确：

```json
{
  "name": "本次剪辑交接",
  "media": [
    {"file": "media/选用视频.mp4", "member": "01-选用视频.mp4", "timeline": true}
  ]
}
```

file使用当前项目内文件，优先项目相对路径；member为包内相对路径，不能越界、重复或占用草稿JSON名；timeline默认true，false只放素材箱，至少一项进入时间线。清单是本次明确组合的技术输入，一个可复用交接组合保留一份，不是另一份业务采用真源；当前业务负责实际采用与顺序，不按文件较新自动更换素材。

只读下载接口为`GET /api/workspaces/{space}/projects/{project}/jianying-download?path={清单项目相对路径}&format=jypack`，format只支持jypack/zip，默认jypack。资源绑定所属空间，清单及媒体均经既有项目文件边界解析；不接受其他项目、隐藏路径或越界链接。新入口不需要EP/人物卡，不修改项目采用或完成状态。

后台复用工具的媒体读取、归档成员与时间线检查；请求缺文件返回404，清单/打包输入错误返回409，不提供残包。修正原清单或补回同一输入后可重试原下载；未点击不会自行打包。HTTP成功和结构核对不声称已在剪映客户端导入，常规下载不逐包打开客户端。Agent调用打包仍需用户明确要求，测试或工具开发的隔离验收按各自授权。

## 完整制作页共用

完整制作页共用对象列表、轮次、分镜、导演表、视频连播、意见和按需下载的展示与交互。Nora、Iris、Chloe 接入分别提供实际资料、标签和操作地址，业务条件由所属业务维护。Chloe按具名项目及其内部V视频提供资料，分镜、历史脚本时码、轮次和下载映射见[视频制作接入](../../chloe-production/references/视频制作流程与记录.md)。Nora 的原接口、路径、轮次、意见及草稿标识继续使用；共用组件不硬编码 Iris 的目录或批准条件。Iris 的整片轮次只按其[生产阶段](../../iris-commercial-production/references/整片制作轮次与网页接入.md)提供，不把任务批次直接当整片轮次。共用页不创建独立后台或任务库，不自动提交任务或打包。

### 按制作对象选择工作流

先从制作清单选择对象（Nora 的 EP、Iris 的 F、Chloe 的 V）。共用工作台读取该对象详情的 `productionWorkflows`：有一套正式制作记录时直接进入对应页面，有两套时先显示「选择查看的制作记录」。进入后在选中的工作流里查看轮次。中间页的选择只影响本次浏览，不改变制作时绑定的工作流。没有正式记录时沿用对象提供的 `productionWorkflow`；兼容没有工作流字段的旧逐段记录。准备稿不计入正式制作记录。

业务接入提供对象详情、原记录、轮次与候选引用。AiMixer 沿用逐 P 视频数据，Songssx 按场提供一个视频和各 P 对应的 GEN 成片区间。Songssx 通用读取器从原任务状态、请求和取回凭据投影整场视频、实际提示词及用图。整轮包通过对象详情地址的 `/rounds/{number}/download` 路径读取，保留原视图参数。新增工作区只需把自己的业务资料映射到现有字段，并使用共用工作台；工作流入口、播放器及轮次选择由共用组件提供。

### Songssx 整场视频下载

Nora、Iris、Chloe 共用播放器的浏览器原生控件保留「下载」。浏览器将下载放在更多菜单时，从该菜单保存当前播放的视频。Songssx 切换 GEN 只跳播，播放源仍是所选场次及轮次的同一个整场文件。整轮 ZIP 与剪映草稿在「资源下载」。

### 整场后处理审阅

整场或整片 MP4 单独提交后处理时，向对应制作轮次的 `review_outputs` 登记一项。Iris 按[任务清单接口](../../iris-commercial-production/references/任务服务接入.md#iris-制作轮次自动登记)由脚本生成该项。填写 `label` 作为展示名称、`postprocess` 作为本次后处理执行目录、`source` 作为实际输入视频版本。两个路径以项目根为起点。Nora 在当轮对应场次登记，Iris 和 Chloe 在作品轮次登记。

共用读取器以执行检查报告核对唯一实际输入及唯一整场 MP4 输出，取回凭据和文件齐备后开放播放。整场产出在「本轮审阅产出」展示，原分段组合仍提供分段播放和意见。分段后处理继续按实际分段执行登记。已有 Nora `songssx_postprocess` 整场播放器关联继续使用，并复用相同的源片校验。

### Songssx 派生整场主播放

局部替换接回或整场后处理完成后，先核对整场时长及 P 段切点仍与原 Songssx 时间轴对应。要将派生整片作为该轮主播放器的来源，在当轮 `review_outputs` 的完整 MP4 条目增加 `playback`，例如 `{"scene":"S001","run":"R006","stage":"场次生成"}`。以实际场次、制作批次和阶段填写，整场后处理的阶段用「后处理」。每场每轮明确选一条。Nora 在所属场次的轮次记录登记。

本地已接回的整片用 `file` 引用准确版本。后台整场后处理用 `postprocess` 与 `source`，仍按取回凭据读取。原场次执行继续提供 GEN 时码、分镜及生成上下文。主播放器、下载和新意见使用所选派生整片；带 `playback` 的视频直接在主播放器展示。「本轮审阅产出」继续用于试片和对照。

### 制作页参考素材

Nora、Iris、Chloe 共用参考素材组件。AiMixer 按当前候选的执行记录显示「公共参考素材」和「本组参考素材」。Songssx 只显示「本段参考素材」，按所选轮次、场次和当前 GEN 取图。点击分段或整场视频播放跨入另一 GEN 时，参考图与该 GEN 的分镜、提示词同步更新。

Songssx 读取原提交请求中该 GEN 的图片绑定，按实际顺序显示 `<Picture N>`。请求尚未落盘时，从该轮装配记录显示已准备的绑定；具体来源见[Songssx 素材绑定](../../studio-h3-songssx/references/ComfyUI-Songssx导演台使用规范.md#素材绑定与检查)。同一图片可被多个 GEN 分别绑定。素材池、项目资产清单及其他 GEN 的绑定都不参与补图。已绑定原图缺失时保留槽位并提示缺失。

新增业务接入按工作流提供轮次和素材数据，复用上述显示规则。共用组件支持两种记录格式，实际可进入的制作记录由各业务的资料适配决定。

## 资料变更与解析接入检查

业务接入负责提供真实资料根、项目／作品身份、源文件、字段、章节、索引与准确资源版本；公共服务负责解析调度和组件展示。变更目录、文件名、编号、表头、状态含义或素材引用时，先核对所属业务的接入说明，再定位对应解析器、数据结构和组件调用，不以链接有效代替字段语义检查。

- Nora输入格式读取[短剧浏览接入](../../nora-serial-drama/references/项目浏览入口规范.md#5-输入格式与解析依赖)。
- Iris制作接入读取[整片轮次与网页接入](../../iris-commercial-production/references/整片制作轮次与网页接入.md)，项目与作品路径读取[建档规范](../../iris-commercial-brief/references/项目建档与README规范.md)。
- Chloe字段与栏目映射读取[固定资料写法](../../chloe-positioning/references/固定资料写法规范.md)，制作接入读取[视频制作流程与记录](../../chloe-production/references/视频制作流程与记录.md)。

原文保持唯一来源；展示标题或业务标签可通过接入映射提供，不复制一份页面专用状态。不改变解析字段、路径或状态含义的规则链接与措辞调整，无需适配解析器或运行页面测试。确需修改公共代码时按实际授权执行，并按[开发维护](浏览后台开发维护规范.md)完成受影响的解析、错误恢复和展示检查，不以改写批准事实迁就组件。

## 项目归档接入

项目标记及 Codex 对话流程由[共用归档](../../studio-archive/SKILL.md)维护；共用读取位于 `scripts/workspace_project_index.py` 的 `read_archive`。只读项目根 README 中的项目管理状态、归档原因、最近归档时间与最近恢复时间；未标记项目不添加 `archive`，页面按进行中展示。显式标记返回 `archive.status`（active／archived）、`reason`、`archivedAt`、`restoredAt`；重复字段、未知状态及缺少原因／归档时间的已归档标记报告错误，不按制作进度推断。

`/api/workspaces` 的项目列表包含归档属性；Nora 与 Iris 读取 projects 下整个项目的 README，Chloe nested 布局读取具名账号项目 README，不读取内部单条视频来决定账号项目是否归档。Nora `/api/projects` 使用同一读取。索引格式、迁移及同步见[项目总索引规范](项目总索引规范.md)，实际分类仍以 README 为准。

ProjectSpace 使用公共 TabNav 区分进行中和已归档，公共 TabSelect 筛选归档原因，EntryCard 展示项目与原因；筛选写入当前页面查询参数，默认进行中，按[共用索引规则](项目总索引规范.md)使用分类内顺序及序号。ProjectSwitcher 保留项目入口并用公共 badge 标明已归档及原因。服务每次列表请求读取标记，不写回项目，不提供网页直接归档或 Codex 批量操作接口。旧 `.archived` 继续表示迁移只读并从列表排除，与本标记独立。
