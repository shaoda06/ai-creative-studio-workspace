# 任务运行资料维护规范

## 归属与保存

统一浏览服务维护本规范。一级工作区创建规范只引用这里，不在业务技能或资料区另建后台维护规则。

所有任务运行资料位于总服务`工作区浏览服务/runtime/`：

```text
runtime/
├── service.json                 本机服务启动配置
├── workspaces.json              附加资料空间登记
├── server.log                   统一进程日志
└── workspaces/
    ├── nora/
    │   ├── comfy-tasks.sqlite   Nora任务账本
    │   └── task-service.json    本空间连接与内部凭证
    └── iris/
        ├── comfy-tasks.sqlite   Iris任务账本
        └── task-service.json
```

每个资料空间使用独立SQLite库，记录任务、状态、事件、任务组和通知。任务归所属空间，由同一进程管理；不按单个项目另建库。项目中的媒体、执行附件、采用和业务记录保留项目原位置，不搬入运行目录。

## 新增一级工作区

1. 按工作区结构规范建立真实资料区及projects，确定唯一空间id；显示名称或业务目录改名不自动改id。
2. 各业务初始化命令传入`--register`时调用共用`workspace_setup.py`登记；Nora使用默认目录，不写重复登记。Iris保持API id `commercial`、runtime_id `iris`及`iris-commercial-production`适配，Chloe使用id `chloe`及`chloe-production`适配。已有相同登记保留显示名称、归档映射等字段；冲突时报错，不覆盖。初始化命令顺序执行。手工登记时在`runtime/workspaces.json`登记id、name、path，业务适配按实际需要登记。默认运行目录为`runtime/workspaces/{id}/`。已有API标识与名字不同的空间可显式指定稳定的`runtime_id`；例如Iris保留API id为commercial、runtime_id为iris。标识只允许小写字母、数字、连字符，不能与已有运行目录重复。
   页面类型与生产接入分开登记。通用资料页默认使用`files`，采用Iris商业流程栏目的资料区登记`"view": "iris-commercial"`；生产记录和视频审阅继续由已登记的`production_adapter`接入。
3. 通过统一启动器加载登记。后台自动建立该空间任务库和连接文件，不要求Agent手工建SQLite或复制其他空间的库与凭证。
4. 核对登记空间、项目索引、只读连接和空任务列表；普通建档不提交生成。业务目录内不创建“工作区浏览服务”。

客户端从总目录向上定位统一服务，根据实际资料路径匹配登记，读取对应集中连接文件。Nora默认连接从workspaces/nora读取；未登记或配置缺失明确报错，不猜空间、不跨库查询，不回退旧目录。

## 备份、迁移与恢复

- 迁移任务库或升级数据库结构前，先查执行、排队、取回和准备任务；等待本次运行结束后，通过既有启动器停止服务，避免复制时继续写入或两个进程调度同库。
- 停止后备份各空间SQLite及本机登记；本次迁移保留一份操作前备份，记录原路径和任务数量。备份、运行库、连接凭证及日志不加入Git或模板分发；不把运行库作为多机同步队列。
- 原库迁到目标位置，保持任务ID、原请求、远端prompt_id、结果、通知及空间归属。旧技术日志和接入说明按历史保留，不作为现行启动入口。验收通过后移除旧运行目录，不长期保留跳转链接。
- 通过统一启动器重开，客户端连接凭证由后台重新生成；核对原任务详情、结果和通知记录可接续，再核对网页。恢复依原任务取回或修复登记，不重提交生成。
- 切换失败时先停止新实例，恢复操作前代码、登记与数据库，再从启动器重开；不在运行中覆盖SQLite。数据库结构变更须明确升级方式及恢复所需匹配版本，本次只变路径，不改表结构。

## 日常留存与退役

任务数据库是执行事实，不随日志清理、缓存清理、项目目录改名或工作区取消登记而删除。技术日志用于排障，可在获授权的整理范围内归档或轮转；通知、请求、响应等事实按既有精简留档规范保留，不以日志替代。

已完成任务随业务资料归档到其他空间时，任务仍归原库。可在目标空间的 `runtime/workspaces.json` 登记 `task_history_archives`。每项填写 `source_space`、目标 `project`、项目内相对 `directory` 和本次确认的 `task_ids`。归档沿用原项目相对文件路径，任务详情按登记打开实际文件。核对原任务记录和所有新文件入口后再退役旧项目目录。

本规范不新增定时备份、任务清理或自动删除。工作区退役时先停止其调度并明确任务和资料的保留位置，按实际整理授权处理备份及旧库；不把取消登记当作删除授权。
