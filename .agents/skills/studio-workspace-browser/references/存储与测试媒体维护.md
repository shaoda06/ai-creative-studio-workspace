# 存储与测试媒体维护

## 项目解析缓存与服务日志

项目解析缓存是可重建的网页数据，不是H3生成缓存。正式启动器在启动服务前调用`ProjectStore.prune_cache()`，清除工作区根路径不符、缓存结构不兼容或项目目录已不存在的缓存，移除清理后空目录；保留当前兼容缓存。普通服务版本递增不清空缓存，只有解析结构或语义不兼容时才递增`CACHE_SCHEMA`。无法识别的文件保留并记录警告，不把整个runtime当作缓存删除。

`scripts/service_logging.py`统一配置服务日志：`runtime/server.log`单份最多10 MiB，保留2份轮转备份，总计约30 MiB。成功的状态、项目、任务轮询GET不逐条记入访问日志，错误、警告、写操作及其他请求仍记录。系统托管的启动阶段输出保存在`runtime/launcher.log`，每次正式启动前清空；服务日志不再写到系统托管进程长期持有的标准输出文件。`request-diagnostics.jsonl`沿用独立轮转配置。

历史大日志需要缩减时，先通过统一启动器停止已核对的服务、等待旧进程退出，再保留近期尾部并清掉旧内容；不得直接删除仍被服务写入的日志。任务SQLite、连接配置、执行回执、迁移备份和模型生成缓存不属于本节清理对象。

新版日志初始化会自动处理超过上限的旧主日志及两份轮转备份，仅保留各文件近期约2 MiB的完整行，随后进入正常轮转；初始化仅由新托管worker执行。

## 项目整理快照

目录整理和迁移需要留存操作前资料时，使用`scripts/project_snapshot.py`，不使用整树复制或将图片、视频、音频重新装入ZIP。业务决定需要留存的对象和位置；工具保存选定记录的原字节、准确资源版本及必要附件引用。原生交付和独有资料按[项目资源与版本管理](项目资源与版本管理.md#历史迁移快照和交付边界)保留，不将其当作缓存自动整理。

脚本使用Python 3.10及以上标准库；选定资料、ZIP输入输出路径相对`--project`指定的项目根目录，`--mapping`、`--destination`使用当前目录相对路径或绝对路径。资源须已登记并只读保存。`--include`必须明确给出本次受影响文件／目录，可重复指定，不默认备份整个项目。选中的媒体及Markdown／JSON中的资源引用写入包内`快照资源引用.json`，文档仍保存原字节；已有ZIP、jypack及模型缓存只留文件位置和原大小／修改时间，不嵌套打包。无法完整解析的原JSON照原字节保留，在结果及清单的`unparsed_documents`中明确列出，不伪造其内部引用。

```bash
python3 .agents/skills/studio-workspace-browser/scripts/project_snapshot.py --project "/实际项目" create \
  --include "本次阶段/受影响文稿.md" --include "本次执行记录/资源关联.json" \
  --output "99-综合资料/其他资料/历史版本/实际事项-整理前快照-实际时间.zip"
python3 .agents/skills/studio-workspace-browser/scripts/project_snapshot.py --project "/实际项目" restore \
  --archive "/实际项目/实际快照.zip" --destination "/尚不存在的独立恢复目录"
```

`create`不覆盖已有快照，先复用同一版本的原入口；`restore`仅写入新的独立目录，按准确版本补回媒体，原项目不变。二者不联网、不生成媒体、不修改采用或任务数据库。成功输出JSON数量；未登记、非只读、引用失效、路径越界或目标已存在时报错，不发布未完整读取的ZIP。恢复目录若仅用于核验，核验和记录完成后清除，不再留一份完整媒体树。

已有完整快照只在用户明确授权后使用`compact --archive "项目内旧快照.zip" --mapping "/本次路径对照.json"`。对照JSON为“包内原媒体路径→本项目准确资源文件”的对象。工具逐项完整比较媒体与固定版本，原文档逐项字节核对、ZIP完整读取通过后，才原位替换为记录和资源引用；原包名称和外部引用保持。缺项或不同内容不替换，不用当前稿补写历史记录。

同一已迁移订单的历史兼容路径确需继续读取时，可在明确整理范围内用`media_files.store_media()`将字节及修改时间一致的历史媒体入口合并为同一份只读数据；保留原路径与执行凭据，不跨独立项目自动查找合并。新整理快照仍使用上述引用机制，不以复制完整历史树代替归档。

相关隔离检查：在`工作区浏览服务/`运行`python3 -B -m unittest tests.test_project_snapshot -v`，覆盖不重复装入媒体及原生包、原记录保留、按具体版本恢复、完整读取失败保留原包、不同媒体拒绝替换和路径边界。

## 隔离测试媒体准备

技术测试目录先按[归属与隔离要求](../../studio-entry/维护规范.md#技术测试与隔离验证)确定。新建或补充样稿、演示及媒体验证材料时，使用本技能`scripts/prepare_test_media.py`准备需留存的媒体，不直接整树复制素材。下载、转码和派生预览的中间文件写入该入口提供的`{tmp}`目录，完成或失败后自动删除；只有清单`files`中声明的必要输入或成果进入测试目录。真实生成仍使用原模型工具和任务记录，本入口不提交生成、不修改业务采用。

示例清单（源地址、命令和输出均须来自本次实际任务，不照抄示例路径）：

```json
{
  "commands": [
    ["ffmpeg", "-nostdin", "-i", "/实际来源/输入.mov", "{tmp}/preview.mp4"]
  ],
  "files": [
    {"source": "/实际来源/输入.mov", "output": "media/final.mov"},
    {"source": "/实际来源/输入.mov", "output": "files/原路径.mov"},
    {"source": "{tmp}/preview.mp4", "output": "media/preview.mp4"}
  ]
}
```

```bash
python3 .agents/skills/studio-workspace-browser/scripts/prepare_test_media.py \
  --root "综合资料/实际测试事项" --manifest "/实际位置/媒体准备.json"
```

命令使用参数数组顺序执行，不使用shell，工作目录为临时目录；只填写已获授权的本地技术处理命令。`source`支持测试根目录内相对路径、外部绝对路径、`{tmp}`绝对路径及HTTP(S)下载；下载文件先进入临时目录。`output`必须位于测试根目录内，已有不同内容则停止，内容更新另存新版本，不覆盖原样稿。

底层统一调用`scripts/media_files.py`的`store_media()`；[PNG保存入口](../../studio-image-processing/references/图片处理工具规范.md#png保存复用与替换)也调用同一实现。同一测试目录内、同扩展名且字节完全相同的文件共用只读数据，所有网页和下载路径照常保留；再次准备不会新增一份数据。外部正式项目只作为读取来源，不能与测试目录硬链接。临时写入目录不参与复用。报告、截图、必要输入及独有测试成果按原规则保留；下载核验包仍按[下载核验包清理](../../nora-serial-drama/references/文件版本与工作稿规范.md#下载核验包清理)收尾。
