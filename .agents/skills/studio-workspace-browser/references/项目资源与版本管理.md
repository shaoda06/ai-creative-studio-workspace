# 项目资源与版本管理

每个项目独立保存图片、视频和音频；业务目录保存索引、制作稿、审核、采用及执行资料。共用存取实现位于本技能`scripts/project_resources.py`，网页在项目“资源／项目资源”中浏览及导入，不使用跨项目资产库代替项目资源。

## 目录和身份

```text
项目/
├── 资源/
│   ├── 资源索引.json
│   ├── 图片/IMG-编号/
│   │   ├── 资源信息.json
│   │   ├── V001/原文件.png + 版本信息.json
│   │   └── V002/修改文件.png + 版本信息.json
│   ├── 视频/VID-编号/…
│   └── 音频/AUD-编号/…
└── 原业务阶段目录/索引、Markdown及执行记录
```

首次产出创建资源编号和V001；同一制作目标的修改、重做和处理结果继续该编号，新增V002、V003，不覆盖旧版。一个任务有多个实际候选时各占一个版本；分支明确记录实际使用的来源版本，不默认以上一版本为源。不同人物、不同机位或另一张独立用途图片使用不同资源编号；同一人物的所有图片不强行并为一个资源。

CH、SC、PR、RA、RV、A及EP/C/P/R等业务编号继续由原业务记录维护；资源版本不取代业务编号、候选v编号、视频R编号或文稿版本。历史迁移的V号是资源整理序号，原文件名、原版本和执行身份保留在来源记录，不伪称当年生成时就有此编号。

JSON记录资源编号、不可变版本、具体文件、来源、实际技术参数及处理关系；Markdown继续记录制作要求、审阅意见、通过／未通过、采用范围及用户决定。资源索引不再保存第二份批准状态。每次输入、审阅、采用和导出都绑定`resource_id + version`，同时保留该版本文件链接以便直接阅读；不使用“最新版本”替代明确采用。

## 上传原件与处理结果

- 用户上传的图片、参考视频和参考音频以`origin=user_upload`导入原字节，保留文件名、实际格式，不删除外部原件；没有生成任务时不补造模型、参数或prompt ID。
- 独立上传默认建立新资源。明确是原素材修订时填写原资源编号，必要时指定真实来源版本；同名不代表同一资源。
- 原件存储与模型输入资格分开。能解码的长音频、暂不适合生成的视频仍可保存为上传原件；具体业务及模型在使用时检查时长、容量、用途、来源授权和采用范围。保存成功不代表审核通过或可直接送模型。
- 音轨提取产生新的音频资源，引用视频的准确版本及实际区间；可独立使用的另一段剪辑也建立新资源并关联来源。同一段声音的降噪、同一张图的返修、同一视频的后处理使用原资源编号新增版本。原件不变；未获授权不自动裁剪、转码或提取。
- 原件本身已满足要求时，正式索引直接引用同一版本，不为“正式”“采用”再复制。只为技术分析短期产生的抽帧、试切放系统临时目录；需要长期保留的证据由原执行记录指向已登记版本。

## 调用与记录

```bash
python3 .agents/skills/studio-workspace-browser/scripts/project_resources.py --project "/实际项目" init
python3 .agents/skills/studio-workspace-browser/scripts/project_resources.py --project "/实际项目" import --file "/用户原件.wav" --key "本次上传身份"
python3 .agents/skills/studio-workspace-browser/scripts/project_resources.py --project "/实际项目" import --file "/已完成处理.wav" --resource-id "AUD-实际编号" --parent "资源/音频/AUD-实际编号/V001/原件.wav" --origin process --key "本次处理身份"
```

从视频取音轨时不填写音频`--resource-id`，以视频版本文件作为`--parent`，同时填写实际`--start`、`--duration`和项目内`--producer`处理记录。处理先按共用音视频工具完成，导入只登记真实结果，不执行媒体加工。

新Nora项目由建档脚本初始化资源索引；Iris建档时调用上述init。旧项目必须完成迁移再启用`managed=true`；向尚未迁移的项目导入一份素材不会自动切换整项目生成流程。

内置Imagegen等真实工具返回的原生文件，可用import命令的`--origin generated --producer <实际项目执行记录>`保存；首次保存返回编号，返修带原`--resource-id`和实际`--parent`。实际工具参数及返回值保留原JSON，来源类型不代表采用。

新生成请求的输出可声明`resource_id`，或由业务适配提供稳定`resource_key`。首次制作分配编号，返修显式携带已有编号；图片编辑用`base_file`，后处理从真实输入关联来源，H3二采按业务明确的缓存来源接续，不将参考视频当成父版本。任务受理前输出改为准确版本文件，结果取回完成才写版本事实。原请求／响应／工作流保留完整技术证据；记录旁的`资源关联.json`只列准确输入输出引用，不复制媒体或整份请求。相同任务、相同输出及导入key重试复用版本，不新增副本。

采用操作更新原业务Markdown及必要索引，指向同一版本文件；不移动文件、不再建立正式路径副本。审核不通过仍保留该版本及原意见。旧版本文件只读，新的实际内容必须另存版本；普通保存及替换入口均拒绝覆盖已经登记的版本。

网页上传、命令行导入、PNG保存和后台取回使用同一项目锁，查重、保存及版本记录写入在锁内完成。首次完成时，在本项目资源区内核对同扩展名文件的完整字节。相同字节可共用只读数据，每个独立产出继续保存各自的版本路径、执行来源和取回凭据。后台普通结果和分段视频取回沿用已分配的版本，原任务同一输出重试继续使用该版本。

## 历史迁移、快照和交付边界

普通旧候选、阶段采用文件和重复输入可在本次明确授权下迁移。先保存旧路径对应关系和受影响小文档原件，再建立项目内资源入口，更新当前业务链接，核对网页、执行凭据和采用事实，最后移除已验证的旧媒体入口及空媒体目录。字节相同且有复制关系的入口可指向同一版本；不同实际生成任务保留各自版本，不根据画面相似合并。不能确定同一制作目标的历史文件保留独立资源，不凭名字猜成返修关系。

`migrate_project_resources.py inspect`只读预览；`stage --audit`保留旧媒体并准备资源及当前链接；`finalize --audit`完整比较原件后才移除旧入口并启用新机制。迁移期间必须确认所属项目无执行中或排队任务；正式服务切换由统一启动器管理。旧技术资料中的地址通过资源索引的历史映射读取，原请求、响应、批准原话和已提交输入事实不改写。每个项目独立核对，不跨项目共享底层媒体。

完整封存快照、`历史制作资料/`及归档只读项目默认保留；用户明确授权精简历史副本时，按[项目整理快照](存储与测试媒体维护.md#项目整理快照)核对并保留原记录及独有内容，不因普通迁移自动整理。原生剪映／导演交付包及验收原件保留原样，不拆包改内部路径；最终人工剪辑交付按原业务保留。普通历史版本不因名字有“历史”就全部免迁。新过程快照只保存当时文档、准确资源版本清单及必要执行证据，不复制项目媒体树；外部接收方需要自包含原生包时，打包器按固定版本临时装入媒体，用户点击下载后清理临时包。手动编辑过或有交付／验收保留依据的原生包不作为缓存删除。

本规范不授权批量删除未采用版本、修改任务数据库、清理`.codex`、删除外部上传原件或撤销任何业务采用。

整理备份统一使用[项目整理快照](存储与测试媒体维护.md#项目整理快照)的`project_snapshot.py`保存原文档和具体资源引用；旧完整快照的授权转换及按引用恢复也从该入口执行，不用整树复制或通用压缩命令重新装入媒体。
