# 商业生产接入公共任务服务

商业业务使用共用[studio-workspace-browser](../../studio-workspace-browser/SKILL.md)提交、查询及恢复任务。浏览入口和任务监控由统一工作区服务维护，生产阶段不运行独立后台或任务页。服务登记和启停交共用工具，商业阶段只维护业务输入、成果归属与采用记录。

任务清单使用本项目的实际文件、输出位置和授权范围，通过studio-comfyui/scripts/comfyui_dispatch.py提交，先prepare-only，内容与授权齐全后入队。F 作品的新视频任务由提交脚本按[下方接口](#iris-制作轮次自动登记)登记本轮。technical 结果适配保存实际成果及媒体报告，审阅决定和采用依据由本阶段维护。

资料和执行附件保留在商业项目内；总技能库中的共用客户端按实际资料区匹配总服务登记，从总后台runtime/workspaces/iris/task-service.json读取统一地址、空间前缀和本空间token。查询、报告及恢复子命令明确传入`--workspace "Iris实际资料根目录"`。读取原任务状态、报告或重试取回时沿用原ID，不重新生成，不复制其他空间任务库或采用记录。


## Iris 制作轮次自动登记

在 Iris 空间的同一份任务清单顶层填写 `iris_round`，与 `tasks` 并列。由阶段提供明确版本和沿用来源，`制作轮次.json` 由脚本写入。

```json
{
  "iris_round": {
    "work": "F001",
    "record": "03-作品/F001-示例/06-视频生产/生产任务-R002-v01.md",
    "storyboard": {"file": "03-作品/F001-示例/04-分镜声音/分镜与声音制作稿-v02.md", "version": "v02"},
    "base_round": 1,
    "note": "修改 S001 的产品递接动作"
  }
}
```

- `work`、`record` 和 `storyboard` 必填。文件路径以 C 项目根为起点，正文和版本须属于同一 F。分镜用已确认的 `04-分镜声音` 逐镜稿，包含正式 P 段计划、逐镜字段和段内时码。可另提供 `script: {file, version}` 引用本轮 `03-创意脚本`，及 `prompts: {P001: "项目相对路径"}` 引用本批各 P 的同版中文提示词。未填写的可选引用不从最新文件猜测。
- 局部重做、补生成和整场后处理用 `base_round` 指定沿用的原轮。脚本按分镜排序，沿用未替换段及其批次。Songssx 整场任务用一个 MP4 对应本场全部 GEN，检查 P 顺序、请求时长及提示词 Shot 数。逐段任务从实际视频输出识别 P 编号。整场后处理核对原片与输出，补生成片段和整场后处理记入本轮审阅产出，供核对和接续。
- 清单放在本作品的 `06-视频生产/执行记录/Rxxx-阶段/`。执行目录可以是同一批次目录或其子目录。脚本从清单的装配结果、R 批次目录、分镜计划及任务真实输出形成轮次索引。轮次按生产记录关联，同一清单重复准备和入队沿用原轮及原任务 ID，历史已登记清单继续从原记录接续。

```sh
python .agents/skills/studio-comfyui/scripts/comfyui_dispatch.py --project "workspaces/Iris Workspace/projects/C001-示例" --plan "03-作品/F001-示例/06-视频生产/执行记录/R002-一采/任务清单.json" --prepare-only
```

从总工作区运行。既有项目使用实际路径及与目录匹配的工具，见[目录迁移与工具切换](../../iris-commercial-brief/references/项目建档与README规范.md#目录迁移与工具切换)。准备成功返回 `production_round`，写准备凭据和本作品轮次索引，无远端上传或入队。执行获授权后沿用同一命令及清单，去掉 `--prepare-only`。分镜或关联校验失败时先修正原输入，尚未入队且已装配的清单按[重新准备](../../studio-comfyui/references/固定脚本接口规范.md#统一分配与提交)接续。成功入队返回原轮号、组 ID 和子任务 ID。

## 视频制作页

业务展示适配由scripts/iris_browser_production.py维护，资料区在统一浏览服务登记production_adapter为iris-commercial-production。适配只读已提交装配记录、实际请求和输出；准备稿不冒充执行，任务完成不自动采用。不要求EP目录，不自行启动后台。H3技术正文及槽位解释调用共用studio-h3-aimixer/scripts/h3_browser_context.py。

网页先选择作品，再按该作品的完整制作轮次和分段显示视频、候选、参考与当次生成文字；原技术批次仍可追溯。缺少分镜快照或本地来源时明确提示；原业务文件在“制作资料”入口。用户主动填写的网页意见统一保存在当前作品生产目录的“视频修改意见.json”，按整片轮次、分段、阶段与R版本区分，旧候选意见保留原标识；它是审阅意见，不替代正式采用或客户决定。不为展示复制技术请求、媒体或另建状态台账。

多作品适配使用明确的 F 编号定位作品，文件与资源访问仍以项目根为边界。新执行写入作品目录。原任务保留原 ID、请求和当时登记的执行路径，迁移后的文件按[目录迁移与工具切换](../../iris-commercial-brief/references/项目建档与README规范.md#目录迁移与工具切换)解析。旧生产来源只从本作品的 `历史执行入口.json` 读取。各作品同名 P/R 的候选、意见与历史上下文分别读取，不能合并。

完整页面的对象、来源、意见与下载接入按[整片制作轮次规范](整片制作轮次与网页接入.md)执行，复用公共页面实现，不在业务阶段复制播放器或重写通用打包器。

## 后台结果接续

按[公共通知接续](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md#后台通知接续)读取最新报告，复用已完成的取回和技术核验。technical成功只证明技术结果；将准确成果、来源及实际规格关联到本F作品原生产批次和制作轮次，不复制媒体或再建执行台账。按[执行与接续](流程规则.md#执行与接续)等本批齐备后集中送审，保留逐段意见、采用和后续授权的原依据。

一采获批后仅按有效授权接续二采；二采和后处理按本单已确认目标与采用约定推进，不因通知完成自动扩大制作或推定客户验收。已有条件式授权满足时直接继续，不重复询问。返修及剪辑交接进入[本业务交接阶段](../../iris-commercial-handoff/SKILL.md)。异常按[公共恢复](../../studio-workspace-browser/references/进度查询与结果处理规范.md#异常与恢复)沿原ID处理，业务记录只补原批次缺项。
