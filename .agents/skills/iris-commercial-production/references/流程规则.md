# 视频生产流程与规则

生产实际输入和输出按[共用资源与版本](../../studio-workspace-browser/references/项目资源与版本管理.md)登记；本阶段在生产任务及作品状态中引用准确版本、客户意见和采用依据。

新视频按作品与P编号在每个输出target声明稳定`resource_key: "视频/F编号/P编号"`，已有资源时直接填写原`resource_id`；一采、二采、后处理沿用同一逻辑资源，新增具体版本。二采从原任务所指缓存接续，实际来源仍按源一采身份与原JSON追溯；唯一上传的参考视频不能被当作返修底本。需要媒体父版本时显式传准确`base_file`，不按最新版推断。

更新日期：2026-11-08。按用户已确认的业务决定和模板正式维护；规则落地本身不授权真实项目生成。

## 流程与接续

按[共用视频制作流程](../../studio-video-production/SKILL.md#生成资产与提示词)接续本批真实输入、提示词、请求核对、提交和候选处理。本阶段按下文维护批次范围、用户审阅和按需样片说明。

输入为当前有效分镜、明确素材版本、可用工具及本次授权；输出为本批生产记录、真实候选与实际决定，样片说明按需整理。已有明确阶段直接接续，不重做整个阶段。

## 执行要点

使用[生产任务模板](../templates/生产任务.md)，同一批次一份业务主记录，各段分别列清。按[共用制作层级](../../studio-storyboard/references/分镜写作规范.md#制作对象场次与分段)核对当前作品、场次和分段的对应。沿用项目现有编号和版本，镜号与生产段分别标识。已完整存在于有效分镜、声音表或内容稿中的制作说明直接引用，只补本轮差异；新生成段的模型正文按[提示词与绑定](#提示词与绑定)单独保存。

新制或修订的分镜按 [Studio 共用逐镜模板](../../studio-storyboard/templates/逐镜正文模板.md)写，按 [Iris 分镜与声音规则](../../iris-commercial-storyboard/references/流程规则.md#执行要点)登记 P 段、SH 镜号和段内时码。准备时锁定本批实际使用的分镜文件及版本，并按[轮次关联](整片制作轮次与网页接入.md#唯一轮次索引)登记。

Iris 使用 AiMixer 制作正式素材时，按“一采→用户审阅→二采”接续。样片或试验可明确只做一轮，其他工作流按实际机制安排。后处理依据本单明确目标选择，不自动补帧、超分、变速或改原声。现有条件式授权仍有效时，条件满足后直接接续，不重复请示；仅准备时明确记录仅准备，不提交生成。

## 提交前确认

1. **确定装配输入**：H3标准版的配置选择、询问及方向确定统一按[共用H3装配规则](../../studio-h3-aimixer/references/参数与基准规范.md#标准版配置选择与装配前询问)执行；本阶段提供作品状态中已确认的工作流、项目默认来源及本批执行授权。其他工作流按其共用工具说明确定装配输入。
2. **让用户看见本轮怎么做**：首次展示或方案有实质变化时，在提交前集中说明本轮是样片、一采、二采还是返修，采用的工作流、配置及依据，画幅和输出规格，以及预计成片总时长。逐段列段号、请求时长、主要画面及对应台词或声源，说明每段为何在此切开、下一段怎么接。需要时说明参考素材和暂留后期的内容。请求时长、预计成片时长和生成后的实测时长分别标明。可直接用短表或链接已准备的分段稿，关键选择和时长仍在消息中讲清楚。直接使用已备正文时复用已有技法说明，首次实际采用未验证写法且尚未告知的按[首次使用提示](../../studio-creative-techniques/references/学习与反馈维护规范.md#首次实际使用时的提示)补充观察重点。
3. **按确认的范围提交**：在[生产任务](../templates/生产任务.md)中写清工作流、实际配置及来源、方向和分段方案，引用作品状态里的决定与本批执行授权。按所展示且已获授权的方案提交，项目默认决定仍保存在作品状态中。原任务状态查询、取回与恢复沿用原执行记录。

## 提示词与绑定

编写、实质修订或提交前核对分段提示词时，按[共用视频提示词](../../studio-video-prompts/SKILL.md)落实本批分镜、实际参考、模型正文和同版中文。客户确认的业务文字、逐句声源及必要口型窗口按本片分镜与声音稿落实；参考中的业务状态有误时，按授权修正或更换素材。

模型格式、槽位、参数装配、缓存技术条件交[H3工具](../../studio-h3/SKILL.md)或实际模型工具；脚本处理明确文件和映射，后台负责通信与任务事实。通过[工具适配](../../iris-commercial-video/references/工具适配.md)定位唯一提供端，不在业务阶段复制工具或服务。

实际提交正文、请求响应、上传后路径、缓存身份及参数以技术档案为准，生产任务主记录只引用相关入口。

新生成段在提交前按[分段提示词模板](../templates/分段提示词.md)保存模型正文及同版中文参考。登记轮次后、送审前，在制作页核对每个新生成段的分镜来源及「提示词」中英文切换。

## 执行与接续

按[任务服务接入](任务服务接入.md)进入统一服务；业务只维护本空间输入、结果归属和采用，不运行第二后台。服务凭据留本地。任务副本与共享基准分开，不为单单内容改公共默认参数；未测模式/适配不得称已验收。

工具超时或中断先查原任务，恢复原ID及原成果，不自动重复付费提交。参数或内容变化保留历史，按本次授权处理新版本，不覆盖旧请求。技术完成不等于内容通过或用户采用。

候选默认按当前授权批次集中展示，列清各段版本及本次审阅重点，用户可整批采用或指定几段修改；采用仍对应具体段和版本。关键视觉/声线等尚未确定时，沿既有原则先少量验证，不增加每段单独审批或无差别固定样片环节。内容视听检查限本次获授权候选，不扩成全库审查。

收到针对具体生成效果的技法反馈时，按审阅所指的段和候选版本定位实际提交正文、模型模式及输入，再按[反馈复核](../../studio-creative-techniques/references/学习与反馈维护规范.md#实际反馈复核)更新对应参考。原意见与采用决定保留在本批记录。

一采审阅内容、角色、声源和动作；二采沿用获批一采真实输入、组序及匹配缓存。技术匹配按工具规范判断，MP4不能冒充潜变量缓存。输出对齐导致工作规格与交付目标不同时如实说明，按实际目标决定后处理。

完成本次范围后记录真实结果、问题及下一步来源，采用和后续授权各自引用原依据。回写作品状态时按[轮次摘要规则](整片制作轮次与网页接入.md#作品状态中的轮次摘要)链接审阅、返修与采用原记录。发现同类缺口核对受影响片段，只移交相关问题到[返修与交接](../../iris-commercial-handoff/SKILL.md)。

## 生产任务字段与填写时点

Agent维护业务内容，用户只作必要内容选择和授权，不负责手填整张表。已有有效决定、来源和技术记录直接引用具体文件/版本/章节，作品状态保存唯一决定事实。

### 每批必填——准备时写清

| 字段 | 具体填什么 | 填写与引用方式 |
| --- | --- | --- |
| 项目、批次及本稿版本 | 这份记录属于哪个订单和生产批次，当前采用哪一稿 | Agent维护业务身份；使用项目既有编号 |
| 本轮目标与范围 | 本轮是一采、二采、样片、返修或明确的后处理，包含哪些段及镜头 | Agent写清范围；不因一个请求自动启动其他阶段 |
| 当前内容依据 | 本轮有效的分镜/声音表、相关内容稿及版本入口 | 指向当前具体依据，不只写模糊的“见分镜”；没有单独声音表时不强制另建 |
| 生成路线与预期规格 | 本轮选用工作流、配置及确认来源、模型/模式、采样阶段、目标画幅/工作尺寸/帧率、预计总时长及交付目标 | 逐段时长和内容沿用分段计划；共用值引用一次，各段差异单独写。提交按[提交前确认](#提交前确认)执行 |
| 本次授权与条件 | 本轮允许执行哪些范围、采用何种有效依据、是否有接续条件 | 引用作品状态中的实际决定；仅准备时明确写“仅准备”，无需虚构生成授权或另加审批 |

### 每段必填——在同一主记录内列清

| 字段 | 具体填什么 | 必填边界 |
| --- | --- | --- |
| 段号、对应镜号、目标时长 | 本段身份、覆盖的镜头和本次目标时长 | 沿用现有段号与镜号，引用对应分镜范围 |
| 内容正文或有效入口 | 起始状态、动作/镜头及先后、结束状态及本段同版提示词文档入口 | 已在有效上游完整定义时引用具体内容，只补本轮差异。模型正文与中文参考按[提示词与绑定](#提示词与绑定)维护 |
| 输入方式与素材依据 | 明确本段使用纯文字还是实际参考；有参考时给出采用版本、真实文件、用途及标签/槽位 | 纯文字任务注明无参考即可，不创建空素材表；没有授权采用的素材不得写成已采用 |

同批共用值只写一次，逐段只填写差异。段内特有业务文字与声音等按下方“按需填写”的触发条件补充；不能为了“逐段必填”重复整份脚本或声音表。

### 发生后必有记录——引用原事实，不在准备时补造

| 字段 | 何时需要 | 由谁提供、业务稿怎么写 |
| --- | --- | --- |
| 实际执行与最终绑定入口 | 任务已准备/登记/执行，已有对应资料时 | 脚本/后台保存任务ID、实际请求、上传后身份与路径、参数和绑定核对结果；主记录链接原任务清单、报告或执行档案，不手抄技术流水 |
| 实际候选与输出入口 | 真实结果返回后 | 引用实际输出/候选及客观规格记录；尚未返回时只沿用原任务状态，不提前写完成 |
| 内容审阅与采用依据 | 审阅或采用决定实际发生后 | Agent记录内容问题，采用/批准事实引用项目原记录，并对应具体段和版本；尚未审阅或采用时保持真实状态，不自动采用 |

准备时这些事情尚未发生，不要求预先填任务ID、结果或采用决定；记录“未执行/待返回/待审”等当前实际状态即可。技术状态由后台维护，不另建手工进度台账。

### 按需填写——满足条件才出现

| 字段 | 什么时候填写 | 最少需要什么 |
| --- | --- | --- |
| 准确业务文字与画面状态 | 画面有必须准确呈现的产品/界面/卡片文字或业务状态时 | 准确文字、对应画面及时间窗口；已有有效内容直接引用，无此需求不新造文字表 |
| 台词、声源、口型与声音环境 | 存在台词、配音、特定声音或口型对应要求时 | 发声者、实际台词/声音依据、必要时间窗口及画内角色口型要求；沿用声音表，只补本段差异 |
| 参考素材明细 | 本段实际使用图片/音频/视频参考时 | 采用版本、文件、用途、标签/槽位；上传后的远端路径及最终API字段引用执行报告 |
| 二采或接续来源 | 本轮是二采或需要沿用既有结果/缓存时 | 引用具体已审一采/来源及采用或接续依据；真实缓存身份/匹配结论由工具记录，不在业务稿重复维护 |
| 返修反馈与本轮差异 | 本轮修改已有内容时 | 问题来源、受影响段/时间范围、本次改什么、哪些原采用仍可复用；实际返修细节沿返修阶段入口记录 |
| 问题、未完成项与下一步 | 有实际问题、未完成范围或待接续动作时 | 具体对象、问题和本轮处理范围；需后续授权时引用原决定，没有则不写成已授权，不为正常任务凑问题 |
| 本阶段交付整理 | 本次确有对外样片/说明稿整理需要时 | 整理稿版本、生产来源与实际附件范围；用户批准/发送/甲方确认引用作品状态，实际导出后才链接PDF及检查报告，不自动导出或发送 |

## 交付整理与完成

确需向甲方说明进展或展示实际样片时，使用[制作进展与样片说明](../templates/制作进展与样片说明.md)从现有资料整理，不因每批生成完成自动新建。仅说明进展而无实际样片时如实说明，不为填表新增生成或预定附件。

本阶段对外字段按以下范围填写；生产来源映射留内部主记录，客户稿不含内部路径、任务编号、服务、缓存、候选状态或技术流水。实质修改先回写生产内容，再整理对外版本。按[跨阶段交付规则](../../iris-commercial-video/references/对外交付.md)审阅Markdown、批准具体版本后导出PDF；有效批准直接沿用，不自动导出或发送。生产完成、整理完成、批准导出与甲方确认分别记录。

### 使用本模板时必填

| 字段 | 具体填什么 | 填写边界 |
| --- | --- | --- |
| 项目名称、版本、日期 | 当前是哪份对外说明 | 标识对外稿，内部生产来源映射留原生产任务，不在客户正文列本机路径或任务编号 |
| 本轮说明目的与覆盖范围 | 本次是说明进展、展示内容方向，还是请甲方审阅具体样片；实际涉及哪些内容/镜头 | 依据真实已完成范围，不把未返回任务或未展示内容写成已齐备 |
| 现有成果与附件对应 | 本轮展示的实际成果；有附件时列文件名、对应内容/镜头、用途或审阅重点 | 附件不存在时不填预定文件名、不造空成果表；若只有进展说明，明确本轮未附样片。已在总说明写清的审阅要求不逐附件重复抄写 |

有样片附件时使用三列表：`实际附件名称｜对应内容/镜头｜用途/审阅重点`。原模板的“展示目的”和“本次需要审阅的内容”合并到第三列，按实际需要写，避免逐行重复。

### 按需填写

| 字段 | 什么时候填写 | 填写内容 |
| --- | --- | --- |
| 画面、声音与业务文字说明 | 实际结果有影响理解、判断或选择的内容时 | 说明相关画面、声音、台词或文字；不强制为三个类别各写一段，也不抄技术流水 |
| 本轮修订说明 | 本轮确有已完成修订、需要让甲方了解时 | 修改了什么及对应范围，来源于有效生产记录，不在对外稿独自新增修改 |
| 本次需要确认的事项 | 确需甲方就本轮内容作具体判断时 | 写清要确认的画面、台词、声线、角色或衔接；仅供知悉时不凑问题、不新造确认步骤 |
| 未展示范围与后续安排 | 只展示部分范围，或有影响本次理解的剩余内容时 | 说明覆盖边界及已有约定的后续安排，不自行承诺新工期、新版本或免费返修 |
| 预览或使用限制 | 实际存在会影响本次判断或使用的限制时 | 说明本次样片用于核对什么、哪些内容未覆盖；不把内部失败、候选状态或模型诊断整段搬入客户稿 |

## 已确认的技术留档边界

新任务按[共用后台精简留档](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md#执行附件精简留档)维护技术凭据、独占提交保护及失败恢复；旧历史按原布局读取，不原位转换或清理。业务候选、采用及客户决定留原业务记录，不再复制技术响应或另建状态台账。


## 整片轮次与制作页

本批方案确定送审或准备执行时，按[制作轮次与网页接入](整片制作轮次与网页接入.md)登记并关联实际执行。局部返修沿用来源轮中未改的分段。生成批次和候选保持实际身份，网页按本轮登记的范围读取。
