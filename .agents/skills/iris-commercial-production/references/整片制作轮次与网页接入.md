# Iris 整片制作轮次与网页接入

## 轮次与批次

制作轮次是明确供审阅的一套整片版本组合。只返修 P004 时，新轮引用该段新候选，未改段引用原具体版本，保留旧轮。把一采组合换为明确的二采或后处理组合也可登记新轮。临时切换候选查看、失败重试和重新下载不新增轮次，不要求全片重生成或重审。生成批次 R 编号与任务 ID 沿用原记录，不能机械当作整片轮次。

Agent 按实际制作安排维护轮次关联；脚本核对路径、版本及候选对应，网页读取并按原位保存意见。打开页面不创建轮次，不生成媒体，不推定采用，不扩大执行授权。

## 唯一轮次索引

每件作品在 `06-视频生产/制作轮次.json` 保存一份索引。按顺序追加明确组合，已登记轮次的范围和来源保持可追溯。只存文件引用与必要说明，不复制媒体、技术请求、提示词或全部脚本文字。

```json
{
  "rounds": [
    {
      "number": 1,
      "created_at": "实际登记时间",
      "note": "本轮范围与审阅目的",
      "script": {"file": "作品/F001-示例/03-创意脚本/制作脚本-v01.md", "version": "v01"},
      "storyboard": {"file": "作品/F001-示例/04-分镜声音/分镜与声音制作稿-v01.md", "version": "v01"},
      "batches": ["06-视频生产/执行记录/R001-一采/提交任务清单-装配结果.json"],
      "segments": [
        {"id": "P001", "duration": 5, "stage": "一采", "run": "R001", "file": "资源/视频/VID-实际编号/V001/P001.mp4"}
      ]
    }
  ]
}
```

所有 `file`、`batches` 都以 C 项目根为起点；图示编号仅为占位。每段引用明确候选和资源版本，不能按最新文件猜选。脚本和分镜的 `version` 与实际文档一致；历史依据尚未找到时相应来源可为 `null`，说明缺项，不用当前稿充当旧版。

逐段生产正文另在生产任务中维护时，轮次可用 `plan: {file, version}` 明确引用；否则沿用该轮分镜。段内可用 `prompt` 引用当时的双语提示词文件。两者只存路径，不抄正文，不用当前稿补旧轮。

尚未形成明确审阅组合时不造“第0轮”。网页读取作品状态指向的当前脚本、分镜和计划分段，显示未生成状态；实际候选继续依据任务证据读取。已有主记录只补轮次入口，不另抄组合或请求。

## 意见、采用与交接

分段意见及整轮意见沿用作品 `视频修改意见.json` 的 `notes`、`rounds`。段级意见可关联 `roundNumber`，旧的不带轮次意见保留为候选历史意见，不自动移入某一新轮。读取不重写旧意见，保存沿用并发核对与原位原子写入。

审阅组合不等于采用。实际采用依据继续在作品状态和原返修交接记录维护；网页关联准确的视频版本，不按任务完成或整片已有视频推定通过。交接清单继续由[返修阶段](../../iris-commercial-handoff/SKILL.md)维护。

## 共用完整制作页

Iris 接入与 Nora 共用的完整页面：作品列表与时长、轮次、分段制作、完整分镜、导演表、分镜对照修改导出、整片连播、意见汇总和资源下载。作品无业务场次时直接按全片组织，不另建场次目录。现有跨标签作品选择与制作页使用同一个 F 身份。

候选所用的实际上下文从原任务读取，当前计划与历史依据分开。台词和导演表读取明确的业务分镜及登记，不从最新稿回填旧请求。来源缺失如实提示，已具备的资料应完整展示。

文件及媒体仍使用项目级边界。轮次、意见、业务缓存和新资源逻辑键带 F 身份；新逻辑资源使用 `视频/F编号/P编号`，同一作品的各采样阶段沿用该资源或明确原 `resource_id`。已有资源编号不重编，跨作品明确复用时引用同一具体版本。

下载只在用户点击时调用共用脚本，沿用默认 jypack、按需 ZIP 及临时文件清理。导演包也按需生成，不按轮次自动导出。未完整登记的采用不冒充可交接成果，专项客户端验收不作为逐包步骤。
