# Iris 整片制作轮次与网页接入

## 轮次与批次

Iris 的编号单位是 C 项目下的一件 F 作品，同一作品各场次和分段共用轮号。

首批制作及每批独立返修方案确定送审或准备执行时登记一轮。只改 P004 的几秒也登记一轮，其余分段明确沿用实际来源轮。独立确定、单独送审或执行的短测按同一规则登记。一次方案内的多个任务和对照候选共用本轮。保存、重试、回片、采用、预览切换和同内容的不同导出格式沿用原轮。一采、二采、后处理共用同一编号序列，形成新的修改方案及版本组合时登记新轮。生成批次 R 和任务 ID 独立追溯。

Agent 按实际制作安排维护轮次关联；脚本核对路径、版本及候选对应，网页读取并按原位保存意见。打开页面不创建轮次，不生成媒体，不推定采用，不扩大执行授权。

## 唯一轮次索引

每件作品在 `06-视频生产/制作轮次.json` 保存一份索引。首次从 1 起，后续按该作品已登记最大轮号加一。登记后把轮号和所选分段写入本批生产任务或后处理记录，执行与取回继续引用本轮。索引保存明确的完整分段组合、原文件引用和本轮范围。局部方案用 `base_round` 指向实际沿用的轮次，用 `changed_segments` 登记受影响的 P；新增、删除或重排分段时登记新的完整顺序。保留该轮实际文档版本或准确快照。后续反馈和决定写在原审阅记录。

组合中的 `segments` 用于完整分段播放。局部试片、并排对照或整片后期文件另用 `review_outputs` 登记该轮的实际产出，每项写 `label` 和 `file`。用 `record` 指向本轮原生产或后处理记录。短测未形成正式替换段时，完整分段组合沿用来源轮，短测文件仍按本轮独立追溯。整片后期文件也保持自身身份。制作页按 `segments` 显示分段和沿用批次，按 `review_outputs` 在所选轮次直接提供试片、对照或后期产出入口。「轮次记录」也可查看同一批资料和原记录。

```json
{
  "rounds": [
    {
      "number": 1,
      "created_at": "实际登记时间",
      "note": "本轮范围与审阅或执行目的",
      "record": "作品/F001-示例/06-视频生产/生产任务-R001-v01.md",
      "script": {"file": "作品/F001-示例/03-创意脚本/制作脚本-v01.md", "version": "v01"},
      "storyboard": {"file": "作品/F001-示例/04-分镜声音/分镜与声音制作稿-v01.md", "version": "v01"},
      "batches": ["作品/F001-示例/06-视频生产/执行记录/R001-一采/提交任务清单-装配结果.json"],
      "segments": [
        {"id": "P001", "duration": 5, "stage": "一采", "run": "R001", "file": "资源/视频/VID-实际编号/V001/P001.mp4", "prompt": "作品/F001-示例/06-视频生产/P001-R001-提示词-v01.md"}
      ]
    }
  ]
}
```

所有 `file`、`batches`、`prompt` 和 `record` 路径都以 C 项目根为起点，图示编号仅为占位。每段引用明确候选和资源版本。新轮次的 `storyboard: {file, version}` 指向实际用稿，脚本也按具体版本登记。逐段生产正文另在生产任务中维护时，用 `plan: {file, version}` 引用当次分段计划。待生成的分段登记计划对应的目标文件，等实际执行记录和文件到达后读取实际候选。

新生成段的 `prompt` 指向[该段同版提示词文档](../templates/分段提示词.md)。制作页「英文」读取实际提交正文，「中文」读取该文档的 `## 中文提示词参考版`。索引只登记引用。复用原候选时沿用其原执行依据，历史轮次保留原分镜和提示词记录，原来缺失的资料如实留空。

首批方案尚未确定时，网页读取作品状态指向的现行资料和计划分段。状态表有「生产任务」时用该记录的分段表，否则沿用现行分镜的分段计划。已登记的批次按原任务显示进度和候选。已有主记录只补轮次入口，不另抄组合或请求。旧编号及意见的归属按历史原记录保留，历史补录须有明确授权与证据，并保留旧索引和对应关系。

## 意见、采用与交接

分段意见及整轮意见沿用作品 `视频修改意见.json` 的 `notes`、`rounds`。段级意见可关联 `roundNumber`，旧的不带轮次意见保留为候选历史意见，不自动移入某一新轮。读取不重写旧意见，保存沿用并发核对与原位原子写入。

整片轮次有一份总体意见，分段意见按该轮的场次和 P 段查看及复制；逐镜意见写在原分段意见内，带 SH 镜号和对应段内时间。临时预览轮次之外的候选时，意见归该候选历史。归档作品从已登记的归档原位读取分段意见及总体意见，沿用原轮次和场次，页面只提供查看和复制。

审阅组合用于确认本轮所看的候选。用户的实际决定记录在对应审阅记录或作品状态的「当前有效决定与授权」。返修与交接阶段在原采用文档中维护具体采用版本和组合。网页依据明确的采用记录关联视频版本。交接清单继续由[返修阶段](../../iris-commercial-handoff/SKILL.md)维护。

### 作品状态中的轮次摘要

「当前阶段与下一步」写实际接续事项。现行版本表里的轮次行保留轮次或版本及原文件入口，「状态及依据」直接链接对应候选的原审阅、返修或采用记录。有明确章节时链接到章节。提交审阅时链接该轮的审阅入口，后续反馈和决定补在对应记录中。「待审」「已采用」等状态由原记录维护。

整理旧轮摘要时，核对候选身份、实际反馈和采用范围，再把过时的状态文字换成原记录链接。历史轮次、执行记录和当时的意见、决定原样保留。收到新决定时在对应记录补记。当前采用组合或接续事项实际变化时，更新各自的记录。

## 共用完整制作页

制作页头的「轮次记录」默认显示当前所选轮次，从同一索引读取实际脚本、分镜及制作记录。作品状态可登记同名 Markdown 作为历史索引原件，制作页从「轮次记录」中提供原件入口。尚未登记轮次时可在同一入口查看已经登记的现行资料。按分段核对画面、动作和台词看「分镜脚本」，核对实际生成请求看「提示词」。

Iris 接入公共制作工作台。场次与段内时码读该轮 `plan` 指向的分段计划，未指定 `plan` 时读该轮分镜。字段按[分镜与声音规则](../../iris-commercial-storyboard/references/流程规则.md#执行要点)填写；生产任务另作分段计划时用同样的字段。没有登记场次时页面显示「整片」；登记场次后，场次筛选只影响当前查看范围，轮次及跨场连播仍用整片组合的分段顺序。既有跨标签作品选择与制作页使用同一个 F 身份。

Songssx 整场轮次沿用同一份 `制作轮次.json`。在 `batches` 引用实际装配结果，同一场的 P 按 GEN 顺序登记，并引用同一个准确的整场视频文件。网页按原任务的请求、输出和取回凭据核对，分段条使用 GEN 成片时码，样片下载每场只收录一个 MP4。选择工作流及进入轮次的规则统一见[共用制作页接入](../../studio-workspace-browser/references/业务接入规范.md#按制作对象选择工作流)。分段参考图按[共用制作页参考素材](../../studio-workspace-browser/references/业务接入规范.md#制作页参考素材)随 GEN 切换。

一件作品继续制作且有原制作归档时，在同一 F 作品内分「现行制作」和「历史归档」。进入作品默认看现行。现行只用本片的制作轮次、任务记录和意见文件。作品状态的「对象 / 当前版本/文件」表可用「制作脚本」「分镜与声音」「资产清单」「生产任务」指定当前资料，填写项目根相对路径，资料位于各自的作品阶段内。已明确引用的工作稿可作为接续依据。历史归档按原登记读取旧轮、旧意见和归档交接文件，意见只可查看与复制。现行和历史分别读取候选及下载依据，即使 P、R 或轮号相同也分开处理。

候选所用的实际上下文从原任务读取，当前计划与历史依据分开。台词和导演表读取明确的业务分镜及登记，不从最新稿回填旧请求。来源缺失如实提示，已具备的资料应完整展示。

分镜脚本和修改意见共用 SH 条。优先使用候选执行记录里完整的镜头时码。计划时码读候选已登记的分段表，核对镜头数量、顺序、计划段长和执行记录已有的镜头时长，跳转点须在可播段内。成片与计划段长不同但跳转点可用时，仍保留原计划时码。早期生产任务表的「生产段」「源摄影镜头」也用于核对镜号。分段明确只有一个镜头且执行记录相符时，可从段首 0 秒定位。页面区分计划时码和执行时码，实际切点以视频画面为准。已知镜号但缺少可靠时码时，只开放普通播放时间意见。

文件及媒体仍使用项目级边界。轮次、意见、业务缓存和新资源逻辑键带 F 身份；新逻辑资源使用 `视频/F编号/P编号`，同一作品的各采样阶段沿用该资源或明确原 `resource_id`。已有资源编号不重编，跨作品明确复用时引用同一具体版本。

作品列表按 `作品状态.md` 的「制作状态」统计。旧作品缺少该字段时，普通作品可用已登记的交接状态。现行与归档分开的作品只用现行制作标签，缺少时显示「未登记制作状态」。页头可展开「作品制作状态」，读取「当前阶段与下一步」及对应记录。

视频采用后，在现行版本表以「视频采用记录」引用本片 `07-返修交接/` 中的原采用文档，填写项目根相对路径。网页按该文档「当前采用组合」表的「段号」「采用版本及文件」匹配具体候选，媒体链接相对于采用文档。分段条显示当前轮选中的版本，其他尝试在「版本切换」列出 R 号和中文技术状态。候选取回以对应文件为准，未取回时同时显示有据可查的后台状态。素材审阅按现行单一资产清单的具体版本与决定分组，卡片可回到清单。历史制作页沿用归档素材和审阅依据。

导演分镜表「当轮」只显示来源分镜版本与所选轮次匹配的登记图。其他版本和有索引依据的归档原图归「历史版本」，随图提供对应登记或原索引；版本依据缺失时如实标明。

页头从本作品状态的交付成果表读取交接入口。动态整片包的时间线文件及顺序须与所选整片轮次一致；清单包含的额外素材箱文件沿用清单。页头和资源下载都显示按清单匹配到的轮次。资源下载可查看整件作品已登记的交接清单，未匹配的清单标为「未关联整片轮次」。已登记的归档草稿直接下载原文件，标明历史版本。交接草稿、审阅样片、素材采用及正式交付各按原记录展示。

## 现行画布与候选产物

「资源下载」按场次、阶段和实际 R 批次列出原画布。一次任务覆盖多个分段时，标签列出该次任务的 P 段。画布来自实际提交任务目录中的 `任务.workflow.json`，缺少画布或提交凭据时显示具体缺项。后处理也提供实际任务画布。

整片交接按作品登记的清单与顺序打包，支持剪映草稿包和视频 ZIP。

同一候选有多个实际保存的产物时，在该任务的执行目录按需保存一份 `视频产物.json`。以准确的候选文件路径作键，每个候选登记具体产物及唯一默认项。所有文件路径相对于 C 项目根，引用真实媒体版本。

```json
{
  "candidates": {
    "资源/视频/VID-实际编号/V001/P001.mp4": {
      "products": [
        {"id": "raw", "label": "原版", "file": "资源/视频/VID-实际编号/V001/P001.mp4", "default": true},
        {"id": "repair", "label": "修复版", "file": "资源/视频/VID-实际编号/V002/P001-修复.mp4"}
      ]
    }
  }
}
```

「产物选择」只切换当前候选播放和单文件下载的媒体。轮次、意见、采用和整片交接继续以原候选及各自正式记录为准。不同任务产生的候选各用自身执行记录。
