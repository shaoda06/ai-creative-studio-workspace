# 视频技术处理规范

## 后处理分步询问

Agent先用`scripts/video_metadata.py`的`probe(Path(实际源视频))`读取实际宽高与帧率，再按下表逐步询问。明确选过的字段直接沿用；不同时打包询问一采、二采及后处理，不由文戏／打戏选择后处理方法。选项不标“推荐”。

| 步骤 | 问题 | 选项 |
| --- | --- | --- |
| 1 输出分辨率 | 请选择输出分辨率，或输入宽×高。 | 保持原分辨率（实际宽×高）；横屏1920×1080（默认）或竖屏1080×1920（默认） |
| 2 输出帧率 | 请选择输出帧率，或输入数值。 | 保持原帧率（实际fps）；30fps（默认）；60fps |
| 3 画面适配 | 源视频与目标比例不同，请选择处理方式。 | 保留比例（输出实际宽×高）；裁切至目标宽×高（上下／左右各裁实际像素） |

第3步仅在源与目标宽高比不一致时出现；放大倍数不是整数不构成询问条件。保留比例将完整画面放入目标尺寸范围，不补边；实际输出可小于目标。裁切先等比缩放至覆盖目标，再居中裁切；需要先缩放时，选项同时显示缩放后的宽高。裁切数字指缩放后画面，两侧不相等时分别显示。原尺寸、原帧率、实际输出及裁切量都从当前源片计算，不硬编码示例值。

显示与装配共用`scripts/video_workflow.py`的`plan_output`。H.264/yuv420p输出宽高须为正偶数；自定义奇数尺寸请用户修改，不静默改写输入。保留比例的计算尺寸取最接近的偶数，裁切的覆盖尺寸向上取偶数，因此比例可有像素取整误差。原帧率显示实际值；自定义输出帧率范围1～240fps，异常输入只返回对应问题。

规格确定且已有执行授权后直接装配，无需追加方法、编码、音轨或最终配置确认。后处理结束不增加配置问答；技术核对、采用与业务收尾按调用阶段现行规则接续，已有自动采用规则继续适用。定制透明通道等任务按其明确规格处理，不套用常规H.264流程。

## 实际装配

视频后处理共用 [RTX-RIFE 画布](workflows/RTX-RIFE-自动切镜保护超分插帧.workflow.json)和[默认 API](workflows/RTX-RIFE-自动切镜保护超分插帧.api.json)。画布的默认链路是 RIFE 插帧、RTX 超分和输出，裁切节点默认旁路。手动使用时填写实际输入和参数，按需要切换各节点的旁路状态。自动装配按以下规则接入本次所需节点，导出任务自己的 API。

实际尺寸需要增大时使用RTX，缩小时使用核心`ImageScale`的Lanczos缩放，尺寸一致不缩放；裁切使用`ImageCrop`。是否超分、缩放、裁切由源文件与已选目标决定，与戏型、LoRA及旧配置编号无关。目标帧率与源相同时直接连接源帧及源fps，跳过RIFE；不同则在源尺寸下先调用`NoraRIFEInterpolationCutTest`按目标帧率重采样，再做尺寸处理。不得仅修改保存帧率造成播放速度改变。

RIFE复用已安装的原`RIFEInterpolation`及已有`flownet.pkl`；节点包及安装验证见[节点与安装包](../../studio-entry/维护规范.md#comfyui节点与安装包)。固定默认`scale=1.0`、`scene_cut_threshold=0.15`、`batch_size=1`、`use_fp16=true`；切镜检测基于64×64 RGB相邻帧差异，跨切点保持源帧，其余位置用原模型。不按预设秒数拆片，不跨切镜混合。阈值0表示关闭保护，须有明确选择；闪光、快速运动和相近构图可能影响检测。

RTX 使用 `target dimensions`、`quality=ULTRA` 及[共用必填输入](../../studio-image-processing/references/ComfyUI-图片超分执行规范.md#rtx节点共用必填输入)。需要裁切时，将 `ImageCrop` 接在本次最后一个启用的画面处理节点之后。输出节点 16 的音频接源音轨，帧率接 RIFE 实际输出或源帧率。保留播放时长，整数帧量化允许不足一帧差异。

输出默认`video/h264-mp4`、`yuv420p`、`crf=19`、`save_metadata=true`、`trim_to_audio=false`、`pingpong=false`、`save_output=true`。节点16的`widgets_values`保留对象格式。尺寸和帧率均满足所选规格时返回复用结果，不插帧、不超分、不重复转码；调用方沿用准确源文件并按业务规则登记，不伪造已执行后处理任务。

完成后按[任务监控规范](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md)取回并核对实际尺寸、帧率、时长、码率和来源，技术结果不代表内容获批。缺少节点或模型如实报错，不自动安装、升级或替换算法。过程文件按[临时资料生命周期](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md#临时资料生命周期)清理，实际提交输入、候选和交付结果保留。

## 调用接口

使用当前Python 3及ffprobe。从技能`scripts`导入，路径由调用方明确；仅本地读取与装配，不上传、不入队、不选择业务来源。

```python
from pathlib import Path
from video_metadata import probe
from video_workflow import questions, plan_output, assemble_output
metadata = probe(Path('/实际项目/源视频.mp4'))
questions(metadata)  # 取第1、2步弹窗参数，逐步调用
questions(metadata, [1920, 1080])  # 根据第1步答案决定有无第3步
plan = plan_output(metadata, [1920, 1080], 30, 'crop')
canvas = assemble_output('planned/源视频.mp4', '本次输出身份', plan)
# canvas为None：直接沿用原文件；否则交现行任务准备与提交入口。
```

`resolution`为`"original"`或`[宽,高]`；`fps`为`"original"`或数值；`fit`仅用`contain`（保留比例）或`crop`（居中裁切），比例相同可省略。`plan_output`输出源尺寸／帧率、目标尺寸、实际尺寸、缩放尺寸、各侧裁切量、目标帧率和`reuse`；UI必须使用同一份计算结果显示。

技术任务（`video_plan.adapter:"technical"`）与Nora任务共用以下顶层字段。无需手工画布时可省略`canvas`；`output_nodes`仍填`["16"]`，输出位置、引用与授权按现有清单提供。

```json
"video_postprocess": {
  "source": "源视频.mp4",
  "resolution": [1920, 1080],
  "fps": 30,
  "fit": "crop"
}
```

`source` 是项目内实际文件，须与 `references` 中唯一视频条目的 `file` 一致。准备器读取该源片的实际规格。技术任务在原清单保留选择，Nora 同时写入 `mapping.postprocess_configuration`。源片满足目标规格时，调用方按 `plan_output.reuse` 沿用原文件。旧的固定方法 `assemble(method, source, prefix, size, crop_offset)` 也读取同一基准。`crop` 和 `upscale` 分别装配 30fps 插帧加裁切或超分。新任务按上述 `video_postprocess` 接口填写目标规格。

回归命令：`python3 -B -m unittest discover -s .agents/skills/studio-video-processing/scripts -p test_video_workflow.py -v`，覆盖动态选项、原规格复用、横竖屏缩放裁切及两类任务准备接口；不调用生成服务。
