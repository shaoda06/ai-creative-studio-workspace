# 视频技术处理规范

## 时间裁剪与兼容播放

RelayVSR 的本地裁段使用[专项分段入口](RelayVSR视频超分.md#分段装配与拼接)。通用时间裁剪由调用方提供源片、实际保留起止及输出位置。时间裁剪使用 FFmpeg，`-ss` 指保留起点，`-t` 指终点减起点。整片兼容转换省略这两个参数。通用精确裁剪或兼容转换使用 H.264 和 `yuv420p`，音轨存在时使用 AAC，封装为 MP4。用 `-map 0:V:0 -map 0:a?` 保留主视频及现有音轨，使用 `-n` 保护已有输出。通过 [共用媒体核对](../SKILL.md)读取实际规格，完整解码并核对实际起止后交回调用方。

## 画面尺寸与适配

工作流与参数按[公共选型及专项指南](../SKILL.md#后处理工作流选择)确认。读取源片实际宽高及帧率，显示与装配都使用 `scripts/video_workflow.py` 的 `plan_output` 计算。

保留完整画面时等比缩放到目标尺寸以内，画幅不一致时实际输出会小于目标。裁切先等比缩放至覆盖目标，再居中裁切。预览显示实际输出、裁切各边像素及需要的中间缩放尺寸。保留比例的尺寸取最接近的偶数，裁切的覆盖尺寸向上取偶数，因此两侧裁切量可能略有差异。

规格确定且已有执行授权后直接装配。技术核对、采用与业务收尾按调用阶段现行规则接续。透明通道等定制任务按其明确规格处理。

## 实际装配

正式基准分别见 [RTX 视频超分](RTX视频超分.md)、[RelayVSR 视频超分](RelayVSR视频超分.md)和 [RIFE 插帧](RIFE视频插帧.md)。三个工作流都能独立使用。组合任务按已选处理步骤装配，并保存本次实际画布与 API。历史任务沿原执行资料和原 ID 接续。

选定 RTX 时，按交付规格使用 RTX 放大。通用尺寸处理使用核心 `ImageScale` 的 Lanczos 缩小，尺寸一致时跳过缩放。裁切使用 `ImageCrop`，接在最后一个启用的画面处理节点之后。目标帧率与源相同时直接连接源帧及源帧率。RIFE 与 RTX 或通用尺寸处理组合时，先在原尺寸调用 RIFE，再进行尺寸处理。只需插帧时装配单独的 RIFE。

明确选用 RelayVSR 时，按[分段装配与拼接](RelayVSR视频超分.md#分段装配与拼接)执行。组合 RelayVSR 与 RIFE 时，先把超分片段拼成整条，使分段边界有连续的相邻帧。按合片核对 [RIFE 运行资源](RIFE视频插帧.md#运行资源)，再按原授权准备和提交 `插帧任务清单.json`。现有节点无法承载整条时，先保留已核对的超分合片，插帧按实际可用条件接续。

输出接实际画面帧、实际帧率与源音轨。保留播放时长，整数帧量化允许不足一帧差异。RTX 和 RIFE 装配的输出节点 16 默认使用 `video/h264-mp4`、`yuv420p`、`crf=19`、`save_metadata=true`、`trim_to_audio=false`、`pingpong=false`、`save_output=true`，`widgets_values` 保留对象格式。

尺寸和帧率均满足所选规格时返回复用结果，调用方沿用准确源文件并按业务规则登记。

完成后按[任务监控规范](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md)取回并核对实际尺寸、帧率、时长、码率和来源，技术结果不代表内容获批。缺少节点或模型如实报错，不自动安装、升级或替换算法。过程文件按[临时资料生命周期](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md#临时资料生命周期)清理，实际提交输入、候选和交付结果保留。

## 调用接口

使用当前Python 3及ffprobe。从技能`scripts`导入，路径由调用方明确；仅本地读取与装配，不上传、不入队、不选择业务来源。

```python
from pathlib import Path
from video_metadata import probe
from video_workflow import plan_output, assemble_output
metadata = probe(Path('/实际项目/源视频.mp4'))
plan = plan_output(metadata, [1920, 1080], 30, 'crop')
canvas = assemble_output('planned/源视频.mp4', '本次输出身份', plan)
# canvas为None：直接沿用原文件；否则交现行任务准备与提交入口。
```

`resolution`为`"original"`或`[宽,高]`；`fps`为`"original"`或数值；`fit`仅用`contain`（保留比例）或`crop`（居中裁切），比例相同可省略。`plan_output`输出源尺寸／帧率、目标尺寸、实际尺寸、缩放尺寸、各侧裁切量、目标帧率和`reuse`；UI必须使用同一份计算结果显示。

RTX、RIFE 以及通用缩放裁切的技术任务（`video_plan.adapter:"technical"`）与 Nora 任务共用以下顶层字段。自动装配时可省略 `canvas`，`output_nodes` 填 `["16"]`。输出位置、引用与授权按现有清单提供。RelayVSR 使用其[分段装配入口](RelayVSR视频超分.md#分段装配与拼接)。

```json
"video_postprocess": {
  "source": "源视频.mp4",
  "resolution": [1920, 1080],
  "fps": 30,
  "fit": "crop"
}
```

`source` 是项目内实际文件，须与 `references` 中唯一视频条目的 `file` 一致。准备器读取该源片的实际规格。技术任务在原清单保留选择，Nora 同时写入 `mapping.postprocess_configuration`。源片满足目标规格时，调用方按 `plan_output.reuse` 沿用原文件。

回归命令：`python3 -B -m unittest discover -s .agents/skills/studio-video-processing/scripts -p test_video_workflow.py -v`，覆盖尺寸与裁切计算、原规格复用、横竖屏缩放裁切及两类任务准备接口。
