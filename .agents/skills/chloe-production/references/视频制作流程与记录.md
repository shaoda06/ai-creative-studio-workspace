# Chloe 视频制作流程与记录

## 制作范围与起点

一条 V 视频对应[共用制作层级](../../studio-storyboard/references/分镜写作规范.md#制作对象场次与分段)的制作对象，P001 等为生成分段，SH001 等为镜头。脚本中按顺序填写“分段计划”的分段编号、镜头编号和时长秒，多个镜头用顿号分隔。覆盖、顺序和成片计划时长按[脚本与分段规则](../../chloe-creative/references/视频项目与脚本规范.md#脚本与修订)统一核对；模型请求余量归实际参数。逐镜内容仍只写在“镜头与分镜”。画幅由每条视频单独确定，不设竖屏默认值。开始生成前，脚本与分段已确认，商品展示有事实来源，实际参考已明确到版本。

共用人物、造型、商品、服装及场景可以直接满足镜头时，直接引用。角色参考按[造型作为视频角色参考](../../chloe-assets/references/模特与服装图片制作流程.md#造型作为视频角色参考)核对同套造型的两张正式图及准确版本；需要特定构图时按[镜头参考图流程](../../chloe-assets/references/镜头参考图制作流程.md)生成，用户批准后2倍超分，Agent核对尺寸并自动登记正式版，再按实际模式作为首帧或画面参考使用。提交前按[镜头图用途与模式](../../chloe-assets/references/镜头参考图制作流程.md#1-判断需求与用途)核对真实图像输入；r2v普通Picture不具备硬首帧语义，固定起始画面须由支持该用途的模式及输入落实，不能只靠提示词承诺。商品证据、参考来源和镜头表达在准备阶段核对；生成的视频由用户审阅，Agent不增加抽帧、听写或画面内容预审。

## 配置与整片推进

按[共用核心的工作流选择](../../studio-video-production/SKILL.md#工作流选择)确定本次工作流，再通过[核心生成入口](../../studio-video-production/SKILL.md#请求核对与生成)接续实际模式。执行前说明当前分段范围、配置和费用影响，使用已确认的配置及授权。整片获批后的执行沿[核心工具入口](../../studio-video-production/SKILL.md#按业务决定调用执行工具)。

按[共用结果交回](../../studio-video-production/SKILL.md#候选与技术结果交回)取得候选，按本轮完整范围统一送审。用户批准后，按所选工作流与已确认的配置、处理方案和授权接续。只批准部分分段时保留批准依据，返修有问题的部分，齐备后再统一继续。改变剧情、分段、模型配置或处理目标时，只确认变化部分。

采用依据引用实际获批版本和技术核对。后处理使用已有报告核对本次尺寸、帧率、时长及音轨，符合已确认规格时接续采用。技术异常保留原产物，按差异处理。

### 无需后处理时直接沿用

使用已有技术报告核对已获批源片。已满足用户确认的规格时，直接在 README 的“当前采用”引用原文件准确版本和实际阶段，依据链接原批准与技术核对。整片均直接沿用时引用原轮次。部分分段需要处理时，沿[整片轮次](#整片轮次)登记处理后的分段与直接沿用的源片组合。

完整组合全部技术合格且已采用后直接进入剪映交接。清单仍按该组合原顺序引用准确文件，各分段的真实阶段不变。页面下载与正式交接的关系按[采用、交接与页面](#采用交接与页面)执行。

## 固定文件与唯一记录

每个视频固定建立：README.md、脚本.md、制作记录.md、制作轮次.json、视频修改意见.json、执行记录/、历史版本/、资源/图片、资源/视频、资源/音频、剪辑交接/、成片/。初始化使用[建档脚本](../../chloe-positioning/scripts/chloe_init.py)，重复初始化只补缺失文件。

- README 的“定位与当前进度”是唯一进度入口。“当前采用”按实际用途保存准确资源引用。采用依据引用制作记录中的审阅编号或技术核对编号。
- 脚本保存唯一当前脚本及分段计划。开始一轮前将当次准确稿件保存至历史版本/脚本-v01.md；同版已存在且内容相同直接引用，内容不同先更新版本，不覆盖历史。当前稿与必要历史稿不属于媒体重复保存。
- 制作记录的执行表保存 E 身份、授权与任务 ID；输入、输出表分别以 E 和槽位关联准确资源。“视频分段执行”只把 P、阶段、候选版本、E、输出槽位和模型分段序号关联起来，不复制任务参数或输出路径。
- 制作轮次.json 只引用脚本版本和分段执行，媒体文件、输入及结论仍在原记录；视频修改意见.json 只保存公共工作台的段级及整轮修改意见，不作为批准或采用记录。
- 共用资源只在综合资料/资源保存一份。资源/共用引用.json 绑定具体版本；输入记录保留当次版本，升级素材使用新的绑定键，不能改写历史输入。公共任务 uploads 直接用 `@shared/资源/图片/IMG-编号/V001/文件.png` 或准确原文件绝对路径，不复制到视频项目。
- 新输出由公共资源机制直接分配到本视频资源区。视频输出的名称保留 P 编号便于识别；同一取回任务重试使用相同输出身份，不再导入副本。失败且无输出不造资源行。

## 视频分段执行

分段关联、阶段枚举和输出槽位按[结果登记接口](结果自动登记.md#分段记录字段)填写。

同一个 E 可以产出多个 P，每个 P 通过不同输出槽位关联；同一 P 同一阶段的每次新候选使用新 R。恢复原任务、补下载、补登记不增加候选版本；新的生成任务使用新 E，存在有效旧产物而重新生成时增加 R。审阅表的 R 编号仅在“制作记录.md#审阅记录”内标识审阅事件，与候选 R 的命名空间分开。

“参数记录”链接 `执行记录/E001/提交任务清单.json` 等本次公共任务原清单，同一清单的 tasks 可以包含多个 E 任务，每个 E 以 `record_dir: 执行记录/E编号` 唯一定位自身任务；同一任务也可产出多个 P。多个 E 直接引用同一原清单，不拆分或复制清单。页面通过原清单同目录的 `原清单名-装配结果.json` 读取后台实际装配的任务、project 与 uploads，按执行目录定位；该文件使用公共 read_journal 读取，不另存展开副本。没有装配结果的直接任务清单必须已包含实际 project、record_dir 和 uploads。video_plan 使用 `adapter: technical`、`metadata: ffprobe`；outputs 或 segment_plan.targets 指定实际产出，references 或 uploads 指向原始准确版本；references 的占位名由公共 H3 装配为上传槽位。

任务清单使用公共后台模型与[提交接入](../../studio-workspace-browser/SKILL.md)检查、准备和执行，不能把准备状态当作已经提交。公共后台会分配输出准确版本，提交后将真实任务 ID 写回原 E 行。请求、状态、回执及技术报告由后台原位维护；业务只引用，不再编造第二份后台状态。

视频生成执行的“提示词或正文”只填写[提示词文件规范](#视频提示词文件)要求的Markdown链接，不直接放正文。后处理通过“上游执行”追到原生成提示词；不复制提示词或改写上游输入。

### 视频提示词文件

编写、实质修订或提交前核对视频提示词时，按[共用视频提示词](../../studio-video-prompts/SKILL.md)落实已确认脚本、实际参考、模型正文和同版中文。连续展示商品时沿脚本中已核实的外观、状态和操作。直接使用已备正文时复用已有技法说明，首次实际采用未验证写法且尚未告知的按[首次使用提示](../../studio-creative-techniques/references/学习与反馈维护规范.md#首次实际使用时的提示)补充观察重点。

每个视频生成E执行按[视频提示词模板](../templates/视频提示词模板.md)在`执行记录/E编号/提示词.md`保存一份提示词文件；制作记录以`[提示词](<执行记录/E编号/提示词.md>)`引用。模板只固定承载章节，正文格式按实际H3模式指南编写，不另造模型格式。两个语言章节内均以 `### P001` 等三级标题分段，按视频分段执行的模型分段序号排序，两边 P 编号、顺序和本次执行范围必须一致，不重复或漏段。共用正文可放在各语言章节最前面的 `### 共用` 中，只写一次；页面按“共用正文＋当前 P 正文”展示。分段标题用于文件定位，不作为模型提示词正文提交。单段旧文件没有 P 标题时仍对应唯一分段；多段文件必须明确 P 标题。

固定二级标题为`## 模型提示词正文`和`## 中文提示词参考版`，两节正文均非空。H3 正文语言沿实际模式指南。参数和工作流仅引用原任务清单。

提交前完成文件并运行本阶段check；尚无提交或完成事实的记录允许暂缺，准备失败或取消不补造提示词；未完成提示词不能提交。已填写链接则必须能读取且两节齐全。提交后该执行提示词保持原样，内容改变使用新的执行记录，不覆盖历史中文参考。后处理不另写提示词，沿上游执行追溯。

页面英文始终读取实际请求，中文读取上述固定章节中的共用正文和当前 P 分段。阶段校验检查文件、章节和填写时点。

## 整片轮次

每轮保存完整分段组合和顺序。首批制作或独立修改方案确定送审、准备执行时登记一轮，后续产生新组合时继续同一视频轮号序列。局部返修只替换受影响 P，其余引用此前执行。保存、上传、取回、恢复、用户批准、采用、页面切换和相同内容导出不增加轮次。轮次号、候选 R 和后台任务 ID 分别追溯。

制作轮次.json 的唯一结构为 format: 1 和 rounds 数组。每轮固定字段如下；不得添加媒体副本、审批结论或第二份参数。

| 字段 | 写法 |
| --- | --- |
| number | 从1起连续递增正整数 |
| created_at | 实际登记时间，ISO格式并含时区 |
| note | 本轮范围与目的 |
| script | 本项目历史版本中的准确脚本路径 |
| segments | 完整有序数组，每项只有 id、execution、slot |
| base_round | 局部修改时引用的既有轮号；首次没有此项 |
| changed_segments | 与 base_round 实际不同的 P 编号；仅有 base_round 时使用 |
| review_outputs | 附加试片和对照用 label 与 resource，resource 使用制作记录中的准确资源引用。后台整场后处理按[共用整场后处理审阅](../../studio-workspace-browser/references/业务接入规范.md#整场后处理审阅)登记执行目录和源片。 |

```json
{"format":1,"rounds":[{"number":1,"created_at":"2026-11-07T12:00:00+08:00","note":"整片一采","script":"历史版本/脚本-v01.md","segments":[{"id":"P001","execution":"E001","slot":"P001视频"}]}]}
```

准备阶段可先登记视频分段执行和轮次，未取回前不造输出资源行。页面保留未取回状态；输出到达后通过原 E/槽位读到准确资源。尚未形成首轮时读取当前脚本计划，不自动造轮次。

## 审阅、返修与异常恢复

用户决定只在制作记录的审阅表写一次；对象引用使用 `[第1轮](<制作轮次.json#round-1>)`，局部决定注明 P 编号及候选版本。整体意见和逐段修改正文在视频修改意见.json 原位保存，审阅记录链接该文件，不逐段抄写同一意见。返修表关联原 E、审阅 R、修改范围及后续 E。

收到针对具体生成效果的技法反馈时，按审阅所指的P段和候选版本追到原E执行，核对实际提交正文、模型模式及输入，再按[反馈复核](../../studio-creative-techniques/references/学习与反馈维护规范.md#实际反馈复核)更新对应参考。反馈原话和采用依据留在本视频的原记录。

修改意见属于特定轮次或候选，公共接口核对已有身份并处理并发保存。按[共用候选返修接续](../../studio-creative-techniques/references/审查与返修方法.md#视频候选的返修接续)处理。主题和脚本内容回[创意](../../chloe-creative/SKILL.md)，商品事实回[选品](../../chloe-selection/SKILL.md)，资产设计回[资产阶段](../../chloe-assets/SKILL.md)。新候选回到原整片审阅范围，未受影响的 P 段沿用原版本，已采用组合保留至新的采用完成。

异常按[核心结果交回与恢复](../../studio-video-production/SKILL.md#候选与技术结果交回)沿原任务及报告处理。真实重生成只在已明确的重试范围和次数内执行，不自动增加额度。

## 后台结果接续

收到视频任务通知按[共用结果交回与恢复](../../studio-video-production/SKILL.md#候选与技术结果交回)接续原任务，将实际结果关联到原执行。自动回写字段与通知含义见[结果登记接口](结果自动登记.md#通知恢复与检查)。

镜头参考图超分的通知按[镜头图片接续](../../chloe-assets/references/镜头参考图制作流程.md#5-批准后2倍超分与自动采用)处理，只更新图片E执行、输出和README镜头用途采用，不写入视频分段执行或制作轮次，不推进一采、二采审阅。

对照本轮范围核对候选是否齐备，按[配置与整片推进](#配置与整片推进)送审。获批文件及处理产物按[采用、交接与页面](#采用交接与页面)接续。缺项或异常沿原任务处理。

## 采用、交接与页面

记录用户决定或技术核对依据，更新采用引用、采用变更及 README 的阶段、处理状态和下一步，再核对引用和页面。完整组合全部合格采用后交[剪映交接](../../chloe-handoff/SKILL.md)。用户人工导出成片，发布时引用具体文件。

制作页使用[共用制作页接入规则](../../studio-workspace-browser/references/业务接入规范.md#按制作对象选择工作流)。作品列表来自实际 V 项目，轮次与播放顺序来自制作轮次，分镜来自对应脚本快照，英文与输入来自原请求，素材及视频引用原资源，采用读取 README。分镜脚本标签读取对应脚本“镜头与分镜”章节，意见使用公共保存协议。

作品列表时长旁的彩色状态直接读取各作品README的“视频状态”：制作中为蓝色、待发布为橙色、已发布为绿色，复用公共状态样式；不按任务执行结果推断、不新增状态记录。“当前阶段”仍用于列表统计。

制作页的任务详情使用所属工作区的公共任务接口，具名项目仅限定资料路径，不另建任务账本。后台审阅链接由本业务接入生成：视频任务进入对应具名项目的视频制作页，共用资产任务进入该项目的共用资产页；读取报告时转换链接，不改写历史请求、任务标识或资源记录。

复用已上传素材时，页面按实际请求和原上传映射读取准确版本。映射写法见[结果登记接口](结果自动登记.md#分段记录字段)。

分镜跳转及“跟视频对齐”优先使用实际请求中的明确镜头时码。缺少执行时码时，读取该候选首次所属轮次绑定的历史脚本，按分段镜号顺序核对时间区间、镜头时长及分段总时长；减去首镜开始时间换算段内时码，并标明“按计划时码定位，实际切点以画面为准”。沿用的候选保留原轮次的时码，不随当前脚本或后续轮次变化。缺失、数量不符或时间不连续时不推测时码；计划时间不代表视频实际切点。

导演分镜表按[本业务接入](../../chloe-creative/references/导演分镜表业务接入.md)记录独立脚本版本、图表版本和候选编号，输出槽位使用该接入模板；当前采用引用同一资源，页面保留候选、采用与全屏查看。任务原目录的 `.workflow.json` 供画布下载。剪映清单保存于剪辑交接/，直接引用采用片段，公共工作台提供包下载。资源下载按当前所选整片轮次统一展示“交接包”“本轮视频”“原画布”三个子章节，不再按制作阶段拆栏。本轮一采、二采、后处理视频均按轮次分段完整顺序引用，混合阶段不拆包，不要求正式采用或已登记交接清单。没有视频则禁用，不跨轮次补入其他版本；有部分视频时显示实际数量，仅打包这些视频。原画布按本轮执行记录汇总，同一执行只展示一次。视频ZIP只含原视频，剪映草稿包按本轮分段顺序建立原速原声时间线。用户点击后临时打包，响应发送完成、失败或中断后清理服务端临时包；不另存原素材、不改变采用、不新增执行或交接记录。正式剪映交接清单继续保存交接时的准确组合及采用依据，旧清单不改写；它是交接事实，不是浏览下载的前置条件。

## 固定校验命令

保存后先执行[固定资料检查](../../chloe-positioning/references/固定资料写法规范.md)，再从工作区总目录运行：

