# Chloe 视频制作流程与记录

## 制作范围与起点

一条 V 视频是一个完整制作对象，P001 等为生成分段，SH001 等为镜头；一个 P 可包含多个 SH。脚本中按顺序填写“分段计划”的分段编号、镜头编号和时长秒，多个镜头用顿号分隔。覆盖、顺序和成片计划时长按[脚本与分段规则](../../chloe-creative/references/视频项目与脚本规范.md#脚本与修订)统一核对；模型请求余量归实际参数。逐镜内容仍只写在“镜头与分镜”。画幅由每条视频单独确定，不设竖屏默认值。开始生成前，脚本与分段已确认，商品展示有事实来源，实际参考已明确到版本。

共用人物、造型、商品、服装及场景可以直接满足镜头时，直接引用；需要特定构图时按[镜头参考图流程](../../chloe-assets/references/镜头参考图制作流程.md)生成，用户批准后2倍超分，Agent核对尺寸并自动登记正式版，再按实际模式作为首帧或画面参考使用。提交前按[镜头图用途与模式](../../chloe-assets/references/镜头参考图制作流程.md#1-判断需求与用途)核对真实图像输入；r2v普通Picture不具备硬首帧语义，固定起始画面须由支持该用途的模式及输入落实，不能只靠提示词承诺。商品证据、参考来源和镜头表达在准备阶段核对；生成的视频由用户审阅，Agent不增加抽帧、听写或画面内容预审。

## 配置与整片推进

H3 模式、配置及参数选择调用[公共 H3](../../studio-h3/SKILL.md)，后处理调用[公共视频处理](../../studio-video-processing/SKILL.md)。业务不维护第二套参数预设。执行前说明当前分段范围、配置和费用影响，使用已确认的配置及授权。

流程固定为：所有分段一采 → 整片用户审阅 → 所有分段二采 → 整片用户审阅 → 按已确认规格处理或直接沿用 → 技术核对与正式采用 → 剪映交接。等待整片当前阶段齐备再交审，不因某段先完成就单独推进下一阶段。

在配置和后处理方案已确认的情况下，用户批准整片一采即接续二采，批准整片二采即接续后处理，不重复询问。只批准部分分段时保留批准依据，返修有问题的分段，齐备后再统一继续。改变剧情、分段、模型配置或处理目标时只确认变化部分，不能借上一阶段批准扩大范围。

每个 P 按实际执行的一采、二采、后处理阶段保存具体候选。成功生成或取回不等于采用。后处理使用已有技术报告核对本次尺寸、帧率、时长、音轨等要求，合格后自动登记正式采用；依据指向二采批准和后处理报告，不伪造额外用户批准。技术异常保留原产物，按差异处理，不自主换参数、裁切或重生成。

### 无需后处理时直接沿用

二采整片批准后，先按公共视频处理的实际规格判断哪些分段需要处理。源文件尺寸、帧率等已满足用户确认要求时，使用该二采任务已有技术报告核对尺寸、帧率、时长和音轨；合格后在 README 的“当前采用”登记 `P编号/二采`，引用原文件的准确资源版本，依据引用原二采批准和技术核对记录。用户不需要额外批准，也不强行提交无变化的处理任务。

直接沿用不创建后处理 E、候选 R、输出记录、资源副本或重复技术报告；整片均沿用时引用原二采轮次，不再登记相同组合。只有部分分段需处理时，完成并核对处理结果后，在一轮完整组合中引用已处理分段的后处理执行和其余分段的原二采执行；新轮次按实际变化填写 base_round 和 changed_segments。每段按实际阶段保存采用，不把同一原文件再登记成后处理产物。

完整组合全部技术合格且已采用后直接进入剪映交接。清单仍按该组合原顺序引用准确文件；资源下载中，纯二采组合归二采交接包，含后处理产物的混合组合归后处理交接包，各分段的真实阶段不变。交接记录、重复下载和历史包规则不变。

## 固定文件与唯一记录

每个视频固定建立：README.md、脚本.md、制作记录.md、制作轮次.json、视频修改意见.json、执行记录/、历史版本/、资源/图片、资源/视频、资源/音频、剪辑交接/、成片/。初始化使用[建档脚本](../../chloe-positioning/scripts/chloe_init.py)，重复初始化只补缺失文件。

- README 的“定位与当前进度”是唯一进度入口；“当前采用”按 `P001/一采`、`P001/二采`、`P001/后处理`保存准确资源引用。采用依据引用制作记录中的审阅编号或技术核对编号，不再抄写结论。
- 脚本保存唯一当前脚本及分段计划。开始一轮前将当次准确稿件保存至历史版本/脚本-v01.md；同版已存在且内容相同直接引用，内容不同先更新版本，不覆盖历史。当前稿与必要历史稿不属于媒体重复保存。
- 制作记录的执行表保存 E 身份、授权与任务 ID；输入、输出表分别以 E 和槽位关联准确资源。“视频分段执行”只把 P、阶段、候选版本、E、输出槽位和模型分段序号关联起来，不复制任务参数或输出路径。
- 制作轮次.json 只引用脚本版本和分段执行，媒体文件、输入及结论仍在原记录；视频修改意见.json 只保存公共工作台的段级及整轮修改意见，不作为批准或采用记录。
- 共用资源只在综合资料/资源保存一份。资源/共用引用.json 绑定具体版本；输入记录保留当次版本，升级素材使用新的绑定键，不能改写历史输入。公共任务 uploads 直接用 `@shared/资源/图片/IMG-编号/V001/文件.png` 或准确原文件绝对路径，不复制到视频项目。
- 新输出由公共资源机制直接分配到本视频资源区。视频输出的名称保留 P 编号便于识别；同一取回任务重试使用相同输出身份，不再导入副本。失败且无输出不造资源行。

## 视频分段执行

固定列：分段编号、制作阶段、候选版本、执行编号、输出槽位、模型分段序号。制作阶段仅为一采、二采、后处理；候选版本为 R001 起的编号，在同一 P 和阶段内唯一；模型分段序号是本次实际 H3 segments 的从零起索引。后处理沿用对应来源分段的索引。

同一个 E 可以产出多个 P，每个 P 通过不同输出槽位关联；同一 P 同一阶段的每次新候选使用新 R。恢复原任务、补下载、补登记不增加候选版本；新的生成任务使用新 E，存在有效旧产物而重新生成时增加 R。审阅表的 R 编号仅在“制作记录.md#审阅记录”内标识审阅事件，与候选 R 的命名空间分开。

“参数记录”链接 `执行记录/E001/提交任务清单.json` 等本次公共任务原清单，同一清单的 tasks 可以包含多个 E 任务，每个 E 以 `record_dir: 执行记录/E编号` 唯一定位自身任务；同一任务也可产出多个 P。多个 E 直接引用同一原清单，不拆分或复制清单。页面通过原清单同目录的 `原清单名-装配结果.json` 读取后台实际装配的任务、project 与 uploads，按执行目录定位；该文件使用公共 read_journal 读取，不另存展开副本。没有装配结果的直接任务清单必须已包含实际 project、record_dir 和 uploads。video_plan 使用 `adapter: technical`、`metadata: ffprobe`；outputs 或 segment_plan.targets 指定实际产出，references 或 uploads 指向原始准确版本；references 的占位名由公共 H3 装配为上传槽位。

任务清单使用公共后台模型与[提交接入](../../studio-workspace-browser/SKILL.md)检查、准备和执行，不能把准备状态当作已经提交。公共后台会分配输出准确版本，提交后将真实任务 ID 写回原 E 行。请求、状态、回执及技术报告由后台原位维护；业务只引用，不再编造第二份后台状态。

视频生成执行的“提示词或正文”只填写[提示词文件规范](#视频提示词文件)要求的Markdown链接，不直接放正文。后处理通过“上游执行”追到原生成提示词；不复制提示词或改写上游输入。

### 视频提示词文件

每个视频生成E执行按[视频提示词模板](../templates/视频提示词模板.md)在`执行记录/E编号/提示词.md`保存一份提示词文件；制作记录以`[提示词](<执行记录/E编号/提示词.md>)`引用。模板只固定承载章节，正文格式按实际H3模式指南编写，不另造模型格式。两个语言章节内均以 `### P001` 等三级标题分段，按视频分段执行的模型分段序号排序，两边 P 编号、顺序和本次执行范围必须一致，不重复或漏段。共用正文可放在各语言章节最前面的 `### 共用` 中，只写一次；页面按“共用正文＋当前 P 正文”展示。分段标题用于文件定位，不作为模型提示词正文提交。单段旧文件没有 P 标题时仍对应唯一分段；多段文件必须明确 P 标题。

固定二级标题为`## 模型提示词正文`和`## 中文提示词参考版`，两节正文均非空。模型正文以英文编写，原对白、歌词和画面文字保留原语言；中文逐节对应最终英文，保留章节键、参考标签、镜号、时间及数值。修改生成准备稿时同步两版，核对实际拼合的共用区与分段区，以及输入记录中的准确版本；不把中文摘要代替完整参考版。参数和工作流仅引用原任务清单，不抄入提示词文件。

提交前完成文件并运行本阶段check；尚无提交或完成事实的记录允许暂缺，准备失败或取消不补造提示词；未完成提示词不能提交。已填写链接则必须能读取且两节齐全。提交后该执行提示词保持原样，内容改变使用新的执行记录，不覆盖历史中文参考。后处理不另写提示词，沿上游执行追溯。

页面英文始终读取实际请求，中文读取上述固定章节中的共用正文和当前 P 分段；准备稿不冒充已提交请求。校验检查文件、章节和填写时点，Agent负责中英含义、时间线及参考绑定一致性，不把格式检查通过当作内容批准。

## 整片轮次

每轮保存完整分段组合和顺序。首批制作或独立修改方案确定送审、准备执行时登记一轮；新的二采、后处理组合同样进入该视频轮号序列。局部返修只替换受影响 P，其余引用此前执行。保存、上传、取回、恢复、用户批准、采用、页面切换和相同内容导出不增加轮次。轮次号、候选 R 和后台任务 ID 分别追溯。

制作轮次.json 的唯一结构为 format: 1 和 rounds 数组。每轮固定字段如下；不得添加媒体副本、审批结论或第二份参数。

| 字段 | 写法 |
| --- | --- |
| number | 从1起连续递增正整数 |
| created_at | 实际登记时间，ISO格式并含时区 |
| note | 本轮范围与目的 |
| script | 本项目历史版本中的准确脚本路径 |
| segments | 完整有序数组，每项只有 id、execution、slot |
| base_round | 局部修改时引用的既有轮号；首次没有此项 |
| changed_segments | 与 base_round 实际不同的 P 编号；仅有 base_round 时使用 |
| review_outputs | 有附加试片、对照或整片后期时使用；每项为 label 和 resource，resource 使用制作记录中同一种准确资源引用 |

```json
{"format":1,"rounds":[{"number":1,"created_at":"2026-11-07T12:00:00+08:00","note":"整片一采","script":"历史版本/脚本-v01.md","segments":[{"id":"P001","execution":"E001","slot":"P001视频"}]}]}
```

准备阶段可先登记视频分段执行和轮次，未取回前不造输出资源行。页面保留未取回状态；输出到达后通过原 E/槽位读到准确资源。尚未形成首轮时读取当前脚本计划，不自动造轮次。

## 审阅、返修与异常恢复

用户决定只在制作记录的审阅表写一次；对象引用使用 `[第1轮](<制作轮次.json#round-1>)`，局部决定注明 P 编号及候选版本。整体意见和逐段修改正文在视频修改意见.json 原位保存，审阅记录链接该文件，不逐段抄写同一意见。返修表关联原 E、审阅 R、修改范围及后续 E。

修改意见属于特定轮次或候选，公共接口核对已有身份并处理并发保存。更换参考、改脚本或改商品信息先判断影响范围，只重做相关分段；已采用组合在新的采用完成前保留，不因新候选到达自动覆盖。

异常按[公共进度与结果处理](../../studio-workspace-browser/references/进度查询与结果处理规范.md)和原任务报告恢复。先确认原任务、请求及输出状态；已授权的取回、登记修复继续原任务。断线、状态未知、回执缺失不能当作失败重新提交。真实重生成只在已明确的重试范围和次数内执行，不自动增加额度。

## 后台结果接续

收到通知按[公共通知接续](../../studio-workspace-browser/references/ComfyUI-任务监控规范.md#后台通知接续)读取报告，复用原任务的取回和技术核验，先按真实任务类型区分图片超分与视频阶段。两者均按原E编号及输出槽位补齐制作记录；只有视频任务补齐对应分段执行和轮次关联。technical成功不表示业务登记或采用已完成，不复制任务参数、媒体或报告。

镜头参考图超分的通知按[镜头图片接续](../../chloe-assets/references/镜头参考图制作流程.md#5-批准后2倍超分与自动采用)处理，只更新图片E执行、输出和README镜头用途采用，不写入视频分段执行或制作轮次，不推进一采、二采审阅。

对照本轮完整P组合确定阶段是否齐备；一个任务组完成不代表整条视频全部分段完成。一采、二采齐备后按[配置与整片推进](#配置与整片推进)交用户审阅；批准即按已确认配置接续下一阶段。需要处理的分段齐备后，连同直接沿用的二采分段按各自原技术报告核对已确认指标，合格后按[采用、交接与页面](#采用交接与页面)登记采用及剪映交接，不新增内容审批。缺项或异常按[审阅、返修与异常恢复](#审阅返修与异常恢复)沿原任务处理。

## 采用、交接与页面

收尾一次完成：记录用户决定或技术核对依据 → 更新对应 P/阶段采用引用和采用变更 → 更新 README 阶段、处理状态与下一步 → 检查引用与页面。引用原审阅或报告，不在多处维护同一结论。本次完整组合（后处理产物及无需处理的二采原文件）全部合格采用后交[剪映交接](../../chloe-handoff/SKILL.md)。成片不另登记，用户人工导出，发布时引用具体文件。

制作页直接使用完整公共 ProductionWorkbench。整片列表来自实际 V 项目；轮次与播放顺序来自制作轮次，分镜来自对应脚本快照，英文与输入来自原请求，素材及视频来自唯一资源文件，意见使用原公共保存协议，采用读取 README。Chloe 的分镜脚本标签只显示对应脚本“镜头与分镜”章节，隐藏分镜修改标签；完整脚本仍保留在原文件，分段审阅意见功能不变。浏览不生成、采用或复制媒体。

导演分镜表按[本业务接入](../../chloe-creative/references/导演分镜表业务接入.md)记录独立脚本版本、图表版本和候选编号，输出槽位使用该接入模板；当前采用引用同一资源，页面保留候选、采用与全屏查看。任务原目录的 `.workflow.json` 供画布下载；实际 H3 请求与已记录输入可重建导演包，点击下载才临时打包。剪映清单保存于剪辑交接/，直接引用采用片段，公共工作台提供包下载。资源下载和轮次交接入口共用交接时点校验结果：可下载或已交接清单按当时采用的准确版本及已有轮次展示；后续替换或取消当前采用，不隐藏之前有效交接的历史包。旧清单不改写，重复下载不新增清单、交接记录或资源。

## 固定校验命令

保存后先执行[固定资料检查](../../chloe-positioning/references/固定资料写法规范.md)，再从工作区总目录运行：

```sh
"工作区浏览服务/.venv/bin/python" .agents/skills/chloe-production/scripts/chloe_production.py check --project "/实际工作区/workspaces/Chloe Workspace/用户提供的项目名/projects/V001-视频名称"
```

Windows 使用浏览服务 `.venv/Scripts/python.exe`。`--project` 必填，指向单条视频的实际绝对目录，无默认项目。脚本仅本地读取，不写文件、不联网、不生成；成功输出 project、rounds、candidates 计数并退出0，资料或引用不符合规范时非零退出并说明错误。它校验完整组合、阶段、唯一候选、源执行、准确资源、局部沿用与脚本关联，不判断画面质量或代替用户批准。

维护时在浏览服务目录使用其虚拟环境运行 `python -m unittest tests.test_chloe_production -q`，检查初始化、准确引用、完整与局部轮次、意见保存、原请求及导演包、共享输入和交接；测试使用临时资料和模拟远端，不写真实项目或执行生成。页面验证使用 `node tests/test_chloe_production_ui.mjs`，覆盖公共工作台的正常、读取错误／重试及三档桌面布局。
