# 视频结果自动登记

## 分段记录字段

“视频分段执行”的固定列为分段编号、制作阶段、候选版本、执行编号、输出槽位、模型分段序号。现有逐段记录支持一采、二采、后处理。候选版本从 R001 起，在同一 P 和阶段内唯一。模型分段序号是实际请求中分段从零起的索引，后处理沿用来源分段的索引。

复用已上传输入时，页面沿同一分段的上游执行读取原上传映射和文件校验依据，用本次请求的素材标识匹配原文件。

## 提交时固定关联

`chloe-video` 接收 `video-first-pass`、`video-second-pass` 和 `video-postprocess`。原执行、实际输入、中英文提示词及授权先按制作规范登记，在原“视频分段执行”建立 E 与 P、槽位、阶段、候选关联，在 `制作轮次.json` 建立完整且有序的本轮组合。结果收尾回填原记录。

在原任务 `video_plan` 中保留 `adapter: technical` 和 `metadata: ffprobe`，增加：

```json
{
  "business_result": {
    "adapter": "chloe-video",
    "document": "制作记录.md",
    "execution": "E003",
    "round": 2,
    "outputs": [{"slot": "P001视频"}, {"slot": "P002视频"}]
  }
}
```

所有路径相对单条视频根目录。`outputs` 按 `segment_plan.targets`（AiMixer 导演台）或 `outputs`（普通任务）的声明顺序一一对应，后台以准确输出路径匹配返回，不把返回先后当分段顺序。提交检查要求执行、槽位和任务类型与轮次阶段一致。

一采、二采只更新原执行和输出，绝不自动批准。脚本读取本轮全部分段（包含沿用的旧执行），全部已完成且有准确资源引用才置 `round_ready: true`，更新README为整片待用户审阅；部分完成返回“等待本轮其余分段”。历史轮次只补结果，不覆盖最新轮次进度。

## 后处理自动采用与交接

在同一个 `business_result` 中增加 `adopt`，指向本视频原制作记录中已通过的整片二采R行；原R对象写 `[第2轮](<制作轮次.json#round-2>)`。每个输出增加确认的技术目标和提交时当前采用值：

```json
{
  "adopt": {"document": "制作记录.md", "review": "R001"},
  "outputs": [{
    "slot": "P001视频",
    "previous": "无",
    "expected": {"width": 1080, "height": 1920, "frame_rate": 30, "duration": 10.1, "audio_tracks": 1}
  }]
}
```

宽高为像素，帧率为fps，时长为秒，音轨为实际条数；不得用例子替代本次确认值。时长基于准确输入技术报告，允许输出帧网格的一帧取整差异；帧率允许0.001fps的表示差异，宽高及音轨数必须匹配。直接复用现有ffprobe技术报告，不再启动媒体探测或做内容审阅。

技术结果匹配且上游确属批准的二采组合时，登记对应P/后处理当前采用与B变更，依据链接原R和技术报告。`previous` 为该用途原采用完整引用，没有填“无”；返回期间采用改变则停止覆盖。全部分段已完成、已采用后，在 `剪辑交接/第N轮.jianying.json` 生成引用原视频的唯一清单，README登记一条J行并进入人工后期；重复接续复用同一清单。混合阶段轮次包含已采用的原二采文件时，照本轮完整顺序写入，不复制媒体、不创造后处理执行。

无须后处理仍按现行直接采用规则引用已批准二采原文件，不为触发本脚本提交空处理任务。浏览页临时打包与正式交接清单各按原用途使用，不生成长期视频副本。

## 通知、恢复与检查

后台 `business_sync` 返回 `execution`、`round`、`stage`、`round_ready`、`adopted`、`handoff`、`historical` 和 `next_action`。正常 `updated` 已包含所写固定文档及视频制作关联检查，Agent直接处理审阅或接续，不再跑同样校验、改写原行或重读视频。出现缺项才按具体错误恢复，技术报告继续复用。原报告恢复命令见[图片结果登记的恢复入口](../../chloe-assets/references/结果自动登记.md#通知与恢复)，owner 改为单条视频根目录，manifest 使用原视频任务清单；同一入口按明确适配选择本业务脚本。

后台不自动提交下一阶段生成。用户批准或既有生成授权由当前业务会话按现有流程接续，登记脚本不把技术完成当生成授权。

隔离回归在 `工作区浏览服务` 目录执行 `.venv/bin/python -m unittest tests.test_chloe_result_completion tests.test_chloe_production_chain tests.test_chloe_handoff_export -v`，覆盖整轮待审、后处理目标不符、自动采用与交接、历史轮次与原文件引用；不提交真实生成。
