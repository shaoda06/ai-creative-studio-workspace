# 会话组织与接续规范

适用：Chloe 的会话职责安排、命名、业务接续与进度查询。会话组织由本规范统一维护，具体制作方法、资产规格、采用及完成条件仍由对应业务技能维护。

## 会话职责与命名

Chloe 使用一个主控、六个长期职能会话，并为每条视频单独使用一个制作会话。长期职能按当前选定的具名项目接续，不按单个模特、发型、服装、场景、声音、素材批次或生成轮次另拆会话。

| 会话名称 | 职责 | 业务技能入口 |
| --- | --- | --- |
| `Chloe｜主控` | 接收需求、安排工作、维护实际会话入口、查询进展及协调跨会话交接 | [Chloe 一级业务](../SKILL.md) |
| `Chloe｜01-账号与选品` | 账号方向、商品筛选、商品事实与选品决定 | [账号定位](../../chloe-positioning/SKILL.md)、[选品](../../chloe-selection/SKILL.md) |
| `Chloe｜02-模特` | 模特设定、面部与基础全身图片（含遮面版）的制作、修改及采用 | [资产与镜头图片](../../chloe-assets/SKILL.md) |
| `Chloe｜03-服装与造型` | 服装及发型资料、参考提取、展示图、穿搭设计、定装图及相应修改与采用 | [资产与镜头图片](../../chloe-assets/SKILL.md) |

主控不编号；长期职能编号固定为01—06，只表示职责，不代表执行顺序。视频会话使用实际视频编号，依次如 `Chloe｜V002视频制作`、`Chloe｜V003视频制作`，标题不附加视频名称、连字符或职能编号。

用户明确要为某条视频先建会话时，先核对该项目的 `projects/` 和项目 README 会话入口表。同一条视频已有会话就直接复用。视频尚未建档时，按项目内的顺序确定未占用的编号，例如首条视频用 `V001`，创建时直接命名为 `Chloe｜V001视频制作`，并将真实会话入口登记在项目 README。主题和视频名称可以之后再定。若本次只授权建会话，等用户明确要建档时再用同一编号建立视频目录。

会话与技能不一一对应：同一视频会话按当前步骤调用多个技能，多个资产会话按各自对象调用同一个资产技能。切换业务技能不要求切换会话。收到执行请求时按[职责分流](#业务会话职责分流)确定承接会话。每条视频的修改和返修继续使用本条会话，不按镜头、分段或一采、二采等制作环节另开会话；下一条视频使用自己的编号和会话。

## 共用资产与单条视频的交接

- **模特、服装与造型**：模特会话维护模特本身、基础发型及基础图片。服装与造型会话维护服装和可复用造型发型，也负责为指定模特搭配服装、鞋履、配饰与发型并制作定装图。定装引用模特、服装和所选发型已采用的准确版本。一件服装可被多个模特引用，一个模特可有多个造型。服装本身是商品时，按[商品资料规则](../../chloe-selection/SKILL.md)确定资料对象。
- **共用资产与镜头图片**：视频会话在本条脚本或制作记录中明确需要的模特、造型、服装、场景、声音及用途；共用资产缺项交对应长期职能会话准备。仅为本条镜头新生成的首帧、组合画面及导演分镜表由视频会话按相应技能完成。
- **采用与引用**：共用资产的说明、修改和采用由对应资产会话维护；视频会话选用并记录本条所需的资产版本。媒体保存、版本绑定及复用按[资源规范](../../chloe-assets/references/资源存储与引用规范.md)执行。
- **交接内容**：传递实际资料路径、对象或视频编号、用途、准确版本、已确认决定、本次待办和完成条件。已有记录直接链接，不复制全部聊天历史，不另造派单或进度台账。涉及同一资料的关联更新由本轮实际维护者完成，其他会话读取更新后的文件接续，避免重复提交或同时改写同一项内容。

## 主控与业务会话接续

1. 主控根据本次需求确定承接会话，读取相关资料及当前进度，复用已有入口。用户已在业务会话明确任务时，直接按[职责分流](#业务会话职责分流)接续。
2. 主控按[会话入口登记](#会话入口登记)维护实际入口；启动说明写明实际工作区或视频项目路径、会话职责、适用业务技能和本规范、所需材料、待办及本次完成条件。会话名称和视频编号必须对应实际对象。
3. 业务会话负责其范围内的讨论、制作、修改、审阅接续与保存。形成可审阅成果、记录用户决定或收尾时，按原业务规则更新对应资料，报告成果入口、实际状态、未解决事项及下一步。只讨论或只读评审不擅自写入资料。
4. 主控从实际文件查询进度并协调下一项工作；返修回到原职责或同一视频会话。一次任务完成不代表长期职能会话关闭，也不自动归档或删除会话。用户已明确授权的阶段接续按原流程执行，不因会话交接增加一次审批。

本轮仅负责跨会话移交时，以交接消息成功发到指定会话为完成条件。移交会话简短汇报接收会话和已移交的内容，随即结束本轮。后续制作、审阅和成果交付由接收会话负责。用户明确要求移交会话跟进时，才按要求查询进度或等待结果。

会话创建、改名和侧栏整理按用户实际授权及当前工具能力执行。只确认组织方案、维护规范、初始化资料或安排业务任务，不自动创建会话；需要新会话但尚无创建授权时，提供启动说明。已有入口直接复用，历史工作不为凑齐编号补建空会话。尚未开展的会话只承接职责和材料入口，不因创建成功启动生成或发布。

### 业务会话职责分流

收到用户明确要执行的任务时，先判断任务是否属于当前会话。职责范围内的任务直接接续。明显属于另一会话的任务，按[会话职责表](#会话职责与命名)和[项目会话入口表](#会话入口登记)确定同一项目内已登记的接收会话。混合任务按依赖顺序处理当前会话负责的部分，只移交职责外的部分。讨论、询问和比较留在当前会话。用户明确指定执行会话时，按本次指定办理。

发送按用户本次明确授权或所属 Chloe 工作区 README 中已记录的用户常设授权执行。授权覆盖时直接发给已登记的对应会话，无需逐次确认。按[交接内容](#共用资产与单条视频的交接)传递用户原始需求、准确资料版本和已确认决定，成功发出后按[移交完成条件](#主控与业务会话接续)收尾。接收会话按任务原有的生成、采用及发布授权继续。

归属不明确、没有已登记的接收会话或发送授权缺失时，先核对已有资料，确需用户决定时只确认缺项。发送未成功时说明具体情况，有专项接续方式时按对应流程办理。

## 会话入口登记

主控将本项目实际使用的主控、长期职能及各视频制作会话，统一登记在 `workspaces/Chloe Workspace/{项目名称}/README.md` 的“项目接续与相关资料”章节，使用[项目README模板](../../chloe-positioning/templates/项目README模板.md)中的会话入口表。

只登记会话名称、职责和真实会话入口。入口保留工具返回的会话ID，有可用链接时一并保存；不自行拼造链接。创建或复用入口后补登，改名更新原行并保留会话ID；没有真实入口时不预填记录。主控接续或安排工作时先查此表，业务会话按[职责分流](#业务会话职责分流)从此表定位相关承接会话。业务进度和执行经过不填入入口表。

## 进度与运营接续

主控从会话入口表找到承接会话，再按[流程与状态](../SKILL.md#流程与状态)读取实际进度和成果。各业务会话按所属阶段维护相关资料；记录位置与状态沿原业务规范执行。

视频制作会话按[剪映交接](../../chloe-handoff/SKILL.md)接续人工后期结果；用户明确制作完成后，按该技能更新制作状态，并向运营与复盘会话交接视频目录、已明确的成片文件及已有资料。满足[自动接续触发条件](../../chloe-positioning/references/社媒运营接入规范.md#自动接续触发条件)后，主动推进发布准备，不把交接变成等待用户再次提醒的停点。有可用承接会话及已获授权的交接方式时沿用；暂时无法完成跨会话交接时，由当前会话按运营规则继续准备，并将成果写回原记录，不为接续擅自新建会话。运营与复盘会话负责成片检查、封面与文案、页面核对、发布方式选择及获授权的发布安排，具体按[成片与发布接续](../../chloe-positioning/references/社媒运营接入规范.md#成片与发布接续)执行。用户提前安排发布准备时，由运营会话按同一规则处理当前可完成部分，缺项如实交接，不倒推制作完成。

复盘由运营与复盘会话按[带货复盘](../../chloe-review/SKILL.md)执行；建议交账号与选品、相关资产或对应视频会话按实际任务处理。
