# 资源存储与引用规范

## 唯一存储与业务引用

共用实际媒体只保存于`Chloe Workspace/综合资料/资源/{图片,视频,音频}/`，由[共用资源管理](../../studio-workspace-browser/references/项目资源与版本管理.md)维护索引、资源编号、V版本、资源信息与版本信息。商品、模特、服装、造型、场景、声音目录只保存说明和引用。所有实际结果包括未采用候选按版本保留，采用不由资源索引推断。

每条视频`资源/`只保存本条真正新增的图片、视频、音频及其索引。`资源/共用引用.json`记录共用资源的准确版本，没有媒体副本。人工剪映成片归本视频`成片/`，交接清单归`剪辑交接/`；两者引用原资源，不再把成片或下载包导入媒体库。原图与遮面版、不同真实生成结果是不同产出，不以相似为理由覆盖。

业务资产编号G/M/O/L/S/A与视频编号V，不替代底层资源编号。业务说明记录当前候选、采用和关系；脚本返回实际资源编号，不手工猜IMG编号。一个资产可以引用多个资源，一个资源也可被多个资产或视频引用。

## 保存、列举与版本

从总目录使用`工作区浏览服务/.venv/bin/python .agents/skills/chloe-assets/scripts/chloe_resources.py --workspace 'workspaces/Chloe Workspace'`，后接动作：

```text
import --file 外部实际文件路径 --key 实际导入或任务输出身份
import --file 外部新结果路径 --key 新输出身份 --resource-id 原资源编号
import --file 外部新结果路径 --key 新输出身份 --origin generated --record 所属范围内实际执行记录
list
list --project 实际视频目录名
```

以上是参数占位说明。默认导入共用资源；仅本视频的新产出添加`--project`。`--record`相对于所属范围：共用为综合资料，视频为视频根目录；生成／处理结果必须给出真实记录。`--parent`用于同一归属内的准确来源版本文件；跨归属来源通过共用引用键及执行记录描述，不伪造项目内parent。

同一实际输出重试沿用同一key，独立任务或新轮次使用新key。同一制作目标修订传原resource-id，独立素材不传。共用存储锁与版本分配复用现有代码，同归属内完全相同的内容按原机制只保留一份物理数据，同时保留独立任务来源。不要把独立任务误写成同一次重试。

导入脚本用于外部原件或尚未入库的新结果；禁止重新导入工作区内已有媒体。共用工具已经直接入库的结果沿用其返回编号、版本和路径，不再走import。工具临时输出成功入库并核对后，按该工具的临时文件收尾规则清理；用户原始外部文件不自动删除。不要长期另留一份“供引用”副本。

## 视频绑定与解析

```text
bind --project 实际视频目录名 --key 任务/镜头/轮次/用途 --resource-id 实际编号 --version V001
resolve --project 实际视频目录名 --key 任务/镜头/轮次/用途
```

绑定保存owner、resource_id、version、workspace相对file，检查版本真实完整；不接受latest或只指向业务说明的动态引用。resolve只读返回实际文件路径，供支持该路径范围的工具使用。

同一个键重复绑定相同版本不变，改绑另一个版本报错；新轮次用新键。共用资源更新采用至V002后，旧任务V001输入保持原样。实际提交记录保存所用键和版本，绑定本身不表示已提交、已采用或已发布。引用由项目资源锁保护并原子写入，多任务追加不覆盖彼此。

无需为每个视频复制共用媒体，也不建立指向共用媒体的项目内硬链接／软链接来绕过路径限制。当前网页和远端工具的项目访问边界不因这份引用表自动扩展；具体接入见[运营接入](../../chloe-positioning/references/社媒运营接入规范.md)。支持不足时先说明限制，不冒用其他空间提交。

## 保留与追溯

不因候选未采用就删除，不覆盖已记录版本文件，不根据文件名或修改时间猜采用。生成、处理、审阅和用户决定各记其事实；资产说明维护当前采用，视频README维护本条有效采用组合，制作记录和引用表保留真实历史输入。默认初始化与绑定不迁移、删除或复制任何已有素材。


## 系统文件格式与唯一维护者

系统文件由共用资源脚本和Chloe引用脚本产生；不由Agent手写索引、猜版本或变更字段名。共用格式真源为studio-workspace-browser/scripts/project_resources.py，Chloe只使用已有结构，不维护第二份资源schema或批准状态。

| 文件 | 必有结构 | 写入入口 |
| --- | --- | --- |
| 资源索引.json | format为1，managed为true，families、next_versions、outputs、files、aliases均为对象；files按所属资源范围内相对路径关联版本记录 | 共用initialize、reserve、finish；Chloe初始化或import调用 |
| 资源信息.json | resource_id、kind、family_key、name、created_at | 共用资源首次分配身份时生成 |
| 版本信息.json | resource_id、version、file、family_key、kind、origin、producer、parent、registered_at、facts；有实际处理区间时另含source_range | 共用finish按真实结果生成 |
| 共用引用.json | format为1，references为对象；每个键的值固定为owner、resource_id、version、file | Chloe initialize_video创建空表，bind追加，resolve只读 |

索引及版本的file相对于资源归属根目录：共用为综合资料，视频为视频根目录；共用引用表的file相对于Chloe工作区根目录，owner固定为综合资料。两种路径基准不同，不得混用。version使用V加至少三位数字，编号与版本取脚本返回值。

producer引用实际执行记录，parent为同一资源归属内的准确父版本记录或null；跨归属输入通过视频共用引用表及制作记录关联。facts保留工具实测信息，图片包含宽高和格式，音视频按实际探测字段保存；不为了满足固定模板编造缺失参数。系统格式的字段扩展由共用工具维护，Chloe不私改其JSON。

Markdown中的资源引用采用[固定资料写法](../../chloe-positioning/references/固定资料写法规范.md)规定的归属、编号、版本标签和原文件链接。检查脚本核对JSON之间、JSON与实际文件以及Markdown与JSON的对应，不改写系统文件，也不以检查结果代替采用决定。

剪映清单是另一类技术文件，采用[共用清单格式](../../studio-workspace-browser/references/业务接入规范.md#项目媒体清单与剪映下载)：name为名称，media为有序数组，每项file为当前视频内原文件路径、member为包内相对文件名、timeline为布尔值。Chloe清单显式填写timeline；不同项member不可重复，至少一项进入时间线。该格式已有共用示例，不在本业务另造JSON模板；业务交接状态只在视频README维护。
