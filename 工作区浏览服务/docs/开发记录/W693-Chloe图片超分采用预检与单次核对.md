# W693：Chloe图片超分采用预检与单次核对

日期：2026-11-16
状态：已完成
关联版本：v0.8.418（已发布）

## 修改原因

同一原图的 Markdown 链接使用不同路径分隔符时，超分回图后曾被误判为来源不一致。工作台核对也曾分多次读取。

## 具体改动

- Chloe 图片登记解析审阅、输入及当前采用的资源链接，按已登记文件身份比对，兼容两种斜杠。准备和入队预检同时核对 RTX 节点的实际上传及清单中填写的成果父版本。即使复用准备报告，入队仍按当前审阅与输入核对。
- 收尾继续检查当前采用是否发生变化。规则规定复用成功报告，同一对象通过一次详情读取一起核对用途、版本及采用状态。
- 复查补齐三处入口。Chloe 与现有图片处理共用原图、RTX、保存节点的连线校验，正式采用使用固定 2 倍 ULTRA 参数。清单及直接提交共用入队校验，开工复查审批。清单 `previous` 在准备、入队和开工时与实际采用版本比对，回图时保留原有并发保护。自动和手动业务恢复均校验原任务连线。
- 共用报告说明区分技术适配和已配置的网页核验。Chloe 使用原清单的用途和已登记成果身份，沿同一对象一次详情读取交付。

## 验证结果

- 18 项隔离回归通过，覆盖混合斜杠采用、错误版本拦截、复用预检报告时重新核对、保存及重复收尾。
- 隔离计时中，正常预检 8.9 毫秒，错误上传拦截 6.9 毫秒，已有取回结果登记 39.8 毫秒。通过真实工作台一次只读详情请求确认现有正式图片，读取并核对耗时 5.175 秒。隔离计时从已有文件和报告开始，未测远端超分及通知耗时。
- 补验运行 93 项，92 项通过，1 项 POSIX 专项按 Windows 平台条件跳过。覆盖错连线、错误倍数、撤回审批后的直接入队和开工、过期 `previous`、回图保留新采用，以及从任务或原报告恢复时的连线拒绝。同步适配了 Windows 下故意替换只读测试图片的夹具。
- 正式前端构建后通过托管启动器重启 8782。服务返回 `version=0.8.418`、`ready=true`、`environment=production`，静态发布标识也为 0.8.418。
- 发布后隔离验收覆盖同图混合斜杠、入队和开工预检、错版拦截及已有结果正式登记。对应耗时为 47.6、14.4、39.3 毫秒。正式工作台一次对象详情请求确认图片用途、准确版本及正式采用标记，耗时 4.554 秒。未在正式业务目录写入测试记录。
- 公共组件复用检查：不涉及。差异限定为后台接入、业务脚本、收尾规则及隔离测试，未修改前端组件、样式或展示页。
