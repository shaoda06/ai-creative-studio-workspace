# W636：恢复旧任务成果状态与入口

日期：2026-11-09
状态：已完成
关联版本：v0.8.343、v0.8.344（已发布）

## 修改原因

旧任务在缺少逐文件下载事件时仍可能有完整取回计数或分段核对状态。详情页没有使用这些凭据，也没有解析已迁移的媒体路径，导致已落盘的成果显示为待取回。

## 具体改动

直接输出的旧任务在完成状态和取回计数覆盖全部目标时显示实际取回结果。分段输出识别其对应文件的旧核对状态，并使用项目资源索引定位迁移后的文件。取回时间仍来自实际事件，已有的失败和缺文件状态按原依据展示。

首次实机复查发现，旧输入映射保留候选路径，后台启动后已把相应凭据转换成资源版本路径。详情把两种项目内路径按同一资源核对，仍使用原凭据判断取回状态。

## 验证结果

任务详情、任务后台及资源迁移合计执行 57 项隔离测试，56 项通过，1 项按现有条件跳过。旧任务的已取回、待取回、实际失败、缺失文件和历史归档入口均有用例覆盖。并发上传用例在本机 Windows 返回 503 和权限错误，改动前的代码复现相同结果。

补充了输入映射和持久任务分别使用两种路径的用例。本地只读重放后台启动的路径转换后，已完成任务的各个成果均能定位已保存文件。

- 公共组件复用检查：暂存静态检查确认无前端源码变更。详情使用现有的状态、链接字段和组件，暂存快照的 1280×640、1366×768、1920×1080 桌面布局检查通过。

- v0.8.344 正式构建通过。启动器等待超时后，同一托管进程继续启动，实际接口返回 v0.8.344 与 ready=true。Chrome 的真实历史详情显示已保存，点击文件入口实际收到 MP4 响应。受影响的文件入口逐一核对 HTTP 范围读取，并对页面打开的样片从同一地址完成首帧解码。Chrome 无头直开页未报告播放就绪。
