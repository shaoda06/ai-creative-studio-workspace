# W469：淘汰失效缓存并限制日志与测试媒体占用

日期：2026-11-03
状态：待发布
关联版本：v0.8.182（待发布，与W468共同切换）

## 修改原因

旧工作区路径留下964份已无法读取的项目缓存，主日志约246MB且主要是正常轮询，同一隔离样稿还保存了23份重复媒体。用户要求处理历史占用，同时让后续缓存、日志和测试媒体有实际的清理及复用机制；本次不处理`.codex`、任务库、迁移备份和独有验证素材。

## 具体改动

正式启动器在新worker启动前淘汰根路径、结构不兼容及已删项目的缓存，保留当前兼容缓存；仅版本递增不清缓存。主日志统一按10 MiB轮转并保留2份备份，过滤正常状态轮询，保留异常与写操作；旧超大日志在旧worker停止后由新worker初始化时保留近期约2 MiB。系统托管标准输出改为每次启动重置的launcher.log，不再长期持有主日志。

将已有PNG只读保存逻辑提取到共用media_files.py，原store_png接口继续使用；MOV、MP4等测试媒体也调用同一实现，同一隔离目录内复用相同内容，保留原路径，不与正式项目硬链接。新增prepare_test_media.py清单入口，临时下载及技术处理使用独立临时目录，成功或失败后清理，只保留清单明确的成果。

已对既有隔离多产物样稿合并10组、23份重复媒体，扣除新增准备清单后净减少328,859,648字节；全部原路径和字节保留。样稿补充可重复执行的媒体准备清单，统一入口、技术测试及PNG维护规范均能到达共用实现。`.codex`、任务库、迁移备份及独有验证素材未清理。

## 验证结果

75项相关回归检查完成，73项通过，2项仅适用于原生Windows的cmd和junction检查在macOS跳过；覆盖缓存退役与兼容复用、日志轮转与异常保留、准备失败清理、PNG版本保护、启动器及项目读取。Windows只读替换分支的隔离模拟通过，不冒充原生Windows验证。

4个受影响技能格式校验、11个新增Markdown路径及锚点核对、差异空白检查通过。样稿3种媒体的Range与下载共6个真实HTTP请求通过；临时静态服务已停止。正式前端v0.8.182构建通过；等待在原制作任务结束后与任务库迁移一起切换。
