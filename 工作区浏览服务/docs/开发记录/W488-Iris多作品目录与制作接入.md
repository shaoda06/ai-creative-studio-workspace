# W488：Iris 多作品目录与制作接入

日期：2026-11-06
状态：已完成
关联版本：v0.8.204，已发布

## 修改原因

Iris 一个项目可以管理多件作品，同片横竖、长短版属于该片的交付版本。原目录、阶段文件、候选、意见与交付默认都在项目层，无法分清不同作品。

## 具体改动

先在 Iris 综合资料保存完整审计方案，更新一级入口、七个阶段、目录与 README 规范、项目/作品状态和阶段模板。项目保留共享原稿、媒体库和整单复盘；作品以稳定的 F 编号管理阶段资料、轮次及交付版本。

生产业务适配新增作品身份与明确的历史来源，旧任务保持原目录及 ID。后台提供作品资料、生产、上下文与意见接口；文件、媒体和剪映清单继续使用项目边界。网页各制作栏目使用同一公共 TabSelect 切换作品，查询及编辑范围跟随作品，项目概况、全部资料和资源库保留项目范围。

先用双作品和三个真实项目的隔离副本验证，再迁移 C001、C002、C003。共归位 79 份业务文件，确认空置的 11 个旧阶段目录移除。原业务文稿留紧凑备份；媒体、历史任务与执行附件保持。

## 验证结果

- 八个 Iris 技能格式检查、159 个规则及模板本地文件链接通过。两处 README 模板中的状态目标引用按生成位置检查，三个项目及作品的六节 README 和状态文件均符合。
- `tests.test_iris_works`、`tests.test_iris_work_migration`、`tests.test_project_production`、`tests.test_workspaces`、`tests.test_project_packages` 合计 35 项通过，覆盖多作品 P001/R001、独立意见、旧来源、结果补回、空/未知作品、越界、按需下载与文稿迁移。
- `tests/test_iris_works_ui.mjs` 与 `tests/test_project_production_ui.mjs` 均通过 1280×640、1366×768、1920×1080。使用独立 Vite、静态媒体和隔离响应，验证切片、读取重试、意见冲突/失败恢复、刷新接续及下载；没有请求真实生成服务或写正式项目意见。
- 三项目副本先执行同一脚本，候选、提示词、采用图片和资源不变，移动文稿的项目内文件链接缺失为 0。副本检查发现无 Markdown 包装的资产路径也需转换，修正后复验通过，再用于正式迁移。
- 正式接口核对 C001/C002/C003 分别为 13/8/2 段、88/26/2 个候选，C002/C003 采用图片仍为 8/5 张。主文档可读、图片视频区间请求为 206、C001 历史上下文可读、C002 剪映清单 8 项输入存在。
- 正式页面实际核对 C001 历史清单、C002 作品正文、C003 作品及生产批次。通过统一启动器发布，`/api/service` 为 0.8.204 且 ready=true；重启前无排队或运行任务。
- 公共组件复用检查：人工核对本次 IrisProject、ProjectSpace 和容器 CSS；作品选择复用 TabSelect，查询错误复用 Result，播放器、意见、下载及预览沿用公共实现。新 CSS 只排列作品工具栏；没有覆盖公共控件的字号、内边距或交互，没有新增公共规格，组件实现说明已同步。提交钩子的暂存静态检查为 0 项需修正、0 项待人工判断，三档桌面公共布局检查全部通过。

本次未提交 H3 真实生成，未对正式项目自动打包，也未逐包打开剪映。业务采用和客户交付事实沿原记录。
